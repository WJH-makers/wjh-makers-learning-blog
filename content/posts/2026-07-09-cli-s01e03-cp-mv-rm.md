## 一、需求:存双份、搬个家、大扫除

昨天 `>` 一口吞掉三行笔记的事,阿零还心有余悸。他列了张今日清单:

1. 把 `notes.md` **复制**进 `backup/`——重要文件从今天起一律双份;

前两件事需要"搬"和"印",最后一件需要"删"。特米听完清单,肚皮上的 `>_` 闪了两下:「前两个随便学。第三个——**学之前,先学怕。**」

## 三、本话目标

- `cp` 复制文件,`cp -r` 复印整棵目录树(源在前,目标在后);
- `mv` 一个命令两种用途:**移动 = 改名**,本质都是换挂钩;
- 直面 `rm`:没有回收站、静默成功、不会喊疼;
- 踩一次经典事故:`rm * .tmp` 多一个空格,glob 无差别展开;
- 建立第一性原理:**`*` 由 shell 展开,rm 收到的从来只是一张名单**;
- 四条保命习惯:先 `ls` 预览、`rm -i`/`-I`、写全路径、动手前 `cp`。

## 四、原理图:rm 收到的是名单,不是星号

```text
你敲的:    rm * .tmp        ← 想删 *.tmp,手一抖多了个空格
              │
              │  shell 先干活:把 * 展开成当前目录的所有名字(按字母序)
              ▼
rm 收到的:  rm backup coffee-shop draft1.tmp draft2.tmp logs notes.md .tmp
              │
              │  rm 照单执行,一视同仁:
              ▼
            文件 → 静默 unlink(成功不吭声)
            目录 → 拒绝(没带 -r):报错
            .tmp → 查无此文件:报错

删除的真相:rm = unlink,把"名字 → 数据"的挂钩摘掉,数据块标记为可复用
            没有回收站,没有 Ctrl+Z;数据被新内容覆盖之前叫"侥幸",之后叫"永别"
危险叠加:  -r 让它钻进目录  -f 让它连问都不问  →  rm -rf = 静默拆掉整棵子树
```

一句话:**rm 本身不危险,危险的是你不知道 shell 递给它的名单上写了什么。**

## 五、上手:先印、再搬、试删一个

```bash
$ cp notes.md backup/notes.md.bak        # 复印:源在前,目标在后
$ ls backup
2026  notes.md.bak

$ cp coffee-shop backup/                 # 想复印整个目录……
cp: -r not specified; omitting directory 'coffee-shop'
$ cp -r coffee-shop backup/coffee-shop-0921   # 目录要 -r,整棵树一起印

$ mv memo.txt memo-0921.txt              # 改名
$ mv memo-0921.txt backup/               # 移动 —— 同一个命令,同一件事
$ ls backup
2026  coffee-shop-0921  memo-0921.txt  notes.md.bak

$ touch draft1.tmp draft2.tmp draft3.tmp # 练习攒下的垃圾(一会儿清掉)
$ rm draft3.tmp                          # 先删一个试试 —— 没有任何输出,这就是"成功"
```

> **特米旁白**:同一块磁盘上 `mv` 只是把挂钩换个位置,搬 1GB 和搬 1KB 一样快;`cp` 是真的逐字节复印。另外 `mv` 撞上同名文件也会**静默覆盖**——不放心就带上 `-i`。

## 六、故意制造一个 Bug:多一个空格的大扫除

清理剩下的 `.tmp`。阿零想敲的是 `rm *.tmp`,实际敲出来的是:

```bash
$ rm * .tmp
```

星号和 `.tmp` 之间,多了一个几乎看不见的空格。回车。

## 七、读懂真实报错

```text
rm: cannot remove 'backup': Is a directory
rm: cannot remove 'coffee-shop': Is a directory
rm: cannot remove 'logs': Is a directory
rm: cannot remove '.tmp': No such file or directory
```

阿零的第一反应:「就四个没删成。」然后 `ls`——家目录只剩三个目录,`notes.md`、`draft1.tmp`、`draft2.tmp` **全没了**。这份报错最毒的地方在于:**报错的全是幸存者,沉默的全是死者。**

根因分三层:

1. shell 把 `*` 展开成家目录**所有**名字,`rm * .tmp` 实际收到 7 个参数——`.tmp` 只是名单末尾一个不存在的名字;
2. rm 照单执行:普通文件静默 unlink,目录(没带 `-r`)拒绝并报错,不存在的报错;
3. 于是「删成功」没有任何回执——**rm 的成功,长得和什么都没发生一模一样**。

自救:早上那一下复印收回了成本——`cp backup/notes.md.bak notes.md`,笔记复活;两个草稿没备份,认栽。预防四件套,从今天起是纪律:

- **删之前,把同样的参数先喂给 `ls`(或 `echo`)看名单**:`ls * .tmp` 当场就会露馅;
- `rm -i` 逐个确认;日常更顺手的是 `rm -I`——超过 3 个文件才问一次;
- 危险目标写全路径、写精确名字:`rm ~/draft1.tmp` 远比在"你以为的目录"里裸敲 glob 稳;
- 动手前 `cp` 一份——保险这东西,永远是出事前买的便宜。

至于 `rm -rf`:`-r` 让它钻目录,`-f` 让它闭嘴。那些"变量为空""路径写错"引发的都市传说,根子全是同一件事——**shell 展开完,rm 只认名单**。对它保持敬畏,但不必恐惧:名单看清楚,它就只是个工具。

> **🪟 双系统对照 · 搬、印、删,PowerShell 上怎么打**

| 干什么 | Linux (bash) | PowerShell 7 | 关键差异 |
|---|---|---|---|
| 复制(含目录) | `cp -r dir dst` | `Copy-Item dir dst -Recurse`(别名 `cp`) | 目录都要显式递归,脾气一致 |
| 移动 / 改名 | `mv`(一个命令两用) | `Move-Item` / `Rename-Item`(两个动词) | PS 把"搬家"和"改名"拆成两个 cmdlet;bash 视为同一件事 |
| 删除 | `rm` / `rm -r` | `Remove-Item`(别名 `rm`/`del`),`-Recurse -Force` | **两边都不进回收站** |
| 逐个确认 | `rm -i` | `Remove-Item -Confirm` | — |
| 预演不执行 | (无原生对应) | `Remove-Item * -WhatIf` | PS 的王牌:先打印"将会删什么",一个不动 |
| 通配符 `*` | **shell 展开**,rm 收到名单 | 原样传给 cmdlet,由 **cmdlet 自己解释** | 哲学分水岭:bash 里命令看不到 `*`;PS 里 cmdlet 看得到,还能配 `-WhatIf` 预演 |

bash 这边没有 `-WhatIf`,所以"把 rm 换成 ls 先跑一遍"就是你手工的 WhatIf——工具没给的安全带,拿习惯补上。

> **🎯 面试直击**:Linux 上 `rm` 删掉的文件去哪了?能恢复吗?
> 哪也没去——`rm` 调用 unlink,把目录里"名字→inode"的挂钩摘掉、引用计数减一,数据块标记为可复用;不移动数据,也没有回收站。数据被新写入覆盖前理论上可恢复(extundelete 一类工具),但完全不可靠,生产上靠**备份策略**,不赌恢复。追问:桌面系统的"回收站"只是把文件 `mv` 进 `~/.local/share/Trash` 的约定——命令行的 `rm` 从来不走这条路。

> [!答案]
> **1-B** `cp` 是复制(copy),`mv` 是移动/改名。**举一反三:**`cp -i` 覆盖前确认;`cp -p` 保留文件属性(权限、时间戳)。🪟 PowerShell 中 `Copy-Item` 等价于 `cp`。
>
> **2-B** `mv` 同时负责移动和重命名——Linux 认为"改名"就是"在同一目录内移动"。**举一反三:**`mv file1 file2 dir/` 可以一次移动多个文件到目标目录。
>
> **3-A** `-r` = recursive(递归),删除目录必需;`-f` = force(强制),跳过所有确认提示。**举一反三:**`-f` 意味着"就算文件不存在也不报错",在脚本中常用于清理操作。
>
> **4-B** `cp -r src/ dest/` 递归复制整个 `src/` 目录,包括以 `.` 开头的隐藏文件。`*` 由 shell 展开,只匹配非隐藏的可见文件。**举一反三:**用 `cp -r src/. dest/` 可以复制所有内容包括隐藏文件。🪟 PowerShell 中 `Copy-Item -Recurse` 行为类似 `cp -r`。
>
> **5-C** `rm -rf /` 会递归强制删除根目录下所有文件,系统将彻底崩溃。**举一反三:**这就是"四条保命习惯"的由来——永远不要在 `rm -rf` 中使用变量而不验证;生产环境建议用 `trash-cli` 等回收站工具替代裸 `rm`。🪟 Windows 上先分清你在哪个壳里:PowerShell 的 `rm` 是 `Remove-Item` 的别名,`-rf` 作为**一个** token 绑不到任何参数,直接报 `A parameter cannot be found that matches parameter name 'rf'`——一个文件都不会动(拆成 `-r -f` 也不行:`-r` 能匹配 `-Recurse`,但 `-f` 在 `-Filter` 和 `-Force` 之间有歧义)。这跟「权限保护」无关,是参数压根没解析。但在 **Git Bash / WSL** 里那是真正的 GNU `rm`,和 Linux 一样危险。
>
> **6-B** `mv` 要求目标是一个已存在的目录,才能把文件移入其中。**举一反三:**如果 `/home/b/` 不存在,`mv` 会将 `file.txt` 重命名为 `/home/b`(变成普通文件放在 `/home/` 下),这往往不是预期行为。安全起见,目标目录末尾加 `/` 表明意图。
>
> **7-B** Shell glob 展开发生在命令执行之前:shell 先把 `*.log` 替换为 `a.log b.log c.log`,然后执行 `rm a.log b.log c.log`。**举一反三:**这意味着 `rm` 命令本身看不到 `*` 字符——它收到的是已展开的文件列表。这也解释了为什么"参数列表太长"(Argument list too long)错误可能出现。🪟 PowerShell 通配符由 cmdlet 自行处理,不经过 shell 展开。
>
> **8-B** 当目标 `project_backup/` 已存在,`cp -r project/ project_backup/` 会将 `project/` 放入 `project_backup/` 内部,变成 `project_backup/project/...`。**举一反三:**注意源路径末尾有无 `/` 的行为差异——`cp -r project project_backup` 和 `cp -r project/ project_backup/` 在 GNU cp 中行为不同。
>
> **9-C** Shell glob 默认行为:`*` 不匹配 `.` 开头的文件名(DOTGLOB 除外)。**举一反三:**要匹配隐藏文件,需要用 `.*` 或者开启 `dotglob` 选项(`shopt -s dotglob`)。注意 `.*` 也会匹配 `.` 和 `..`,可能造成危险操作。
>
> **10-B** "先 ls 再 rm"是最稳妥的实操习惯。**举一反三:**C 选项 `alias rm='rm -i'` 在交互式使用中有用,但在脚本中可能导致问题(非交互模式无效)。D 选项"移到 /tmp"是 `trash-cli` 工具的思路,回收站式删除更安全。
>
> **Q1** `cp`=复制,原文件保留,如 `cp app.conf app.conf.bak`;`mv`=移动/改名,原文件消失(位置或名字改变),如 `mv draft.md final.md`;`rm`=删除,永久移除文件/目录(无回收站),如 `rm temp.txt`。**核心差异:**`cp` 生成副本,`mv` 改标签,`rm` 销毁数据。
>
> **Q2** Linux 的 `rm` 是"真删除"——数据直接从文件系统中标记为可覆盖,不经过中间暂存区(回收站)。意味着误删后普通手段无法恢复。**补救措施:**①立刻停止写入磁盘(防止覆盖) ②用 `extundelete`/`testdisk` 等取证工具尝试恢复 ③最根本的是养成备份习惯(`rsync`/快照)和使用 `trash-cli` 工具。🪟 Windows 的文件删除默认进回收站,`Shift+Delete` 才永久删除,概念不同。
>
> **Q3** 命令序列:`mv old_config config` → `cp config/app.conf config/app.conf.bak` → `rm -r config/temp`。**举一反三:**在执行 `rm -r` 前,建议先 `ls config/temp/` 确认要删的内容,或用 `rm -ri config/temp` 逐项确认。
>
> **Q4** 可能原因:①当前目录不在 `/home/user/test`,而是其他位置(先用 `pwd` 确认) ②文件名包含不可见字符或空格,shell 展开后路径断开(用 `ls -b` 或 `ls | cat -A` 检查) ③文件确实是隐藏文件(如 `.data.bak`),`*` 不匹配 `.` 开头。**排查:**先 `pwd`→`ls -la`→确认精确文件名→用 Tab 补全避免手敲。
>
> **Q5** 脚本逻辑:①`cp -r ~/app ~/backups/app-$(date +%Y%m%d)` ②`[ $(find ~/app -type f | wc -l) -eq $(find ~/backups/app-$(date +%Y%m%d) -type f | wc -l) ] && echo "OK" || echo "MISMATCH"` ③`find ~/backups -maxdepth 1 -type d -name "app-*" -mtime +7 -exec rm -rf {} \;`。**举一反三:**生产备份应使用 `rsync -a` 而不是 `cp`,rsync 支持增量、校验和、排除模式;并建议使用 `tar`+`gzip` 压缩存档节省空间。

## 运行前边界、回滚与验证

- **运行前**：示例以 GNU/Linux 的 Bash 为主；先用 `command --help`、`man command` 或发行版文档确认本机版本和参数。不要把教程中的 IP、域名、用户、路径直接复制到生产机器。
- **先确认作用域**：涉及文件、仓库、容器或远端主机时，先运行 `pwd`、`whoami`、`git status`、`docker context show` 或 `ssh -G 主机别名`，确认当前目标；对重要数据先做可恢复备份。
- **完成后验证**：用只读命令确认结果，例如 `ls -la`、`git status`、`systemctl status 服务名`、`docker ps` 或 `curl -fS URL`；失败时停止扩大操作范围，先读报错。
- **删除边界**：`rm`/`Remove-Item` 不会进入回收站。先用 `ls -- 路径` 或 PowerShell 的 `-WhatIf` 预演；避免对变量、通配符或当前目录直接使用递归强制删除。
- **远端边界**：首次连接核验主机指纹；传输前先确认目标路径和账号，`rsync` 删除模式必须先加 `--dry-run`。远程改网络或防火墙时保留一个已登录会话和云控制台回退路径。
