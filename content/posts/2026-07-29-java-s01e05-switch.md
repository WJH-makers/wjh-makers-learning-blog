## 三、本话目标

- 用 `switch` 替代成串的 `if-else`;
- 理解老式 `switch` 的 `break` 与「穿透」;
- 用现代**箭头 `switch`**(`->`)彻底避免穿透;
- 区分箭头**标签**与 `switch` **表达式**:箭头标签既可用于语句也可用于表达式;表达式能直接赋值 / `return`,且必须穷尽所有可达情况。

---

## 四、原理图

```text
老式(语句):  switch (值) { case A: ...; break; default: ...; }   忘 break 就穿透
现代(表达式): 名称 = switch (值) { case A -> ...; default -> ...; };
              ↑ 箭头不穿透;整个 switch 会「算出一个值」赋给左边;表达式必须覆盖所有情况
```

一句话点破二者的本质差别:传统冒号标签会穿透,箭头标签不会。`switch` 既可以是**语句**(做事),也可以是**表达式**(算出一个值);箭头标签可用于两者。

## 五、代码:按编号报价(现代写法)

```java
public class Cafe {
    static double priceOf(int choice) {
        return switch (choice) {           // 整个 switch 算出一个 double,直接 return
            case 1 -> 15.0;   // 美式
            case 2 -> 18.0;   // 拿铁
            case 3 -> 20.0;   // 卡布奇诺
            default -> throw new IllegalArgumentException("没有编号 " + choice);
        };
    }

    public static void main(String[] args) {
        int choice = 2;
        System.out.println("编号 " + choice + " → ¥" + priceOf(choice));
    }
}
```

注意 `default` 这行:因为这里的 `switch` 当表达式用，必须**穷尽所有情况**(每条路都得有结果)。对 `int` 这类开放取值，通常要写 `default`；但对覆盖完整的 `enum` 或密封类型层级，编译器可证明穷尽时不必写 `default`。这是表达式比普通语句更安全的地方。

> **豆豆旁白**:`default -> throw ...` 里的抛异常,细节留到第 11 话《调试》再讲,这里先照着用 —— 你只需知道「遇到没登记的编号,就当场喊停、别蒙混过关」。

## 六、故意制造一个 Bug(老式写法)

换成老式 `switch`,并「手滑」漏掉 `break`:

```java
double price = 0;
switch (choice) {           // choice = 1
    case 1: price = 15.0;   // ← 漏了 break
    case 2: price = 18.0;   // 穿透到这里,被覆盖
    case 3: price = 20.0;   // 又被覆盖
}
System.out.println(price);  // 期望 15.0,实际 20.0
```

---

## 七、读懂现象(又是 Logic Bug)

不报错,但点「美式(1)」却收了「卡布奇诺(20 元)」的钱。因为 `case 1` 命中后没 `break`,程序**继续往下穿透**,`price` 被 18、20 依次覆盖 —— 正是漫画里那颗一路滚到底的球。

## 八、修复,并用测试证明

回到箭头 `switch`(结构上就不可能穿透)。用测试锁死每个编号的价:

```java
@Test
void price_matches_menu() {
    assertEquals(15.0, Cafe.priceOf(1));
    assertEquals(18.0, Cafe.priceOf(2));
    assertEquals(20.0, Cafe.priceOf(3));
}
```

> **⏳ 版本时光机 · switch 的三十年进化**
>
> | JDK 版本 | 写法 | 关键变化 |
> |---|---|---|
> | Java 1.0 ~ 13 | 老式**语句**:`case 1: ...; break;` | 靠 `break` 刹车,忘写就穿透 |
> | Java 14 · 箭头标签 | `case 1 -> ...;` 一分支一动作 | 结构上**不再穿透**;可用于 switch 语句或表达式 |
> | Java 14 · 表达式 | `var p = switch(x){ case 1 -> 15.0; ... };` | switch 从「语句」升级成「**表达式**」,能赋值 / `return`、**强制穷尽** |
> | Java 21 → 25 | 模式匹配:`case String s -> ...; case null -> ...` | 能按「**类型**」分支,不再只比常量值 |
>
> 一句演进小结:从「靠人手动刹车、只会比常量」一路走到「结构上防穿透、能返回值、还能按类型匹配」—— 越新越安全、越会算。**箭头和表达式同在 Java 14 落地(JEP 361),模式匹配在 Java 21 转正(JEP 441),25 沿用为基线。**

那句「能按类型分支」先埋个钩子:等第二季讲到多态、一个变量可能装着好几种对象时,`switch` 会摇身一变,直接问「你到底是哪种类型」,那才是它真正的大招。

## 🎯 随堂练习

先自己做,再对答案。每道答案都带一句「举一反三」,帮你把这一个点连成一片。

### 选择题(10 道)

1. 老式 `switch` 里 `case 1:` 命中后漏写 `break`,会发生什么?
   - A) 编译报错　B) 只执行 `case 1` 然后退出　C) 继续向下**穿透**执行后面的 case　D) 跳到 `default`
2. 本话那段漏 `break` 的老式 `switch`(`choice = 1`),最终 `price` 是?
   - A) `15.0`　B) `18.0`　C) `20.0`　D) `0`
3. 箭头写法 `case 1 -> 15.0;` 为什么不会穿透?
   - A) 因为编译器悄悄插了 `break`　B) 因为每个分支是独立滑道,结构上就不连通　C) 因为它只能写一行　D) 因为它必须有 `default`
4. 老式 `switch` 与箭头 `switch` 的本质区别是?
   - A) 一个快一个慢　B) 一个是**语句**(做事、靠 `break` 刹车),一个是**表达式**(算出一个值)　C) 一个能用于 `int`,一个只能用于 `String`　D) 没有区别,只是写法不同
5. 把 `switch` 当表达式赋值时,编译器为什么逼你写 `default`?
   - A) 语法习惯　B) 因为表达式必须**穷尽所有情况**,每条路都得算出结果　C) 为了兼容老代码　D) 为了性能优化
6. 箭头 `switch` 和 `switch` 表达式是哪个版本落地的?
   - A) Java 8　B) Java 11　C) Java 14(JEP 361)　D) Java 21
7. `switch` 的**模式匹配**(`case String s ->`)在哪个版本转正?
   - A) Java 14　B) Java 17　C) Java 21(JEP 441)　D) Java 25
8. 点「美式」却收了 20 元,这个事故属于?
   - A) 编译错误　B) 运行期异常　C) Logic Bug:能跑完、不报错,结果是错的　D) 环境问题
9. `default -> throw new IllegalArgumentException(...)` 的意义是?
   - A) 让代码好看　B) 遇到没登记的编号当场喊停,而不是蒙混过关返回一个假值　C) 提高性能　D) 必须这么写,否则编译不过
10. 豆豆面对穿透 Bug 时用的排查方法是?
    - A) 直接猜哪里错了　B) 把所有 case 都加上 `break` 试试　C) 调回放逐格倒看:现象 → 报错 → 假设 → 只改一处 → 重跑　D) 重启电脑

> [!答案]
> **1-C**　老式 `switch` 命中后不会自动停,会一路滚到底。**举一反三**:这也解释了为什么有人**故意**漏 `break` 来让多个 case 共用一段逻辑 —— 但可读性差,现在有更好的写法。
> **2-C**　`price` 被 `15.0` → `18.0` → `20.0` 依次覆盖,最后是 `20.0`。**举一反三**:这类「被后面覆盖」的 Bug,盯住变量的赋值顺序就能抓住。
> **3-B**　箭头是「一分支一结果」的独立滑道,不存在往下滚的通路。**举一反三**:靠结构消灭错误,比靠人「记得写 break」可靠得多 —— 好设计让错误写不出来。
> **4-B**　语句「做事」,表达式「算出一个值」。**举一反三**:能直接 `return`、能赋给变量的是 *switch 表达式*；箭头标签本身既能写在语句里，也能写在表达式里。
> **5-B**　赋值要求每条路都有值,漏一种情况直接编译不过。**举一反三**:配合 `enum` 或密封类时更爽 —— 全部枚举值都覆盖了就可以不写 `default`,以后新增枚举值,编译器会立刻提醒你漏了。
> **6-C**　箭头和表达式同在 Java 14 落地(JEP 361)。**举一反三**:版本题在面试里就是考你「有没有真在用新语法」,记住关键节点即可。
> **7-C**　模式匹配 for switch 在 Java 21 转正(JEP 441),Java 25 沿用为基线。**举一反三**:等第二季讲多态,「一个变量可能装着好几种对象」时,它就是主角。
> **8-C**　程序照跑不误,错的是结果不是语法。**举一反三**:凡是「不报错但收错钱」的问题,都得靠测试钉死,编译官帮不了。
> **9-B**　让非法输入当场暴露,而不是悄悄返回 0 元。**举一反三**:「fail fast」是工程通则 —— 错误越早暴露,排查成本越低。
> **10-C**　别猜,调回放一格一格倒着看,每次只改一处变量。**举一反三**:这套「现象→假设→改一处→重跑」的排障法,在第 11 话调试和第五季线上排障里会反复出现。
