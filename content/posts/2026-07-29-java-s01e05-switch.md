## 三、本话目标

- 用 `switch` 替代成串的 `if-else`;
- 理解老式 `switch` 的 `break` 与「穿透」;
- 用现代**箭头 `switch`**(`->`)彻底避免穿透;
- 理解箭头 `switch` 是**表达式**:能直接赋值 / `return`,且被编译器**强制穷尽**。

---

## 四、原理图

```text
老式(语句):  switch (值) { case A: ...; break; default: ...; }   忘 break 就穿透
现代(表达式): 名称 = switch (值) { case A -> ...; default -> ...; };
              ↑ 箭头不穿透;整个 switch 会「算出一个值」赋给左边;必须覆盖所有情况
```

一句话点破二者的本质差别:老式 `switch` 是**语句**(它「做事」,靠 `break` 刹车);箭头 `switch` 是**表达式**(它「算出一个值」,一分支一结果,天生不穿透)。

## 五、代码:按编号报价(现代写法)

```java
public class Cafe {
    static double priceOf(int choice) {
        return switch (choice) {           // 整个 switch 算出一个 double,直接 return
            case 1 -> 15.0;   // 美式
            case 2 -> 18.0;   // 拿铁
            case 3 -> 20.0;   // 卡布奇诺
            default -> throw new IllegalArgumentException("没有编号 " + choice);
        };
    }

    public static void main(String[] args) {
        int choice = 2;
        System.out.println("编号 " + choice + " → ¥" + priceOf(choice));
    }
}
```

注意 `default` 这行:因为箭头 `switch` 当表达式用时**必须穷尽所有情况**(每条路都得有结果),编译器会逼你把 `default` 补上 —— 漏一种可能,直接编译不过。这是它比老式 `switch` 更安全的地方:**你不可能忘记处理某个分支**。

> **豆豆旁白**:`default -> throw ...` 里的抛异常,细节留到第 11 话《调试》再讲,这里先照着用 —— 你只需知道「遇到没登记的编号,就当场喊停、别蒙混过关」。

## 六、故意制造一个 Bug(老式写法)

换成老式 `switch`,并「手滑」漏掉 `break`:

```java
double price = 0;
switch (choice) {           // choice = 1
    case 1: price = 15.0;   // ← 漏了 break
    case 2: price = 18.0;   // 穿透到这里,被覆盖
    case 3: price = 20.0;   // 又被覆盖
}
System.out.println(price);  // 期望 15.0,实际 20.0
```

---

## 七、读懂现象(又是 Logic Bug)

不报错,但点「美式(1)」却收了「卡布奇诺(20 元)」的钱。因为 `case 1` 命中后没 `break`,程序**继续往下穿透**,`price` 被 18、20 依次覆盖 —— 正是漫画里那颗一路滚到底的球。

## 八、修复,并用测试证明

回到箭头 `switch`(结构上就不可能穿透)。用测试锁死每个编号的价:

```java
@Test
void price_matches_menu() {
    assertEquals(15.0, Cafe.priceOf(1));
    assertEquals(18.0, Cafe.priceOf(2));
    assertEquals(20.0, Cafe.priceOf(3));
}
```

> **⏳ 版本时光机 · switch 的三十年进化**
>
> | JDK 版本 | 写法 | 关键变化 |
> |---|---|---|
> | Java 1.0 ~ 13 | 老式**语句**:`case 1: ...; break;` | 靠 `break` 刹车,忘写就穿透 |
> | Java 14 · 箭头 | `case 1 -> ...;` 一分支一动作 | 结构上**不再穿透**,`break` 退休 |
> | Java 14 · 表达式 | `var p = switch(x){ case 1 -> 15.0; ... };` | switch 从「语句」升级成「**表达式**」,能赋值 / `return`、**强制穷尽** |
> | Java 21 → 25 | 模式匹配:`case String s -> ...; case null -> ...` | 能按「**类型**」分支,不再只比常量值 |
>
> 一句演进小结:从「靠人手动刹车、只会比常量」一路走到「结构上防穿透、能返回值、还能按类型匹配」—— 越新越安全、越会算。**箭头和表达式同在 Java 14 落地(JEP 361),模式匹配在 Java 21 转正(JEP 441),25 沿用为基线。**

那句「能按类型分支」先埋个钩子:等第二季讲到多态、一个变量可能装着好几种对象时,`switch` 会摇身一变,直接问「你到底是哪种类型」,那才是它真正的大招。

### 一、选择题（10 道）

1. [基础] 经典 `switch` 中，漏写 `break` 会导致什么？
   - A) 编译报错　B) 只执行匹配的 case　C) 穿透（fall-through）到下一个 case　D) 直接退出 switch

2. [基础] 经典 `switch` 的括号中可以使用以下哪种类型？
   - A) `double`　B) `boolean`　C) `String`　D) `float`

3. [基础] `default` 分支在 `switch` 中的作用是？
   - A) 必须放在最后　B) 当所有 case 都不匹配时执行　C) 可以省略，没有默认行为　D) 永远第一个执行

4. [理解] 以下代码输出什么？`int x = 2; switch(x) { case 1: System.out.print("A"); case 2: System.out.print("B"); case 3: System.out.print("C"); }`
   - A) B　B) BC　C) ABC　D) 编译报错

5. [理解] Java 14+ 的箭头 `switch`（`case X -> ...`）和经典 `switch` 的本质区别是？
   - A) 箭头版不需要 `switch` 关键字　B) 箭头版每个 case 不穿透，无需 `break`　C) 箭头版不支持 `default`　D) 箭头版只能用于枚举

6. [应用] 以下哪个场景**不适合**使用 `switch`？
   - A) 根据星期数字输出中文星期名　B) 根据分数段（0-59/60-79/80-89/90-100）输出等级　C) 根据 HTTP 状态码返回提示信息　D) 根据菜单编号返回菜品名称

7. [分析] 以下代码有几处需要修复的问题？`switch(score) { case score > 90: ...; break; }`
   - A) 0 处　B) 1 处　C) 2 处　D) 3 处

8. [分析] 以下 switch 表达式的结果是什么？`int n = 3; String s = switch(n) { case 1 -> "一"; case 3 -> "三"; default -> "其他"; };`
   - A) "一"　B) "三"　C) "其他"　D) 编译报错：default 和 case 3 冲突

9. [判断] 以下关于 case 穿透的说法正确的是？
   - A) 穿透是设计缺陷，应永远避免　B) 多个 case 共享同一处理逻辑时可以利用穿透　C) 箭头 switch 也支持穿透　D) 在 `default` 后加 `break` 是多余的

10. [综合] 以下代码输出什么？`int day = 5; String result = switch(day) { case 1, 2, 3, 4, 5 -> "工作日"; case 6, 7 -> "周末"; default -> "无效"; }; System.out.println(result);`
    - A) 编译报错　B) "工作日"　C) "周末"　D) "无效"

> [!答案]
> **1-C**：经典 `switch` 从匹配的 case 入口开始执行，没有 `break` 就一直往下"穿透"执行所有后续 case，这叫 fall-through。**举一反三**：穿透不一定是 bug——多个 case 共享同一代码时故意不加 break 是合法做法：`case 1: case 2: doSomething(); break;`。
> **2-C**：经典 `switch` 支持 `byte`/`short`/`int`/`char` 及它们的包装类，以及 `String`（Java 7+）和 `enum`。**不支持** `boolean`（只有两个值，用 if-else 即可）、`long`、`float`、`double`。
> **3-B**：`default` 是"兜底"分支，所有 case 都不匹配时执行。不要求放在最后（但惯例是最后），可以省略——但如果所有可能值都被 case 覆盖则可放心省略。**举一反三**：即使"理论上不会走到"，也保留 default 打印警告或抛异常——这是防御性编程。
> **4-B**：`case 2` 匹配后执行 `print("B")`，没有 `break`，穿透到 `case 3` 继续执行 `print("C")`，最终输出 "BC"。**举一反三**：用箭头 switch 则天然不穿透：`case 2 -> System.out.print("B");` 只执行 B。
> **5-B**：箭头 `switch` 每个 case 独立，执行完自动退出，不需要 `break`。经典 `switch` 依赖 `break` 防止穿透。这是两者最核心的语法差异。**举一反三**：箭头 switch 还能作为表达式返回值，经典 switch 只是语句。
> **6-B**：`switch` 做的是**等值匹配**（`case 1:`、`case 2:`），而分数段是**范围判断**（≥90、≥80），需要用 if-else。虽然可以写成 `switch(score / 10)` 近似模拟但可读性差。其他三项都是等值匹配。**举一反三**：确认 switch 是否合适只需看判断逻辑是不是"值 == 某个常量"的形式。
> **7-C**：① `switch(score)` 中 `score` 未声明类型；② `case score > 90` 语法错误——case 后只能跟常量表达式（如 `case 90:`），不能是关系表达式。正确的写法应该是 if-else 而非 switch。**举一反三**：编译器会给出 "constant expression required" 错误，一眼就能定位。
> **8-B**：switch 表达式从上到下匹配，`n=3` 命中 `case 3 ->`，返回 `"三"`，后续不再执行。`default` 只在所有 case 都不匹配时使用——这里 case 3 已匹配，default 不执行。**举一反三**：switch 表达式中所有分支必须覆盖所有可能值（或加 default），否则编译报错。
> **9-B**：经典 switch 中故意利用穿透让多个 case 共享代码是常见做法：`case 1: case 2: case 3: System.out.println("Q1"); break;`。A 错：恰当使用穿透可以减少重复。C 错：箭头 switch 天然不穿透。D 错：default 后面的 break 不是多余的——如果 default 在中间位置则必须加 break 防止穿透到后续 case。
> **10-B**：`case 1,2,3,4,5 ->` 是 Java 14+ 的多值 case 语法，`day=5` 匹配，返回 "工作日"。**举一反三**：多值 case 比经典 switch 的 fall-through 写法 `case 1: case 2: case 3: ...` 更紧凑、更不容易出错。

### 二、解答题（3 道）

1. [概念阐述] 经典 `switch` 和箭头 `switch` 的三大区别是什么？请结合代码分别说明：①语法形式；②break/穿透行为；③能否返回值。

2. [场景解释] 咖啡机系统需要将用户输入的菜单编号映射为饮料名称和价格。目前的菜单有 5 款（美式/拿铁/摩卡/卡布奇诺/冰美式）。请设计两种实现方案——经典 switch 和箭头 switch 表达式——并对比优劣。

3. [综合分析] 解释 switch 表达式中 `yield` 关键字的用途。什么情况下必须用 `yield` 而无法直接用箭头？请写一个需要 `yield` 的代码示例（比如 case 内需要先计算再返回结果），并对比 `yield` 方案和传统 if-else 方案。

> [!答案]
> **1**　三大区别：①**语法**：经典版 `case X:` + 冒号，箭头版 `case X ->`。②**穿透**：经典版漏 `break` 会穿透，需手动控制；箭头版天然不穿透。③**返回值**：经典版是语句，不能直接返回值；箭头版是表达式，可以 `String s = switch(x) { case 1 -> "A"; default -> "Z"; };`。**举一反三**：新项目优先用箭头 switch——更安全（避免遗漏 break）、更简洁（可以做值映射）。
> **2**　经典版：`switch(code) { case 1: name="美式"; price=15.0; break; case 2: name="拿铁"; price=18.0; break; ... default: name="未知"; price=0; }`——需要为每个 case 手动加 break，且 name 和 price 需要分别赋值。箭头表达式版：用 `record` 或 String 拼接返回："`switch(code) { case 1 -> "美式:15元"; case 2 -> "拿铁:18元"; ... default -> "未知"; }`——一行返回所有信息。箭头版明显更简洁安全；但若每个 case 需要修改多个外部变量，经典版更直接。**举一反三**：真正的生产系统会用 Map 或枚举而非 switch 做映射——switch 更适合 3-8 个分支的小规模分派。
> **3**　`yield` 用于 switch 表达式中需要在 case 块内执行多行逻辑后才返回值的场景。箭头 `->` 后只能跟单条表达式或单条语句；如果 case 需要先计算、再判断、最后返回，就需要用冒号 case + `yield`：`case 3: { int discount = calculate(); yield price - discount; }`。if-else 替代方案更冗长但更灵活（支持复杂嵌套逻辑）。**举一反三**：`yield` 不是关键字而是受限标识符——只在 switch 表达式中有特殊含义，其他地方仍可当变量名使用。

### 三、代码题（2 道）

1. [基础实现] 写一个 Java 14+ 箭头 switch 方法 `getSeason(int month)`：12/1/2 → "冬季"，3/4/5 → "春季"，6/7/8 → "夏季"，9/10/11 → "秋季"，其他 → "无效月份"。返回对应的季节字符串，测试 month = 8 和 month = 13。

2. [综合设计] 写一个"优惠计算器"：旧版用经典 switch（故意漏一个 break 让两个 case 共享逻辑），新版用箭头 switch 表达式。需求：输入 `type`（1=普通/2=会员/3=超级会员），满 50 元后：普通无折扣，会员 9 折，超级会员 8 折 + 返 5 元积分。①用经典 switch 实现（1 和 2 故意不穿透，3 独立）；②用箭头 switch 表达式实现同一逻辑；③对比代码行数和安全风险。

> [!答案]
> **1 验收**：
> ```java
> public static String getSeason(int month) {
>     return switch (month) {
>         case 12, 1, 2 -> "冬季";
>         case 3, 4, 5 -> "春季";
>         case 6, 7, 8 -> "夏季";
>         case 9, 10, 11 -> "秋季";
>         default -> "无效月份";
>     };
> }
>
> System.out.println(getSeason(8));  // 夏季
> System.out.println(getSeason(13)); // 无效月份
> ```
> **举一反三**：多值 case（`case 12, 1, 2`）比经典写法的"空 case 穿透"更清晰。但需注意 Java 14+ 才能使用此语法。
>
> **2 验收**：
> ```java
> // ① 经典 switch 版
> int type = 2;
> double total = 80;  // 满 50
> double discount = 1.0;
> int points = 0;
>
> switch (type) {
>     case 1:
>         discount = 1.0;  // 普通无折扣
>         break;
>     case 2:
>         discount = 0.9;  // 会员 9 折
>         break;
>     case 3:
>         discount = 0.8;  // 超级会员 8 折
>         points = 5;      // +5 积分
>         break;
>     default:
>         System.out.println("无效类型");
> }
> double finalPrice = total * discount;
> System.out.println("原价:" + total + " 实付:" + finalPrice + " 积分:" + points);
> // type=2, total=80 → 实付:72.0, 积分:0
>
> // ② 箭头 switch 表达式版
> double discount2 = switch (type) {
>     case 1 -> 1.0;
>     case 2 -> 0.9;
>     case 3 -> {
>         // case 3 有多行逻辑，用 yield
>         points = 5;
>         yield 0.8;
>     }
>     default -> 1.0;
> };
>
> // ③ 对比：经典版 19 行，箭头版 12 行；经典版漏 break 风险显著
> ```
> 运行验证：type=3, total=80 → 实付 64.0, 积分 5。**举一反三**：注意 `points` 在箭头版中是从外部修改的——箭头 switch 的值来自每个分支的 `->` 表达式或 `yield`，而副作用（如修改外部变量、打印日志）仍然有效。
