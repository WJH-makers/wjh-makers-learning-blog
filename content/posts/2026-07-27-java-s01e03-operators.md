## 四、原理图

```text
算术  +  -  *  /  %(取余)
比较  >  <  >=  <=  ==  !=      结果是 boolean
逻辑  &&(与)  ||(或)  !(非)     短路求值
```

陷阱:`5 / 2` == `2`(两个 int,砍掉小数);要小数得让至少一个是 `double` → `5.0 / 2` == `2.5`。

**短路求值**顺带记一下:`&&` 左边为 `false` 就不看右边,`||` 左边为 `true` 就不看右边 —— 后面判空、防越界都靠它「先挡一道再往下走」。

> **豆豆旁白**:别小看 `%` 取余,它是运算街最能干的杂工。「第 N 位顾客免单」用 `n % 10 == 0`;「判断奇偶」用 `n % 2`;「让编号在 0~len 之间循环」用 `i % len`。凡是「转圈、跳格、每逢整数就触发」的需求,先想想它。

## 五、代码:算价与找零

```java
public class Cafe {
    public static void main(String[] args) {
        double price = 15.0;   // 单价
        int qty = 3;           // 杯数
        double paid = 50.0;    // 顾客付款

        double total = price * qty;      // 总价 45.0
        double change = paid - total;    // 找零 5.0
        boolean enough = paid >= total;  // 够不够付

        System.out.println("总价 ¥" + total + " · 找零 ¥" + change + " · 付款充足:" + enough);
    }
}
```

光「钱够」还不够,还得「有货」才能出杯 —— 两个条件同时成立,用逻辑与 `&&` 串起来:

```java
int stock = 2;                                   // 库存 2 杯
boolean canServe = enough && stock >= qty;       // 钱够 且 货够,才出杯
```

`&&` 还顺带帮你**防空转**:如果 `enough` 是 `false`,右边 `stock >= qty` 根本不会去算(短路)。等以后右边是「查数据库」这种昂贵操作时,这一下短路能省下真金白银。

## 六、故意制造一个 Bug

想算「人均消费」:3 杯 45 元,4 个人一起付,人均多少?

```java
int people = 4;
int subtotal = 45;               // 3 杯共 45 元(先用整数演示整除)
int avg = subtotal / people;     // ← 期望 11.25,实际得到 11
System.out.println("人均 ¥" + avg);
```

---

## 七、读懂现象(这是逻辑 Bug,不报错)

程序照跑不误,但结果 `人均 ¥11` 是错的 —— 这类**能运行、结果却不对**的叫 **Logic Bug**,编译官不会拦你,得靠自己发现。

最常见的错觉是「`11.25` 被塞进 `int` 盒子、砍成了 `11`」。**但 `11.25` 从来没被算出来过。** `subtotal` 和 `people` 都是 `int`,`45 / 4` 走的是**整数除法** —— 在做除法的那一步,小数部分就被直接丢弃,直接得 `11`。

一句话钉死:**丢精度发生在「除法」本身,不是「赋值」那一刻。**

---

## 八、修复,并用测试证明

用 `double` 保留小数:

```java
static double perPerson(double total, int people) {
    return total / people;   // total 是 double,结果就是 double
}
```

> **豆豆锐评**:只要除号两边**有一个是小数**,Java 就会把另一个也自动提升成 `double` 再算,小数就保住了 —— 这叫**类型提升**。`45.0 / 4` 得 `11.25`,`45 / 4` 得 `11`,差一个点,差一场投诉。

```java
@Test
void split_45_among_4() {
    assertEquals(11.25, Cafe.perPerson(45.0, 4));
}
```

> **🎯 面试直击**:`System.out.println(5 / 2)` 和 `5 % 2` 各输出什么?
> 分别是 `2` 和 `1`。`/` 对两个 `int` 是整除(砍小数,不四舍五入),`%` 取余数。追问防身:① 想要 `2.5`,把任一操作数写成 `double`(`5.0 / 2`),靠类型提升保精度;② `%` 还能判奇偶(`n % 2 == 0`)、做环形编号(`i % len`);③ 陷阱升级:`5 / 0` 抛 `ArithmeticException`,但 `5.0 / 0` 不抛,得到 `Infinity` —— 整数除零炸、浮点除零不炸,这一对经常连着考。

### 一、选择题（10 道）

1. [基础] `int result = 5 / 2;` 的结果是？
   - A) `2.5`　B) `2`　C) `3`　D) `2.0`

2. [基础] `10 % 3` 的结果是？
   - A) `3`　B) `1`　C) `0`　D) `3.33`

3. [基础] 以下哪个操作符优先级最高？
   - A) `+`　B) `*`　C) `=`　D) `+=`

4. [理解] `double d = 5 / 2;` 执行后 `d` 的值是？
   - A) `2.5`　B) `2.0`　C) `2`　D) 编译报错

5. [理解] `int a = 5; int b = a++;` 执行后 `a` 和 `b` 的值分别是？
   - A) a=5, b=5　B) a=6, b=5　C) a=5, b=6　D) a=6, b=6

6. [应用] `byte b = 10; b = b + 1;` 和 `byte b = 10; b += 1;` 的区别是？
   - A) 两者都编译通过　B) 前者编译失败，后者通过　C) 两者都编译失败　D) 前者通过，后者失败

7. [分析] `System.out.println(1 + 2 + "3" + 4 + 5);` 输出？
   - A) `12345`　B) `3345`　C) `612`　D) `1 + 2 + "3" + 4 + 5`

8. [分析] `int x = 10; double y = 3.0;` 则 `x / y` 的结果类型是？
   - A) `int`　B) `double`　C) `float`　D) 编译报错

9. [判断] 以下关于 `%` 取模的说法正确的是？
   - A) `-5 % 3` 的结果是 -2　B) `5 % 0` 的结果是 0　C) `%` 只能用于整数　D) `5.5 % 2.0` 编译错误

10. [综合] 以下代码输出什么？`int a = 5; int b = 2; double c = a / b; double d = (double) a / b; System.out.println(c + ", " + d);`
    - A) `2.5, 2.5`　B) `2.0, 2.5`　C) `2, 2.5`　D) 编译报错

> [!答案]
> **1-B**：两个 `int` 相除执行**整数除法**，小数部分直接截断（不是四舍五入）。**举一反三**：要得到 2.5，需至少一个操作数为浮点：`5.0 / 2` 或 `(double)5 / 2`。
> **2-B**：`%` 是取余（取模）运算符，`10 / 3 = 3` 余 `1`。**举一反三**：`a % b` 的正负号与 `a` 一致——`-10 % 3` 结果是 `-1`。
> **3-B**：乘除模 `* / %` 优先级高于加减 `+ -`，赋值 `= +=` 等优先级最低。使用括号 `()` 可以覆盖任何优先级。**举一反三**：不确定优先级时，直接加括号——既保证正确又提高可读性。
> **4-B**：`5 / 2` 先以整数除法执行得 `2`，然后 `2` 再转为 `double` 赋给 `d`，结果是 `2.0`。关键：类型转换发生在除法之后，不是之前。**举一反三**：想要 `2.5`，应写 `5.0 / 2` 或 `(double)5 / 2`。
> **5-B**：`a++` 是**后置自增**——先取 `a` 的原值 5 赋给 `b`，然后 `a` 再自增为 6。`++a`（前置自增）则是先自增再取值。**举一反三**：自增/自减操作符建议仅在极简场景（如 `for` 步进）使用；嵌套在复杂表达式中极易产生混乱。
> **6-B**：`b = b + 1` 中 `b` 被提升为 `int`，结果的 `int` 不能自动转回 `byte`，编译失败。`b += 1` 是复合赋值运算符，编译器自动插入 `(byte)` 强转，等价于 `b = (byte)(b + 1)`。**举一反三**：所有复合赋值（`+=` `-=` `*=` `/=` `%=`）都自带隐式强转，这是它们和普通赋值最本质的区别。
> **7-B**：执行顺序从左到右：`1 + 2 = 3` → `3 + "3" = "33"`（遇到字符串后后续全部转为字符串拼接）→ `"33" + 4 = "334"` → `"334" + 5 = "3345"`。关键转折：一旦字符串出现，后面的 `+` 全是拼接而非加法。**举一反三**：想先算加法再拼字符串，加括号：`System.out.println((1 + 2 + 4 + 5) + "3");` → `"123"`。
> **8-B**：`int / double` 时 `int` 自动提升为 `double`，结果类型为 `double`。自动类型提升链：`byte/short/char → int → long → float → double`。**举一反三**：想保留除法结果为 `int`，两个操作数都必须是 `int`，或对结果强制转型 `(int)(x / y)`（同样截断小数）。
> **9-A**：负数取模结果的符号与被除数一致，`-5 % 3 = 1 * -3 + (-2)`，结果为 -2。B 错：`% 0` 在运行时会抛出 `ArithmeticException`。C 错：`%` 可用于浮点数，如 `5.5 % 2.0 = 1.5`。**举一反三**：取模常用于循环索引回绕——`index % array.length` 确保索引不越界。
> **10-B**：`a / b` 整数除得 `2`，赋给 `c` 时转为 `2.0`；`(double) a / b` 先把 `a` 转为 `5.0`，除 `2` 得 `2.5`。**举一反三**：强转的时机至关重要——`(double)(a / b)` 只会得到 `2.0`，和 `c` 完全一样。

### 二、解答题（3 道）

1. [概念阐述] 什么是整数除法截断？它和数学中的除法有什么不同？Java 如何实现保留小数的除法？

2. [场景解释] 咖啡机系统要计算"买 5 杯咖啡，第二杯半价"的金额。假设每杯 20 元，促销期间买 2 送 1——说明这两类优惠的算式逻辑和可能遇到的整除/余数问题。

3. [综合分析] 总结 Java 表达式计算中"类型自动提升"的完整规则链。结合具体例子说明：① `byte`/`short`/`char` 参与运算的特殊性；② 赋值时何时需要显式强转；③ 复合赋值（`+=`等）的隐式强转机制。

> [!答案]
> **1**　整数除法截断是指两个整数相除结果仍为整数，小数部分直接丢弃（不进行四舍五入）。例如数学中 `5 ÷ 2 = 2.5`，但 Java int 运算时 `5 / 2 = 2`。要获得小数结果，方法有三：①将任一操作数写成浮点字面量 `5.0 / 2`；②显式强转 `(double)5 / 2`；③使用浮点类型变量。**举一反三**：截断不是 bug 而是设计选择——整数除法在数组索引计算、分页逻辑等场景中非常实用，例如"第 13 条记录在第几页"用 `(total + pageSize - 1) / pageSize` 向上取整。
> **2**　"第二杯半价"：买 5 杯 → 半价杯数 = 5 / 2 = 2 杯（整数除法截断），总价 = 5 × 20 - 2 × 10 = 90 元。注意当总杯数为奇数时，最后一杯不享受半价——这正是整数除法截断的妙用。买 2 送 1：买 5 杯 → 赠送杯数 = 5 / 2 = 2 杯，实际只需付 3 杯的钱 = 60 元。这里用 `%` 处理余数：如果老板要求"3 杯一组"，需计算 `5 / 3 = 1` 组赠品 + `5 % 3 = 2` 杯余数。**举一反三**：真实点单系统计算优惠时经常用整数除法和取模配合——`count / N` 计算满几组，`count % N` 计算余下多少。
> **3**　完整提升链：`byte/short/char → int → long → float → double`。`byte`/`short`/`char` 特殊性：只要出现在算术表达式中，即使两个 `byte` 相加也会先各自提升为 `int`，所以 `byte c = a + b;` 编译失败。赋值时的强转规则：大范围赋给小范围需显式强转（如 `int`→`byte`），否则编译报错；反过来可隐式。复合赋值的隐式强转：`b += 1` 等价于 `b = (byte)(b + 1)`，编译器自动插入了强转——这解释了为什么 `+=` 能通过编译而 `b = b + 1` 不能。**举一反三**：理解类型提升是阅读编译错误的基础，看到"incompatible types: possible lossy conversion from int to byte"就知道该加 `(byte)` 强转或用复合赋值。

### 三、代码题（2 道）

1. [基础实现] 写一个"秒数转换器"：给定一个总秒数 `totalSeconds = 7384`，用 `/` 和 `%` 分解为 小时:分钟:秒，输出格式 `"7384 秒 = X 小时 Y 分钟 Z 秒"`。要求结果正确（7384 秒 = 2 小时 3 分钟 4 秒）。

2. [综合设计] 写一个"收银机核心计算"程序：咖啡单价 15.9 元，买 3 杯打 8 折（总价 × 0.8）。请用 `int` 以"分"为单位重新实现——单杯 1590 分，3 杯 8 折。对比两次计算：浮点版和整数分版，打印差值，说明为什么会出现这个差值。

> [!答案]
> **1 验收**：
> ```java
> int totalSeconds = 7384;
> int hours = totalSeconds / 3600;
> int remaining = totalSeconds % 3600;
> int minutes = remaining / 60;
> int seconds = remaining % 60;
> System.out.println(totalSeconds + " 秒 = " + hours + " 小时 "
>     + minutes + " 分钟 " + seconds + " 秒");
> // 输出: 7384 秒 = 2 小时 3 分钟 4 秒
> // 验证: 2×3600 + 3×60 + 4 = 7200 + 180 + 4 = 7384 ✓
> ```
> **举一反三**：先 `/` 取高位再 `%` 取余，是数值拆分的标准模式——同类问题（分解金额为元角分、分解字节为 GB/MB/KB）都用同样的套路。
>
> **2 验收**：
> ```java
> // 浮点版
> double priceFloat = 15.9;
> double totalFloat = priceFloat * 3 * 0.8;
> System.out.println("浮点版总价: " + totalFloat);
> // 输出: 38.16 或 38.160000000000004（精度问题）
>
> // 整数分版
> int priceCents = 1590;        // 15.90 元 = 1590 分
> int totalCents = priceCents * 3 * 8 / 10;  // 3 杯 8 折
> System.out.println("分版总价: " + totalCents + " 分 = "
>     + (totalCents / 100.0) + " 元");
> // 输出: 3816 分 = 38.16 元
>
> // 差异
> System.out.println("差值: " + (totalCents / 100.0 - totalFloat));
> // 浮点版可能出现 0.000000000000004 的微小偏差
> ```
> 运行验证：整数分版计算结果精确为 38.16 元，浮点版可能略有偏差。**举一反三**：整数分版的关键技巧——先乘后除，避免整数除法截断精度。如果写成 `priceCents * 3 / 10 * 8`，`1590*3/10=477` 被截断后再乘 8 就差了 8 分钱！正确的顺序是 `priceCents * 3 * 8 / 10`。
