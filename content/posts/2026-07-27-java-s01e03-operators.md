- 踩一次「整数除法丢精度」的逻辑坑并修好;
- 用比较 / 逻辑运算符判断「够不够买」。

## 四、原理图

```text
算术  +  -  *  /  %(取余)
比较  >  <  >=  <=  ==  !=      结果是 boolean
逻辑  &&(与)  ||(或)  !(非)     短路求值
```

陷阱:`5 / 2` == `2`(两个 int,砍掉小数);要小数得让至少一个是 `double` → `5.0 / 2` == `2.5`。

**短路求值**顺带记一下:`&&` 左边为 `false` 就不看右边,`||` 左边为 `true` 就不看右边 —— 后面判空、防越界都靠它「先挡一道再往下走」。

> **豆豆旁白**:别小看 `%` 取余,它是运算街最能干的杂工。「第 N 位顾客免单」用 `n % 10 == 0`;「判断奇偶」用 `n % 2`;「让编号在 0~len 之间循环」用 `i % len`。凡是「转圈、跳格、每逢整数就触发」的需求,先想想它。

## 五、代码:算价与找零

```java
public class Cafe {
    public static void main(String[] args) {
        double price = 15.0;   // 单价
        int qty = 3;           // 杯数
        double paid = 50.0;    // 顾客付款

        double total = price * qty;      // 总价 45.0
        double change = paid - total;    // 找零 5.0
        boolean enough = paid >= total;  // 够不够付

        System.out.println("总价 ¥" + total + " · 找零 ¥" + change + " · 付款充足:" + enough);
    }
}
```

光「钱够」还不够,还得「有货」才能出杯 —— 两个条件同时成立,用逻辑与 `&&` 串起来:

```java
int stock = 2;                                   // 库存 2 杯
boolean canServe = enough && stock >= qty;       // 钱够 且 货够,才出杯
```

`&&` 还顺带帮你**防空转**:如果 `enough` 是 `false`,右边 `stock >= qty` 根本不会去算(短路)。等以后右边是「查数据库」这种昂贵操作时,这一下短路能省下真金白银。

## 六、故意制造一个 Bug

想算「人均消费」:3 杯 45 元,4 个人一起付,人均多少?

```java
int people = 4;
int subtotal = 45;               // 3 杯共 45 元(先用整数演示整除)
int avg = subtotal / people;     // ← 期望 11.25,实际得到 11
System.out.println("人均 ¥" + avg);
```

---

## 七、读懂现象(这是逻辑 Bug,不报错)

程序照跑不误,但结果 `人均 ¥11` 是错的 —— 这类**能运行、结果却不对**的叫 **Logic Bug**,编译官不会拦你,得靠自己发现。

最常见的错觉是「`11.25` 被塞进 `int` 盒子、砍成了 `11`」。**但 `11.25` 从来没被算出来过。** `subtotal` 和 `people` 都是 `int`,`45 / 4` 走的是**整数除法** —— 在做除法的那一步,小数部分就被直接丢弃,直接得 `11`。

一句话钉死:**丢精度发生在「除法」本身,不是「赋值」那一刻。**

---

## 八、修复,并用测试证明

用 `double` 保留小数:

```java
static double perPerson(double total, int people) {
    return total / people;   // total 是 double,结果就是 double
}
```

> **豆豆锐评**:只要除号两边**有一个是小数**,Java 就会把另一个也自动提升成 `double` 再算,小数就保住了 —— 这叫**类型提升**。`45.0 / 4` 得 `11.25`,`45 / 4` 得 `11`,差一个点,差一场投诉。

```java
@Test
void split_45_among_4() {
    assertEquals(11.25, Cafe.perPerson(45.0, 4));
}
```

> **🎯 面试直击**:`System.out.println(5 / 2)` 和 `5 % 2` 各输出什么?
> 分别是 `2` 和 `1`。`/` 对两个 `int` 是整除(砍小数,不四舍五入),`%` 取余数。追问防身:① 想要 `2.5`,把任一操作数写成 `double`(`5.0 / 2`),靠类型提升保精度;② `%` 还能判奇偶(`n % 2 == 0`)、做环形编号(`i % len`);③ 陷阱升级:`5 / 0` 抛 `ArithmeticException`,但 `5.0 / 0` 不抛,得到 `Infinity` —— 整数除零炸、浮点除零不炸,这一对经常连着考。

## 🎯 随堂练习

先自己做,再对答案。每道答案都带一句「举一反三」,帮你把这一个点连成一片。

### 选择题(10 道)

1. `int subtotal = 45, people = 4; int avg = subtotal / people;` 之后 `avg` 是?
   - A) `11.25`　B) `11`　C) `12`　D) 编译错误
2. 上一题的小数是在哪一步丢的?
   - A) 赋值给 `int` 变量的那一刻　B) 除法那一步,`11.25` 从来没被算出来过　C) `println` 打印时　D) 变量声明时
3. 想让 45 元 4 个人分出 `11.25`,正确做法是?
   - A) `double avg = 45 / 4;`　B) `(double)(45 / 4)`　C) 让除号至少一边是小数,如 `45.0 / 4`　D) 先乘 100 再除
4. `int a = 45, b = 4; double avg = a / b;` 打印 `avg` 得到?
   - A) `11.25`　B) `11.0`　C) `11`　D) 编译错误
5. 「第 100 位顾客免单」用哪个表达式判断?
   - A) `n / 100 == 0`　B) `n % 100 == 0`　C) `n == 100 % n`　D) `n % 0 == 100`
6. `paid >= total` 这个表达式的结果类型是?
   - A) `int`　B) `boolean`　C) `double`　D) 取决于两边的类型
7. `enough && stock >= qty` 中,当 `enough` 为 `false` 时?
   - A) 右边照样计算一遍　B) 短路,右边根本不执行　C) 编译错误　D) 整体结果为 `true`
8. `5 / 0` 和 `5.0 / 0` 分别是什么结果?
   - A) 都抛 `ArithmeticException`　B) 都得 `Infinity`　C) 前者抛 `ArithmeticException`,后者得 `Infinity`　D) 前者得 `0`,后者抛异常
9. 「人均 ¥11」这个事故属于哪一类?
   - A) 编译错误,编译官会拦下　B) 逻辑 Bug:能跑完、语法没错,结果是错的　C) 运行期异常　D) 拼写错误
10. 短路求值在真实工程里最大的价值是?
    - A) 让代码写得更短　B) 先挡一道再往下走,避免空指针、越界和昂贵操作的空转　C) 加快编译速度　D) 自动并行计算

> [!答案]
> **1-B**　两个 `int` 相除走整数除法,直接砍掉小数得 `11`。**举一反三**:笔试里凡是看到「两个整型变量相除」,先怀疑整除陷阱。
> **2-B**　精度丢在**除法本身**,不是赋值那一刻。**举一反三**:所以拿 `double` 去接结果救不回来 —— 要救必须在除号动手之前。
> **3-C**　只要一边是小数,另一边会被自动提升成 `double`。**举一反三**:工程里更常见的写法是 `total * 1.0 / people`,本质一样。
> **4-B**　`a / b` 先整除得 `11`,再提升成 `11.0` 赋给 `double`。**举一反三**:这是第 2 题的直接推论,也是「以为用了 double 就安全」的经典翻车点。
> **5-B**　`%` 取余为 0 表示整除,即每逢 100 触发一次。**举一反三**:判奇偶 `n % 2 == 0`、环形编号 `i % len`,凡「转圈、跳格、每逢整数触发」都先想 `%`。
> **6-B**　所有比较运算符的结果都是 `boolean`。**举一反三**:所以它能直接塞进 `if`,也能像本话那样先存进变量再复用。
> **7-B**　`&&` 左边为 `false` 就不看右边,这叫短路求值。**举一反三**:`obj != null && obj.getName().isEmpty()` 靠的就是这一下,顺序写反立刻空指针。
> **8-C**　整数除零抛 `ArithmeticException`,浮点除零得 `Infinity`(`0.0 / 0.0` 还会得 `NaN`)。**举一反三**:浮点不抛异常反而更危险 —— `Infinity` 会一路污染后续计算,不炸但全错。
> **9-B**　程序笑嘻嘻跑完,错的是结果不是语法,这类叫 Logic Bug。**举一反三**:编译官只管语法和类型,逻辑对不对只能靠测试钉死,这也是本话最后写 JUnit 的原因。
> **10-B**　短路让你能「先判空、先判边界,再访问」。**举一反三**:等右边是查数据库、调接口这种昂贵操作时,短路省下的是真金白银。
