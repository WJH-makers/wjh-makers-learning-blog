## 二、漫画 · HTTP 快递员

> **〔1〕** `coffee-app` 孤零零待在一座小岛上,顾客的手机在对岸挥手,中间隔着大海。
> 阿零:「它俩……根本连不上啊。」

> **〔2〕** 一位 `HTTP` 快递员划船登场:「我负责两岸往返。每次交互 = 一趟**请求(Request)**去、一趟**响应(Response)**回。」
> 豆豆:「记住这个词:**一问一答**。HTTP 是**无状态**的——这一趟快递不记得上一趟,谁是谁得靠别的办法认(第 6 话讲)。」

> **〔3〕** 快递员亮出方法牌:`GET`(取货)、`POST`(交货)、`PUT`(整件替换)、`DELETE`(退货)。
> 豆豆:「查菜单用 `GET`,下单用 `POST`——**方法表明你想干什么**。」

> **〔4〕** 回执单上盖着状态码:`200` 成功、`404` 查无此地址、`405` 方法用错、`500` 服务器自己炸了。
> 豆豆:「状态码是快递员的**回执**,一眼看出成没成、是谁的锅。」

> **〔5〕** 阿零心急,用 `GET` 去调一个只收 `POST` 的下单口,回执"啪"盖了个 `405`。
> 豆豆(叼豆子):「方法用错,人家直接退件。`405 Method Not Allowed`——记住这个红章。」

## 五、代码:用 HttpClient 发一次请求

Java 11 起内置了现代化的 `HttpClient`(在 `java.net.http`),不用再依赖第三方库:

```java
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;

public class HttpDemo {
    public static void main(String[] args) throws Exception {
        HttpClient client = HttpClient.newHttpClient();

        HttpRequest request = HttpRequest.newBuilder()
            .uri(URI.create("https://httpbin.org/get"))   // 一个回显请求的测试站
            .GET()                                          // 方法:取
            .build();

        HttpResponse<String> resp =
            client.send(request, HttpResponse.BodyHandlers.ofString());

        System.out.println("状态码:" + resp.statusCode());   // 200
        System.out.println("响应体:" + resp.body());
    }
}
```

`newBuilder()` 一步步拼出请求(URL、方法、头、体),`send` 发出去、拿回 `HttpResponse`,`statusCode()` 就是那张回执章。

## 六、故意制造一个 Bug:方法用错

`httpbin.org/post` 这个地址**只收 POST**,却用 GET 去调:

```java
HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://httpbin.org/post"))   // 只接受 POST 的地址
    .GET()                                           // ← 故意用错方法
    .build();
```

## 七、读懂现象:405 Method Not Allowed

```text
状态码:405
```

`405` 的意思是:**地址找到了,但你用的方法它不支持**。这和 `404`(地址根本不存在)是两码事——`404` 是"查无此人",`405` 是"人在、但你敲错了门"。改用 POST 并带上请求体即可:

```java
.uri(URI.create("https://httpbin.org/post"))
.POST(HttpRequest.BodyPublishers.ofString("{\"item\":\"美式\"}"))
.header("Content-Type", "application/json")
```

> **豆豆锐评 · 状态码是排障的第一现场**
> 看到报错先看状态码分类:**4xx 是你(请求方)的锅**——参数错、方法错、没权限、地址错;**5xx 是服务器的锅**——它自己炸了。分清这一点,能省掉一半"到底该改客户端还是改服务端"的扯皮。常背:200 成功、201 已创建、400 参数错、401 未认证、403 无权限、404 找不到、405 方法错、500 服务器内部错误。

> **⏳ 版本时光机 · Java 发 HTTP 请求的写法**

| JDK 版本 | 写法 | 问题 |
|---|---|---|
| Java 8 及以前 | `HttpURLConnection` | 冗长、要手动拼流、难用 |
| 老项目常见 | 第三方 Apache HttpClient / OkHttp | 得额外加依赖 |
| Java 11+ | **内置 `java.net.http.HttpClient`** | 官方、支持 HTTP/2、异步、无需第三方 |

> **🎯 面试直击**:GET 和 POST 有什么区别?
> 语义上:GET 用于**获取**资源、**幂等**(调多次结果一样)、参数在 URL、可被缓存;POST 用于**提交/创建**、**非幂等**(调两次可能下两单)、数据在请求体、不被缓存。追问点:① 幂等性是设计约定不是强制,别把有副作用的操作塞进 GET;② URL 长度有限,大量数据/敏感数据用 POST;③ 真正的安全靠 HTTPS,不是靠"POST 看不见"。

## 八、用测试证明:能拿到预期状态码

把"发请求"抽成方法,就能测它:

```java
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.Tag;
import static org.junit.jupiter.api.Assertions.*;

class HttpDemoTest {
    @Test
    @Tag("integration")   // 依赖外网,标记为集成测试,可单独跑
    void get_returns_200() throws Exception {
        var client = java.net.http.HttpClient.newHttpClient();
        var req = java.net.http.HttpRequest.newBuilder()
            .uri(java.net.URI.create("https://httpbin.org/get")).GET().build();
        var resp = client.send(req, java.net.http.HttpResponse.BodyHandlers.ofString());
        assertEquals(200, resp.statusCode());
    }
}
```

> **豆豆旁白**:碰网络、数据库的测试叫**集成测试**,慢且依赖环境,用 `@Tag` 标出来单独跑;纯逻辑的**单元测试**(第三季那种)要快、要能天天跑。两者分开,是成熟工程的习惯。
