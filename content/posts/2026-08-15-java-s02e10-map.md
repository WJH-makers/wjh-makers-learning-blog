# 《从零开始学 Java》22 · Map 菜单索引

> 连载特刊 · 第二季「对象大陆」第 10 话 · 主线基线 Java 25(最新 LTS)
> 长期项目:**豆豆咖啡站**。承接上一话——会员已能去重,而那个藏在 HashSet 肚子里的 HashMap,今天走到台前。

## 一、需求:按名字秒查咖啡

顾客报「拿铁」,咖啡站得**立刻**给出它的价格和库存。阿零用 `List<Coffee>` 存菜单,每次查都从头遍历——菜单十几款还行,将来上百款、每笔订单都遍历一遍,顾客能等到睡着。

豆豆:「你要的不是『一排货』,是『**报名字直接拉抽屉**』。键 → 值的直接映射——`Map`。给一个键,O(1) 拿到值,不用挨个找。」

## 二、漫画 · 掀开 HashMap 的底板

> **〔1〕** 一面墙全是带名牌的抽屉,阿零喊一声「拿铁」,对应抽屉「唰」地自己弹开。
> 豆豆:「`Map` 就是键值对:给一个键,直接拿到值。这面墙,就是咖啡站的菜单索引。」

> **〔2〕** 阿零好奇抽屉背后是啥,豆豆一把掀开底板——**一排编号的桶(数组)** 露了出来。
> 豆豆:「键先算 `hashCode`,再折算成桶的下标。理想情况一个桶一个值,拉开即得。」

> **〔3〕** 【特写格】某个桶里,好几个键顺着一条链子挂成一串(链表);旁边一个更挤的桶,链子已经「长」成了一棵**红黑树**,枝桠分明。
> 豆豆:「哈希撞车时,多个键落进同一个桶,先用**链表**串起来;链表太长、查得慢,才升级成**红黑树**,把桶内查找从 O(n) 压到 O(log n)。」

> **〔4〕** 阿零查一个菜单上没有的「摩卡」,抽屉拉开空空如也,他却对着空气伸手去拿——「啪」摔一跤。
> 豆豆(叼着豆子叉腰):「键不存在,`get` 给你的是 `null`。你不判空就直接 `.price()`,可不就摔个 NullPointerException。」

## 三、本话目标

- 用 `Map<K,V>` / `HashMap` 存取键值对;
- 熟练 `put` / `get` / `getOrDefault` / `containsKey` / 遍历 `entrySet`;
- 讲清 HashMap 底层「数组 + 链表 + 红黑树」与**精确的树化条件**;
- 踩一次「对不存在的键取值得到 `null`,再调用 → NPE」并修好。

## 四、原理图:HashMap 三层底盘

```text
Map<String, Coffee> menu = new HashMap<>();
menu.put("拿铁", latte);            放
menu.get("拿铁");                   取(键不存在返回 null)
menu.getOrDefault("摩卡", 缺省值);   取不到给默认,不返回 null
menu.containsKey("拿铁");           判断键是否存在

底层三层:
  数组(桶)   —— 键的 hashCode 折算成下标,理想情况直接命中
  链表       —— 多个键撞进同一个桶,先用链表串起来
  红黑树     —— 链表太长时升级,把桶内查找 O(n) → O(log n)
```

> **豆豆锐评**:一个容易被面试官挖的细节——**HashMap 允许一个 `null` 键、多个 `null` 值**(`null` 键固定放在 0 号桶);但 **`Map.of(...)` / `List.of(...)` 这些不可变工厂一律不许 `null`**,传进去当场 `NullPointerException`。所以别拿 `Map.of` 去装可能为 null 的数据,那是两套规矩。

## 五、代码:菜单索引

```java
import java.util.HashMap;
import java.util.Map;

// 全季统一:Coffee 固定三字段(含 stock),沿用第 19 话升级的 record
record Coffee(String name, double price, int stock) {}

public class MenuIndex {
    public static void main(String[] args) {
        Map<String, Coffee> menu = new HashMap<>();
        menu.put("美式", new Coffee("美式", 15.0, 20));
        menu.put("拿铁", new Coffee("拿铁", 18.0, 10));

        Coffee c = menu.get("拿铁");
        System.out.println(c.name() + " ¥" + c.price() + " 库存 " + c.stock());

        for (Map.Entry<String, Coffee> e : menu.entrySet()) {   // 遍历所有键值对
            System.out.println(e.getKey() + " → 库存 " + e.getValue().stock());
        }
    }
}
```

> **🔀 豆豆的多解台 · 遍历 Map,三种姿势怎么选?**

| 解法 | 代码要点 | 适合什么时候 | 坑 |
|---|---|---|---|
| `entrySet` | `for (var e : map.entrySet()) { e.getKey(); e.getValue(); }` | **同时要键和值**(最常见、最高效) | —— 首选,一次拿到键值对 |
| `keySet` | `for (var k : map.keySet()) { map.get(k); }` | 只关心键,或只需按键零星取值 | 循环里再 `get` 等于**查两遍**,值多时浪费 |
| `forEach` + lambda | `map.forEach((k, v) -> ...)` | 处理逻辑简单、一行能写完 | lambda 里不能改 map 结构;异常处理不如 for 直观 |

豆豆锐评:**要键又要值,默认 `entrySet`**——一次遍历直接拿到键值对,别用 `keySet` 再 `get` 白查两遍。至于 `forEach` 那行 lambda 语法,你先眼熟,**第三季专讲 Lambda 与 Stream** 时再系统展开。

## 六、故意制造一个 Bug:对 null 调方法

查一个菜单上没有的「摩卡」,直接用返回值:

```java
Coffee c = menu.get("摩卡");        // 键不存在,返回 null
System.out.println(c.price());      // ← 故意:对 null 调方法
```

## 七、读懂真实报错

```text
Exception in thread "main" java.lang.NullPointerException:
        Cannot invoke "Coffee.price()" because "c" is null
        at MenuIndex.main(MenuIndex.java:14)
```

现代 JDK(自 Java 14 起的**帮助性 NPE 提示**)明确点名 `because "c" is null`,连是哪个变量为 null 都告诉你了。根因:`get` 对不存在的键返回 `null`,你不判空直接 `.price()` 必崩。修法两条:先 `containsKey` 判断,或用 `getOrDefault` 给个兜底值。

> **🎯 面试直击**:HashMap 什么时候把链表转成红黑树?
> **两个条件同时满足才树化**:① 单个桶内元素个数 **≥ 8**,**且** ② 整个哈希表的容量 **≥ 64**。若元素到了 8 但容量还不到 64,HashMap **优先扩容**(把桶摊开)而不是树化——因为容量小的时候,扩容比建树更划算。反过来,当树的节点删到 **≤ 6** 时,退化回链表。追问点:为什么阈值是 8 和 6 不是同一个数?中间留个缓冲(6~8),避免元素在阈值附近反复增删时「树↔链表」来回抖动。

## 八、修复,并用测试证明

```java
static double priceOf(Map<String, Coffee> menu, String name) {
    Coffee c = menu.get(name);
    return c == null ? 0.0 : c.price();   // 缺货返回 0,绝不崩
}
```

```java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.assertEquals;

class MenuIndexTest {
    @Test
    void price_lookup_is_null_safe() {
        var menu = Map.of("美式", new Coffee("美式", 15.0, 20));
        assertEquals(15.0, MenuIndex.priceOf(menu, "美式"));
        assertEquals(0.0, MenuIndex.priceOf(menu, "摩卡"));   // 不存在,兜底为 0,不崩
    }
}
```

## 🎯 随堂练习
先自己做，再对答案。选择难度递进，解答从概念到综合，代码含边界验证。

### 一、选择题（10 道）

1. [基础] `Map` 用于存储什么类型的数据？- A) 只能存一种　B) 键值对（key-value）　C) 有序列表　D) 不重复的元素
2. [基础] 用什么方法向 `Map` 中添加键值对？- A) `add()`　B) `put()`　C) `insert()`　D) `set()`
3. [基础] `map.get(key)` 在 key 不存在时返回什么？- A) 抛异常　B) `null`　C) `0`　D) `""`
4. [进阶] 判断 key 是否存在应该用哪个方法？- A) `get(key) == null`　B) `containsKey(key)`　C) `contains(key)`　D) `exists(key)`
5. [进阶] `keySet()` 和 `entrySet()` 遍历的区别是什么？- A) 无区别　B) `keySet()` 只拿 key、后续还需 `get()` 再查一次；`entrySet()` 一次性拿 key+value　C) `keySet()` 更快　D) `entrySet()` 不能用 for-each
6. [进阶] `HashMap` 的底层数据结构是什么？- A) 数组 + 链表 + 红黑树　B) 双向链表　C) 只有数组　D) 红黑树
7. [进阶] `HashMap` 什么时候链表会转红黑树？- A) 任意时候　B) 链表长度 ≥ 8 **且** 数组长度 ≥ 64　C) 链表长度 ≥ 8 即可　D) 数组满了
8. [综合] `HashMap` 和 `TreeMap` 的区别是什么？- A) 完全相同　B) `HashMap` 无序 O(1)，`TreeMap` 按 key 排序 O(log n)　C) `HashMap` 不允许 null key　D) `TreeMap` 更快
9. [综合] 下面代码的 `map.get(null)` 输出什么？```java Map<String, String> map = new HashMap<>(); map.put(null, "空值"); System.out.println(map.get(null));```- A) 抛 NPE　B) `"空值"`　C) `null`　D) 编译错误
10. [综合] `getOrDefault(key, defaultValue)` 相比手动 `if (map.containsKey(k)) ... else ...` 的优势是什么？- A) 没优势　B) 一行代码解决"有则返回、无则默认"，且原子性更好（在并发场景有细微差别）　C) 不可读　D) 只适用于 TreeMap

> [!答案] **1-B**　`Map<K,V>` 存储键值对，每个 key 唯一对应一个 value。**2-B**　`put(key, value)` 添加或替换。**3-B**　返回 `null`，不抛异常。但如果 value 本身就可能是 `null`，无法区分"不存在"和"存了 null"——这时用 `containsKey`。**4-B**　`containsKey` 语义明确，不受 value 是否为 null 的影响。**5-B**　`entrySet()` 一次迭代同时拿到 key 和 value，避免 `map.get(key)` 的二次哈希查找——性能更好。**6-A**　`HashMap` = 数组（桶）+ 链表（解决冲突）+ 红黑树（链表太长时优化为 O(log n)）。**7-B**　树化条件：链表长度 ≥ `TREEIFY_THRESHOLD`(8) **且** 桶数组长度 ≥ `MIN_TREEIFY_CAPACITY`(64)。退化回链表阈值是 ≤6。**8-B**　`HashMap` 基于哈希表，O(1) 查 but 无序；`TreeMap` 基于红黑树，O(log n) 但按 key 排序。**9-B**　`HashMap` 允许一个 null key（存在下标为 0 的桶里），`get(null)` 正常返回对应的 value。**10-B**　一行代码 + 意图清晰。尤其在 `ConcurrentHashMap` 中，`getOrDefault` 是原子操作，而分两步的 `containsKey` + `get` 之间有竞态窗口。
**举一反三**：第 6、7 题是面试八股标配——"HashMap 底层"和"树化条件 8 且 64"，背精确数字是加分项（尤其 64 这个条件经常被漏掉）。

### 二、解答题（3 道）

1. [概念] `HashMap` 的工作原理：从 `put(key, value)` 到 "数组 + 链表 + 红黑树"，一步一步描述发生了什么。
2. [场景] 咖啡站需要"按咖啡名查价格"的功能。为什么用 `HashMap<String, Double>` 而不是 `ArrayList` 遍历？分析从 100 条记录里查找某款咖啡的时间复杂度差异。
3. [综合] 为什么 `HashMap` 的 key 必须是不可变的（或至少 `hashCode` 稳定）？如果一个对象被用作 key 后，其 `hashCode` 发生了变化，会发生什么？用具体例子说明。

> [!答案] **1**　`put(key, value)` 流程：①计算 key 的 `hashCode()` → 扰动函数处理（`h ^ h>>>16`）→ 对数组长度取模定位桶下标。②如果桶为空，直接放入。③如果桶非空：遍历桶内的链表/红黑树，用 `equals()` 比较——找到相同 key 则替换 value，没找到则在末尾追加。④插入后如果链表长度 ≥ 8 且数组长度 ≥ 64，链表转为红黑树；如果链表长度 ≤ 6，退化为链表。⑤`size++` 后如果超过 `threshold`（容量 × 负载因子 0.75），扩容——数组翻倍，所有元素重新哈希（rehash）分布。**举一反三**：第 ③ 步中的"扰动函数"把 hashCode 的高位和低位混合——因为取模时低位决定桶位置，单纯用低位容易碰撞。**2**　`ArrayList` 查找需要遍历——O(n)，100 条平均查 50 次；`HashMap` 哈希查找——O(1)，一次哈希计算直接定位桶，桶内至多比较几个元素。100 条时差距不大，但万级/百万级数据量时差异是天壤之别。**举一反三**：`HashMap` 的空间换时间——预分配数组（桶）来换 O(1) 查找；`ArrayList` 省内存但慢。实际项目中的"菜单索引"、"用户缓存"、"配置查找"几乎都是 Map 场景。**3**　如果 key 的 `hashCode` 在放入 Map 后发生了变化，该 key 的桶位置已经变了，但 Map 内部仍记录它原来的桶位置。后果：`map.get(key)` 会去新的桶位置找——找不到；但 `map.containsKey(key)` 也找不到；而 `map.size()` 不会减少——这个 key-value 成了**泄露的幽灵条目**（无法访问、无法删除、占着内存）。经典例子：
> ```java
> Map<List<String>, String> map = new HashMap<>();
> List<String> key = new ArrayList<>(List.of("A"));
> map.put(key, "值");
> key.add("B");  // key 内容变了 → hashCode 变了
> map.get(key);  // null！找不到！
> ```
> **举一反三**：这就是为什么推荐用不可变对象做 key——`String`、`Integer`、`record`。如果必须用可变对象，至少保证用作 key 后不再修改其参与 `hashCode` 的字段。

### 三、代码题（2 道）

1. [基础] 创建 `Map<String, Double> menu`，存入 "美式"(15.9)、"拿铁"(18.5)、"摩卡"(22.0)。用 `entrySet()` 遍历打印 `"美式: 15.9元"` 格式。再用 `getOrDefault` 安全查询 "焦糖玛奇朵"（不存在时返回 0.0），打印结果。
2. [综合] 实现按值排序：给定 `Map<String, Integer>`（咖啡名 → 销量），按销量从高到低排序输出排行榜。提示：用 `entrySet()` 转 `List` + `sort` + `Comparator` 实现。写边界测试：空 Map、单元素、销量相同（验证不丢数据）。

> [!答案] **1 验收**：
> ```java
> Map<String, Double> menu = new HashMap<>();
> menu.put("美式", 15.9);
> menu.put("拿铁", 18.5);
> menu.put("摩卡", 22.0);
> // entrySet 遍历
> for (var entry : menu.entrySet()) {
>     System.out.println(entry.getKey() + ": " + entry.getValue() + "元");
> }
> // 安全查询
> double price = menu.getOrDefault("焦糖玛奇朵", 0.0);
> System.out.println("焦糖玛奇朵: " + price);  // 0.0
> System.out.println(menu.containsKey("焦糖玛奇朵")); // false
> ```
> **举一反三**：`var`（Java 10+）省去了手写 `Map.Entry<String, Double>` 的麻烦。**2 验收**：
> ```java
> static List<Map.Entry<String, Integer>> topSales(Map<String, Integer> sales) {
>     List<Map.Entry<String, Integer>> list = new ArrayList<>(sales.entrySet());
>     list.sort((a, b) -> b.getValue().compareTo(a.getValue())); // 降序
>     return list;
> }
> // 边界测试:
> Map<String, Integer> empty = Map.of();
> System.out.println(topSales(empty));  // []
> Map<String, Integer> single = Map.of("美式", 100);
> System.out.println(topSales(single)); // [美式=100]
> Map<String, Integer> tied = new HashMap<>();
> tied.put("拿铁", 50); tied.put("美式", 50);  // 销量相同
> System.out.println(topSales(tied));  // [拿铁=50, 美式=50] —— 都在，不丢
> Map<String, Integer> multi = new HashMap<>();
> multi.put("美式", 30); multi.put("拿铁", 80); multi.put("摩卡", 50);
> System.out.println(topSales(multi)); // [拿铁=80, 摩卡=50, 美式=30]
> ```
> **举一反三**：`Map` 本身不保证顺序，但转成 `List<Entry>` 后可以任意排序——这是"按值排序"的标准做法。如果数据量大可以考虑 `PriorityQueue`（堆排序）只取 Top N。
