## 六、第二场 · 候选人 B:一道死循环,一道超卖

**第一题(排障)**:备注校验 `^(\w+\s?)+$` 让服务 CPU 100% 假死。B 走五步法:观察(单核拉满、无异常)→ 收集(jstack 两次都停在 `java.util.regex.Matcher.match`)→ 假设(嵌套量词灾难性回溯)→ 改一个变量(输入截到 10 字符立刻返回,坐实指数爆炸)→ 修(消嵌套量词 + 入口限长,回看 #63)。阿零画了三颗星。

**第二题(上机)**:#79 事故的最小复刻——「这段扣库存,大促夜超卖过。**复现它,修好它。我只提问。**」

```java
class Stock {
    private final Map<String, Integer> shelf =
            new ConcurrentHashMap<>(Map.of("燕麦拿铁", 100));

    boolean deduct(String name) {
        Integer left = shelf.get(name);      // 查:读到瞬间的旧值
        if (left != null && left > 0) {
            shelf.put(name, left - 1);       // 扣:两步棋,中间没人拦
            return true;
        }
        return false;
    }
}
```

## 八、B 的修复:把两步棋合成一步

B 给出层次答案:单机三选(synchronized 收窄/CAS 自旋/CHM `compute`),多实例上分布式锁(回看 #48)。上机选 CAS(回看 #71):

```java
class Stock {
    private final AtomicInteger left = new AtomicInteger(100);

    boolean deduct() {
        while (true) {
            int cur = left.get();
            if (cur <= 0) return false;                         // 卖完即止
            if (left.compareAndSet(cur, cur - 1)) return true;  // 查+扣,一步原子
        }
    }
    int left() { return left.get(); }
}
```

JUnit 齐射作证,虚拟线程一任务一线程(回看 #78):

```java
@Test
void no_oversell_under_fire() throws Exception {
    var stock = new Stock();
    var ready = new CountDownLatch(200);
    var go = new CountDownLatch(1);
    var sold = new AtomicInteger();
    try (var pool = Executors.newVirtualThreadPerTaskExecutor()) {
        for (int i = 0; i < 200; i++) pool.submit(() -> {
            ready.countDown(); go.await();   // 齐步,同一瞬间开火
            if (stock.deduct()) sold.incrementAndGet();
            return null;
        });
        ready.await(); go.countDown();
    }
    assertEquals(100, sold.get());   // 一杯不多
    assertEquals(0, stock.left());   // 一杯不少
}
```

全绿,质检员盖章。阿零写下:**录用**——「步步有证据。事故不挑你背过的考,排障才是通用解。」

> [!答案]
> **选择题**
> 1-B。三条尺子:原理 > 名词(如「树化把 O(n) 兜回 O(log n)」而非「超 8 就变红黑树」)、边界 > 结论(如「树化还需容量≥64,退化阈值≤6」而非只背数字)、排障 > 背诵(现象→证据→假设→验证→修复)。★举一反三:这三条尺子是本话的灵魂——你面试别人时用量,面试时也被这样量。

> 2-B。树化的完整条件:链表长度>8 && 数组容量≥64;退化条件:红黑树节点≤6 时退化回链表。只背「>8 变红黑树」缺少边界条件——容量不够时先扩容。★举一反三:追问边界条件是区分「背的」和「懂的」的最快方式。
>
> 3-B。JEP 374 在 JDK 15 默认禁用偏向锁(因维护代价高、现代应用收益递减),JDK 18 彻底移除相关代码。现代 JDK 只有两条路:无锁→轻量级 CAS→重量级。★举一反三:面试中说「偏向锁」且没有标注「已移除」,会被立刻追问现代 JDK 状态——版本意识是工程师的基本素质。
>
> 4-B。`left = shelf.get(name)` 和 `shelf.put(name, left-1)` 之间,另一个线程可能也读到了相同的 `left`,然后各自用相同的旧基点做 `left-1` 写入,后写入的覆盖先写入的——少扣。★举一反三:所有「先读再写」的并发操作都有 check-then-act 竞态——解决手段是让读写原子化(CAS/compute/锁)。
>
> 5-B。排障五步法:①观察(现象)——②收集(日志/堆栈/指标)——③假设(根据证据形成根因猜测)——④改一个变量验证(最小实验,确认假设)——⑤修复(根治并加入回归测试)。★举一反三:五步法中④最被忽视——跳过验证直接修,可能修错地方。
>
> 6-B。CHM 保证 `get`/`put`/`remove` 等单个操作的线程安全(不会破坏内部结构),但复合操作(先 get 再 put)不原子——两个线程可能都读到旧值,互相覆盖。正确做法:用 `compute`/`merge`/`computeIfAbsent`/`replace` 等原子复合方法。★举一反三:这个问题和「volatile 不保证 count++ 原子性」是同一类——单个操作安全≠组合操作安全。
>
> 7-B。阿零在引导 B 自我发现「线程安全容器 ≠ 你的业务逻辑是线程安全的」——这是并发编程的核心认知。CHM 保证它自己的数据不错,但不管你的业务逻辑组合。★举一反三:好面试官不直接告诉答案,而是通过提问引导候选人自己发现盲区——阿零正在成长为这样的面试官。
>
> 8-B。`compareAndSet(cur, cur-1)` 是 CAS 操作:比较当前值是否仍是 `cur`,是则更新为 `cur-1`,否则自旋重试——无锁(lock-free)原子操作。★举一反三:CAS 解决超卖是最精简的单机方案,多实例需要分布式锁(Redis/ZK)或数据库行锁。
>
> 9-B。虚拟线程是 JVM 管理的轻量级线程,创建成本极低(几微秒),设计上就是一任务一线程、用完即弃。池化是平台线程「创建成本高」时代的补偿方案,虚拟线程时代不需要也不应该池化。★举一反三:面试考核的是「是否理解技术背后的设计意图」,不是「能否背出用法」。
>
> 10-B。C 的简历只有一行,但他展现了**解决真实问题的能力和态度**。阿零收他为学徒,正是认同「技术可以学,排障思维和学习意愿更珍贵」——也呼应了他自己从 S1E1 走来的路。★举一反三:技术招聘不是在找「已经会一切的人」,而是在找「能学会一切的人」。
>
> **解答题**
>
> **Q1** 得分示例:①原理>名词——问「HashMap 为什么用红黑树不用 AVL」→得分回答:「链表 O(n)退化,红黑树在插入/删除时比 AVL 旋转更少,在 HashMap 这种频繁插入的场景下更适合;AVL 查询更快但写代价高」;丢分回答:「因为红黑树快」。②边界>结论——问「线程池核心线程满了怎么办」→得分回答:「先入队列(优先级:corePool→队列→maxPool→拒绝策略),队列类型决定了缓冲行为,无界队列可能导致 OOM」;丢分回答:「满了就创建新线程」。③排障>背诵——问「线上 CPU 飙到 100%」→得分回答:「`top -Hp` 找高 CPU 线程→`jstack` 导出堆栈→看线程状态(RUNNABLE 在干什么/BLOCKED 在等什么)→结合代码定位」;丢分回答:「重启服务」或「不知道」。★举一反三:如果你被面试,时刻提醒自己——每个回答后面都可以加一句「为什么」,准备了这句话才算真的懂。
>
> **Q2** 偏向锁的设计初衷:当一个锁一直被同一个线程获取时,通过偏向锁省去 CAS 操作(在 Mark Word 记录线程 ID 即可)。但现实中:①现代应用很少满足「锁长期由一个线程持有」;②偏向锁的「撤销」操作需要走到安全点(Stop-The-World),代价高,特别是高并发下批量撤销会引发明显停顿;③JEP 374 的数据显示移除偏向锁后**没有性能退化**,反而消除了一大段复杂的维护代码。所以 JDK 15 默认禁用,JDK 18 代码移除,现代路径:无锁→CAS 轻量级自旋→重量级阻塞。★举一反三:这个案例是「版本演进去掉旧假设」的教科书——技术在进步,我们背的八股也要跟着进步。
>
> **Q3** 追问设计:①「HashMap 链表转红黑树的条件是 >8,那为什么是 8,不是 6 或 10?」→目的是考察是否理解 Poisson 分布的概率计算(HashMap 设计文档中提到,负载因子 0.75 下,链表长度达到 8 的概率约为 0.00000006)。②「退化回链表的阈值为什么是 ≤6,而不是 7? 8 和 6 之间这个差值有什么作用?」→目的是考察是否理解「缓冲区间」的设计——避免在 7、8 之间频繁树化/链化来回切换。③「扩容时红黑树如何拆分?」→目的是考察是否看过源码——按高低位分组,若拆完某一组 ≤6 则退化为链表。★举一反三:设计追问的原则:①问数字的来源②问边界条件的含义③问实现细节。
>
> **Q4** 两个线程 T1 和 T2 同时执行 `deduct` 的时间线:
> ```
> T1: left = shelf.get("拿铁")  → 读到 10
> T2: left = shelf.get("拿铁")  → 也读到 10 (还没人写过)
> T1: shelf.put("拿铁", 10-1=9) → 写入 9
> T2: shelf.put("拿铁", 10-1=9) → 写入 9 (覆盖 T1 的结果!)
> ```
> 本来期望两杯各扣 1 变成 8,实际只剩 9。覆写发生的时刻:当两个线程基于同一个「旧快照」(`left=10`)各自算出新值并写入时,后写入的(T2)直接覆盖了(T1)的写入——T1 的扣减操作被静默吞掉了。★举一反三:check-then-act 的根本问题在于「check 和 act 之间的世界变了」——要解决就必须让 check 和 act 原子:①CAS(比较并交换,check 和 act 在硬件指令级合为一体)②compute 原子复合③悲观锁。
>
> **Q5** 评估标准设计:
> **初级**:核心考察「能做」。①基础语法与集合使用(能写正确代码);②基本的异常处理与调试能力(能读堆栈);③能独立完成小功能。排障:能定位简单的 NPE/ArrayIndexOutOfBounds。
> **中级**:核心考察「能懂」。①JVM 内存模型与 GC 基础(知道 heap/stack,能调 GC 日志);②多线程安全(能识别 check-then-act 和锁的正确用法);③数据库索引与事务(能写 EXPLAIN、理解隔离级别);④框架原理(Bean 生命周期、AOP)。排障:能用 jstack/jmap/EXPLAIN 独立定位线上问题。
> **高级**:核心考察「能设计」+「能传下去」。①分布式系统设计(一致性、CAP、拆分权衡);②JVM 深度(能分析 GC 日志、JIT 行为、内存泄漏);③架构决策能力(选型矩阵,not rocket science);④带人能力(能像阿零一样通过提问引导,而非直接给答案)。排障:能从零构建排障体系(监控、告警、日志规范、事故复盘流程)。
> 「排障能力」贯穿各层的原因:代码人人会写,bug 人人会出——能独立从现象走到根因的工程师,才是有战斗力的工程师。初级排自己代码的错,中级排同级代码的错,高级排跨系统的错并建立预防机制。★举一反三:如果你在面试,用本话的三条尺子自问——我的回答里,原理够不够深?边界够不够细?碰到没见过的场景,我有没有一套排障的肌肉记忆?
