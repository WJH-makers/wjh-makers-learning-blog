## 一、需求:给访问日志做一次体检

上一话阿零学会了用 `|` 串流水线。今天豆豆直接下单:「咖啡站上线一早上,`access.log` 攒了一堆访问记录。我要一份**体检报告**:一共来了多少次?谁来得最勤?各状态码几次?错误率多高?——**用你昨天那根管子。**」

这就是本卷第一场实战:四个新工位 `cut / sort / uniq / wc` 接上管道,把一堆原始日志**榨成几个数字**。原料就是咖啡站的访问日志(每行一次访问,空格分隔):

```text
192.0.2.10 - - [24/Sep/2026:08:01:12 +0800] "GET /menu HTTP/1.1" 200 1043
192.0.2.12 - - [24/Sep/2026:08:04:31 +0800] "GET /coffee HTTP/1.1" 404 512
192.0.2.10 - - [24/Sep/2026:08:07:20 +0800] "POST /order HTTP/1.1" 500 77
...(共 10 行)
```

字段位置先数清楚:**第 1 列 = IP,第 9 列 = 状态码**(按空格切)。

## 二、漫画 · 四工位流水线

> **〔1〕** 车间里一字排开四台机器,牌子分别写着 `cut` `sort` `uniq` `wc`。管道工把上一话那根竖管往机器之间一接。
> 管道工:「昨天你会接管子了。今天认识管子上的**四个工位**。」

> **〔2〕** 管道工拍第一台 `cut`:「**切**。日志是一排排字段,`cut` 负责按分隔符切下你要的那一列——第 1 列 IP,还是第 9 列状态码。」

> **〔3〕** 拍第二台 `sort`:「**排**。把相同的排到一起。」再拍 `uniq`:「**去重计数**。」特米插话:「注意——`uniq` 只认**相邻**的重复。不先 `sort`,它就瞎。」

> **〔4〕** 阿零抢着敲 `cut -d' ' -f1 access.log | uniq -c`,想数每个 IP 几次,结果每个都是 `1`,一个没合并。
> 阿零:「怎么全是 1?!」特米(叹气):「因为你**没先 sort**。相同 IP 没挨在一起,`uniq` 当然看不见。」

> **〔5〕** 阿零补上 `sort`,数字对了。管道工拍最后一台 `wc`:「**数**。`wc -l` 数行数——一行一次访问,行数就是**总访问量**。」

> **〔6〕** 四台机器咔咔运转,一份体检报告从管尾吐出。阿零举着报表:「原来一屏乱码日志,能榨成这么几个数!」

## 三、本话目标

- `cut -d -f`:按分隔符切出指定列(IP=第1列,状态码=第9列);
- `sort` / `sort -rn`:字典序排 vs 按数字倒序排,理解 `-n` 为什么必须;
- `uniq -c`:去重并计数,牢记**必须先 sort**(只去相邻重复);
- `wc -l`:数行数 = 数访问次数;
- 把四者串成流水线,产出**总量 / Top IP / 状态码分布 / 错误率**四份数据。

## 四、原理图:四工位各司其职

```text
原始日志 ──▶ cut ──▶ sort ──▶ uniq -c ──▶ sort -rn ──▶ 报表
             切列     排序      去重计数     按数倒排

cut  -d' ' -f1   -d 指定分隔符(delimiter),-f 指定第几列(field)
sort              默认按"字符串字典序";-n 按数值,-r 倒序
uniq -c           把"连续相同"的行压成一行,-c 在前面标出现次数
                  ⚠ 只看相邻!所以上游必须先 sort
wc   -l           数行数(-l=lines,-w 词,-c 字节)
```

**黄金搭档:`sort | uniq -c | sort -rn` —— 排好、数一遍、按热度倒排。这三节几乎是日志分析的固定咒语。**

## 五、上手:一步步做出体检报告

**① 总访问量**(几行 = 几次访问):

```bash
$ wc -l logs/access.log
10 logs/access.log
```

**② Top IP**(谁来得最勤):

```bash
$ cut -d' ' -f1 logs/access.log | sort | uniq -c | sort -rn
      3 192.0.2.11
      3 192.0.2.10
      2 192.0.2.12
      1 192.0.2.14
      1 192.0.2.13
```

读法:`.11` 和 `.10` 各来 3 次并列榜首。四个工位:切出 IP → 排序聚拢 → 去重计数 → 按次数倒排。

**③ 各状态码分布**(第 9 列):

```bash
$ cut -d' ' -f9 logs/access.log | sort | uniq -c | sort -rn
      5 200
      2 404
      1 500
      1 403
      1 201
```

一眼看出:成功(200/201)6 次,客户端错(403/404)3 次,服务端错(500)1 次。

**④ 错误率**(4xx/5xx 占比,用 grep 数分子、wc 数分母):

```bash
$ grep -E '" (4|5)[0-9][0-9] ' logs/access.log | wc -l    # 4xx+5xx 行数
4
$ wc -l < logs/access.log                                  # 总行数(< 喂文件,输出不带文件名)
10
```

4/10 = **40% 错误率**——上线第一早上就该报警了。把这份报告落地存档:

```bash
$ cut -d' ' -f9 logs/access.log | sort | uniq -c | sort -rn > logs/status-report.txt
```

> **特米旁白**:`wc -l logs/access.log` 会带上文件名(`10 logs/...`),而 `wc -l < logs/access.log` 用重定向喂进去、只吐数字 `10`。要拿数字进一步算的时候,用后者更干净。

## 七、读懂真实报错

这个坑又是**不报错**的那种——它给你一个「看起来对、其实全错」的结果:

```text
      1 192.0.2.10
      1 192.0.2.11
      1 192.0.2.10
      1 192.0.2.12
      1 192.0.2.11
      1 192.0.2.13
      1 192.0.2.10
      ...
```

每个都是 `1`,`.10` 出现了三处独立的 `1`,根本没合并。根因:**`uniq` 只压缩「连续相邻」的重复行**。原始日志里 `.10` 的三次访问被别的 IP 隔开了,不相邻,`uniq` 就当它们是三个不同的东西。修法就是漫画那句——**先 sort 让相同的挨到一起,uniq 才看得见**:

```bash
$ cut -d' ' -f1 logs/access.log | sort | uniq -c
      3 192.0.2.10
      3 192.0.2.11
      2 192.0.2.12
      1 192.0.2.13
      1 192.0.2.14
```

**记死这条:`uniq` 前面永远跟一个 `sort`。** 这是新手最高频的日志分析翻车点。

> **🪟 双系统对照 · 四工位在 PowerShell 上怎么摆**

bash 靠「切字符列」,PowerShell 靠「对象属性 + 分组」,思路完全不同:

| 干什么 | Linux (bash) | PowerShell 7 |
|---|---|---|
| 切某列 | `cut -d' ' -f1` | `-split ' '` 后取 `[0]`,或 `Select-Object` 属性 |
| 排序 | `sort` / `sort -rn` | `Sort-Object` / `Sort-Object -Descending` |
| 去重计数 | `sort \| uniq -c` | `Group-Object` (自带 Count,**不需要先排序**) |
| 数行数 | `wc -l` | `Measure-Object -Line` 或 `(...).Count` |

同一个「Top IP」需求:

```powershell
Get-Content logs\access.log |
  ForEach-Object { ($_ -split ' ')[0] } |
  Group-Object | Sort-Object Count -Descending |
  Select-Object Count, Name
```

注意 PowerShell 的 `Group-Object` **不用先排序**——它按对象分组,不像 `uniq` 只看相邻行。这正是「对象管道 vs 文本流」在本话最实用的一处:bash 的 `uniq` 有「必须先 sort」的坑,PS 的 `Group-Object` 天生没有。但服务器上没有 `Group-Object`,`sort | uniq -c` 的咒语还得背熟。

> **🎯 面试直击**:`sort | uniq -c` 为什么不能只用 `uniq -c`?
> 因为 `uniq` 只合并**相邻**的重复行,乱序数据里相同项不相邻就漏统计。必须先 `sort` 把相同行聚在一起。追问:统计 Top N 的完整咒语是 `sort | uniq -c | sort -rn | head -n N`——排序聚拢、去重计数、按热度倒排、取前 N。

## 八、用命令验证:报表数字对得上吗

交叉验证——不同 IP 的个数,不该超过总访问量:

```bash
$ wc -l < logs/access.log                       # 总访问量:10 次
10
$ cut -d' ' -f1 logs/access.log | sort -u | wc -l   # 不同 IP 数(sort -u = sort | uniq)
5
$ echo $?
0
```

10 次访问来自 5 个 IP,数量自洽,报表可信。(`sort -u` 是「排序并去重」的一步写法,比 `sort | uniq` 更短。)

### 解答题(5 道)

**Q1 概念:** `cut`、`sort`、`uniq`、`wc` 在数据管道中各扮演什么角色?用"工厂流水线"比喻说明。

**Q2 解释:** 为什么 `uniq -c` 必须在 `sort` 之后才能正确工作?举例说明不先排序会导致什么结果。

**Q3 操作:** 写出命令,统计 Apache/Nginx 日志 `access.log` 中每种 HTTP 状态码的出现次数,按出现次数降序排列。

**Q4 排障:** 菜菜用 `cut -d' ' -f1 access.log | sort | uniq -c | sort -rn` 统计 IP 访问频次,但输出中有些 IP 出现了多次(如 `192.0.2.1` 显示为两行),分析可能的原因。

**Q5 综合设计:** 日志文件 `access.log` 每行格式:`IP - - [时间] "方法 URL 协议" 状态码 字节数`。设计管道完成:①提取所有返回 404 状态码的 URL ②统计每个 URL 出现次数 ③按次数降序排列,显示 Top 10 ④将结果存入 `404_top10.txt`。

> [!答案]
> **1-B** `-d` = delimiter(分隔符),`-f` = field(字段,从 1 开始编号)。**举一反三:**`cut -d: -f1,3` 提取以冒号分隔的第 1 和第 3 列;`cut -c 1-5` 按字符位置截取(第 1~5 个字符)。🪟 PowerShell 中 `(echo $line).Split(':')[0]` 实现类似功能。
>
> **2-B** 默认字典序:字符串比较,`10` < `2`(因为 `'1'` < `'2'` 的 ASCII 值)。`-n` 数值序:`2` < `10`(因为数值比较)。**举一反三:**这是初学者最常见陷阱——`sort` 不加 `-n` 时,`1,10,2,20` 排成 `1,10,2,20` 而非 `1,2,10,20`。
>
> **3-C** `-l`=lines(行数),`-w`=words(单词数),`-c`=bytes(字节数),`-m`=chars(字符数)。**举一反三:**`wc` 不加选项同时输出行数、单词数、字符数。`wc < file`(重定向)不显示文件名,适合在管道中使用。
>
> **4-A** `uniq` 只移除相邻的重复行,不排序会导致非连续的重复行被保留。**举一反三:**`uniq -c` 的输出格式:`次数 行内容`(如 `3 hello`)。`uniq -d` 只显示重复的行,`uniq -u` 只显示唯一的行。
>
> **5-B** `-r` = reverse,逆序排列。**举一反三:**`sort -rn` 数值降序;`sort -r` 字典降序。`sort -t: -k2 -n` 按冒号分隔后第 2 字段数值排序。
>
> **6-B** 以逗号为分隔符,第 1 字段=Alice,第 2 字段=30,第 3 字段=Engineer。`-f2` 提取第 2 个字段,即 `30`。**举一反三:**`cut` 的字段编号从 1 开始(不是 0);`-f1,3` 可以同时提取多个字段。
>
> **7-B** `cut -d' ' -f1` 提取以空格分隔的第 1 个字段(IP 地址),然后 `sort|uniq -c|sort -rn|head -3` 标准流程。**举一反三:**A 选项缺少提取 IP 字段这一步;`sort|uniq -c|sort -rn` 是管道编程的经典"三板斧"。
>
> **8-A** `-t:` 指定字段分隔符为冒号,`-k3` 指定按第 3 个字段排序。**举一反三:**`-t` 和 `-k` 是 `sort` 最强大的两个选项,可以按 CSV 文件的任意列排序。`-k3,3n` 表示严格按第 3 字段数值排序。
>
> **9-B** `sort` 排序→`uniq -c` 合并相邻重复行并计数→`sort -rn` 按计数降序。这是"频率分析"的标准管道路径。**举一反三:**这个组合可以用于任何需要统计频率的场景:IP 访问量、404 URL、API 调用次数、单词出现频率等。
>
> **10-B** `wc` 的"单词"定义为:由空白字符(空格、制表符、换行符)分隔的连续非空白字符序列。**举一反三:**`wc -w` 适合快速估量文本量,但不适合精确的中文分词(中文词间没有空格)。🪟 PowerShell 中 `(Get-Content file).Count` 获取行数。
>
> **Q1** 工厂流水线比喻:①`cut`=分拣工:从每一行中切出指定字段。②`sort`=整理工:将行按规则重新排列。③`uniq -c`=计数员:合并相同行并统计次数。④`wc -l`=总统计员:数一数总共多少行。**协作模式:**`cut` 提取 → `sort` 归类 → `uniq -c` 计数 → `sort -rn` 按频次排名 → `head` 取 Top N。
>
> **Q2** `uniq` 只检查相邻行是否相同。输入 `a\na\nb\na`(a 出现 3 次但不全相邻),`uniq -c` 输出 `2 a\n1 b\n1 a`(把不连续的 a 当作新行)。先 `sort` 把所有相同行聚到一起:`sort | uniq -c` 输出 `3 a\n1 b`。**教训:**`sort | uniq -c` 不是建议,是必须。
>
> **Q3** 假设日志格式中状态码在第 9 个空格分隔字段:`awk '{print $9}' access.log | sort | uniq -c | sort -rn`。如果日志格式不同,也可用:`grep -oP '"\s+\d{3}\s+' access.log | awk '{print $2}' | sort | uniq -c | sort -rn`。**举一反三:**需要更精确解析时,`awk` 比 `cut` 灵活得多(awk 自动将连续空白视为一个分隔符,而 cut 严格要求单个字符)。
>
> **Q4** 可能原因:①日志中 IP 前后有额外的空格或制表符,导致 `cut` 切出来的 IP 不干净(如 `192.0.2.1` 和 ` 192.0.2.1`) ②有些行格式不一致(如某些行多了或少了字段),导致 IP 不在第 1 字段 ③日志中包含不同格式的行(如错误页面),这些行解析出来的"IP"实际是时间戳或其他字段。**排查:**`awk '{print $1}' access.log | sort | uniq -c | sort -rn` 用 awk 替代 cut;awk 默认以空白字符分隔且合并连续空白,更鲁棒。
>
> **Q5** 命令:`grep ' 404 ' access.log | awk '{print $7}' | sort | uniq -c | sort -rn | head -10 | tee 404_top10.txt`。解析:①`grep ' 404 '` 过滤状态码为 404 的行(空格包围避免匹配 1404 等数字) ②`awk '{print $7}'` 提取 URL(通常在第 7 字段)③-⑥标准频率统计 + 保存。**举一反三:**生产日志的格式可能因 CDN/代理而不同,建议先用 `head -1 access.log | awk '{for(i=1;i<=NF;i++) print i,$i}'` 打印每个字段的编号和内容,确认目标字段位置。

## 运行前边界、回滚与验证

- **运行前**：示例以 GNU/Linux 的 Bash 为主；先用 `command --help`、`man command` 或发行版文档确认本机版本和参数。不要把教程中的 IP、域名、用户、路径直接复制到生产机器。
- **先确认作用域**：涉及文件、仓库、容器或远端主机时，先运行 `pwd`、`whoami`、`git status`、`docker context show` 或 `ssh -G 主机别名`，确认当前目标；对重要数据先做可恢复备份。
- **完成后验证**：用只读命令确认结果，例如 `ls -la`、`git status`、`systemctl status 服务名`、`docker ps` 或 `curl -fS URL`；失败时停止扩大操作范围，先读报错。
