## 三、本话目标

- 用 `if / else` 让程序分支;
- 记牢 Java 的 `if` **只接受 `boolean`**,没有「非零即真」;
- 分清 `=`(赋值)和 `==`(比较);
- 用三元运算符写简洁的二选一;
- 踩一次 `if (a = b)` 的编译错误。

---

## 四、原理图

```text
if (条件) {          ← 括号里必须是 boolean,别的类型一律编译报错
    // 条件为 true 时执行
} else {
    // 否则执行
}

三元:  结果 = 条件 ? 值A : 值B ;
```

关键一条:**`if(...)` 的括号里,要的是 `boolean`,不是「有没有值」。** `==` 比较两值是否相等、结果是 `boolean`;`=` 是把右边赋给左边、结果是右边那个值。C 允许「非零即真」,所以 `if (x = 5)` 在 C 里悄悄通过;Java 没有这条,`if (x = 5)` 交出来的是 `int`,和 `boolean` 对不上,**编译官当场打回** —— 同一个手滑,Java 帮你提前暴露。

## 五、代码:够钱才出杯

```java
public class Cafe {
    public static void main(String[] args) {
        double total = 45.0;
        double paid = 30.0;

        if (paid >= total) {
            System.out.println("出杯!找零 ¥" + (paid - total));
        } else {
            System.out.println("余额不足,还差 ¥" + (total - paid));
        }

        String vip = paid >= 100 ? "金卡顾客" : "普通顾客";   // 三元:一行搞定二选一
        System.out.println(vip);
    }
}
```

三元 `条件 ? A : B` 是 `if-else` 的浓缩版:只在「二选一算出一个值」时用它,清爽;但别拿它嵌套三四层充聪明 —— 嵌套三元没人读得懂,那种场景老老实实写 `if-else`。别忘了 `else if` 还能把「够钱 / 差一点点 / 差很多」这类多档情况一档档接下去,后面菜单变复杂时你会用到。

输出:

```text
余额不足,还差 ¥15.0
普通顾客
```

## 六、故意制造一个 Bug

把判断写成一个等号:

```java
if (paid = total) {   // ← 故意:= 而不是 ==
    System.out.println("出杯!");
}
```

---

## 七、读懂真实报错

```text
Cafe.java:6: error: incompatible types: double cannot be converted to boolean
        if (paid = total) {
                 ^
1 error
```

`double cannot be converted to boolean` —— `paid = total` 是**赋值**,它的结果是一个 `double`,而 `if(...)` 只收 `boolean`。**这正是 Java 没有「非零即真」的好处**:同样把 `==` 手滑成 `=`,C 会默默放行、埋一颗定时炸弹,Java 直接在编译台把你摁住。

> **豆豆锐评**:唯一拦不住的例外,是**左边本来就是 `boolean`** 的时候。`if (flag = true)` 能编译通过,但它先把 `true` 赋给 `flag`、再拿这个 `true` 去判断 —— 结果**永远进这个分支**,`else` 成了死代码。这种「能跑、但逻辑恒真」的坑最阴险,所以别赌类型,一律写 `==`(判 `boolean` 甚至直接写 `if (flag)`)。

---

## 八、修复,并用测试证明

改回 `>=`。把「能否负担」抽成方法:

```java
static boolean canAfford(double paid, double total) {
    return paid >= total;
}
```

```java
@Test
void cannot_afford_when_short() {
    assertFalse(Cafe.canAfford(30.0, 45.0));
    assertTrue(Cafe.canAfford(50.0, 45.0));
}
```

> **🎯 面试直击**:为什么 Java 里 `if (x = 5)` 编译不过,C 里却能跑?
> 因为 **Java 的 `if` 只接受 `boolean`,不存在「非零即真」**。`x = 5` 的结果是 `int`,与 `boolean` 不兼容,编译期直接报错。C 的 `if` 判的是「是否非零」,赋值表达式返回 `5`(非零)于是被当真,漏洞就此埋下。追问防身:`if (flag = true)` 在 Java 中**能过**(`flag` 是 `boolean`)但恒真 —— 这是唯一漏网场景,评审时要盯死。

## 🎯 随堂练习

先自己做,再对答案。每道答案都带一句「举一反三」,帮你把这一个点连成一片。

### 选择题(10 道)

1. Java 里 `if (...)` 的括号里必须是什么?
   - A) 任意非零的值　B) `boolean` 表达式　C) `int` 或 `boolean`　D) 只要不是 `null` 就行
2. `if (paid = total)`(两者都是 `double`)会怎样?
   - A) 悄悄通过,恒为真　B) 运行期抛异常　C) 编译报错 `double cannot be converted to boolean`　D) 编译通过,结果不确定
3. 同一个手滑,C 能跑、Java 编不过,根因是?
   - A) Java 语法更啰嗦　B) C 的 `if` 判「是否非零」,Java 的 `if` 只认 `boolean`　C) C 没有编译器检查　D) Java 的 `=` 不是赋值
4. 如果 `flag` 本来就是 `boolean`,`if (flag = true)` 会?
   - A) 编译报错　B) 编译通过,但先赋值再判断,**永远为真**　C) 编译通过,等价于 `if (flag)`　D) 运行期抛异常
5. `String vip = paid >= 100 ? "金卡顾客" : "普通顾客";` 这行用的是?
   - A) 三元运算符,二选一算出一个值　B) 一种特殊的 `if` 语句　C) `switch` 的简写　D) 逻辑运算符
6. `=` 和 `==` 的正确描述是?
   - A) 两者都能比较相等　B) `=` 赋值、结果是右边那个值;`==` 比较、结果是 `boolean`　C) `==` 赋值、`=` 比较　D) 在 `if` 里两者等价
7. `double total = 45.0, paid = 30.0;` 跑本话那段 `if-else`,输出是?
   - A) `出杯!找零 ¥15.0`　B) `余额不足,还差 ¥15.0`　C) 什么都不输出　D) 编译错误
8. 把判断抽成 `static boolean canAfford(double paid, double total)` 的主要好处是?
   - A) 运行更快　B) 逻辑能被 JUnit 直接断言,可验证　C) 少写几行代码　D) 避免类型转换
9. 「够钱 / 差一点点 / 差很多」这种多档判断,最合适的是?
   - A) 嵌套三元　B) `else if` 一档档接下去　C) 多写几个独立 `if`　D) 用 `while`
10. 关于三元运算符,下列建议正确的是?
    - A) 能用三元就别用 `if`,越短越好　B) 只在「二选一算出一个值」时用;嵌套三四层就该换回 `if-else`　C) 三元比 `if` 执行更快,应优先　D) 三元只能用于数字

> [!答案]
> **1-B**　这道门只认 `true`/`false` 两块牌子。**举一反三**:所以 `if (list)`、`if (1)` 在 Java 里都编不过,必须写成 `if (!list.isEmpty())`、`if (n != 0)`。
> **2-C**　赋值表达式的结果是 `double`,和 `boolean` 对不上,编译期就被打回。**举一反三**:看到 `cannot be converted to boolean`,第一反应就去数括号里的等号有几个。
> **3-B**　Java 没有「非零即真」这条规则。**举一反三**:严格的类型系统把 C 里要跑起来才暴露的坑,提前到了编译台上。
> **4-B**　这是唯一漏网场景:先把 `true` 赋给 `flag`,再拿 `true` 去判断,`else` 成了死代码。**举一反三**:所以判 `boolean` 直接写 `if (flag)`,别写 `== true`,连手滑的机会都不给。
> **5-A**　`条件 ? A : B` 是 `if-else` 的浓缩版,整体**算出一个值**。**举一反三**:它是表达式(有值),`if` 是语句(做事),这个区别在第 5 话的箭头 `switch` 会再考一次。
> **6-B**　一个是「写进去」,一个是「问一句」。**举一反三**:等第二季讲对象,`==` 比较引用地址、`equals` 比较内容,这一对还会再坑你一次。
> **7-B**　`30.0 >= 45.0` 为假,走 `else`,差额 `45.0 - 30.0`。**举一反三**:同时 `paid >= 100` 也为假,所以还会打印「普通顾客」。
> **8-B**　写死在 `main` 里的 `println` 没法自动验证,抽成方法才能断言返回值。**举一反三**:把「逻辑」从「IO / main」里剥出来,是全系列反复强调的可测性原则。
> **9-B**　`else if` 天生就是为多档设计的。**举一反三**:等分支再多、还要按值分拣时,下一话的 `switch` 比一长串 `else if` 更清爽。
> **10-B**　三元用在二选一取值最漂亮,嵌套则没人读得懂。**举一反三**:可读性优先于「短」—— 代码写一次、被读一百次。
