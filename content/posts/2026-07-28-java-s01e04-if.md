## 三、本话目标

- 用 `if / else` 让程序分支;
- 记牢 Java 的 `if` **只接受 `boolean`**,没有「非零即真」;
- 分清 `=`(赋值)和 `==`(比较);
- 用三元运算符写简洁的二选一;
- 踩一次 `if (a = b)` 的编译错误。

---

## 四、原理图

```text
if (条件) {          ← 括号里必须是 boolean,别的类型一律编译报错
    // 条件为 true 时执行
} else {
    // 否则执行
}

三元:  结果 = 条件 ? 值A : 值B ;
```

关键一条:**`if(...)` 的括号里,要的是 `boolean`,不是「有没有值」。** `==` 比较两值是否相等、结果是 `boolean`;`=` 是把右边赋给左边、结果是右边那个值。C 允许「非零即真」,所以 `if (x = 5)` 在 C 里悄悄通过;Java 没有这条,`if (x = 5)` 交出来的是 `int`,和 `boolean` 对不上,**编译官当场打回** —— 同一个手滑,Java 帮你提前暴露。

## 五、代码:够钱才出杯

```java
public class Cafe {
    public static void main(String[] args) {
        double total = 45.0;
        double paid = 30.0;

        if (paid >= total) {
            System.out.println("出杯!找零 ¥" + (paid - total));
        } else {
            System.out.println("余额不足,还差 ¥" + (total - paid));
        }

        String vip = paid >= 100 ? "金卡顾客" : "普通顾客";   // 三元:一行搞定二选一
        System.out.println(vip);
    }
}
```

三元 `条件 ? A : B` 是 `if-else` 的浓缩版:只在「二选一算出一个值」时用它,清爽;但别拿它嵌套三四层充聪明 —— 嵌套三元没人读得懂,那种场景老老实实写 `if-else`。别忘了 `else if` 还能把「够钱 / 差一点点 / 差很多」这类多档情况一档档接下去,后面菜单变复杂时你会用到。

输出:

```text
余额不足,还差 ¥15.0
普通顾客
```

## 六、故意制造一个 Bug

把判断写成一个等号:

```java
if (paid = total) {   // ← 故意:= 而不是 ==
    System.out.println("出杯!");
}
```

---

## 七、读懂真实报错

```text
Cafe.java:6: error: incompatible types: double cannot be converted to boolean
        if (paid = total) {
                 ^
1 error
```

`double cannot be converted to boolean` —— `paid = total` 是**赋值**,它的结果是一个 `double`,而 `if(...)` 只收 `boolean`。**这正是 Java 没有「非零即真」的好处**:同样把 `==` 手滑成 `=`,C 会默默放行、埋一颗定时炸弹,Java 直接在编译台把你摁住。

> **豆豆锐评**:唯一拦不住的例外,是**左边本来就是 `boolean`** 的时候。`if (flag = true)` 能编译通过,但它先把 `true` 赋给 `flag`、再拿这个 `true` 去判断 —— 结果**永远进这个分支**,`else` 成了死代码。这种「能跑、但逻辑恒真」的坑最阴险,所以别赌类型,一律写 `==`(判 `boolean` 甚至直接写 `if (flag)`)。

## 八、修复,并用测试证明

改回 `>=`。把「能否负担」抽成方法:

```java
static boolean canAfford(double paid, double total) {
    return paid >= total;
}
```

```java
@Test
void cannot_afford_when_short() {
    assertFalse(Cafe.canAfford(30.0, 45.0));
    assertTrue(Cafe.canAfford(50.0, 45.0));
}
```

> **🎯 面试直击**:为什么 Java 里 `if (x = 5)` 编译不过,C 里却能跑?
> 因为 **Java 的 `if` 只接受 `boolean`,不存在「非零即真」**。`x = 5` 的结果是 `int`,与 `boolean` 不兼容,编译期直接报错。C 的 `if` 判的是「是否非零」,赋值表达式返回 `5`(非零)于是被当真,漏洞就此埋下。追问防身:`if (flag = true)` 在 Java 中**能过**(`flag` 是 `boolean`)但恒真 —— 这是唯一漏网场景,评审时要盯死。
