## 三、本话目标

- 用 `if / else` 让程序分支;
- 记牢 Java 的 `if` **只接受 `boolean`**,没有「非零即真」;
- 分清 `=`(赋值)和 `==`(比较);
- 用三元运算符写简洁的二选一;
- 踩一次 `if (a = b)` 的编译错误。

---

## 四、原理图

```text
if (条件) {          ← 括号里必须是 boolean,别的类型一律编译报错
    // 条件为 true 时执行
} else {
    // 否则执行
}

三元:  结果 = 条件 ? 值A : 值B ;
```

关键一条:**`if(...)` 的括号里,要的是 `boolean`,不是「有没有值」。** `==` 比较两值是否相等、结果是 `boolean`;`=` 是把右边赋给左边、结果是右边那个值。C 允许「非零即真」,所以 `if (x = 5)` 在 C 里悄悄通过;Java 没有这条,`if (x = 5)` 交出来的是 `int`,和 `boolean` 对不上,**编译官当场打回** —— 同一个手滑,Java 帮你提前暴露。

## 五、代码:够钱才出杯

```java
public class Cafe {
    public static void main(String[] args) {
        double total = 45.0;
        double paid = 30.0;

        if (paid >= total) {
            System.out.println("出杯!找零 ¥" + (paid - total));
        } else {
            System.out.println("余额不足,还差 ¥" + (total - paid));
        }

        String vip = paid >= 100 ? "金卡顾客" : "普通顾客";   // 三元:一行搞定二选一
        System.out.println(vip);
    }
}
```

三元 `条件 ? A : B` 是 `if-else` 的浓缩版:只在「二选一算出一个值」时用它,清爽;但别拿它嵌套三四层充聪明 —— 嵌套三元没人读得懂,那种场景老老实实写 `if-else`。别忘了 `else if` 还能把「够钱 / 差一点点 / 差很多」这类多档情况一档档接下去,后面菜单变复杂时你会用到。

输出:

```text
余额不足,还差 ¥15.0
普通顾客
```

## 六、故意制造一个 Bug

把判断写成一个等号:

```java
if (paid = total) {   // ← 故意:= 而不是 ==
    System.out.println("出杯!");
}
```

---

## 七、读懂真实报错

```text
Cafe.java:6: error: incompatible types: double cannot be converted to boolean
        if (paid = total) {
                 ^
1 error
```

`double cannot be converted to boolean` —— `paid = total` 是**赋值**,它的结果是一个 `double`,而 `if(...)` 只收 `boolean`。**这正是 Java 没有「非零即真」的好处**:同样把 `==` 手滑成 `=`,C 会默默放行、埋一颗定时炸弹,Java 直接在编译台把你摁住。

> **豆豆锐评**:唯一拦不住的例外,是**左边本来就是 `boolean`** 的时候。`if (flag = true)` 能编译通过,但它先把 `true` 赋给 `flag`、再拿这个 `true` 去判断 —— 结果**永远进这个分支**,`else` 成了死代码。这种「能跑、但逻辑恒真」的坑最阴险,所以别赌类型,一律写 `==`(判 `boolean` 甚至直接写 `if (flag)`)。

## 八、修复,并用测试证明

改回 `>=`。把「能否负担」抽成方法:

```java
static boolean canAfford(double paid, double total) {
    return paid >= total;
}
```

```java
@Test
void cannot_afford_when_short() {
    assertFalse(Cafe.canAfford(30.0, 45.0));
    assertTrue(Cafe.canAfford(50.0, 45.0));
}
```

> **🎯 面试直击**:为什么 Java 里 `if (x = 5)` 编译不过,C 里却能跑?
> 因为 **Java 的 `if` 只接受 `boolean`,不存在「非零即真」**。`x = 5` 的结果是 `int`,与 `boolean` 不兼容,编译期直接报错。C 的 `if` 判的是「是否非零」,赋值表达式返回 `5`(非零)于是被当真,漏洞就此埋下。追问防身:`if (flag = true)` 在 Java 中**能过**(`flag` 是 `boolean`)但恒真 —— 这是唯一漏网场景,评审时要盯死。

## 🎯 随堂练习

先自己做，再对答案。选择1-3基础识记，4-6理解应用，7-9分析判断，10综合；解答递进；代码题从写到验证。

### 一、选择题（10 道）

1. [基础] `if` 语句的括号里必须是一个什么类型的表达式？
   - A) `int`　B) `boolean`　C) `String`　D) 可以是任意类型

2. [基础] 以下比较两个整数是否相等，语法正确的是？
   - A) `if (a = b)`　B) `if (a == b)`　C) `if (a equals b)`　D) `if (a != = b)`

3. [基础] `else` 子句可以单独使用吗？
   - A) 可以　B) 不可以，必须跟在 `if` 或 `else if` 之后　C) 可以但必须有 `break`　D) 只能在 `switch` 中使用

4. [理解] `if (x = 5)` 在 Java 中会怎样？
   - A) 编译报错：int 不能转为 boolean　B) 永远为 true　C) 编译通过但逻辑错误　D) 运行时异常

5. [理解] 以下代码输出什么？`int x = 3; if (x > 5) System.out.println("A"); System.out.println("B");`
   - A) A　B) B　C) AB　D) 编译报错

6. [应用] 判断"x 在 10 到 20 之间（含边界）"的正确写法是？
   - A) `if (10 <= x <= 20)`　B) `if (x >= 10 && x <= 20)`　C) `if (x >= 10 || x <= 20)`　D) `if (x >= 10 & x <= 20)`

7. [分析] 以下代码输出什么？`int score = 95; if (score >= 60) System.out.println("及格"); else if (score >= 90) System.out.println("优秀"); else System.out.println("不及格");`
   - A) 及格　B) 优秀　C) 及格优秀　D) 不及格

8. [分析] 以下三元运算符等价于哪个 `if-else`？`String s = (age >= 18) ? "成年" : "未成年";`
   - A) `if (age >= 18) s = "未成年"; else s = "成年";`　B) `if (age >= 18) s = "成年"; else s = "未成年";`　C) `if (age < 18) s = "未成年";`　D) 无法用 if-else 表达

9. [判断] 以下代码段的问题是什么？`boolean flag = false; if (flag == true) { ... }`
   - A) 编译错误　B) 运行时错误　C) 没有逻辑问题但写法冗余　D) 逻辑反转

10. [综合] 分析以下代码，哪个说法正确？`int a = 5, b = 10; if (a > 0) if (b > 5) System.out.println("A"); else System.out.println("B");`
    - A) 输出 A，else 和第一个 if 配对　B) 输出 A，else 和最近的 if 配对　C) 输出 B，else 和第一个 if 配对　D) 编译报错

> [!答案]
> **1-B**：Java 的 `if` 条件必须是 `boolean` 类型，这与 C 语言不同（C 中非 0 即真）。这个设计让 Java 更安全——`if (x = 5)` 在 C 中是赋值后判断真值（危险），在 Java 中直接编译报错。
> **2-B**：`==` 是比较运算符，`=` 是赋值运算符，`equals()` 是对象方法（String 等引用类型用）。`!= =` 是非法运算符。**举一反三**：对 String 等引用类型，内容比较用 `equals()` 而非 `==`。
> **3-B**：`else` 不能独立存在，必须紧跟在 `if` 或 `else if` 代码块之后。每个 `else` 只与最近的、尚未配对的 `if` 绑定（dangling else 规则）。
> **4-A**：`x = 5` 是赋值表达式，返回 `int` 类型的值 5。`if` 要求 `boolean`，所以编译报错。这是 Java 比 C 安全的设计之一。**举一反三**：如果是 `boolean flag = false; if (flag = true)` 则会编译通过——因为赋值返回 `boolean` 的 `true`。
> **5-B**：没有花括号时，`if` 只控制紧跟它的**一条**语句。所以 `System.out.println("B");` 不受 `if` 影响，总是执行，输出 B。**举一反三**：即使只有一行，也养成加花括号的习惯，避免后续加代码时忘记补。
> **6-B**：数学中的 `10 ≤ x ≤ 20` 不能直接写成 `10 <= x <= 20`，Java 会先算 `10 <= x` 得到 `true`，再算 `true <= 20` 会编译报错。正确写法是 `x >= 10 && x <= 20`。D 使用 `&` 虽然也能工作但不会短路——`&&` 在左边为 false 时不再计算右边，性能更好。**举一反三**：`&` 和 `&&` 真正区别在表达式有副作用时显现，如 `if (obj != null && obj.getValue() > 0)` 用 `&` 会空指针。
> **7-A**：`if-else if-else` 从上到下依次判断，**第一个为 true 的块执行后，后续全部跳过**。`score >= 60` 先被命中，输出"及格"即结束，`score >= 90` 不会被判断。**举一反三**：写判断条件时遵循**先窄后宽**原则——最严格的条件放最前面。
> **8-B**：三元运算符 `条件 ? 值1 : 值2` 的两个分支都有返回值，等价于对应赋值方向的 if-else。**举一反三**：三元运算符适合简单的二选一赋值；嵌套三元如 `a > b ? (a > c ? a : c) : (b > c ? b : c)` 虽然能求三数最大值，但可读性极差，不建议使用。
> **9-C**：`flag == true` 是冗余写法，直接写 `if (flag)` 即可。同样 `flag == false` 应写成 `if (!flag)`。冗余本身不报错，但在 code review 中会被指出。
> **10-B**：Java 的 dangling else 规则：`else` 总是和最近的、尚未配对的 `if` 配对。这里 `else` 和 `if (b > 5)` 配对，所以 `a > 0 && b > 5` 成立时输出 A，`a > 0 && b <= 5` 时输出 B。用花括号明确范围可消除歧义。**举一反三**：嵌套 if 一律加花括号，别靠缩进推测配对关系。

### 二、解答题（3 道）

1. [概念阐述] `&` 与 `&&`（以及 `|` 与 `||`）的区别是什么？什么是"短路求值"？为什么它在实际编程中很重要？

2. [场景解释] 咖啡机点单系统需要判断"是否满足满减条件"：①满 100 减 15；②会员额外再打 9 折；③但如果用了优惠券，就不能再享受满减。请画出这三种优惠的决策逻辑树（用文字描述 if-else 分支即可）。

3. [综合分析] 三元运算符、if-else、switch 三者的适用场景分别是什么？在什么情况下三元运算符比 if-else 更适合，反过来又是什么情况？请用代码示例对比说明。

> [!答案]
> **1**　`&` 和 `|` 是**逻辑运算符**（也用作位运算），两边的表达式**都会被计算**。`&&` 和 `||` 是**短路运算符**：`&&` 左边为 `false` 时不再计算右边；`||` 左边为 `true` 时不再计算右边。短路求值的重要性体现在防御式编程中：`if (obj != null && obj.getValue() > 0)`——如果不用短路，即使 `obj` 为 `null` 也会计算右半部分，导致 `NullPointerException`。**举一反三**：短路不仅是性能优化，更是**安全保证**——90% 的使用场景都需要短路，直接用 `&` 的场合屈指可数（比如两边都是需要执行的方法调用）。
> **2**　决策树：先判断是否使用了优惠券 → 如果用了，直接计算原价（跳过满减）；如果没用，先判断是否满 100（`total >= 100`）→ 满 100 则减 15（`total -= 15`）；然后判断是否为会员（`isMember == true`）→ 会员则再打 9 折（`total *= 0.9`）。关键点：①优惠券和满减互斥；②会员折扣在满减之后叠加；③顺序影响最终金额——先减再打折比先打再减对顾客更有利。**举一反三**：实际业务中这类多层优惠嵌套很常见，用 if-else 画决策树能避免"遗漏组合场景"的 bug。
> **3**　三元运算符适合：单一的二选一赋值，如 `String label = (count > 1) ? "多杯" : "单杯";`，一行搞定、意图清晰。if-else 适合：多条语句的复杂分支、需要 `else if` 多路判断、分支内部有副作用（如修改多个变量、打印日志等）。switch 适合：对单个变量的等值多路分发（如订单状态码映射）。三元不宜嵌套——代码不可读；if-else 不宜用来做简单的值赋值——太过啰嗦。**举一反三**：现代 Java 中 switch 表达式也可以做值赋值，相对于三元更适合 3 路以上的简单映射场景。

### 三、代码题（2 道）

1. [基础实现] 写一个咖啡杯型判断程序：变量 `size` 取值 1/2/3，分别对应小杯（360ml）/中杯（500ml）/大杯（660ml）。用 if-else 打印对应容量，如果输入不合法则打印"无此杯型"。分别用 `size = 2` 和 `size = 5` 测试。

2. [综合设计] 写一个"BMI 体重评级"程序：`double weight = 70.0;`（kg），`double height = 1.75;`（m），计算 `bmi = weight / (height * height)`。按中国标准：<18.5 偏瘦，18.5~23.9 正常，24~27.9 偏胖，≥28 肥胖。用 if-else if-else 输出评级。然后改写为三元运算符嵌套版（仅输出评级字符串），对比两种写法的可读性。

> [!答案]
> **1 验收**：
> ```java
> int size = 2;
> if (size == 1) {
>     System.out.println("小杯 360ml");
> } else if (size == 2) {
>     System.out.println("中杯 500ml");
> } else if (size == 3) {
>     System.out.println("大杯 660ml");
> } else {
>     System.out.println("无此杯型");
> }
> // size=2 → "中杯 500ml"; size=5 → "无此杯型"
> ```
> **举一反三**：这种"等值多路判断"用 switch 更清晰——代码量和可读性都优于 if-else，且 Java 14+ 的箭头 switch 还能直接返回值。
>
> **2 验收**：
> ```java
> double weight = 70.0, height = 1.75;
> double bmi = weight / (height * height);
> System.out.printf("BMI: %.1f\n", bmi);
>
> // if-else 版（推荐）
> String level;
> if (bmi < 18.5) {
>     level = "偏瘦";
> } else if (bmi < 24) {
>     level = "正常";
> } else if (bmi < 28) {
>     level = "偏胖";
> } else {
>     level = "肥胖";
> }
> System.out.println("评级(if-else): " + level);
>
> // 三元嵌套版（不推荐，可读性差）
> String level2 = bmi < 18.5 ? "偏瘦" :
>                 bmi < 24 ? "正常" :
>                 bmi < 28 ? "偏胖" : "肥胖";
> System.out.println("评级(三元): " + level2);
>
> // bmi = 70/(1.75*1.75) = 22.86 → 正常
> ```
> 运行验证：`bmi = 22.86`，输出"正常"。**举一反三**：if-else 版好处在于每个分支可以加额外的副作用（如打印提示、调整其他变量），三元版虽简洁但仅适合纯值映射。特别注意 `else if (bmi < 24)` 不需要写 `bmi >= 18.5 &&` 前缀——因为前面已排除 <18.5 的情况。
