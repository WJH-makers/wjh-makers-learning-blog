## 一、需求:小票要有名字、备注和排版

顾客说「我叫张三,美式少冰」。咖啡站要把这些拼成一张多行小票。字符串处理该正式登场了。

---

## 二、漫画

> **〔1〕** 字符串王国,每个 `String` 都被封进玻璃罩,标着「只读」。
> 豆豆:「`String` **不可变**:任何『修改』其实都是造了个新字符串。」

> **〔2〕** 阿零用 `==` 比两个名字,明明字一样却判成「不相等」。
> 豆豆:「`==` 比的是**是不是同一个罐子**,`equals` 才比**罐子里的内容**。」

---

## 三、本话目标

- 理解 String 不可变;
- 分清 `==`(引用相同)与 `equals`(内容相同);
- 用 `StringBuilder` 高效拼接、用文本块排版小票;
- 踩一次用 `==` 比较字符串内容的逻辑坑。

---

## 四、原理图

```text
String 不可变:s = s + "x" 是新建对象,不是改原来的
==      比较引用(是不是同一个对象)
equals  比较内容(字符是否逐个相同)   ← 比字符串内容一律用它
StringBuilder:需要大量拼接时用它,避免产生一堆临时字符串
文本块 """ ... """:多行文本原样排版
```

## 五、代码:拼一张小票

```java
public class Cafe {
    static String receipt(String customer, String coffee, String note, double price) {
        // 文本块:多行小票原样排版
        return """
               —— 豆豆咖啡站 ——
               顾客:%s
               咖啡:%s(%s)
               应付:¥%.2f
               ——————————————
               """.formatted(customer, coffee, note, price);
    }

    public static void main(String[] args) {
        String note = "少冰";
        String order = new StringBuilder("美式").append(" / ").append(note).toString();
        System.out.println(order);
        System.out.print(receipt("张三", "美式", note, 15.0));
    }
}
```

## 六、故意制造一个 Bug

判断「这位顾客是不是会员『张三』」时用了 `==`:

```java
String input = new String("张三");     // 运行时新建,和字面量不是同一个对象
if (input == "张三") {                 // ← 故意:比引用
    System.out.println("欢迎会员张三");
} else {
    System.out.println("查无此会员");   // 实际走这里
}
```

---

## 七、读懂现象(Logic Bug)

不报错,但明明输入了「张三」,却打印「查无此会员」。因为 `new String("张三")` 和字面量 `"张三"` 是**两个不同对象**,`==` 判引用 → `false`。字符串比内容,必须用 `equals`。

---

## 八、修复,并用测试证明

```java
static boolean isMember(String input, String member) {
    return member.equals(input);   // 常量在前,天然防 input 为 null 的 NPE
}
```

```java
@Test
void member_matched_by_content() {
    assertTrue(Cafe.isMember(new String("张三"), "张三"));
    assertFalse(Cafe.isMember("李四", "张三"));
}
```
