## 四、原理图:一次「修改」发生了什么

```text
String s = "美式";
s = s + "少冰";

 堆内存里:
   ["美式"]      ← 旧对象,没人指了 → 等 GC 回收
   ["少冰"]      ← 字面量
   ["美式少冰"]  ← 新建的第三个对象   ┐
                                      s ┘  变量 s 现在指向它

结论:s 变了,但没有任何一个字符串对象「被改」过。变的是「s 指向谁」。

==      比较引用(两个变量是不是指同一个对象)
equals  比较内容(字符是否逐个相同)   ← 比字符串内容,一律用它
```

为什么 Java 要把 String 设计成不可变?因为它太常用了——做 Map 的 key、做常量、在多线程间传递……不可变意味着**它绝不会被人偷偷改掉**,可以安全共享、可以缓存 hash、可以放进「字符串常量池」复用。安全和性能,都建立在「改不动」这个前提上。

## 五、代码:拼一张小票

```java
public class Cafe {
    static String receipt(String customer, String coffee, String note, double price) {
        // 文本块:多行小票原样排版,不用满屏 + "\n"
        return """
               —— 豆豆咖啡站 ——
               顾客:%s
               咖啡:%s(%s)
               应付:¥%.2f
               ——————————————
               """.formatted(customer, coffee, note, price);
    }

    public static void main(String[] args) {
        String note = "少冰";
        String order = "美式" + " / " + note;     // 单次拼接,大方用 +,一点不慢
        System.out.println(order);
        System.out.print(receipt("张三", "美式", note, 15.0));
    }
}
```

注意 `order` 这行:三段字符串,直接 `+` 拼,清清爽爽——**别听人忽悠说「+ 拼接慢就得换 StringBuilder」**,下面第七节后面专门破这个迷信。

## 六、故意制造一个 Bug

判断「这位顾客是不是会员『张三』」时,顺手用了 `==`:

```java
String input = new String("张三");     // 用 new 运行时新建,和字面量不是同一只罐子
if (input == "张三") {                 // ← 故意:比的是引用
    System.out.println("欢迎会员张三");
} else {
    System.out.println("查无此会员");   // 实际走这里
}
```

---

## 七、读懂现象(Logic Bug)

**不报错**,但明明输入了「张三」，却打印「查无此会员」。因为 `new String("张三")` 在堆里**新建了一只罐子**,和字面量 `"张三"`(常量池里的那只)是**两个不同对象**;`==` 比引用 → 两只手指没指同一只罐子 → `false`。

> **🎯 面试直击**:`==` 和 `equals` 有什么区别?String 为什么用 `equals` 比?
> `==` 比**引用**(是不是同一个对象),`equals` 比**内容**。基本类型没有 equals,`==` 比值;引用类型比内容一律用 `equals`。追问点:`Object.equals` 默认也是比引用,是 `String` **重写**了它才变成比内容;所以你自己写的类要比内容,也得重写 `equals`(第二季讲)。

现在破除那个流传最广的性能迷信:

> **豆豆锐评 · 「+ 拼接慢」是老黄历**
> 单次(或几次)`+` 拼接,现代 JDK 编译时会走 **`invokedynamic` + `StringConcatFactory`** 动态生成一条高效的拼接逻辑,**一点不慢**,可读性还最好。真正的性能杀手是**在循环里反复 `+`**:那样每转一圈就新建一个中间字符串,几千次循环就是几千个垃圾对象。`StringBuilder` 的价值,**只在循环拼接**这一个场景——它用一块可变缓冲,全程只造一个对象。

> **🔀 豆豆的多解台 · 拼字符串,到底用哪种?**

| 方案 | 写法 | 适合什么时候 | 说明 |
|---|---|---|---|
| `+` | `a + b + c` | **单次/少量拼接**(绝大多数场景) | 现代 JDK 编译成 `invokedynamic`,快且最好读 |
| `StringBuilder` | `sb.append(x)` 循环后 `toString()` | **循环里反复拼接** | 唯一真正需要它的场景,避免造一堆临时对象 |
| `String.join` | `String.join(" / ", a, b, c)` | 用**固定分隔符**连一串 | 拼列表/路径最省心,免得手写分隔符 |
| 文本块 `"""..."""` | 多行原样写 | **多行模板**(小票、SQL、JSON) | 所见即所得,免掉满屏 `\n` |
| `formatted` | `"¥%.2f".formatted(p)` | 需要**格式化**(补零、对齐、精度) | 配文本块拼小票的黄金搭档 |

> 豆豆锐评:**默认用 `+`,循环才换 `StringBuilder`,多行用文本块**。记住这一句,你已经超过一半张口就说「+ 慢」的人。

## 八、修复,并用测试证明

```java
static boolean isMember(String input, String member) {
    return member.equals(input);   // 常量写在前:input 万一是 null 也不会 NPE
}
```

```java
@Test
void member_matched_by_content() {
    assertTrue(Cafe.isMember(new String("张三"), "张三"));  // 内容相同即会员,不管是不是同一只罐子
    assertFalse(Cafe.isMember("李四", "张三"));
}
```

`member.equals(input)` 而不是 `input.equals(member)`——把已知非 null 的常量放前面,天然躲开「input 为 null 时调 `.equals` 崩掉」的坑。这是一个能白拿的好习惯。

### 一、选择题（10 道）

1. [基础] 以下代码输出什么？`String s1 = "coffee"; String s2 = "coffee"; System.out.println(s1 == s2);`
   - A) `true`　B) `false`　C) 编译报错　D) 不确定

2. [基础] 比较两个 String 的**内容**是否相等，应该使用？
   - A) `==`　B) `=`　C) `equals()`　D) `compareTo()`

3. [基础] `"Hello".length()` 的返回值是？
   - A) 4　B) 5　C) 6　D) 编译报错

4. [理解] String 被称为"不可变"（immutable）的含义是？
   - A) String 变量声明后不能重新赋值　B) String 对象创建后内容不能修改　C) String 不能作为方法参数　D) String 不能使用 `+` 拼接

5. [理解] `String s = "Java"; s = s + "Bean";` 执行后，堆上创建了几个 String 对象？
   - A) 1 个　B) 2 个　C) 3 个　D) 0 个

6. [应用] `String s = "Hello World"; System.out.println(s.substring(0, 5));` 输出？
   - A) `Hello`　B) `Hello `　C) `World`　D) 编译报错

7. [分析] 以下代码输出什么？`String s1 = new String("abc"); String s2 = new String("abc"); System.out.println(s1 == s2); System.out.println(s1.equals(s2));`
   - A) `true true`　B) `false false`　C) `true false`　D) `false true`

8. [分析] `"abc".charAt(3)` 会发生什么？
   - A) 返回 `'\0'`　B) 返回 `null`　C) 抛出 `StringIndexOutOfBoundsException`　D) 编译报错

9. [判断] 关于字符串常量池，以下说法正确的是？
   - A) 所有 String 对象都进入常量池　B) 只有字面量 `"abc"` 创建的 String 进入常量池　C) `new String("abc")` 创建的也进入常量池　D) 常量池在堆外独立存放

10. [综合] 以下代码输出什么？`String s = "Hello"; s.concat(" World"); System.out.println(s);`
    - A) `Hello`　B) `Hello World`　C) `World`　D) 编译报错

> [!答案]
> **1-A**：字面量 `"coffee"` 被存入字符串常量池，两个变量指向池中同一个对象，`==` 比较引用地址相同，返回 `true`。**举一反三**：如果其中一个是 `new String("coffee")` 创建的，则 `==` 为 false——始终用 `equals()` 比较内容，别依赖常量池这个"巧合"。
> **2-C**：`equals()` 比较字符串内容是否相同（区分大小写），`equalsIgnoreCase()` 忽略大小写。`==` 比较引用地址，`compareTo()` 按字典序比较（返回 int）。**举一反三**：`equals` 是 Object 类定义的方法，String 重写了它来实现内容比较。
> **3-B**：`length()` 返回字符个数，"Hello" 共 5 个字符。注意 `length()` 是方法（带括号），数组的 `length` 是属性（不带括号）。**举一反三**：中文字符在 Java 中每个也算 1 个 `char`（BMP 范围内），`"你好".length()` 返回 2。
> **4-B**：String 底层是 `private final byte[]`，创建后内容无法修改。`s = s + "Bean"` 看起来"改"了 s，实际是创建了一个新 String 对象，然后把 s 指向新对象——原 `"Java"` 对象并没有被修改。**举一反三**：不可变带来的好处：线程安全、可安全共享（常量池）、哈希码可缓存。
> **5-C**：`"Java"` 字面量创建对象 1，`"Bean"` 字面量创建对象 2，拼接 `"Java" + "Bean"` 创建新对象 `"JavaBean"` 作为对象 3。共 3 个。**举一反三**：如果是编译期常量拼接（`String s = "Java" + "Bean";`），JVM 会在编译时直接优化成 `"JavaBean"`，只创建 1 个对象。
> **6-A**：`substring(begin, end)` 是左闭右开区间 `[0, 5)`，取索引 0~4 共 5 个字符，即 `Hello`。**举一反三**：`substring(6)` 返回 `"World"`（从索引 6 到末尾）。Java 7 之前 substring 共享底层数组，JDK 7 后改为复制，避免内存泄漏。
> **7-D**：`new String("abc")` 在堆上创建独立对象，两次 `new` 创建两个不同对象，`==` 比较引用地址得 false。但内容都是 "abc"，`equals()` 比较内容得 true。**举一反三**：如果你想手动把 `new` 出来的 String 放入常量池，调用 `s.intern()` ——它返回常量池中该字符串的引用。
> **8-C**：`"abc"` 有效索引 0~2，`charAt(3)` 越界，抛出 `StringIndexOutOfBoundsException`（类似数组的 `ArrayIndexOutOfBoundsException`）。**举一反三**：获取最后一个字符的公式：`s.charAt(s.length() - 1)`，务必先验证 `s.length() > 0`。
> **9-B**：只有通过字面量（`"abc"`）或编译期常量表达式创建的 String 才会自动进入常量池。`new String("abc")` 在堆上创建新对象，不会自动进入池（除非调用 `intern()`）。D 错：常量池在 Java 7+ 被移入堆内存。**举一反三**：`String.intern()` 可以将堆中的 String 手动放入常量池，但滥用会导致常量池膨胀。
> **10-A**：`concat()` 方法也是不可变操作——它在背后创建了一个新 String `"Hello World"`，但没有赋值给 `s`（`s = s.concat(...)` 才对）。所以原 `s` 仍是 `"Hello"`。**举一反三**：所有 String 方法（`concat`/`substring`/`replace`/`toUpperCase` 等）都返回新对象，不修改原字符串——忘了接收返回值是经典 bug。

### 二、解答题（3 道）

1. [概念阐述] String 为什么被设计成不可变（immutable）？不可变带来了哪四大好处？请结合字符串常量池、线程安全、哈希缓存、安全性分别说明。

2. [场景解释] 咖啡机系统需要生成小票字符串（如 "美式×2=30.0 | 拿铁×1=18.0 | 总价:48.0"）。假设订单有几十种饮品，在循环中不断用 `+` 拼接字符串会有什么性能问题？应该如何改进？请给出两种方案并对比。

3. [综合分析] `==` vs `equals()` 是 Java 面试经典问题。请从三个层次回答：①对基本类型和引用类型，`==` 分别比较什么？②`equals()` 的默认行为（Object 类）和 String 的覆盖行为有什么区别？③描述一个需要重写 `equals()` 和 `hashCode()` 的场景，并说明为什么两者必须同步重写。

> [!答案]
> **1**　String 底层是 `private final byte[]`，创建后内容不能修改。四大好处：①**字符串常量池**——不可变让相同字面量的 String 可以安全共享同一对象，节省内存。②**线程安全**——多个线程同时访问同一个 String 不需要任何同步，因为谁也不能改它。③**哈希码缓存**——String 的 `hashCode()` 计算一次后缓存起来（`hash` 字段），后续调用直接返回，因为内容永远不会变。④**安全性**——作为类名、文件路径、数据库连接字符串等时不会被第三方代码恶意篡改。**举一反三**：Java 类加载器用 String 标识类名——如果 String 可变，攻击者就可以在类加载后修改类名绕过安全检查，这是安全层面最核心的考虑。
> **2**　性能问题：每次 `+` 操作都创建新 String 对象，循环 N 次总共创建约 N(N+1)/2 个中间字符串对象，时间和空间都是 O(n²)。两种改进方案：①`StringBuilder`（非线程安全，性能最好，单线程首选）——`StringBuilder sb = new StringBuilder(); for(...) sb.append(...); String result = sb.toString();`②`StringBuffer`（线程安全但性能稍差，多线程场景用）。对比：`StringBuilder` 内部是可变的 `byte[]`，`append` 直接往缓冲区写，只在最后 `toString()` 时创建一次 String 对象。**举一反三**：现代 JVM 自动优化编译期可确定的简单拼接，但循环中的动态拼接仍然需要手动用 StringBuilder。
> **3**　①`==` 对基本类型比较值的大小，对引用类型比较内存地址（是否指向同一个对象）。②Object 类的 `equals()` 默认实现就是 `==`（比较引用）。String 重写了 `equals()`：先判断引用是否相同，是则直接返回 true；再判断是否是 String 类型；最后逐字符比较内容。③需要重写的场景：自定义类（如 `Coffee`）需要按业务字段（名称+价格）判断相等时。为什么两者必须同步重写：`hashCode()` 的规约规定"两个对象 `equals()` 为 true，则 `hashCode()` 必须相等"——否则在 HashMap/HashSet 中会出现"存入后取不出来"的诡异 bug。**举一反三**：IDEA 可以一键生成 `equals()` 和 `hashCode()` 的覆盖方法，但你要理解它们为什么成对出现。

### 三、代码题（2 道）

1. [基础实现] 给定一个邮箱地址 String，请提取其中的用户名和域名。要求：①用 `indexOf('@')` 找 @ 位置；②用 `substring()` 分别提取 @ 前后部分；③处理边界：没有 @ 时打印"无效邮箱"。测试：`"admin@coffee.com"` → 用户名 admin，域名 coffee.com。

2. [综合设计] 写一个"购物小票生成器"：给定 `String[] items = {"美式", "拿铁", "摩卡"}` 和 `int[] qty = {2, 1, 3}` 和 `double[] price = {15.0, 18.0, 22.0}`，请用 StringBuilder 构建小票字符串，格式如下（注意对齐），并统计总价。同时用 String `+` 拼接实现一次，在循环 10000 次后对比 StringBuilder 和 `+` 拼接的耗时差异（用 `System.currentTimeMillis()`）。

```
===== 购物小票 =====
美式    ×2 =  30.0
拿铁    ×1 =  18.0
摩卡    ×3 =  66.0
===================
总价:           114.0
```

> [!答案]
> **1 验收**：
> ```java
> String email = "admin@coffee.com";
> int atIndex = email.indexOf('@');
> if (atIndex == -1) {
>     System.out.println("无效邮箱");
> } else {
>     String username = email.substring(0, atIndex);
>     String domain = email.substring(atIndex + 1);
>     System.out.println("用户名: " + username + ", 域名: " + domain);
> }
> // 输出: 用户名: admin, 域名: coffee.com
> // 边界测试: "invalid-email" → 无效邮箱
> // 边界测试: "a@" → 用户名: a, 域名: (空)
> ```
> **举一反三**：如果邮箱有多个 `@`（如 `"a@b@c"`），`indexOf` 只返回第一个的位置。用 `lastIndexOf('@')` 可处理含多个 `@` 的情况（取最后一个作为分隔）。
>
> **2 验收**：
> ```java
> String[] items = {"美式", "拿铁", "摩卡"};
> int[] qty = {2, 1, 3};
> double[] price = {15.0, 18.0, 22.0};
>
> // StringBuilder 版
> long t1 = System.currentTimeMillis();
> for (int round = 0; round < 10000; round++) {
>     StringBuilder sb = new StringBuilder();
>     sb.append("===== 购物小票 =====\n");
>     double total = 0;
>     for (int i = 0; i < items.length; i++) {
>         double subtotal = qty[i] * price[i];
>         total += subtotal;
>         sb.append(String.format("%-6s ×%-2d = %5.1f\n", items[i], qty[i], subtotal));
>     }
>     sb.append("===================\n");
>     sb.append(String.format("总价:           %5.1f\n", total));
>     if (round == 0) System.out.print(sb); // 只打印第一次
> }
> long t2 = System.currentTimeMillis();
> System.out.println("StringBuilder 10000次: " + (t2 - t1) + "ms");
>
> // String + 拼接版（对比）
> long t3 = System.currentTimeMillis();
> for (int round = 0; round < 10000; round++) {
>     String receipt = "===== 购物小票 =====\n";
>     double total = 0;
>     for (int i = 0; i < items.length; i++) {
>         double subtotal = qty[i] * price[i];
>         total += subtotal;
>         receipt += String.format("%-6s ×%-2d = %5.1f\n", items[i], qty[i], subtotal);
>     }
>     receipt += "===================\n";
>     receipt += String.format("总价:           %5.1f\n", total);
> }
> long t4 = System.currentTimeMillis();
> System.out.println("String + 拼接 10000次: " + (t4 - t3) + "ms");
> // 典型结果：StringBuilder 约 10-20ms，+ 拼接约 50-100ms（5倍以上差异）
> ```
> 运行验证：小票格式正确对齐，`%-6s` 左对齐留 6 格宽度，`%5.1f` 右对齐 5 位 1 位小数。性能对比：StringBuilder 显著更快——因为循环内 `+` 拼接每轮都创建多个临时字符串对象。**举一反三**：真实场景中小票可能有几十项，差距更明显。记住口诀——"少量拼接无所谓，循环拼接用 Builder"。
