# AI 编码 CLI 速查 · 终端里的 AI 协作全周期

> 基线：2026 年主流终端 AI 编码工具的通用能力，以能力维度组织，不绑定单一产品版本。本文不写任何厂商私有 flag（各家不同且会过时）——凡遇到具体参数，一律以 `--help` 实测输出为准；下文 `<cli>` 表示你手上那个工具的可执行文件名。

## 快速导航

| 阶段 | 一句话 |
|------|--------|
| 1、心智模型 | 有绿灯可验收的任务才值得交出去 |
| 2、会话式使用 | 仓库根启动，先出计划，按轮验收 |
| 3、非交互与脚本化 | 一次性任务走管道，退出码不可全信 |
| 4、上下文管理 | 给路径和 diff，不给整个仓库 |
| 5、权限与沙箱 | 自动模式必须配隔离，否则等于裸奔 |
| 6、与 Git 协作 | 分支兜底、小步提交、逐块 review |
| 7、多轮与续接 | 关键结论落盘，长会话不如重开 |
| 8、MCP 与外部工具 | 每加一个 server 就多一段攻击面和常驻开销 |
| 9、成本与额度 | 成本随轮数超线性涨，前缀一变缓存全失效 |
| 10、排障与维护 | 先看认证、代理、证书，再怀疑模型 |
| 11、安全红线 | 密钥、生产、不可逆——三条永不授权 |
| 常见错误速判 | 症状 → 病因 → 先试哪条 |
| 一页纸口诀 | 九条浓缩全篇的心智模型 |

## 1、心智模型：什么值得交给 AI CLI

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `<cli> --help` | 先看清这家 CLI 有哪些模式与内置命令 | 凭记忆写 flag 是最常见的翻车方式；各家交互模式、非交互模式、权限开关的命名完全不同 |
| `git status --porcelain` | 开工前确认工作区干净 | 输出非空就先 commit 或 `git stash -u`；脏工作区里 AI 的改动和你的改动会混在一起，事后无法拆分 |
| `git switch -c ai/<任务名>` | 开工第一条命令：先切分支 | 在 `main` 上直接让 AI 改代码，是所有事故的共同前提 |
| `<项目自带测试命令>`（`mvn -q test` / `npm test` / `pytest -q`） | 跑通基线绿灯 | **这是「值不值得交」的第一判据**：没有可自动验收的信号，AI 改完你只能靠肉眼读代码，成本高于自己写 |
| `git grep -n "<关键符号>"` | 划定任务边界，确认涉及哪几个文件 | 边界模糊的任务（"优化一下性能"）返工率最高；先自己缩到 3~5 个文件再开口 |
| `git log --oneline -10 -- <path>` | 看这块代码的改动史 | 改动极频繁的文件通常业务规则复杂且隐含约定，不适合整体重写，只适合小步改 |
| `tokei` / `cloc .` | 估仓库规模 | 需额外安装；主要用于判断「能不能让它自己找」——超大仓库必须由你指定路径 |

**适合交**：有测试兜底的重构、样板代码、跨文件的机械改名、写单测、读陌生代码并给出调用链、日志/报错定位。
**不适合交**：需求本身还没想清楚、口头约定多于文档的业务逻辑、无法回滚的一次性操作、需要确定性输出的构建步骤（同一提示词两次结果不同是常态）。

## 2、会话式使用

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `cd <repo-root> && <cli>` | 在仓库根启动会话 | 启动目录决定默认上下文根与配置发现范围；在子模块目录里启动，会看不到上层的规则文件和兄弟模块 |
| `/help`（会话内） | 列出内置斜杠命令 | 多数产品用 `/` 前缀，但具体有哪些命令只有 help 说了算 |
| `Ctrl-C` | 中断当前这一轮生成 | 多数实现是「中断」而非「退出」；被打断时文件可能已经改了一半，恢复输入前先 `git diff` 复查 |
| `Ctrl-D` | 结束会话 | 会话结束通常意味着上下文丢失，退出前先确认这家 CLI 有没有续接能力（见第 7 节） |
| `> 只读分析，先给方案和影响面，不要改文件` | 首轮只要计划 | 一次性把大任务喂进去是返工主因；先对齐边界，再授权写盘 |
| `git diff` | 每轮结束后人肉验收 | 会话越长越容易偏航；按轮验收比最后一次性 review 便宜一个数量级 |
| `script -q -c "<cli>" ai-session.log` | 录制整段会话（Linux） | macOS 的 BSD `script` 无 `-c`，改写成 `script -q ai-session.log <cli>`；Windows 用 PowerShell `Start-Transcript -Path ai.log`。TUI 会写入大量终端控制字符，日志只适合事后 `grep`，不适合直接阅读 |

## 3、非交互与脚本化

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `<cli> <非交互模式> "<任务>"` | 一次性任务，不进 TUI | 各家 flag 名不同（`-p` / `--print` / `run` / `exec` 都有），**先 `--help` 确认再写进脚本** |
| `cat error.log \| <cli> "定位这个异常的根因"` | 用 stdin 喂输入 | 管道模式下 stdin 已被占用，任何需要交互确认的行为都会死锁；务必同时开启非交互/自动确认 |
| `<cli> ... > out.md 2> err.log` | 分离正文与诊断 | 进度条、提示信息通常走 stderr；不分离的话 `out.md` 会混进控制字符 |
| `echo $?` | 读退出码 | **退出码 0 不代表任务做对了**：模型在正文里说"我失败了"而进程正常退出是常态。CI 里必须自己跑测试/校验，别把退出码当验收标准 |
| `timeout 600 <cli> ...` | 防止挂死 | 非交互模式下最容易出的故障是无限等待输入；配 `< /dev/null` 一起用更稳 |
| `set -euo pipefail` | 脚本严格模式 | 缺了它，前一步失败后面还会照跑，AI 会基于错误的中间结果继续 |
| `git diff --name-only origin/main...HEAD \| <cli> "<任务>"` | 只针对本次改动跑 | CI 里的标准姿势：范围越小越快越便宜，也更容易复现 |
| `xargs -P 4` | 批量并行 | 并发会撞限流（见第 9 节），并发数要设上限并配退避重试 |

**进 CI 的四个前提**：① 非交互模式 + 超时；② 最小权限 token（只读 checkout，禁 push）；③ 容器沙箱；④ 用例/lint 作为唯一验收信号，AI 的自述一律不采信。

## 4、上下文管理

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `rg -n "<符号>" -g '!{node_modules,dist,target,build}'` | 先自己定位，把文件+行号交给它 | 让 AI 在全仓库盲搜是最贵的用法：搜索本身要烧掉大量输入 token，且命中率不如 ripgrep |
| `git diff --stat` / `git diff -- <path>` | 把「改了什么」作为上下文 | 比整文件复制省一个数量级；review 类任务优先喂 diff |
| `tree -L 2 -I 'node_modules\|target'` | 给一张项目地图 | ⚠ Windows **自带 `tree.com`，但整个命令只有 `/F`（列文件）和 `/A`（ASCII）两个开关**——既不能限深也不能排除，这个场景用不上；改用 PowerShell `Get-ChildItem -Depth 1`（`-Depth` 本身就会开启递归，不必再加 `-Recurse`） |
| 仓库根的规则/记忆文件（各家有约定文件名） | 固化长期约定（技术栈、代码风格、禁区） | **它进每次请求的前缀**：写太长每轮都在烧钱，而且一改动就让前缀缓存整体失效（见第 9 节）。保持短、稳、少改 |
| 各家的 ignore 配置 | 屏蔽 `dist/`、`target/`、快照测试、大 JSON | 多数工具默认尊重 `.gitignore`，但不保证；敏感目录必须显式排除，别赌默认行为 |
| `git check-ignore -v .env` | 确认密钥文件确实被忽略 | 返回空 = 没被忽略 = 可能被读进上下文 |
| `<cli> "<任务>" < <(git log --oneline -30)` | 用进程替换喂结构化上下文 | bash/zsh 专属语法；PowerShell 用 `... \| <cli>` |
| 会话内的清空/压缩上下文命令 | 任务切换时重置 | 不清就串味：上一个任务里被否掉的结论，会被当成既定事实继续用 |

## 5、权限与沙箱

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| 三档权限心智：只读 / 逐次确认 / 全自动 | 按任务风险选档 | 全自动只在沙箱里用。默认档应该是「读随便读，写要问，执行要问」 |
| `git worktree add ../sandbox-<任务> <branch>` | 把 AI 关进独立工作目录 | 主工作区不受影响，可并行多个会话互不踩踏；用完 `git worktree remove` |
| `docker run --rm -it -v "$PWD:/w" -w /w --network none <image>` | 断网容器沙箱 | 断网能挡住数据外传，但装依赖也会失败；需要联网时改用白名单代理或私有 registry |
| `docker run ... -v "$PWD:/w:ro"` | 只读挂载 | 纯分析/review 任务的最佳配置：它能看，改不了 |
| `useradd -m aiwork` + 专用低权限账号 | 不要把你的 sudo 借给它 | 一旦 AI 能 `sudo`，沙箱等于不存在 |
| 允许列表：`ls` `rg` `git diff` `git status` `cat` | 白名单放行只读命令 | 白名单永远比黑名单可靠：黑名单挡不住 `bash -c "..."`、`eval`、别名和拼接 |
| ⚠ 禁止列表：`rm -rf`、`git push`、`kubectl`、`terraform apply`、`aws`/`gcloud` 写操作、包发布 | 这些不进任何自动档 | 后果不可逆或对外可见；见第 11 节 |
| 提示注入认知 | AI 读到的 issue、网页、依赖 README 里可能藏指令 | 这就是自动模式必须沙箱的根本原因：不是不信模型，是不信它读到的内容 |

## 6、与 Git 协作（让 AI 改代码的安全流程）

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `git switch -c ai/<任务名>` | 隔离分支 | 唯一成本几乎为零的兜底手段；没有它，下面所有恢复操作都无从谈起 |
| `git stash -u` | 开工前收起未完成的本地改动 | `-u` 才包含未跟踪文件；不带 `-u` 时新建的文件会留在工作区被 AI 一并"整理" |
| `git add -p` | 逐块 review 后再入暂存区 | 比 `git add .` 慢，但这一步是唯一能拦住"顺手改了别的地方"的关卡 |
| `git diff --stat` → `git diff` | 先看面、再看点 | 改动文件数远超预期时，别读细节，直接推倒重来并收窄任务 |
| `git commit` 小步多提 | 每轮一提交 | 提交点就是回滚点；一个大提交里混了三轮改动，出问题只能整体丢弃 |
| `git restore --worktree <path>` | 撤销单个文件的未暂存改动 | 比 `git checkout -- .` 语义清晰，也不会误伤整个工作区 |
| ⚠ `git reset --hard` | 丢弃全部未提交改动 | **不可恢复**。安全替代：先 `git stash -u` 或 `git diff > /tmp/wip.patch` 存档，再重置 |
| ⚠ `git clean -fdx` | 删除所有未跟踪文件 | 会连 `.env`、本地配置、构建缓存一起删。安全替代：先 `git clean -nd` 干跑看清单 |
| ⚠ `git push --force` | 覆盖远端历史 | **永不授权给 AI**。人工执行时也用 `--force-with-lease`，它会在远端有新提交时拒绝覆盖 |
| ⚠ `--no-verify` | 跳过 pre-commit 钩子 | 钩子（lint/格式化/密钥扫描）正是 AI 改动的最后一道闸；禁止出现在任何自动流程里 |
| `git reflog` | 找回被 reset/rebase 丢掉的提交 | 救命稻草：只要 commit 过，绝大多数误操作都能从这里捞回来 |
| `git revert <sha>` | 已推送的改动用它撤销 | 已推送的历史不要 reset；revert 生成新提交，不破坏他人已拉取的历史 |

## 7、多轮与续接

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| 续接/恢复会话（各家有 resume 类能力） | 接着上次的上下文继续 | flag 名各家不同，先 `--help`；不确定能不能续，就别轻易退出会话 |
| `git log --oneline ai/<任务名>` | 用提交历史当断点记录 | 比"回忆上次聊到哪"可靠得多：提交信息就是进度快照 |
| 把结论写进临时 `NOTES.md`（不提交） | 让新会话能冷启动 | 上下文压缩必然丢细节，**关键决策和踩过的坑必须落盘**；写完记得加进 ignore |
| 重开一个干净会话 | 长会话纠偏的首选 | 在跑偏的长会话里反复纠正，往往比重开更贵、更慢、更容易越偏越远 |
| `git worktree` + 多会话 | 并行推进独立任务 | 同一目录开多个会话会互相覆盖文件；并行必须配独立 worktree |

## 8、MCP 与外部工具

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| MCP = 模型与外部工具/资源之间的标准化接入协议 | 统一挂载数据库、浏览器、文档检索等能力 | 传输方式分本地 stdio 与远程 HTTP 两类，排障思路完全不同 |
| 项目级 / 用户级配置作用域 | 决定这个 server 谁能用 | 团队共享的放项目级并入库；带凭据的放用户级，**绝不要提交进仓库** |
| `<server 启动命令> < /dev/null` | 单独手动跑一遍 server | 排障第一步。**stdio 传输下，任何往 stdout 打印的日志都会破坏协议**——server 的日志必须走 stderr |
| 工具数量控制 | 按需启用，不要全量挂载 | 每个 server 的工具定义都常驻在每次请求的前缀里：既是持续的 token 成本，也会拉低模型选对工具的概率 |
| 供应链审视 | 只装可信来源的 server | 装一个第三方 server ≈ 把仓库的读写权外包出去；先看源码和权限范围 |
| 优先用现成 CLI | `rg`、`gh`、`jq`、`curl` 能解决的别上 server | 本地 CLI 更快、更省 token、也更容易审计 |

## 9、成本与额度

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| token = 输入 + 输出 | 计费基本单位 | 编码场景下**输入远大于输出**：优化重点永远在「少喂」，不在「少写」 |
| 长会话的累计成本 | 每一轮都要重发全部历史 | 成本随轮数超线性增长。这是"重开会话比纠偏便宜"的数学原因 |
| 前缀缓存（prompt caching） | 命中后输入部分大幅降价 | **缓存是前缀精确匹配**：前缀里任何一个字节变了（时间戳、随机 ID、工具集顺序变动），它后面的全部失效重算 |
| 稳定前缀设计 | 静态内容放前面，易变内容放最后 | 规则文件、系统提示、工具列表要短而稳；把「当前时间」「本次任务描述」这类每次都变的内容放到最末尾 |
| 缓存写入有溢价 | 首次写缓存比普通输入更贵 | 只用一次的前缀开缓存是纯亏；要复用两次以上才回本。缓存还有有效期，闲置会过期 |
| 上下文窗口 ≠ 免费额度 | 塞满窗口既慢又贵 | 而且质量会下降：超长上下文中段的信息更容易被忽略。窗口大是容错空间，不是使用目标 |
| 分级用模型 | 大模型跑小任务是纯浪费 | 格式转换、改名、跑测试这类任务用小模型即可；难的推理才上大模型 |
| 429 限流 | 请求过快被拒 | 响应头通常带 `retry-after`。正确做法是**指数退避 + 随机抖动**；死循环立即重试只会让限流更久 |
| CI 预算护栏 | 超时 + 并发上限 + 单次任务范围收窄 | 无人值守的循环是账单爆炸的头号来源；一定要有硬上限 |

## 10、排障与维护

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `<cli> --version` | 确认版本 | 报 bug 和查文档的第一句话；CI 里应该锁版本，避免上游 breaking change 半夜炸掉流水线 |
| 认证状态检查（登录/whoami 类命令） | 401/403 的第一嫌疑 | 令牌过期是最高频故障；重新登录再排查其它，别一上来就怀疑网络 |
| `HTTPS_PROXY` / `HTTP_PROXY` / `NO_PROXY` | 走代理 | 三个都要设，`NO_PROXY` 漏配会让内网地址也绕道代理而失败 |
| `NODE_EXTRA_CA_CERTS=<ca.pem>` | Node 系 CLI 信任企业自签 CA | 症状是 `unable to verify the first certificate` / `self-signed certificate in chain`；非 Node 实现改用 `SSL_CERT_FILE` |
| `LANG=zh_CN.UTF-8` / Windows `chcp 65001` | 修中文乱码 | 终端编码不对时输出会变问号或方块，和模型无关 |
| `TERM` / 终端宽度 | 修 TUI 错位 | 在 tmux、CI、IDE 内置终端里 TUI 渲染异常，多半是 TERM 或宽度探测问题，优先改用非交互模式 |
| `timeout` + `< /dev/null` | 治「挂住不动」 | 管道环境下 stdin 不是 TTY，工具若等待交互确认就会永久阻塞 |
| verbose / debug 日志开关 | 看真实请求与工具调用 | 出问题先开 debug 看它到底读了哪些文件、调了哪些工具，比猜快得多 |
| 缓存与会话目录清理 | 磁盘占用异常时 | 长期使用后会话历史会膨胀到 GB 级；清理前先确认里面没有你还要续接的会话 |

## 11、安全红线（密钥、生产环境、不可逆操作）

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| ⚠ 密钥绝不粘贴进提示词 | 用环境变量 + ignore 传递 | **一旦粘贴，就按已泄露处理：立刻轮换。** 删除聊天记录不等于没泄露——本地日志、崩溃报告、服务端留存都可能已经记下 |
| `gitleaks detect` / `git secrets --scan` | 提交前扫密钥 | 真实可用的开源工具；接进 pre-commit 钩子，这是 AI 改动最后一道自动闸门 |
| `git check-ignore -v .env` | 确认密钥文件不进上下文 | 见第 4 节；配套把 `.env` 系列、所有 `.pem` / `.key` 私钥、`id_rsa` 系列密钥全部写进 ignore |
| ⚠ 生产凭据不进 AI 会话环境 | 环境隔离 | 需要连库分析时只给**只读副本**的凭据；AI 会话所在 shell 里不应存在能写 prod 的任何 token |
| ⚠ 永不授权的命令族 | `rm -rf`、`git push --force`、`DROP`/`TRUNCATE`/无 `WHERE` 的 `DELETE`、`kubectl delete`、`terraform apply`、`docker system prune`、`npm publish`、`systemctl` 对生产的操作 | 共同特征：**不可逆或对外可见**。这类操作永远由人执行，AI 最多产出待执行的命令文本 |
| `--dry-run` / `-n` 先干跑 | 任何批量删改前的强制步骤 | `rsync`、`git clean`、`kubectl`、`terraform plan` 都能先干跑看清单；`rm` 这类没有干跑能力的命令，删前先把目标备份到别处 |
| ⚠ 供应链：AI 建议的包可能不存在 | 装之前先核实 | 模型会编造出看似合理的包名，攻击者会抢注这些名字。安装前 `npm view <pkg>` / `pip index versions <pkg>` 或直接看仓库主页 |
| ⚠ 提示注入 | AI 读到的外部内容可能携带指令 | 处理外部 issue、抓取的网页、第三方依赖文档时，必须断网沙箱 + 人审 diff，不要开自动写盘 |
| 数据留存政策 | 企业环境先确认 | 代码会不会被用于训练、日志保存多久、是否跨境——上生产项目前必须有明确答案 |

## 常见错误速判

| 症状 | 多半是 | 先试这条 |
|------|--------|----------|
| 命令挂住不动，无任何输出 | 管道下等待交互确认，stdin 不是 TTY | `timeout 120 <cli> ... < /dev/null`，并加上非交互模式 |
| 退出码 0，但事情根本没做 | 把 AI 的自述当验收标准了 | 跑项目自己的测试；`git diff --stat` 看是否真有改动 |
| 改动散落到一堆不相干的文件 | 任务边界太模糊 | `git restore .` 回退，把任务收窄到 3~5 个文件重来 |
| 它反复读错文件 / 找不到代码 | 启动目录不是仓库根，或被 ignore 挡住 | 回到仓库根启动；`git check-ignore -v <path>` 确认该路径没被排除 |
| 明明配了缓存但成本没降 | 前缀里有每次都变的内容 | 检查规则文件是否刚改过、提示里是否带了时间戳/随机 ID/变动的工具集 |
| 报 429 / rate limit | 并发太高或短时请求过密 | 降并发，按 `retry-after` 做指数退避 + 抖动重试 |
| 401 / 403 | 令牌过期或权限不足 | 重新登录；确认用的是有对应权限的账号，而不是网络问题 |
| TLS 证书错误 | 企业 MITM 代理 | Node 系设 `NODE_EXTRA_CA_CERTS`，其它设 `SSL_CERT_FILE` |
| 输出中文乱码 / TUI 错位 | 终端编码或 TERM 不对 | `LANG=zh_CN.UTF-8`；Windows `chcp 65001`；实在不行改走非交互模式 |
| MCP server 连不上、协议报错 | stdio 下 server 把日志打到了 stdout | 单独手动跑该 server，确认 stdout 只有协议数据，日志全走 stderr |
| 会话越聊越离谱 | 上下文串味 + 历史里带着错误结论 | 清空上下文或直接重开会话，把已确认的结论重新喂一遍 |

## 一页纸口诀

1. **先切分支，再开口**——`git switch -c ai/xxx` 是成本最低、收益最高的一条命令。
2. **没有绿灯就别交**——任务必须有能自动跑的验收信号，否则你省下的时间都会在 review 时还回去。
3. **给路径和 diff，不给整个仓库**——你花十秒 `rg` 定位，能省掉它一整轮的盲搜与 token。
4. **退出码不可信，测试才可信**——AI 说"完成了"和事情做对了是两件事。
5. **白名单永远优于黑名单**——黑名单挡不住 `bash -c`、`eval` 和字符串拼接。
6. **自动模式必须配沙箱**——不是不信模型，是不信它读到的 issue、网页和依赖文档。
7. **前缀短而稳**——规则文件每改一次，后面的缓存全部作废，下一次请求全量重算。
8. **重开比纠偏便宜**——长会话每轮重发全部历史，成本和跑偏概率一起往上涨。
9. **密钥粘出去就当已泄露**——立刻轮换，删记录不算数；生产凭据永远不进 AI 会话环境。

## 运行前边界、回滚与验证

- **运行前**：示例以 GNU/Linux 的 Bash 为主；先用 `command --help`、`man command` 或发行版文档确认本机版本和参数。不要把教程中的 IP、域名、用户、路径直接复制到生产机器。
- **先确认作用域**：涉及文件、仓库、容器或远端主机时，先运行 `pwd`、`whoami`、`git status`、`docker context show` 或 `ssh -G 主机别名`，确认当前目标；对重要数据先做可恢复备份。
- **完成后验证**：用只读命令确认结果，例如 `ls -la`、`git status`、`systemctl status 服务名`、`docker ps` 或 `curl -fS URL`；失败时停止扩大操作范围，先读报错。
- **删除边界**：`rm`/`Remove-Item` 不会进入回收站。先用 `ls -- 路径` 或 PowerShell 的 `-WhatIf` 预演；避免对变量、通配符或当前目录直接使用递归强制删除。
- **Git 回滚边界**：`reset --hard`、rebase 和强推会改写本地或共享历史。先保存 `git status`/`git log --oneline`，共享分支优先 `git revert`；必须强推时使用 `--force-with-lease` 并与协作者确认。
- **权限边界**：先用 `stat`/`ls -ld` 查所有者和现有权限；按最小权限原则修改，避免 `chmod -R 777`。`sudo` 仅用于明确的单条命令，不在不理解的脚本前盲加。
- **远端边界**：首次连接核验主机指纹；传输前先确认目标路径和账号，`rsync` 删除模式必须先加 `--dry-run`。远程改网络或防火墙时保留一个已登录会话和云控制台回退路径。
- **容器边界**：先执行 `docker context show`、`docker ps -a` 和 `docker system df`；清理命令只对确认无用的资源执行，带卷的删除额外确认持久化数据和备份。
