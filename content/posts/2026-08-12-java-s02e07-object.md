# 《从零开始学 Java》19 · Object 神殿

> 第二季「对象大陆」第 7 话 · 基线 JDK 25 · 承接:OOP 四件套齐备的咖啡站。

---

## 一、需求:两个「张三」应该算同一个会员

会员用对象表示。可 `new Member("张三")` 两次,程序却认为是两个人 —— 因为默认的相等判断比的是「是不是同一个对象」,而不是「内容是否相同」。

---

## 二、漫画

> **〔1〕** Object 神殿高踞云端,所有类顺着家谱往上都连到它。
> 豆豆:「你写的每个类,不写 `extends` 也默默继承了 `Object`。」

> **〔2〕** 神殿门口三块碑:`equals`(判内容相等)、`hashCode`(相等的对象哈希也要相等)、`toString`(自我描述)。
> 豆豆:「重写 `equals` 就必须一起重写 `hashCode`,这是铁律。」

---

## 三、本话目标

- 理解 `Object` 是所有类的根,默认 `equals` 比引用;
- 重写 `equals` + `hashCode`(成对出现)与 `toString`;
- 认识 `record`:现代 JDK 自动生成这三者;
- 踩一次「只重写 equals 不重写 hashCode」埋下的隐患。

---

## 四、原理图

```text
Object 提供:equals(默认比引用)、hashCode、toString(默认类名@哈希)
契约:a.equals(b) 为真  ⇒  a.hashCode() == b.hashCode()   (反之不要求)

现代捷径:record Member(String id, String name) { }
          自动生成 equals / hashCode / toString / 构造器 / 访问器
```

---

## 五、代码:两种写法

手写版(理解契约):

```java
import java.util.Objects;

class Member {
    private final String id;
    Member(String id) { this.id = id; }

    @Override public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Member m)) return false;
        return Objects.equals(id, m.id);      // 按 id 判等
    }
    @Override public int hashCode() { return Objects.hash(id); }   // 必须和 equals 用同一字段
    @Override public String toString() { return "Member(" + id + ")"; }
}
```

现代版(推荐,值对象首选):

```java
record MemberRecord(String id, String name) {}   // 一行,三件套全自动
```

```java
public class Demo {
    public static void main(String[] args) {
        System.out.println(new Member("m01").equals(new Member("m01")));            // true
        System.out.println(new MemberRecord("m01", "张三").equals(new MemberRecord("m01", "张三"))); // true
    }
}
```

## 六、故意制造一个 Bug

只重写 `equals`,故意不写 `hashCode`(下一话用到 HashSet 就会出事):

```java
class Member {
    private final String id;
    Member(String id) { this.id = id; }
    @Override public boolean equals(Object o) {
        return o instanceof Member m && Objects.equals(id, m.id);
    }
    // 没有 hashCode —— 编译能过,但埋雷
}
```

---

## 七、读懂现象(不报错,但违约)

编译、运行都不报错。可一旦把这些 Member 放进 `HashSet`,两个「相等」的对象却因为哈希不同被分到不同桶里,双双留下 —— 去重失效。这违反了「相等则哈希相等」的契约。**equals 和 hashCode 必须成对重写**;记不住就用 `record`。

---

## 八、修复,并用测试证明

补上 `hashCode`(或直接用 `record`):

```java
@Test
void equal_objects_share_hashcode() {
    var a = new MemberRecord("m01", "张三");
    var b = new MemberRecord("m01", "张三");
    assertEquals(a, b);
    assertEquals(a.hashCode(), b.hashCode());   // 契约成立,才能安全进 Set/Map
}
```
