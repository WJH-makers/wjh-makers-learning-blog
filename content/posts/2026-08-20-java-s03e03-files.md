## 三、本话目标

- 用 `Path` 表示文件位置,`Files` 读写文件;
- 认识第一个 **checked 异常** `IOException`——编译官强制你处理;
- 用 **try-with-resources** 自动关闭资源,告别手动 `finally` 关流;
- 踩一次"相对路径找不到文件"的坑并看懂 `NoSuchFileException`;
- 用测试验证"存进去再读出来,数据一致"。

## 四、原理图:Path 是地址,Files 是搬运工

```text
Path.of("menu.csv")     一张写着位置的纸条(未必真有文件)
        │
        ▼   交给搬运工 Files
Files.writeString(path, text)   写
Files.readString(path)          读(小文件)
Files.readAllLines(path)        读成 List<String>(按行)
Files.newBufferedReader(path)   开一个可逐行读的流(大文件,配 try-with-resources)
```

两个关键提醒:

- **相对路径**(`menu.csv`)是相对**进程的工作目录**——从哪儿敲 `java` 命令,就从哪儿找;换个目录运行就找不到。要稳,用绝对路径或显式指定目录。
- **字符编码**:Java 18 起(JEP 400)默认字符集统一为 **UTF-8**,中文菜单跨平台不再乱码——这是近年最省心的默认值之一。

## 五、代码:把菜单存进文件、再读回来

```java
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.LinkedHashMap;
import java.util.Map;

public class MenuStore {
    private static final Path FILE = Path.of("menu.csv");

    // IOException 是 checked 异常:方法要么 throws、要么 try —— 编译官盯着
    static void save(Map<String, Integer> stock) throws IOException {
        StringBuilder sb = new StringBuilder();
        stock.forEach((name, qty) -> sb.append(name).append(',').append(qty).append('\n'));
        Files.writeString(FILE, sb.toString());   // 默认 UTF-8
    }

    static Map<String, Integer> load() throws IOException {
        Map<String, Integer> stock = new LinkedHashMap<>();
        if (Files.notExists(FILE)) return stock;       // 没文件就返回空,别硬读
        for (String line : Files.readAllLines(FILE)) {
            if (line.isBlank()) continue;
            String[] p = line.split(",");
            stock.put(p[0], Integer.parseInt(p[1]));
        }
        return stock;
    }
}
```

调用处必须处理这个 checked 异常:

```java
public static void main(String[] args) {
    Map<String, Integer> menu = new LinkedHashMap<>();
    menu.put("美式", 20);
    menu.put("拿铁", 15);
    try {
        MenuStore.save(menu);                     // 写盘
        Map<String, Integer> loaded = MenuStore.load();  // 关机后再读回
        System.out.println("读回菜单:" + loaded);
    } catch (IOException e) {
        System.out.println("菜单读写失败:" + e.getMessage());
    }
}
```

## 七、读懂真实报错:NoSuchFileException

```text
Exception ... java.nio.file.NoSuchFileException: menu.csv
	at java.base/...
	at MenuStore.load(MenuStore.java:19)
```

`NoSuchFileException` 后面直接跟着**它去找的那个路径**。八成不是文件没了,而是**你以为的"当前目录"和程序真正的工作目录不是同一个**。排查一句话:先 `System.out.println(FILE.toAbsolutePath())` 打出它到底在找哪儿,真相立刻浮现。

> **豆豆锐评 · 为什么流一定要关**
> 文件流、网络连接这类资源占着操作系统的句柄,不关就**泄漏**——句柄耗尽会让程序再也打不开新文件。手写 `finally { reader.close(); }` 容易漏、还可能在 close 时又抛异常盖住原始错误。**try-with-resources** 帮你在括号里的资源用完后**逆序自动关闭**,前提是它实现了 `AutoCloseable`(几乎所有流都实现了)。

> **⏳ 版本时光机 · 文件读写怎么一步步变简单的**

| JDK 版本 | 写法 | 变化 |
|---|---|---|
| Java 6 | `FileReader` + `BufferedReader`,手动 `finally { close() }` | 啰嗦、易漏关 |
| Java 7 | `try (var r = new BufferedReader(...)) { }` 自动关 | try-with-resources 登场 |
| Java 11 | `Files.readString` / `writeString` 一行读写小文件 | 小文件党福音 |
| Java 18 | 默认字符集转 **UTF-8**(JEP 400) | 中文跨平台不再乱码 |

> **🔀 豆豆的多解台 · 读文件,选哪个 API?**

| 方式 | 代码要点 | 适合 |
|---|---|---|
| `Files.readString(path)` | 一次读成一个 `String` | 小文件、要整块内容 |
| `Files.readAllLines(path)` | 按行读进 `List<String>` | 小文件、按行处理(本话用它) |
| `Files.newBufferedReader` + try-with-resources | 逐行读、省内存 | 大文件 |
| `Files.lines(path)` | 返回**流**,惰性逐行 | 大文件 + 流式处理(是 Stream,**下一话专讲**) |

豆豆锐评:菜单这种小文件,`readAllLines` 最省事;等文件大到几百 MB,再换 `newBufferedReader` 或 `Files.lines` 逐行,别一次性全读进内存。

## 八、修复后用测试证明:存进去 = 读出来

```java
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.io.TempDir;
import java.nio.file.Path;
import java.util.*;
import static org.junit.jupiter.api.Assertions.*;

class MenuStoreTest {
    @Test
    void save_then_load_roundtrip(@TempDir Path dir) throws Exception {
        // @TempDir 给一个临时目录,测试完自动清理,不污染真实文件
        Path file = dir.resolve("menu.csv");
        java.nio.file.Files.writeString(file, "美式,20\n拿铁,15\n");
        List<String> lines = java.nio.file.Files.readAllLines(file);
        assertEquals(2, lines.size());
        assertEquals("美式,20", lines.get(0));
    }
}
```

JUnit 的 `@TempDir` 专为文件测试而生:给你一个用完即焚的临时目录,**测试不碰你的真实文件、也不会互相干扰**。

### 二、解答题（3 道）

1. [概念] `Path` 接口和 `java.io.File` 的区别是什么？为什么现代 Java 项目推荐用 `Path`/`Files` 而非 `File`？

2. [场景] 咖啡站有一个 `menu.csv` 文件记录菜单。设计 `MenuStore.load()` 的容错逻辑：文件不存在返回空 Map；某行格式错误（缺少逗号、数量非数字）跳过该行并打印警告；所有错误用统一的 `IOException` 路径处理。描述你的设计思路。

3. [综合] 对比三种读文件方案：`Files.readString()`、`Files.readAllLines()`、`Files.newBufferedReader()` + try-with-resources。从适用文件大小、内存占用、API 复杂度三个维度分析，并给出选型决策树。

> [!答案] **1** `Path` 是接口，可对接不同文件系统（ZIP、云存储等），`File` 只支持本地；`Path` 的方法更语义化（`resolve`/`relativize`/`getParent`）；配套 `Files` 工具类提供丰富便捷方法。**举一反三**：`Files` 的静态方法在 Java 11（`readString`/`writeString`）和 Java 18（UTF-8 默认）后体验大幅提升。
> [!答案] **2** 容错三层：①`Files.notExists(path)` → 返回空 Map，不抛异常（首次运行还没有文件是正常状态）；②`Files.readAllLines(path)` 外 catch `IOException`（文件损坏等）；③逐行解析时 `try { Integer.parseInt(...) } catch (NumberFormatException e)`，记录 `"第X行格式错误：跳过"`。关键设计——不要把"数据格式错误"和"文件系统错误"混在一起处理。**举一反三**：可以用 `Files.lines(path)` 惰性读并配合 Stream API 的 `filter/map` 处理。
> [!答案] **3** 决策树：①文件 < 几 KB，要整块内容 → `readString`，一行代码；②文件 < 几 MB，按行处理 → `readAllLines`，返回 List 直接遍历；③文件 > 几十 MB → `newBufferedReader` + 逐行，内存可控。`Files.lines()` 是第四种：返回惰性 Stream，适合大文件 + 流式过滤/映射。**举一反三**：大文件不只是"内存不够"的问题——`readAllLines` 读 1GB 文件会把整个文件变成 String 数组留在堆里，GC 压力巨大。

### 三、代码题（2 道）

1. [基础] 写一个 `writeMenu` 方法：接收 `Map<String, Integer>`（菜单→价格），写入 `menu.txt`（格式："美式,20" 每行一条）。再写 `readMenu` 方法读回并打印。在 main 中验证写进去再读回来数据一致（roundtrip）。用 `Files.writeString` 和 `Files.readAllLines`，正确处理 `IOException`。

2. [综合] 用 try-with-resources 实现一个 `countLines(Path path)` 方法：返回文件的行数（忽略空行）。要求：①用 `BufferedReader` 逐行读；②如果文件不存在，返回 0（不抛异常）；③其他 IO 错误包装成 `FileCountException`（继承 `RuntimeException`，带 cause）；④用 `@TempDir` 写测试验证：3 行文件（含 1 空行）应返回 2，空文件返回 0，不存在文件返回 0。

> [!答案] **1 验收**：
> ```java
> static void writeMenu(Path file, Map<String, Integer> menu) throws IOException {
>     StringBuilder sb = new StringBuilder();
>     menu.forEach((name, price) -> sb.append(name).append(',').append(price).append('\n'));
>     Files.writeString(file, sb.toString());
> }
> static Map<String, Integer> readMenu(Path file) throws IOException {
>     Map<String, Integer> menu = new LinkedHashMap<>();
>     if (Files.notExists(file)) return menu;
>     for (String line : Files.readAllLines(file)) {
>         if (line.isBlank()) continue;
>         String[] p = line.split(",");
>         menu.put(p[0], Integer.parseInt(p[1]));
>     }
>     return menu;
> }
> public static void main(String[] args) throws IOException {
>     Map<String, Integer> original = Map.of("美式", 20, "拿铁", 18);
>     Path file = Path.of("menu.txt");
>     writeMenu(file, original);
>     Map<String, Integer> loaded = readMenu(file);
>     System.out.println(original.equals(loaded)); // true
> }
> ```
> **举一反三**：`LinkedHashMap` 保持插入顺序，菜单打印时顺序一致更友好。
> [!答案] **2 验收**：
> ```java
> class FileCountException extends RuntimeException {
>     public FileCountException(String msg, Throwable cause) { super(msg, cause); }
> }
> static long countLines(Path path) {
>     if (Files.notExists(path)) return 0;
>     try (var reader = Files.newBufferedReader(path)) {
>         return reader.lines().filter(line -> !line.isBlank()).count();
>     } catch (NoSuchFileException e) {
>         return 0; // 并发删除的极端情况
>     } catch (IOException e) {
>         throw new FileCountException("统计行数失败：" + path, e);
>     }
> }
> // 测试（JUnit）:
> @Test void count_skips_blanks(@TempDir Path dir) throws IOException {
>     Path f = dir.resolve("test.txt");
>     Files.writeString(f, "美式\n\n拿铁\n");
>     assertEquals(2, countLines(f));
> }
> @Test void empty_file_returns_zero(@TempDir Path dir) throws IOException {
>     Path f = dir.resolve("empty.txt");
>     Files.createFile(f);
>     assertEquals(0, countLines(f));
> }
> @Test void nonexistent_returns_zero() {
>     assertEquals(0, countLines(Path.of("no-such-file.txt")));
> }
> ```
> **举一反三**：`BufferedReader.lines()` 返回 Stream，配合 `filter`/`count` 用到了下一话的 Stream 知识——这是 NIO 和 Stream 的经典合体写法。
