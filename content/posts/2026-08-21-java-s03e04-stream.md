## 一、需求:老板的三个问题

打烊,老板探头:「今天卖了多少杯?销售额多少?哪款最火?」

第二季在接口话里,我们埋了一句「Lambda 第三季专讲」。今天它正式上岗——搭档 Stream,把"怎么做"变成"要什么"。

## 二、漫画 · 订单流水线

> **〔1〕** 一条传送带轰隆启动,订单一件件滑上去。带子分三个工位:`filter`(筛)、`map`(变)、`reduce/collect`(合)。
> 豆豆:「这就是 **Stream 流水线**。数据在带子上流过每个工位,最后汇成结果。」

> **〔2〕** 每个工位插着一张**便携指令卡**,上面写着 `o -> o.item().equals("美式")`。
> 豆豆:「这张卡就是 **Lambda**——一小段能当参数传来传去的『行为』。`->` 左边是入参,右边是要做的事。」

> **〔3〕** 阿零好奇地伸手按了下"启动"却只装了 `filter`,带子纹丝不动。
> 阿零:「坏了?」豆豆(叼豆子):「没坏。`filter` 是**中间工位,懒**——不给它一个『终点』(收集/求和),整条带子根本不会转。这叫**惰性求值**。」

> **〔4〕** 阿零装上终点工位 `.sum()`,带子瞬间飞转,吐出结果 `5`。
> 豆豆:「记住:**中间操作攒动作,终端操作才真跑**。」

> **〔5〕** 阿零想省事,把同一条带子按了两次启动。带子"哐"地卡死冒烟。
> 豆豆:「一条流**只能用一次**。想再跑,重新 `stream()` 拉一条新带子。」

## 三、本话目标

- 用 Lambda 写出"一段行为",看懂 `->` 与方法引用 `Type::method`;
- 用 Stream 的 `filter / map / mapToInt / sum / collect` 组一条统计流水线;
- 理解**惰性求值**:中间操作 vs 终端操作;
- 踩一次"流被重复消费"的坑并看懂报错;
- 用测试验证统计结果。

## 四、原理图:一条流水线的三段

```text
orders.stream()                     ① 从集合拉出一条流(带子启动)
      .filter(o -> ...)             ② 中间操作:筛(懒,不立即执行)
      .map(Order::item)             ③ 中间操作:变(懒)
      .collect(...) / .sum()        ④ 终端操作:合(此刻整条流水线才真正跑)
```

两条铁律:

- **惰性**:只有终端操作(`collect`/`sum`/`count`/`forEach`)会触发执行;没有终端操作,前面的 `filter`/`map` 一动不动。
- **一次性**:一条流被终端操作消费后就作废,再用抛异常。要复用,重新 `stream()`。

## 五、代码:一行回答老板的三个问题

订单用第二季学的 `record` 承载:

```java
import java.util.*;
import java.util.stream.Collectors;

record Order(String item, int qty, double amount) {}

public class SalesReport {
    public static void main(String[] args) {
        List<Order> orders = List.of(
            new Order("美式", 2, 30.0),
            new Order("拿铁", 1, 18.0),
            new Order("美式", 3, 45.0));

        // ① 今天卖了多少杯:取出每单杯数,求和
        int cups = orders.stream().mapToInt(Order::qty).sum();

        // ② 销售额:取出每单金额,求和
        double revenue = orders.stream().mapToDouble(Order::amount).sum();

        // ③ 各单品销售额:按 item 分组,组内金额求和
        Map<String, Double> byItem = orders.stream()
            .collect(Collectors.groupingBy(Order::item,
                     Collectors.summingDouble(Order::amount)));

        System.out.printf("共 %d 杯 · 销售额 ¥%.2f%n", cups, revenue);
        System.out.println("各单品:" + byItem);
    }
}
```

输出:

```text
共 6 杯 · 销售额 ¥93.00
各单品:{美式=75.0, 拿铁=18.0}
```

`Order::qty` 是**方法引用**,等价于 `o -> o.qty()`——当 Lambda 只是"调一个方法"时,用 `::` 更短。`filter(o -> o.item().equals("美式"))` 里的 `o -> ...` 就是一张 Lambda 指令卡。

## 七、读懂真实报错:流已被操作过

```text
Exception in thread "main" java.lang.IllegalStateException:
    stream has already been operated upon or closed
	at java.base/java.util.stream.AbstractPipeline.<init>(...)
	at SalesReport.main(SalesReport.java:23)
```

报错说得很直白:**这条流已经被操作过或关闭了**。Stream 不是集合,它是"一次性的流水线视图"——`count()`(终端操作)跑完,带子就拆了。修法:每次要用重新拉一条 `orders.stream()`,别把 `stream` 变量存起来反复用。

> **豆豆锐评 · Stream 不是集合的替代品**
> 别看见集合就 `.stream()`。流适合"一串**变换 + 聚合**"(筛、映射、分组、求和);如果你只是想遍历做副作用(打印、改外部状态),老实用 for-each 更清楚。尤其别在 `forEach` 里改外部变量凑计数——那是把函数式写成了命令式,该用 `reduce`/`collect`。

> **⏳ 版本时光机 · 收集结果的写法怎么变的**

| JDK 版本 | 写法 | 变化 |
|---|---|---|
| Java 8 | `.collect(Collectors.toList())` | 返回**可变** List,啰嗦 |
| Java 16 | `.toList()` | 一步到位,返回**不可变** List(改它会抛异常) |
| Java 24+ | `.gather(...)`(Stream Gatherers,JEP 485 已转正) | 可自定义中间操作,补齐流水线的自定义工位 |

日常收集优先用 `.toList()`;要可变结果再 `.collect(Collectors.toCollection(ArrayList::new))`。

> **🎯 面试直击**:Stream 的中间操作和终端操作有什么区别?
> 中间操作(`filter`/`map`/`sorted`…)返回新的 Stream、**惰性**,只是"攒动作"不执行;终端操作(`collect`/`sum`/`count`/`forEach`/`reduce`…)触发整条流水线真正运行,并产出结果或副作用。追问点:① 没有终端操作,中间操作一行都不会跑;② 一条流只能被消费一次;③ `filter` 后再 `map`,元素是**逐个流过**全流水线的(不是一层跑完再跑下一层),这叫融合(loop fusion),省去中间集合。

### 一、选择题（10 道）

1. [基础] `orders.stream().filter(...).collect(...)` 中，哪一个是**终端操作**？
- A) `stream()`　B) `filter()`　C) `collect()`　D) 都不是

2. [基础] `stream.filter(o -> o.price() > 20)` 中，`o -> o.price() > 20` 是什么语法？
- A) 匿名内部类　B) **Lambda 表达式**　C) 方法引用　D) 泛型

3. [基础] 方法引用 `Order::item` 等价于哪个 Lambda？
- A) `o -> o`　B) `o -> o.item()`　C) `(o) -> item(o)`　D) `Order.item()`

4. [进阶] 只声明 `stream.filter(...)` 而不加终端操作，结果会怎样？
- A) 编译失败　B) 立即执行 filter　C) **什么都不执行**（惰性求值）　D) 抛异常

5. [进阶] `filter` 和 `map` 的核心区别是？
- A) 完全相同　B) `filter` 筛选/丢弃元素，`map` 转换每个元素　C) `filter` 改变元素值，`map` 删除元素　D) filter 是终端操作，map 是中间操作

6. [进阶] 一条 Stream 调用 `count()` 后，能否继续调用 `sum()`？
- A) 可以，Stream 可复用　B) **不可以**，流已被消费关闭　C) 取决于元素类型　D) 可以，但结果可能不对

7. [进阶] `Collectors.groupingBy(Order::item)` 的返回类型是？
- A) `List<Order>`　B) `Set<String>`　C) `Map<String, List<Order>>`　D) `Map<String, Order>`

8. [综合] 要统计每个单品的**总杯数**，正确的写法是？
- A) `groupingBy(Order::item, summingInt(Order::qty))`　B) `groupingBy(Order::item)`　C) `map(Order::item).sum()`　D) `filter(Order::item).count()`

9. [综合] 以下代码的结果是什么？
```java
Stream.of("a", "b", "c").map(String::toUpperCase).filter(s -> s.equals("B")).count()
```
- A) 0　B) 1　C) 2　D) 3

10. [综合] `.toList()`（Java 16+）和 `.collect(Collectors.toList())` 的区别是？
- A) 完全相同　B) `.toList()` 返回**不可变** List　C) `.toList()` 效率更低　D) `.toList()` 只在 Stream 上可用

> [!答案] **1-C** `collect()` 是终端操作，触发流水线执行。`filter()` 是中间操作，惰性。`stream()` 是数据源。**举一反三**：常见的终端操作还有 `sum`、`count`、`forEach`、`reduce`。
> [!答案] **2-B** `(参数) -> { 表达式 }` 是 Lambda 语法。当只有一行表达式时可省略 `{}` 和 `return`。**举一反三**：Lambda 本质是实现函数式接口的匿名方法——编译器根据上下文推断参数类型。
> [!答案] **3-B** `Order::item` 等价于 `o -> o.item()`。方法引用更简洁，当 Lambda 只是"调一个方法"时优先用。**举一反三**：还有其他形式——`System.out::println`（实例方法引用）、`String::valueOf`（静态方法引用）、`String::new`（构造器引用）。
> [!答案] **4-C** 中间操作是惰性的，没有终端操作就不会触发执行。**举一反三**：这就像搭好流水线但没按启动键——所有工位都空转。
> [!答案] **5-B** `filter(Predicate)` 保留满足条件的，丢弃不满足的（元素个数可能变少）；`map(Function)` 把每个元素变成另一个值（个数不变，类型可能变）。两者都是中间操作。**举一反三**：`flatMap` 是一对多——把一个元素展开成 Stream 再拍平。
> [!答案] **6-B** 流是一次性的，`count()` 消费后流关闭，再调用抛 `IllegalStateException: stream has already been operated upon or closed`。**举一反三**：想复用就重新 `list.stream()` 拉一条新流。
> [!答案] **7-C** `groupingBy` 返回 `Map<K, List<T>>`，键是分组依据，值是该组所有元素组成的 List。**举一反三**：第二个参数可传下游收集器，如 `summingInt`、`counting`。
> [!答案] **8-A** `groupingBy(分类器, 下游收集器)` 的典型用法——先按单品分类，再对每组求和。**举一反三**：没有 `summingInt` 的话，会得到 `Map<String, List<Order>>`，还得手动累加。
> [!答案] **9-B** 流水线：`a,b,c` -> MAP 大写 -> `A,B,C` -> FILTER 等于 B -> 只剩 `B` -> count = 1。注意 filter 判断的是大写后的字符串，"B" 只有一个。**举一反三**：中间操作按流水线融合执行——一个元素穿过全流水线后，下一个元素才开始，不是全 filter 完再全 map。
> [!答案] **10-B** `.toList()` 返回不可变 List（`Collections.unmodifiableList`），改它会抛异常。`collect(Collectors.toList())` 返回可变 ArrayList。**举一反三**：要不可变结果优先用 `.toList()`，更简洁；要可变结果用 `collect(Collectors.toCollection(ArrayList::new))`。

### 二、解答题（3 道）

1. [概念] Stream 的中间操作和终端操作有什么区别？为什么说"没有终端操作，中间操作一行都不会跑"？

2. [场景] 咖啡站有一批订单：`List<Order>`（Order 有 item、qty、amount）。分别用 Stream 写出：①找出所有美式订单并打印；②各单品杯数排名（从多到少）；③总销售额。每个需求一行链式调用完成。

3. [综合] Stream 不是集合的替代品——什么场景适合用 Stream，什么场景更适合用传统的 for-each 循环？从"副作用"角度分析在 `forEach` 里修改外部变量的风险，并给出更函数式的替代方案。

> [!答案] **1** 中间操作返回新的 Stream，惰性（攒动作不执行）；终端操作触发全流水线运行并产出结果/副作用。若没有终端操作，整条流水线就是"只定义了但从未触发"的蓝图。**举一反三**：`sorted()` 也是中间操作，但没有终端操作时不会真的排序——这叫"惰性求值"，与 `Collections.sort()`（立即排序）截然不同。
> [!答案] **2** ①`orders.stream().filter(o -> "美式".equals(o.item())).forEach(System.out::println)`；②`orders.stream().collect(groupingBy(Order::item, summingInt(Order::qty))).entrySet().stream().sorted(Map.Entry.<String,Integer>comparingByValue().reversed()).forEach(...)`；③`orders.stream().mapToDouble(Order::amount).sum()`。**举一反三**：需求②如果只需前三名，可以加 `.limit(3)`。
> [!答案] **3** Stream 适合"一串变换 + 聚合"——过滤、映射、分组、求和，无副作用。for-each 适合"遍历做副作用"——打印、写文件、发通知。`forEach` 中修改外部变量（如 `int total; list.forEach(i -> total += i)`）是反模式：①需要外部可变状态（`total` 不是 effectively-final 会编译报错）；②该用 `mapToInt().sum()`。替代方案：用 `reduce`/`collect` 代替手动累加。**举一反三**：IDE 的"for 循环转 Stream"自动重构功能可帮你识别哪些循环适合改写。

### 三、代码题（2 道）

1. [基础] 给定 `List<Integer> prices = List.of(15, 22, 18, 35, 12)`，用 Stream 完成：①过滤出大于 20 的元素；②每个元素加价 10%（即 ×1.1）；③对处理后的值求和。要求链式调用，并验证结果（22 和 35 → 24.2 和 38.5 → 总和 62.7）。

2. [综合] 给定 `List<Order>`（record: item、qty、amount），写一个 `salesSummary(List<Order>)` 方法返回统计对象 `Summary(totalCups, totalRevenue, bestSeller)`。要求：①用 Stream 一次遍历完成（提示：可用 `reduce` 或多次 stream）？②空列表时 `bestSeller` 为 "无销售"；③边界：负数 qty 的脏数据用 `filter` 排除。

> [!答案] **1 验收**：
> ```java
> List<Integer> prices = List.of(15, 22, 18, 35, 12);
> double total = prices.stream()
>     .filter(p -> p > 20)          // 22, 35
>     .mapToDouble(p -> p * 1.1)    // 24.2, 38.5 —— 注意用 mapToDouble 避免装箱
>     .sum();                        // 62.7
> System.out.println(total);        // 62.7
> // 验证：22*1.1 + 35*1.1 = 24.2 + 38.5 = 62.7
> ```
> **举一反三**：`mapToDouble`/`mapToInt` 返回 `DoubleStream`/`IntStream`，避免了 `Stream<Double>` 的装箱开销。
> [!答案] **2 验收**：
> ```java
> record Order(String item, int qty, double amount) {}
> record Summary(int totalCups, double totalRevenue, String bestSeller) {}
> 
> static Summary salesSummary(List<Order> orders) {
>     List<Order> valid = orders.stream()
>         .filter(o -> o.qty() > 0 && o.amount() > 0).toList(); // 排除脏数据
>     int cups = valid.stream().mapToInt(Order::qty).sum();
>     double revenue = valid.stream().mapToDouble(Order::amount).sum();
>     String best = valid.stream()
>         .collect(Collectors.groupingBy(Order::item, Collectors.summingInt(Order::qty)))
>         .entrySet().stream()
>         .max(Map.Entry.comparingByValue())
>         .map(Map.Entry::getKey)
>         .orElse("无销售");
>     return new Summary(cups, revenue, best);
> }
> 
> public static void main(String[] args) {
>     List<Order> orders = List.of(
>         new Order("美式", 2, 30.0), new Order("拿铁", 1, 18.0),
>         new Order("美式", 3, 45.0), new Order("拿铁", -1, -10.0) // 脏数据
>     );
>     Summary s = salesSummary(orders);
>     System.out.println(s.totalCups() + "杯  ¥" + s.totalRevenue()); // 6杯  ¥93.0
>     System.out.println("最火：" + s.bestSeller());                    // 最火：美式
>     // 边界：空列表
>     Summary empty = salesSummary(List.of());
>     System.out.println(empty.bestSeller());                          // 无销售
> }
> ```
> **举一反三**：`groupingBy` + `summingInt` 是统计分组总和的经典组合；`max(comparingByValue())` 找出最大值的键；`orElse` 优雅处理空集合。
