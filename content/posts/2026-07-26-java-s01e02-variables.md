- 看穿 `char` 的本质(无符号整数)与整型**溢出**;
- 踩一次「类型装错」的编译错误。

## 四、原理图:8 种基本类型

```text
整数   byte(1字节, -128~127)  short(2)  int(4, 最常用)  long(8, 后缀 L)
小数   float(4, 后缀 f)  double(8, 最常用)
字符   char(2字节, 单引号 '美')  ← 本质是 0~65535 的无符号整数
真假   boolean(true / false)
```

两条要刻进脑子的规律:

- **类型标签一旦贴上,盒子只能装对应的东西**,编译官在编译期就按标签检查;
- **每个整数盒子都有上限**。`int` 顶到 `2147483647`,再 `+1` 不会报错,而是**绕回**到最小值 `-2147483648` —— 这就是溢出。它不报错、结果却诡异,是最难查的一类坑。

## 五、代码:咖啡站的第一批变量

```java
public class Cafe {
    // 招呼语先照着写成 static 方法用 —— static 是什么、参数与返回值怎么设计,
    // 留到第 8 话《方法》正式拆解,这一话你只管调用。
    static String greeting() {
        return "豆豆咖啡站 · 营业中 ☕";
    }

    public static void main(String[] args) {
        String name = "美式";      // 名称(String 是引用类型,不算 8 种基本类型,后面细讲)
        double price = 15.0;        // 单价(元):有小数,必须 double
        int stock = 20;             // 库存(杯):整数用 int
        boolean open = true;        // 是否营业
        char grade = 'A';           // 豆子等级:一个字符,单引号

        System.out.println(greeting());
        System.out.println(name + " ¥" + price + " · 库存 " + stock
                + " · 等级 " + grade + " · 营业:" + open);
        // char 露出真身:'A' 其实是编号 65
        System.out.println("等级 A 的编号是 " + (int) grade);
    }
}
```

输出:

```text
豆豆咖啡站 · 营业中 ☕
美式 ¥15.0 · 库存 20 · 等级 A · 营业:true
等级 A 的编号是 65
```

`(int) grade` 把 `char` 强转成它背后的数字,`'A'` 现出原形就是 `65`。**字符只是整数的一层皮**,这层认知第十话讲字符串编码时会正式兑现。

## 七、读懂真实报错

```text
Cafe.java:12: error: incompatible types: possible lossy conversion from double to int
        int price = 15.0;
                    ^
1 error
```

`possible lossy conversion from double to int` —— 把 `double` 塞进 `int` 会**丢掉小数**(lossy = 有损失),编译官不允许这种静默损失,当场拦下。价格必须能带小数,盒子只能是 `double`。

> **豆豆锐评**:注意编译官拦的是**方向**,不是数值。`double d = 15;` 反过来能过 —— 整数升成小数不丢东西;`int i = 15.0;` 就被拦 —— 小数降成整数会丢。「从小盒子倒进大盒子自动,从大盒子倒进小盒子要你亲手签字(强转)」,这句能帮你记一辈子的类型转换方向。

## 八、修复,并用测试证明

改回 `double price = 15.0;`。把「美式单价」抽成方法,交给 JUnit 钉死:

```java
static double americanoPrice() {
    return 15.0;
}
```

```java
@Test
void americano_should_be_15() {
    assertEquals(15.0, Cafe.americanoPrice());
}
```

> **🎯 面试直击**:`int` 的最大值 `+1` 等于几?
> 等于**最小值** `-2147483648`(不是报错、也不是变大)。`int` 是 32 位有符号数,顶到 `2147483647` 再加 1 就溢出、从最高位绕回负数。追问防身:统计累加、订单金额分(× 100)这类会越滚越大的场景,该用 `long`(64 位);仍怕溢出就用 `Math.addExact(...)`,它会在溢出时直接抛异常,而不是悄悄给你算错账。

## 🎯 随堂练习

先自己做,再对答案。每道答案都带一句「举一反三」,帮你把这一个点连成一片。

### 选择题(10 道)

1. 在豆豆的比喻里,「声明一个变量」相当于?
   - A) 开一个什么都能装的万能格子　B) 开一个贴了类型标签、容量固定的格子　C) 给数据取个别名,不占地方　D) 在硬盘上建一个文件
2. `int price = 15.0;` 会发生什么?
   - A) 正常运行,price 是 15　B) 运行期抛异常　C) 编译期报 `possible lossy conversion from double to int`　D) 编译通过但 price 为 0
3. Java 里 `char` 的本质是?
   - A) 长度为 1 的字符串　B) 1 字节的 ASCII 码　C) 2 字节、0~65535 的无符号整数　D) 和 `int` 完全等价的 4 字节整数
4. `int max = 2147483647; max = max + 1;` 之后 `max` 是多少?
   - A) `2147483648`　B) `-2147483648`　C) `0`　D) 抛出异常
5. 下面哪一行**不能**通过编译?
   - A) `double d = 15;`　B) `long n = 100L;`　C) `float f = 1.5;`　D) `char c = 'A';`
6. `System.out.println((int) 'A');` 输出什么?
   - A) `A`　B) `65`　C) `0`　D) 编译错误
7. 关于 8 种基本类型,下列说法正确的是?
   - A) `String` 是其中之一　B) `boolean` 只装 `true` / `false`　C) `byte` 占 2 字节　D) `double` 占 4 字节
8. 「从小盒子倒进大盒子自动,从大盒子倒进小盒子要你亲手签字」说的是?
   - A) 变量作用域规则　B) 自动类型提升 vs 强制类型转换　C) 值传递 vs 引用传递　D) 装箱与拆箱
9. 累加营业额时担心数值越滚越大,最稳的做法是?
   - A) 继续用 `int`,每次判断结果是不是变负了　B) 用 `long`;仍怕溢出就用 `Math.addExact(...)`,溢出直接抛异常　C) 改用 `short` 省内存　D) 用 `boolean` 标记有没有超
10. 整型溢出最麻烦的地方在于?
    - A) 编译期就会报错,必须改代码　B) 一定抛异常让程序崩掉　C) 不报错也不崩,结果悄悄变错　D) 只是让程序变慢

> [!答案]
> **1-B**　类型标签决定「能装什么、占多大」,编译期就按标签检查。**举一反三**:这正是静态类型语言的核心红利 —— 装错在编译期被拦,而不是上线后炸给顾客看。
> **2-C**　`double` → `int` 会丢小数,编译官不接受静默损失。**举一反三**:报错关键词 `lossy conversion` 一出现,就去看是不是把「大盒子」往「小盒子」倒。
> **3-C**　`char` 骨子里是 0~65535 的无符号整数,字符只是它的马甲。**举一反三**:所以 `'A' + 1` 得到的是 `66`(int),字符编码那一话会再见到它。
> **4-B**　顶到最大值再 +1 会从顶上绕回最底,得 `-2147483648`。**举一反三**:笔试最爱考 `Integer.MAX_VALUE + 1`;真实场景是累加计数用 `int` 撑爆变负。
> **5-C**　`1.5` 是 `double` 字面量,给 `float` 必须写 `1.5f`。**举一反三**:同理整数字面量默认是 `int`,超过 21 亿要写 `L` 后缀,否则先溢出再赋值给 `long` 也救不回来。
> **6-B**　强转扒掉马甲,`'A'` 的真身是编号 `65`。**举一反三**:反过来 `(char) 65` 得到 `'A'`;大小写差 32 就是从这套编号来的。
> **7-B**　`String` 是引用类型不算基本类型;`byte` 1 字节、`double` 8 字节。**举一反三**:「8 种基本类型有哪些」是 Java 基础第一考点,记法:4 整数 + 2 小数 + 1 字符 + 1 真假。
> **8-B**　小→大自动提升,大→小必须强转(等于你签字认领精度损失)。**举一反三**:转换方向这一条能解释后面 90% 的类型报错。
> **9-B**　`long` 是 64 位;`Math.addExact` 在溢出时抛异常,而不是悄悄算错账。**举一反三**:凡是「钱、计数、时间戳」这类只增不减的量,默认就该用 `long`。
> **10-C**　溢出既不报错也不崩,只让结果诡异,是最难查的一类坑。**举一反三**:所有「不报错但结果错」的问题都只能靠测试和断言兜住,编译官帮不了你。
