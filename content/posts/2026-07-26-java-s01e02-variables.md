## 四、原理图:8 种基本类型

```text
整数   byte(1字节, -128~127)  short(2)  int(4, 最常用)  long(8, 后缀 L)
小数   float(4, 后缀 f)  double(8, 最常用)
字符   char(2字节, 单引号 '美')  ← 本质是 0~65535 的无符号整数
真假   boolean(true / false)
```

两条要刻进脑子的规律:

- **类型标签一旦贴上,盒子只能装对应的东西**,编译官在编译期就按标签检查;
- **每个整数盒子都有上限**。`int` 顶到 `2147483647`,再 `+1` 不会报错,而是**绕回**到最小值 `-2147483648` —— 这就是溢出。它不报错、结果却诡异,是最难查的一类坑。

## 五、代码:咖啡站的第一批变量

```java
public class Cafe {
    // 招呼语先照着写成 static 方法用 —— static 是什么、参数与返回值怎么设计,
    // 留到第 8 话《方法》正式拆解,这一话你只管调用。
    static String greeting() {
        return "豆豆咖啡站 · 营业中 ☕";
    }

    public static void main(String[] args) {
        String name = "美式";      // 名称(String 是引用类型,不算 8 种基本类型,后面细讲)
        double price = 15.0;        // 单价(元):有小数,必须 double
        int stock = 20;             // 库存(杯):整数用 int
        boolean open = true;        // 是否营业
        char grade = 'A';           // 豆子等级:一个字符,单引号

        System.out.println(greeting());
        System.out.println(name + " ¥" + price + " · 库存 " + stock
                + " · 等级 " + grade + " · 营业:" + open);
        // char 露出真身:'A' 其实是编号 65
        System.out.println("等级 A 的编号是 " + (int) grade);
    }
}
```

输出:

```text
豆豆咖啡站 · 营业中 ☕
美式 ¥15.0 · 库存 20 · 等级 A · 营业:true
等级 A 的编号是 65
```

`(int) grade` 把 `char` 强转成它背后的数字,`'A'` 现出原形就是 `65`。**字符只是整数的一层皮**,这层认知第十话讲字符串编码时会正式兑现。

## 七、读懂真实报错

```text
Cafe.java:12: error: incompatible types: possible lossy conversion from double to int
        int price = 15.0;
                    ^
1 error
```

`possible lossy conversion from double to int` —— 把 `double` 塞进 `int` 会**丢掉小数**(lossy = 有损失),编译官不允许这种静默损失,当场拦下。价格必须能带小数,盒子只能是 `double`。

> **豆豆锐评**:注意编译官拦的是**方向**,不是数值。`double d = 15;` 反过来能过 —— 整数升成小数不丢东西;`int i = 15.0;` 就被拦 —— 小数降成整数会丢。「从小盒子倒进大盒子自动,从大盒子倒进小盒子要你亲手签字(强转)」,这句能帮你记一辈子的类型转换方向。

> **🎯 面试直击**:`int` 的最大值 `+1` 等于几?
> 等于**最小值** `-2147483648`(不是报错、也不是变大)。`int` 是 32 位有符号数,顶到 `2147483647` 再加 1 就溢出、从最高位绕回负数。追问防身:统计累加、订单金额分(× 100)这类会越滚越大的场景,该用 `long`(64 位);仍怕溢出就用 `Math.addExact(...)`,它会在溢出时直接抛异常,而不是悄悄给你算错账。

## 🎯 随堂练习

先自己做，再对答案。选择1-3基础识记，4-6理解应用，7-9分析判断，10综合；解答递进；代码题从写到验证。

### 一、选择题（10 道）

1. [基础] 以下哪个**不是** Java 基本数据类型？
   - A) `int`　B) `String`　C) `double`　D) `boolean`

2. [基础] `byte` 类型的取值范围是？
   - A) 0 ~ 255　B) -128 ~ 127　C) -32768 ~ 32767　D) 0 ~ 65535

3. [基础] 以下哪个标识符命名是合法的？
   - A) `int 1st = 10;`　B) `int _count = 10;`　C) `int class = 10;`　D) `int my-var = 10;`

4. [理解] `char c = 'A'; int n = c;` 执行后 `n` 的值是？
   - A) 编译报错　B) 65　C) `'A'`　D) 0

5. [理解] `float f = 3.14;` 编译能过吗？
   - A) 能　B) 不能，因为 `3.14` 默认为 `double`　C) 能但精度丢失　D) 不能，应写成 `3.14d`

6. [应用] `double price = 0.1 + 0.2; System.out.println(price == 0.3);` 输出？
   - A) `true`　B) `false`　C) 编译报错　D) 运行时异常

7. [分析] `byte b = 100; b = b + 1;` 编译结果？
   - A) 通过，b = 101　B) 通过，b = -128　C) 编译失败：int 不能赋给 byte　D) 运行时异常

8. [分析] 以下代码有几处编译错误？`short s1 = 1; short s2 = 2; short s3 = s1 + s2;`
   - A) 0 处　B) 1 处　C) 2 处　D) 3 处

9. [判断] 关于 `char`，以下说法正确的是？
   - A) `char` 占 1 字节　B) `char` 可以存负数　C) `char` 的默认值是 `''`　D) `char` 可以参与算术运算，本质是数字

10. [综合] `byte a = 127; a++; System.out.println(a);` 输出？
    - A) 127　B) 128　C) -128　D) 编译报错

> [!答案]
> **1-B**：`String` 是引用类型，不是基本类型。Java 8 种基本类型：`byte`/`short`/`int`/`long`/`float`/`double`/`char`/`boolean`。
> **2-B**：`byte` 占 1 字节（8 位），有符号，范围 -128 ~ 127。无符号 0~255 是 C 语言的 `unsigned char`，Java 没有无符号基本类型。
> **3-B**：标识符只能以字母、下划线 `_`、美元符 `$` 开头，不能以数字开头（A 错），不能是关键字（C 错），不能含连字符（D 错）。
> **4-B**：`char` 本质是 Unicode 码点（数字），`'A'` 对应十进制的 65。`char` 可直接赋值给 `int`，反过来需要强制转型。
> **5-B**：Java 中带小数点的字面量默认为 `double`，`3.14` 是 64 位，不能直接赋给 32 位的 `float`。应加 `F` 后缀：`float f = 3.14F;`。
> **6-B**：`0.1 + 0.2` 在二进制浮点数中无法精确表示，结果为 `0.30000000000000004`，不等于 `0.3`。这是浮点精度问题的经典案例，金融计算应换 `BigDecimal`。
> **7-C**：`b + 1` 中 `b` 被自动提升为 `int`，结果为 `int` 类型，不能直接赋给 `byte`。需显式转型 `b = (byte)(b + 1);`。但 `b += 1;` 可以通过——复合赋值自带隐式强转。
> **8-B**：第 3 行 `s1 + s2` 两个 `short` 运算时都自动提升为 `int`，结果也是 `int`，赋给 `short` 类型的 `s3` 会编译失败。
> **9-D**：`char` 占 2 字节（A 错），是无符号的 0~65535（B 错），默认值是 `'\u0000'` 而非空字符串（C 错）。它本质是 unsigned 16-bit 整数，可以 `+` `-` 运算。
> **10-C**：`byte` 最大值 127，二进制 `0111_1111`。`++` 后变成 `1000_0000`，即十进制的 -128——这是**整型溢出**，从最大正数绕回最小负数。**举一反三**：所有整数类型都有溢出风险，`int` 也不例外——`Integer.MAX_VALUE + 1 == Integer.MIN_VALUE`。

### 二、解答题（3 道）

1. [概念阐述] 为什么说 `char` "本质是数字"？请举例说明 `char` 和 `int` 之间的联系与转换规则。

2. [场景解释] 为什么金额计算不推荐用 `float` 或 `double`？实际项目中应该用什么替代？请结合 0.1 + 0.2 的例子说明。

3. [综合分析] Java 的 8 种基本类型中，哪些可以直接参与算术运算？`byte`、`short`、`char` 在运算时有什么特殊性？请系统总结自动类型提升的规则。

> [!答案]
> **1**　`char` 在 Java 内部存储为 16 位无符号整数（Unicode 码点），每个字符对应一个整数编号。`char c = 'A'; int n = c;` 是合法的隐式转换，`n` 得到 65。`int` 转 `char` 则需要显式转型：`char c = (char) 65;`。`char` 可以直接参与算术表达式：`'B' - 'A'` 结果为 1，数字字符 `'5' - '0'` 得到整数 5。**举一反三**：Java 中 `char` 的算术能力是很多字符处理算法（如进制的字符转数字）的基础，但要注意 `char` 只能表示 0~65535，超出 BMP 平面的 emoji 需要用两个 `char`（代理对）表示。
> **2**　因为浮点数以二进制形式存储，十进制小数 0.1 和 0.2 在二进制中是无限循环小数，存储时被截断，导致 `0.1 + 0.2` 结果为 `0.30000000000000004` 而非精确的 `0.3`。实际项目推荐两种方案：①使用 `BigDecimal`（适合任意精度的金融计算）；②将金额转为最小单位整数，如"分"用 `long` 存（适合性能敏感场景）。**举一反三**：不仅是加法，浮点除法、乘法同样有精度问题，`==` 比较浮点数永远是不安全的做法。
> **3**　8 种基本类型中，除 `boolean` 外其余 7 种都可以参与算术运算。特殊性在于 `byte`/`short`/`char` 三者：只要出现在算术表达式中，就会先自动提升为 `int`（哪怕两个 `byte` 相加也要先各自提成 `int`）。完整的自动提升链：`byte/short/char → int → long → float → double`。运算时以操作数中"最宽"的类型为结果类型。例如 `int + double` → `double`。`long + float` → `float`（虽然 long 64 位，但 float 在提升链中更靠后）。**举一反三**：这是理解"为什么 `byte b = 1; b = b + 1;` 编译失败而 `b += 1;` 成功"的关键——后者是复合赋值运算符，自带隐式强转，相当于 `b = (byte)(b + 1)`。

### 三、代码题（2 道）

1. [基础实现] 声明 8 种基本类型的变量各一个并赋上合理值（注意 `long` 需 `L` 后缀、`float` 需 `F` 后缀），然后逐行打印 "类型名: 值"，最后验证 `char` 和 `int` 的转换关系——打印 `'A' + 1` 的结果。

2. [综合设计] 写一个整型溢出观察程序：从 `int` 最大值往回数 3 步开始，每次 +1，循环 5 次，打印每轮的值。然后用 `byte` 做同样实验：从 125 开始每次 +1，循环 5 次，观察溢出现象。最后用 `long` 做一次对比——从 `Long.MAX_VALUE` 加 1 看结果。

> [!答案]
> **1 验收**：
> ```java
> byte b = 100;
> short s = 10000;
> int i = 1000000;
> long l = 10000000000L;
> float f = 3.14F;
> double d = 3.1415926535;
> char c = 'A';
> boolean flag = true;
>
> System.out.println("byte: " + b);
> System.out.println("short: " + s);
> System.out.println("int: " + i);
> System.out.println("long: " + l);
> System.out.println("float: " + f);
> System.out.println("double: " + d);
> System.out.println("char: " + c);
> System.out.println("boolean: " + flag);
>
> // char 本质是数字
> System.out.println("'A' + 1 = " + ('A' + 1)); // 输出 66，即 'B' 的码点
> System.out.println("(char)('A' + 1) = " + (char)('A' + 1)); // 输出 B
> ```
> 运行验证：所有变量正确打印，`'A' + 1` 输出 66。**举一反三**：`'A' + 1` 不加 `(char)` 转型时结果是 `int` 66——因为 `char` 参与运算自动提升为 `int`。
>
> **2 验收**：
> ```java
> // int 溢出演示
> int n = Integer.MAX_VALUE - 2; // 2147483645
> for (int i = 0; i < 5; i++) {
>     System.out.println(n);
>     n++;
> }
> // 输出: 2147483645, 2147483646, 2147483647, -2147483648, -2147483647
> // 注意第 4 行从正数最大值跳到了负数最小值！
>
> System.out.println("---");
>
> // byte 溢出演示
> byte x = 125;
> for (int i = 0; i < 5; i++) {
>     System.out.println(x);
>     x++;
> }
> // 输出: 125, 126, 127, -128, -127
> // byte 同样溢出，只是范围更小
>
> System.out.println("---");
>
> // long 溢出演示
> long big = Long.MAX_VALUE;
> System.out.println("Long.MAX_VALUE = " + big);
> System.out.println("Long.MAX_VALUE + 1 = " + (big + 1));
> // 输出负数，long 同样会溢出——只是范围大到日常很难碰到
> ```
> 运行验证：int 溢出发生在 2147483647 → -2147483648；byte 溢出发生在 127 → -128；long 溢出同样原理。**举一反三**：`Math.addExact(a, b)` 可以在溢出时抛异常而非静默翻转为负数，关键场景应该使用它兜底。
