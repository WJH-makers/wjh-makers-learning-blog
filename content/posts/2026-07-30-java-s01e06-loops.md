## 三、本话目标

- 用 `for` 做固定次数的重复;
- 用 `while` / `do-while` 做「直到某条件」的重复;
- 理解 `break`(跳出)/ `continue`(跳过本轮);
- 踩一次「忘记更新条件」的死循环。

---

## 四、原理图

```text
for (int i = 0; i < n; i++) { ... }   次数已知:起点 i=0、条件 i<n、每轮 i++
while (条件) { ... }                   次数未知,先判断再执行(可能一次都不执行)
do { ... } while (条件);               至少执行一次,再判断
```

死循环根因:**循环体里没有任何一句让「条件」逐步趋向 `false`**。`for` 把「起点/条件/步进」三样并排写在括号里,最不容易漏;`while` 的步进散落在循环体内,最容易忘 —— 阿零翻的正是这个车。

## 五、代码:做 5 杯 + 卖到库存为止

```java
public class Cafe {
    public static void main(String[] args) {
        // for:固定做 5 杯
        for (int i = 1; i <= 5; i++) {
            System.out.println("第 " + i + " 杯美式 ☕");
        }

        // while:一直卖,直到库存为 0
        int stock = 3;
        while (stock > 0) {
            System.out.println("售出一杯,剩余 " + (stock - 1));
            stock--;                 // ← 关键:让条件趋向结束
        }
    }
}
```

> **豆豆旁白**:其实还有第四种循环 —— `for-each`(`for (T x : 一排东西)`),专门「逐个取出、不管下标」。但它得**先有一排东西**可遍历,下一话数组登场后你会天天用它。先记住一句:for-each 底层是把活儿交给一个叫**迭代器(Iterator)**的角色,一个一个递给你 —— 第二季讲集合时,会有个叫 **CME** 的幽灵,专挑你「一边 for-each 一边改集合」的时候现身。这句先埋着,到时你会想起来。

`break` 和 `continue` 是循环里的两个开关:`break` 是「够了,整个循环立刻退出」,`continue` 是「这一杯跳过,直接做下一杯」。

```java
for (int i = 1; i <= 10; i++) {
    if (i == 4) continue;      // 第 4 位顾客临时走了 —— 跳过这一轮,不出杯
    if (i == 8) break;         // 豆子用完了 —— 整条传送带立即停机
    System.out.println("第 " + i + " 杯出杯 ☕");
}
```

上面这段会做 1、2、3、5、6、7 杯:`continue` 只跳过第 4 轮、循环照转;`break` 到第 8 轮直接掀桌走人,后面的 9、10 根本不做。

## 六、故意制造一个 Bug

把 `stock--` 删掉:

```java
while (stock > 0) {
    System.out.println("售出一杯,剩余 " + stock);
    // stock--;   ← 故意删掉
}
```

## 七、读懂现象(死循环)

终端疯狂刷屏「售出一杯,剩余 3」永不停止,得手动 `Ctrl+C` 才能停。`stock` 永远是 3,`stock > 0` 永远为 `true` —— 这就是**死循环**:忘了让条件靠近终点。它不报错、不崩溃,只会把一个 CPU 核**吃满到 100%**,在真实服务器上就是一次线上事故。

---

## 八、修复,并用测试证明

补回 `stock--`。把「按库存能卖多少杯」抽成方法:

```java
static int cupsSold(int stock) {
    int sold = 0;
    while (stock > 0) { sold++; stock--; }
    return sold;
}
```

```java
@Test
void sells_exactly_stock() {
    assertEquals(3, Cafe.cupsSold(3));
    assertEquals(0, Cafe.cupsSold(0));   // 库存 0:while 一次都不进,直接返回 0
}
```

> **🎯 面试直击**:线上某台机器 CPU 突然飙到 100%,怎么定位?
> 经典四步:① `top` 找到吃满 CPU 的 Java 进程 PID;② `top -Hp <pid>` 找到最忙的**线程** ID;③ 把线程 ID 转成十六进制,在 `jstack <pid>` 输出里搜它的栈;④ 栈顶往往就卡在某个**死循环 / 空转**的方法上。追问防身:死循环、正则回溯、频繁 Full GC 都能打满 CPU —— 本话的空转 `while` 就是最朴素的一种。(`jstack` 到第五季会带你亲手用。)

### 一、选择题（10 道）

1. [基础] `for(int i = 0; i < 3; i++) { ... }` 循环体执行了几次？
   - A) 2　B) 3　C) 4　D) 无限

2. [基础] `while` 和 `do-while` 的核心区别是？
   - A) 没有区别　B) `do-while` 至少执行一次循环体　C) `while` 更快　D) `do-while` 不需要条件

3. [基础] `break` 在循环中的作用是？
   - A) 跳过本次迭代的剩余代码　B) 终止整个循环　C) 回到循环开头　D) 暂停循环

4. [理解] 以下 `for` 循环的错误是什么？`for(int i = 0; i < 10; i--) { ... }`
   - A) 语法错误　B) 死循环　C) 一次也不执行　D) 逻辑错误导致无限循环

5. [理解] `for( ; ; )` 是什么含义？
   - A) 编译报错　B) 无限循环　C) 一次也不执行　D) 执行一次

6. [应用] 以下代码输出什么？`for(int i = 0; i < 5; i++) { if(i == 3) continue; System.out.print(i); }`
   - A) `0124`　B) `01234`　C) `012`　D) `0123`

7. [分析] 以下代码输出什么？`int i = 0; while(i < 3) { i++; } System.out.println(i);`
   - A) 3　B) 2　C) 0　D) 编译报错

8. [分析] 以下代码的问题是？`int sum = 0; for(int i = 1; i <= 10; i++) sum = i; System.out.println(sum);`
   - A) 语法错误　B) 逻辑错误：`=` 应为 `+=`　C) 死循环　D) 没有问题

9. [判断] 以下哪个场景**不适合**使用 `for-each`（增强 for 循环）？
   - A) 遍历数组的所有元素　B) 累加数组中的数值　C) 在遍历过程中修改数组元素的值　D) 查找数组中是否存在某个元素

10. [综合] 三个循环结构执行后 `sum` 的值分别是？①`int sum=0; for(int i=1; i<=3; i++) sum+=i;`　②`int sum=0; int i=1; while(i<=3) sum+=i++;`　③`int sum=0; int i=1; do sum+=i; while(++i<=3);`
    - A) 6, 6, 6　B) 6, 6, 10　C) 3, 6, 10　D) 6, 10, 10

> [!答案]
> **1-B**：`i` 取值 0,1,2 时 `i<3` 成立，循环体执行 3 次；`i` 变 3 时条件不成立，退出。**举一反三**：条件写成 `i <= 3` 则执行 4 次（0,1,2,3）。
> **2-B**：`while` 先判断后执行，条件不成立一次也不执行；`do-while` 先执行一次再判断，保证循环体至少执行一次。**举一反三**：`do-while` 适合"先展示再询问"的交互场景——如先显示菜单，再问用户是继续还是退出。
> **3-B**：`break` 完全终止循环，跳出到循环体之后的第一条语句。`continue` 才是跳过本次迭代的剩余代码（A 描述的）。**举一反三**：多层嵌套循环中，`break` 只跳出最内层循环；带标签的 `break label;` 可以跳出指定外层。
> **4-D**：`i--` 让 i 不断减小，条件 `i < 10` 永远成立，形成无限循环（死循环）。正确写法应该是 `i++`。**举一反三**：任何循环在写步进表达式时都要确保"向终止条件靠近"——如果越走越远，就是死循环。
> **5-B**：三个表达式全部省略的 `for(;;)` 等价于 `while(true)`——条件永远为真，无限循环。**举一反三**：`for(;;)` 比 `while(true)` 更老派但两者等价；现代 Java 用 `while(true)` 更直观。
> **6-A**：i=0,1,2,4 时打印，i=3 时 `continue` 跳过 `print`。最终输出 `0124`。**举一反三**：`continue` 只跳过本轮循环剩余代码，循环计数器照样步进——不要和"终止循环"混淆。
> **7-A**：循环 3 次后 `i=3`，条件 `i<3` 不成立退出循环，打印 3。注意 `i++` 在 while 体内，和 for 循环不同。**举一反三**：`while(i++ < 3)` 则最终 i=4——因为条件判断时 i 的值和循环后的值差 1。
> **8-B**：期望累加 1 到 10 得到 55，但 `sum = i` 是覆盖赋值而非累加，最终 `sum = 10`（最后一次循环的值）。改为 `sum += i` 才行。这是典型的**逻辑 Bug**——编译器不会报错，运行也不崩溃，但结果完全错误。**举一反三**：发现累加结果不对时，打印每次循环的变量值是最快的定位手段。
> **9-C**：`for-each`（`for(int x : arr)`）遍历的是数组**副本**，修改 `x` 不会改变原数组元素。需要修改原数组元素时必须用传统 `for` + 索引。**举一反三**：对于对象数组，`for-each` 可以修改对象的内容（如 `obj.field = 5`）但无法改变数组元素本身指向哪个对象。
> **10-A**：三个循环结构都累加 1+2+3=6。关键解析：②中 `sum += i++` 先加 i 再自增，循环为 i=1→sum+1→i=2, i=2→sum+2→i=3, i=3→sum+3→i=4 退出；③中 `do-while` 先加 i=1，再 `++i` 使 i 变 2，判断 ≤3 继续，最终 sum=1+2+3=6。**举一反三**：`i++` vs `++i` 在循环条件中的执行时机不同，仔细追踪每轮变量的变化。

### 二、解答题（3 道）

1. [概念阐述] `break` 和 `continue` 的区别是什么？如果循环嵌套了两层，内部的 `break` 会跳出几层？如何跳出外层循环？

2. [场景解释] 咖啡机系统需要循环运行：显示菜单 → 用户输入编号 → 计算价格 → 问"是否继续(y/n)"。请说明为什么用 `do-while` 比 `while` 更合适，并画出循环的执行流程图（文字描述即可）。

3. [综合分析] 死循环有哪些常见成因？如何在开发中预防？如果程序已经进入死循环，运行时如何终止它？请至少列出 3 种常见死循环模式并给出预防建议。

> [!答案]
> **1**　`break`：完全终止当前循环，跳到循环体后的第一条语句。`continue`：跳过本轮循环的剩余代码，直接进入下一轮的条件判断。内层 `break` 只跳出最内层循环，外层照常执行。跳出外层需用标签：`outer: for(...) { for(...) { break outer; } }`——`outer:` 是标签，`break outer` 直接跳出标有该标签的循环。**举一反三**：标签循环虽然可行但影响可读性，更多时候用方法提取 + `return` 替代——更清晰。
> **2**　`do-while` 适合的场景是"至少执行一次再询问"——用户打开咖啡机程序，应当先看到菜单，然后决定点什么、是否继续。用 `while` 的话需要在循环外额外写一次"显示菜单"的代码才能保证首次可见，造成重复。`do-while` 的流程：显示菜单 → 读取选择 → 计算 → 询问是否继续 → 判断条件 → 回到第一步或退出，天然匹配交互式控制台程序。**举一反三**：几乎所有"菜单驱动"的控制台程序都推荐 `do-while` 作为主循环。
> **3**　三大死循环模式：①**步进方向错误**——`for(int i=0; i<10; i--)`，i 不断减小，条件永远成立；预防：检查步进是否让变量向终止条件靠近。②**忘记更新循环变量**——`while(flag) { ... }` 但循环体内没改 flag；预防：用 for 代替 while 强制显式步进。③**条件永远为真**——`while(true)` 但忘记在合适的条件下 break；预防：确保每个 infinite loop 有明确的退出路径。运行时终止：IDE 中按停止按钮（红色方块），命令行按 `Ctrl+C`。**举一反三**：开发时加循环次数计数器作为安全阀——如果循环超过预期次数就抛异常退出，这是嵌入式开发中的 watchdog 思想。

### 三、代码题（2 道）

1. [基础实现] 用 `for` 循环实现："打印 1 到 10 的累加过程"。格式：`1 + 2 + 3 + ... + 10 = 55`。要求：①用 `for` 循环累加；②输出累加算式（注意最后一个数后不加 `+`）；③用 `while` 循环重新实现一次，对比代码结构。

2. [综合设计] 写一个"九九乘法表"打印程序：用双层 `for` 循环打印标准的小九九表（1×1=1 到 9×9=81），要求①左对齐、每列等宽；②不打印重复项（即只打印 i≤j 的下三角）；③在内层循环中加入条件判断：如果乘积是两位数（≥10）则用红色提示词 `[大]` 标记——帮助我们观察乘积何时突破个位数。

> [!答案]
> **1 验收**：
> ```java
> // for 循环版
> int sum = 0;
> StringBuilder sb = new StringBuilder();
> for (int i = 1; i <= 10; i++) {
>     sum += i;
>     sb.append(i);
>     if (i < 10) sb.append(" + ");
> }
> System.out.println(sb.toString() + " = " + sum);
> // 输出: 1 + 2 + 3 + ... + 10 = 55
>
> // while 循环版（对照）
> int sum2 = 0, i2 = 1;
> StringBuilder sb2 = new StringBuilder();
> while (i2 <= 10) {
>     sum2 += i2;
>     sb2.append(i2);
>     if (i2 < 10) sb2.append(" + ");
>     i2++;
> }
> System.out.println(sb2.toString() + " = " + sum2);
> // 对比：while 版循环变量初始化和步进分散在循环外/尾，不如 for 版紧凑
> ```
> **举一反三**：已知次数的循环用 for 更清晰，while 适合"不知道要跑几次"的条件循环。
>
> **2 验收**：
> ```java
> for (int i = 1; i <= 9; i++) {
>     for (int j = 1; j <= i; j++) {
>         int result = i * j;
>         System.out.printf("%d×%d=%-3d ", j, i, result);
>         if (result >= 10) System.out.print("[大]");
>     }
>     System.out.println();
> }
> /* 输出示例（前 3 行）：
> 1×1=1
> 1×2=2   2×2=4
> 1×3=3   2×3=6   3×3=9
> ... 到第 9 行
> 观察：[大]标记首次出现在 2×5=10（i=5, j=2），即乘积≥10 时
> */
> ```
> 运行验证：下三角正确，`%-3d` 使输出等宽对齐；`[大]` 标记精准出现在乘积≥10 的位置。**举一反三**：双层循环中，外循环控制"行"（i=1到9代表被乘数/行号），内循环控制"列"（j=1到i），条件 `j<=i` 实现下三角不重复打印——这是矩阵类输出的经典模式。
