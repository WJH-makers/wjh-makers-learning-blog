## 一、事故:长龙,与冒烟的 VIP

周末上午十点,取餐口的队伍拐了三个弯。阿零的初版"排队"是 `ArrayList<Ticket>`:叫一号就 `remove(0)`,后面所有人集体前挪一步——队伍越长,挪得越久。更麻烦的是充了 888 的年卡 VIP 站在队尾质问:"我凭什么和白嫖党一个队?"

阿零(早已不是当年的小白):"排队该用 `Queue` 我知道,先进先出。但 VIP 优先怎么才算**合法**?总不能 `add(0, vip)` 硬塞队头吧——那叫插队,不叫优先级。"

豆豆:"今天把 Queue 全家请出来:窗口排队的、两头开口的、按优先级叫号的。顺便,送走一位不该再上岗的老同志。"

## 二、漫画 · 排队窗口与锦标赛塔

> **〔1〕** 取餐长龙做"广播体操":`ArrayList` 每叫一号,全队向前挪一步,队尾 VIP 头顶冒烟。
> 豆豆(叼着豆子叉腰):「`remove(0)` 挪整队,这不叫排队,这叫全员搬家。排队要的是**两头干活,中间不动**。」

> **〔2〕** 豆豆支起「叫号窗口」:队尾入口写着 `offer`,队头出口写着 `poll`,窗口顶上一支潜望镜写着 `peek`(只看不取)。旁边另立三个红色按钮 `add / remove / element`,贴着封条:「空队按下即爆」。
> 豆豆:「同一件事两套方法——**温柔派**空了给 `null` 或 `false`,**暴躁派**空了直接抛异常。选一派,别混用。」

> **〔3〕** 【环形跑道格】`ArrayDeque` 是首尾相接的圆环跑道,`head` 与 `tail` 两面小旗在环上追着跑,元素从不挪窝。跑道边,拄拐的「Stack 老爷子」举牌:"栈,祖传手艺"——浑身挂满铁锁。
> 豆豆:「他继承自 Vector,每个方法都背一把锁,单线程也照付锁费。栈的活儿,如今也归 ArrayDeque。」

> **〔4〕** VIP 需求上桌,豆豆搬出一座「锦标赛塔」:完全二叉树,每个座位只和自己的两个下家比,赢者坐上面,塔顶宝座金光闪闪。
> 豆豆:「`PriorityQueue`,二叉小顶堆。它只承诺一件事:**塔顶永远是当前最该叫的号**。塔中间坐得乱七八糟,它根本不管。」

> **〔5〕** 阿零把整座塔按座位号抄上大屏:「即将叫号:VIP-3、VIP-4、普通-1、普通-2、VIP-5」。VIP-5 号拍桌而起,大屏角落里 Logic Bug 怪比了个耶。
> 阿零:「堆……堆坏了?我明明传了比较器!」

> **〔6〕** 豆豆一把拔掉大屏电源;JUnit 质检员从柜台后探头:「证据呢?」
> 豆豆:「堆没坏,是你把『塔顶最小』脑补成了『全塔有序』。要顺序,就一个一个 `poll`——别的都是幻觉。第八节上证据。」

## 三、本话目标

- 分清 Queue 两派 API:`offer/poll/peek`(特殊值)vs `add/remove/element`(异常);
- 用 ArrayDeque 当队列,讲清环形数组为什么两头都是 O(1);
- 说明白老 Stack 为什么弃用,栈一律换 ArrayDeque;
- 用 PriorityQueue + 比较器让 VIP 合法优先,吃透二叉堆与「迭代 ≠ 优先级」;
- 记住 BlockingQueue 的名字,给番外卷二占座。

## 四、原理图:Queue 家族地图

```text
Queue(排队窗口,先进先出)
 ├─ ArrayDeque      环形数组双端队列:head/tail 两个指针绕圈追,
 │                  两头进出都 O(1),从不整体搬家;既当队列又当栈
 ├─ LinkedList      双向链表,也实现 Deque:能装 null,
 │                  但节点散落堆里,缓存不友好
 ├─ PriorityQueue   二叉小顶堆:出队按优先级,不按先来后到
 └─ BlockingQueue   阻塞派接口:队空取会等、队满放会等,
                    线程之间递订单的传送带 —— 番外卷二《并发深水区》再拆
```

两派 API,一张表记死:

| 动作 | 暴躁派(空了就抛) | 温柔派(空了给信号) |
|---|---|---|
| 入队 | `add(e)`(有界队满 → IllegalStateException) | `offer(e)`(队满 → 返回 false) |
| 出队 | `remove()`(空 → NoSuchElementException) | `poll()`(空 → 返回 null) |
| 看队头 | `element()`(空 → NoSuchElementException) | `peek()`(空 → 返回 null) |

堆的座位表也只有一条规矩:数组下标 `i` 的父座在 `(i-1)/2`,两个子座在 `2i+1`、`2i+2`,**只保证父 ≤ 子**——兄弟之间、隔房亲戚之间,谁也不让谁。

> **豆豆锐评**:ArrayDeque **禁止装 null**——因为 `null` 是温柔派的"空队"信号,装进去你就分不清"队空了"还是"取到个 null"。业务代码默认温柔派 + 判空;想空队就炸、炸了好排查,再选暴躁派。

## 五、代码:叫号系统 v1 → VIP 版

先来后到版,ArrayDeque 上岗:

```java
import java.util.ArrayDeque;
import java.util.Queue;

record Ticket(int no, boolean vip) {
    @Override
    public String toString() { return (vip ? "VIP-" : "普通-") + no + "号"; }
}

public class CallSystem {
    public static void main(String[] args) {
        Queue<Ticket> queue = new ArrayDeque<>();
        queue.offer(new Ticket(1, false));
        queue.offer(new Ticket(2, false));

        System.out.println("下一位:" + queue.peek());   // 只看不取
        System.out.println("叫号:" + queue.poll());
        System.out.println("叫号:" + queue.poll());
        System.out.println("空队再看:" + queue.peek());  // 温柔派:null
    }
}
```

```text
下一位:普通-1号
叫号:普通-1号
叫号:普通-2号
空队再看:null
```

好奇按一下暴躁派按钮 `queue.element()`,当场兑现封条上的承诺:

```text
Exception in thread "main" java.util.NoSuchElementException
	at java.base/java.util.ArrayDeque.getFirst(ArrayDeque.java:400)
	at java.base/java.util.ArrayDeque.element(ArrayDeque.java:549)
	at CallSystem.main(CallSystem.java:19)
```

VIP 版:换 PriorityQueue,配一个比较器(告诉容器"谁排前面"的小裁判——今天先够用,细节下一话展开):

```java
static final Comparator<Ticket> CALL_ORDER = Comparator
        .comparing((Ticket t) -> !t.vip())     // VIP 在前(false 排 true 前)
        .thenComparingInt(Ticket::no);         // 同级按号码

Queue<Ticket> queue = new PriorityQueue<>(CALL_ORDER);
// 到店顺序:1普、2普、3V、4V、5V
```

> **🔀 豆豆的多解台 · 栈,到底用什么?**

| 解法 | 代码要点 | 适合什么时候 | 坑 |
|---|---|---|---|
| Stack(弃用) | `new Stack<>()`,push/pop | 只出现在老代码和老教材里 | 继承 Vector,**全方法加锁**,单线程也付锁费;迭代方向从栈底到栈顶,**和出栈顺序正好相反**,倒序反直觉 |
| ArrayDeque(推荐) | `Deque<T> s = new ArrayDeque<>();` `s.push(x); s.pop();` | 单线程下队列、栈的**默认选择** | 不许装 null(见上文锐评) |
| LinkedList | 也实现 Deque,push/pop 同款 | 确实要装 null,或同一容器还要中间插删 | 每个元素一个节点对象,内存散、缓存不友好 |

豆豆锐评:**默认 ArrayDeque**,没有之一——环形数组两头 O(1)、无锁费、内存紧凑;Stack 留在博物馆,LinkedList 只在你真需要 null 或中间操作时出场。

## 七、观察真实现象

```text
=== 大屏 · 即将叫号 ===
VIP-3号
VIP-4号
普通-1号
普通-2号
VIP-5号
```

VIP-5 号被排到两位普通顾客后面!堆真坏了?没有——按到店顺序 offer 完,堆的底层数组恰好是 `[VIP-3, VIP-4, 普通-1, 普通-2, VIP-5]`:每次 `offer` 只把新号从座位往上"顶"到父 ≤ 子成立为止(siftUp),VIP-5 的父座 VIP-4 比它小,它就地坐下——坐在了普通顾客后面的下标 4。**迭代器按数组下标 0、1、2、3、4 扫**,把堆的内部座次当成了叫号顺序。此刻 `poll` 五次的真实顺序其实完全正确:VIP-3、VIP-4、VIP-5、普通-1、普通-2。

> **🎯 面试直击**:PriorityQueue 底层什么结构?为什么迭代是无序的?
> 数组实现的完全二叉树(二叉小顶堆),不是红黑树(那是 HashMap 树化的事,回看第 22 话)。堆只维护"父 ≤ 子"这一条**局部**约束,兄弟与跨子树之间无序;迭代器按底层数组下标顺扫,自然乱。追问点:`peek` O(1),`offer/poll` O(log n);想按优先级输出只能连续 `poll`,n 个元素共 O(n log n)——这正是堆排序。

## 八、修复,并用测试证明

要顺序,就复制一座堆,连续 `poll` 到空——预览大屏,绝不动真队列(偷懒等价写法:`queue.stream().sorted(CALL_ORDER).toList()`):

```java
static List<Ticket> board(Queue<Ticket> queue) {
    var copy = new PriorityQueue<>(queue);   // 复制堆(连比较器一起带走)
    var view = new ArrayList<Ticket>();
    while (!copy.isEmpty()) view.add(copy.poll());
    return List.copyOf(view);
}
```

JUnit 质检员收证据:

```java
import org.junit.jupiter.api.Test;
import java.util.List;
import java.util.PriorityQueue;
import static org.junit.jupiter.api.Assertions.assertEquals;

class CallSystemTest {
    @Test
    void board_shows_poll_order_and_keeps_queue_intact() {
        var queue = new PriorityQueue<>(CallSystem.CALL_ORDER);
        for (int no = 1; no <= 5; no++) queue.offer(new Ticket(no, no >= 3)); // 3~5 号是 VIP

        assertEquals(List.of(
                new Ticket(3, true), new Ticket(4, true), new Ticket(5, true),
                new Ticket(1, false), new Ticket(2, false)),
            CallSystem.board(queue));           // 大屏 = 真实叫号顺序
        assertEquals(5, queue.size());          // 预览完,真队列一人未少
    }
}
```

绿灯。大屏重新通电:VIP-3、VIP-4、VIP-5、普通-1、普通-2——VIP-5 号坐回了他该在的位置。

9. PriorityQueue 的 offer 和 poll 的时间复杂度是?
   - A) offer O(1), poll O(1)　B) offer O(log n), poll O(log n)　C) offer O(n)　D) poll O(n²)
10. BlockingQueue(预告)和普通 Queue 的根本区别是?
    - A) 速度　B) 队空取会等,队满放会等(支持生产者-消费者线程间传递)　C) 不支持 offer　D) 空队取返回 0

> [!答案]
> **1-B**　offer/poll/peek 温柔派(空/满给 null 或 false),add/remove/element 暴躁派(空/满抛异常)。**举一反三**:温柔派默认——写了判空就能安全用;暴躁派适合「空就应该炸,炸了才好查」的场景。
> **2-B**　`poll()` 空队返回 null,如果你之前 offer 了一个 null,就分不清是真空队还是取到了 null 元素。**举一反三**:HashMap 允许 null key/value,Hashtable 和 ConcurrentHashMap 不允许——每种容器的 null 策略各有理由,选型时要一并考虑。
> **3-B**　`Deque<T> stack = new ArrayDeque<>()`;`push` 就是 `addFirst`,`pop` 就是 `removeFirst`。**举一反三**:用统一接口 Deque,以后要换 LinkedList 只要改 new——而 Stack 类不能向上转型成 Deque,因为它继承 Vector 走的是另一条路。
> **4-B**　Stack extends Vector,Vector 每个方法都是 synchronized——即使单线程也照付锁费;迭代方向从栈底到栈顶(和出栈顺序反了)反直觉。**举一反三**:Vector/Stack/Hashtable 是 JDK 1.0 的遗留,现代替代品是 ArrayList/ArrayDeque/HashMap;面试问「Stack 为什么不用」的时候,务必提 `synchronized` 的锁费问题。
> **5-C**　PriorityQueue 底层是数组存储的完全二叉树(二叉小顶堆),父子下标关系:父 `(i-1)/2`,左子 `2i+1`,右子 `2i+2`。**举一反三**:堆不是红黑树——红黑树全树有序(中序遍历即有序),堆只保证「父 ≤ 子」。TreeSet 用红黑树,PriorityQueue 用二叉堆。
> **6-C**　迭代器按数组下标 0→size 顺序扫描——底层数组只是「满足父 ≤ 子」的局部约束,相邻下标之间没有任何排序关系。**举一反三**:`PriorityQueue.toString()` 输出的顺序也具有欺骗性——那是数组顺序,不是优先级顺序;面试官拿这一点考你是否真懂堆。
> **7-B**　连续 poll 是最直接的方式:每次 O(log n),n 个元素 O(n log n),正好是堆排序。**举一反三**:也可以用 `stream().sorted(comparator)` 复制后再排,但那是 O(n log n) 的排序,不依赖 PriorityQueue 了,只是当成容器用了。
> **8-B**　peek 窥看队头不删除,poll 取走队头并删除。**举一反三**:在 ArrayDeque 空队上做 poll→null,peek→null;但 element→抛 NoSuchElementException;remove→同抛。写测试时故意对空队调 element 可验证暴躁派的爆炸行为。
> **9-B**　offer:元素放堆底后 siftUp 上浮 O(log n);poll:把堆底搬到堆顶后 siftDown 下沉 O(log n)。peek 直接取数组 [0] → O(1)。**举一反三**:面试追问 siftUp/siftDown 的细节——只需要答「比较父/子然后交换位置重新维持堆序」,不用背代码。
> **10-B**　BlockingQueue 专为线程间通信设计:生产者线程 offer 到有界队满时阻塞等待消费者腾位,消费者 poll 到空队时阻塞等待生产者放入。**举一反三**:线程池的 workQueue 就是 BlockingQueue——生产者提交任务,消费者(线程)取任务,这是番外卷二的核心概念。

5. 咖啡站叫号系统:VIP 和普通顾客混排,PriorityQueue + Comparator 把 VIP 排前面,同级按到店时间。写出 Comparator 实现。

> [!答案]
> **1**　| 操作 | 温柔派 | 暴躁派 | 说明 ||---|---|---|---|| 入队 | offer(e)→false | add(e)→抛异常 | offer 更安全,有界队满不炸 || 出队 | poll()→null | remove()→抛异常 | poll 配合判空 || 看队头 | peek()→null | element()→抛异常 | peek 最常用 |　**举一反三**:温柔派日常用,暴躁派只在你硬断言「此时队不可能空/满」 时用于快速暴露逻辑 bug。
> **2**　Stack 继承 Vector 全方法加锁;迭代方向反直觉(从栈底到栈顶);接口不干净(push/pop 混在 List 里)。ArrayDeque 无锁、接口统一走 Deque(push/pop 即 addFirst/removeFirst)、环形数组 O(1)。**举一反三**:用 `Deque<T> s = new ArrayDeque<>()` 声明——接口是 Deque,以后换实现只改 new 后面的类名;声明 Stack 就一辈子绑在那条继承链上了。
> **3**　插入序列:5, 2, 8, 1, 9, 3。→ 每一步 siftUp:5 → 2,5 → 2,5,8 → 1,2,8,5 → 1,2,8,5,9 → 1,2,3,5,9,8。数组表示:`[1, 2, 3, 5, 9, 8]`。**举一反三**:即便数组中 3 在 2 前面,这不代表堆坏了——只保证父 ≤ 子,兄弟之间排序不关心;手推一遍堆操作比看十遍定义管用。
> **4**　堆的 for-each 是数组顺序(父 ≤ 子的局部约束,兄弟无序),不可直接当有序名单。正确做法:new PriorityQueue<>(旧堆) 复制后连续 poll 到空,或 `queue.stream().sorted(comparator).toList()`。**举一反三**:这两种写法都是 O(n log n)——前者依赖堆出队,后者依赖排序;选哪种看是否要把结果按不同比较器排序。
> **5**　```java
Comparator<Order> ORDER = Comparator
    .comparing((Order o) -> !o.vip())     // VIP 在前(false 排 true 前)
    .thenComparing(Order::arrivedAt);     // 同级按到店时间
```　**举一反三**:Comparator 的组装链是 Java 8+ 的强力工具——先 comparing,再 thenComparing,再 reversed;只改装配顺序就能换排序策略,不用重写 compare 方法。
