## 一、需求:给访问日志做一次体检

上一话阿零学会了用 `|` 串流水线。今天豆豆直接下单:「咖啡站上线一早上,`access.log` 攒了一堆访问记录。我要一份**体检报告**:一共来了多少次?谁来得最勤?各状态码几次?错误率多高?——**用你昨天那根管子。**」

这就是本卷第一场实战:四个新工位 `cut / sort / uniq / wc` 接上管道,把一堆原始日志**榨成几个数字**。原料就是咖啡站的访问日志(每行一次访问,空格分隔):

```text
192.168.1.10 - - [24/Sep/2026:08:01:12 +0800] "GET /menu HTTP/1.1" 200 1043
192.168.1.12 - - [24/Sep/2026:08:04:31 +0800] "GET /coffee HTTP/1.1" 404 512
192.168.1.10 - - [24/Sep/2026:08:07:20 +0800] "POST /order HTTP/1.1" 500 77
...(共 10 行)
```

字段位置先数清楚:**第 1 列 = IP,第 9 列 = 状态码**(按空格切)。

## 二、漫画 · 四工位流水线

> **〔1〕** 车间里一字排开四台机器,牌子分别写着 `cut` `sort` `uniq` `wc`。管道工把上一话那根竖管往机器之间一接。
> 管道工:「昨天你会接管子了。今天认识管子上的**四个工位**。」

> **〔2〕** 管道工拍第一台 `cut`:「**切**。日志是一排排字段,`cut` 负责按分隔符切下你要的那一列——第 1 列 IP,还是第 9 列状态码。」

> **〔3〕** 拍第二台 `sort`:「**排**。把相同的排到一起。」再拍 `uniq`:「**去重计数**。」特米插话:「注意——`uniq` 只认**相邻**的重复。不先 `sort`,它就瞎。」

> **〔4〕** 阿零抢着敲 `cut -d' ' -f1 access.log | uniq -c`,想数每个 IP 几次,结果每个都是 `1`,一个没合并。
> 阿零:「怎么全是 1?!」特米(叹气):「因为你**没先 sort**。相同 IP 没挨在一起,`uniq` 当然看不见。」

> **〔5〕** 阿零补上 `sort`,数字对了。管道工拍最后一台 `wc`:「**数**。`wc -l` 数行数——一行一次访问,行数就是**总访问量**。」

> **〔6〕** 四台机器咔咔运转,一份体检报告从管尾吐出。阿零举着报表:「原来一屏乱码日志,能榨成这么几个数!」

## 三、本话目标

- `cut -d -f`:按分隔符切出指定列(IP=第1列,状态码=第9列);
- `sort` / `sort -rn`:字典序排 vs 按数字倒序排,理解 `-n` 为什么必须;
- `uniq -c`:去重并计数,牢记**必须先 sort**(只去相邻重复);
- `wc -l`:数行数 = 数访问次数;
- 把四者串成流水线,产出**总量 / Top IP / 状态码分布 / 错误率**四份数据。

## 四、原理图:四工位各司其职

```text
原始日志 ──▶ cut ──▶ sort ──▶ uniq -c ──▶ sort -rn ──▶ 报表
             切列     排序      去重计数     按数倒排

cut  -d' ' -f1   -d 指定分隔符(delimiter),-f 指定第几列(field)
sort              默认按"字符串字典序";-n 按数值,-r 倒序
uniq -c           把"连续相同"的行压成一行,-c 在前面标出现次数
                  ⚠ 只看相邻!所以上游必须先 sort
wc   -l           数行数(-l=lines,-w 词,-c 字节)
```

**黄金搭档:`sort | uniq -c | sort -rn` —— 排好、数一遍、按热度倒排。这三节几乎是日志分析的固定咒语。**

## 五、上手:一步步做出体检报告

**① 总访问量**(几行 = 几次访问):

```bash
$ wc -l logs/access.log
10 logs/access.log
```

**② Top IP**(谁来得最勤):

```bash
$ cut -d' ' -f1 logs/access.log | sort | uniq -c | sort -rn
      3 192.168.1.11
      3 192.168.1.10
      2 192.168.1.12
      1 192.168.1.14
      1 192.168.1.13
```

读法:`.11` 和 `.10` 各来 3 次并列榜首。四个工位:切出 IP → 排序聚拢 → 去重计数 → 按次数倒排。

**③ 各状态码分布**(第 9 列):

```bash
$ cut -d' ' -f9 logs/access.log | sort | uniq -c | sort -rn
      5 200
      2 404
      1 500
      1 403
      1 201
```

一眼看出:成功(200/201)6 次,客户端错(403/404)3 次,服务端错(500)1 次。

**④ 错误率**(4xx/5xx 占比,用 grep 数分子、wc 数分母):

```bash
$ grep -E '" (4|5)[0-9][0-9] ' logs/access.log | wc -l    # 4xx+5xx 行数
4
$ wc -l < logs/access.log                                  # 总行数(< 喂文件,输出不带文件名)
10
```

4/10 = **40% 错误率**——上线第一早上就该报警了。把这份报告落地存档:

```bash
$ cut -d' ' -f9 logs/access.log | sort | uniq -c | sort -rn > logs/status-report.txt
```

> **特米旁白**:`wc -l logs/access.log` 会带上文件名(`10 logs/...`),而 `wc -l < logs/access.log` 用重定向喂进去、只吐数字 `10`。要拿数字进一步算的时候,用后者更干净。

## 六、故意制造一个 Bug:uniq 前忘了 sort

阿零想数每个 IP 的访问次数,顺手就接了 uniq,漏掉中间的 sort:

```bash
$ cut -d' ' -f1 logs/access.log | uniq -c
```

## 七、读懂真实报错

这个坑又是**不报错**的那种——它给你一个「看起来对、其实全错」的结果:

```text
      1 192.168.1.10
      1 192.168.1.11
      1 192.168.1.10
      1 192.168.1.12
      1 192.168.1.11
      1 192.168.1.13
      1 192.168.1.10
      ...
```

每个都是 `1`,`.10` 出现了三处独立的 `1`,根本没合并。根因:**`uniq` 只压缩「连续相邻」的重复行**。原始日志里 `.10` 的三次访问被别的 IP 隔开了,不相邻,`uniq` 就当它们是三个不同的东西。修法就是漫画那句——**先 sort 让相同的挨到一起,uniq 才看得见**:

```bash
$ cut -d' ' -f1 logs/access.log | sort | uniq -c
      3 192.168.1.10
      3 192.168.1.11
      2 192.168.1.12
      1 192.168.1.13
      1 192.168.1.14
```

**记死这条:`uniq` 前面永远跟一个 `sort`。** 这是新手最高频的日志分析翻车点。

> **🪟 双系统对照 · 四工位在 PowerShell 上怎么摆**

bash 靠「切字符列」,PowerShell 靠「对象属性 + 分组」,思路完全不同:

| 干什么 | Linux (bash) | PowerShell 7 |
|---|---|---|
| 切某列 | `cut -d' ' -f1` | `-split ' '` 后取 `[0]`,或 `Select-Object` 属性 |
| 排序 | `sort` / `sort -rn` | `Sort-Object` / `Sort-Object -Descending` |
| 去重计数 | `sort \| uniq -c` | `Group-Object` (自带 Count,**不需要先排序**) |
| 数行数 | `wc -l` | `Measure-Object -Line` 或 `(...).Count` |

同一个「Top IP」需求:

```powershell
Get-Content logs\access.log |
  ForEach-Object { ($_ -split ' ')[0] } |
  Group-Object | Sort-Object Count -Descending |
  Select-Object Count, Name
```

注意 PowerShell 的 `Group-Object` **不用先排序**——它按对象分组,不像 `uniq` 只看相邻行。这正是「对象管道 vs 文本流」在本话最实用的一处:bash 的 `uniq` 有「必须先 sort」的坑,PS 的 `Group-Object` 天生没有。但服务器上没有 `Group-Object`,`sort | uniq -c` 的咒语还得背熟。

> **🎯 面试直击**:`sort | uniq -c` 为什么不能只用 `uniq -c`?
> 因为 `uniq` 只合并**相邻**的重复行,乱序数据里相同项不相邻就漏统计。必须先 `sort` 把相同行聚在一起。追问:统计 Top N 的完整咒语是 `sort | uniq -c | sort -rn | head -n N`——排序聚拢、去重计数、按热度倒排、取前 N。

## 八、用命令验证:报表数字对得上吗

交叉验证——不同 IP 的个数,不该超过总访问量:

```bash
$ wc -l < logs/access.log                       # 总访问量:10 次
10
$ cut -d' ' -f1 logs/access.log | sort -u | wc -l   # 不同 IP 数(sort -u = sort | uniq)
5
$ echo $?
0
```

10 次访问来自 5 个 IP,数量自洽,报表可信。(`sort -u` 是「排序并去重」的一步写法,比 `sort | uniq` 更短。)
