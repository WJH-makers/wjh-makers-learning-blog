## 四、原理图

```text
double[] prices = {15.0, 18.0, 20.0};
下标            0     1     2       长度 prices.length == 3
合法下标范围:0 .. length-1        ← 想要「最后一个」永远是 length-1
```

`prices.length` 是**数组自带的一个字段**(注意:没有括号),它记着这排格子有几个。合法下标从 `0` 到 `length - 1`,伸手够到 `length` 就摔出围栏。数组一旦建好,`length` 就**定死了**、不能再改 —— 想加菜得换更大的数组,这也是第二季要请出 `List` 的原因。

## 五、代码:遍历菜单

```java
import java.util.Arrays;

public class Cafe {
    public static void main(String[] args) {
        String[] menu = {"美式", "拿铁", "卡布奇诺"};
        double[] prices = {15.0, 18.0, 20.0};

        // 普通 for:需要下标时用(注意 i < length,不是 <=)
        for (int i = 0; i < menu.length; i++) {
            System.out.println((i + 1) + ". " + menu[i] + " ¥" + prices[i]);
        }

        // for-each:只关心元素、不关心下标时用(上一话预告过的那个)
        double sum = 0;
        for (double p : prices) sum += p;
        System.out.println("整单打包价 ¥" + sum);
        System.out.println(Arrays.toString(prices));
    }
}
```

普通 `for` 的条件是 `i < menu.length` 而**不是** `i <= menu.length` —— 差这一个等号,就会在最后多够一次、摔出围栏。这正是 off-by-one 最常见的犯案现场。


## 七、读懂真实报错

```text
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException:
        Index 3 out of bounds for length 3
        at Cafe.main(Cafe.java:12)
```

`Index 3 out of bounds for length 3` —— 长度是 3,合法下标 0~2,下标 3 已越界。注意这是**运行期**异常(编译能过),编译官管不了下标,得靠自己守住 `0 .. length-1`。报错还贴心地给了 `at Cafe.main(Cafe.java:12)` —— 直接告诉你摔在第 12 行,顺着去改就行。

## 八、修复,并用测试证明

想取「最后一个」,用 `length - 1`。把「整单合计」抽成方法:

```java
static double totalOf(double[] prices) {
    double sum = 0;
    for (double p : prices) sum += p;
    return sum;
}
```

```java
@Test
void total_of_menu() {
    assertEquals(53.0, Cafe.totalOf(new double[]{15.0, 18.0, 20.0}));
}
```

> **🎯 面试直击**:`length`、`length()`、`size()` 有什么区别?
> 一句话分清:**数组**取长度用字段 `arr.length`(无括号);**String** 取长度用方法 `s.length()`(有括号);**集合**(`List`/`Set`/`Map`,第二季登场)取元素个数用方法 `.size()`。追问防身:为什么数组是字段、String 是方法?数组长度是 JVM 在创建时就定死的**只读属性**,直接暴露成字段;String 的长度要由内部字符数据算出,封装成方法更合理。三者混用是最高频的「找茬」笔试题,写错一个括号就露馅。

### 一、选择题（10 道）

1. [基础] `int[] arr = new int[5];` 中 `arr[5]` 会发生什么？
   - A) 返回 0　B) 返回 null　C) 编译报错　D) 运行时抛出 `ArrayIndexOutOfBoundsException`

2. [基础] 以下哪个是正确的数组声明语法？
   - A) `int arr[];`　B) `int[] arr;`　C) `int arr[5];`　D) A 和 B 都正确

3. [基础] `int[] arr = new int[3];` 创建后 `arr[0]` 的值是？
   - A) `null`　B) `0`　C) 未定义　D) 编译报错

4. [理解] `String[] names = {"张三", "李四", "王五"};` 中 `names.length` 的值是？
   - A) 2　B) 3　C) 4　D) 编译报错

5. [理解] `int[] a = {1, 2, 3}; int[] b = a; b[0] = 99;` 执行后 `a[0]` 的值是？
   - A) 1　B) 99　C) 编译报错　D) 运行时异常

6. [应用] 以下代码输出什么？`int[] arr = {1, 2, 3, 4, 5}; for(int x : arr) { x = x * 2; } System.out.println(arr[0]);`
   - A) 2　B) 1　C) 5　D) 编译报错

7. [分析] 以下代码的问题是什么？`int[] arr = new int[3]; for(int i = 0; i <= arr.length; i++) { arr[i] = i; }`
   - A) 语法错误　B) 逻辑错误：会越界访问 arr[3]　C) 数组未初始化　D) 没有问题

8. [分析] `int[] arr = new int[-5];` 会发生什么？
   - A) 编译报错　B) 运行时抛出 `NegativeArraySizeException`　C) 创建一个空数组　D) 创建长度为 5 的数组

9. [判断] 关于 Java 数组，以下说法错误的是？
   - A) 数组长度一旦创建不可改变　B) 数组下标从 0 开始　C) 可以用 `arr.size()` 获取长度　D) `new int[0]` 是合法的，创建空数组

10. [综合] 以下代码输出什么？`int[] a = {1, 2, 3}; int[] b = {1, 2, 3}; System.out.println(a == b); System.out.println(a.equals(b));`
    - A) `true true`　B) `false false`　C) `true false`　D) `false true`

> [!答案]
> **1-D**：长度为 5 的数组有效索引是 0~4，访问 arr[5] 会在运行时抛出 `ArrayIndexOutOfBoundsException`——编译器不检查索引值。**举一反三**：遍历时条件应写 `i < arr.length`，不要写 `i <= arr.length`。
> **2-D**：A 和 B 都可以，`int arr[]` 是 C 风格的兼容写法，`int[] arr` 是 Java 推荐写法（类型信息更清晰）。C 错误：声明时不能指定长度。**举一反三**：统一用 `int[] arr`，团队规范中保持一致。
> **3-B**：`int` 数组元素默认值为 `0`。不同元素类型的默认值：`int/short/byte/long` → 0，`double/float` → 0.0，`boolean` → false，`char` → `'\u0000'`，引用类型 → `null`。**举一反三**：这是 Java 的安全设计——不会让变量处于"未初始化"的未定义状态。
> **4-B**：`length` 是数组的**属性**（不是方法），返回数组的容量 3。注意索引范围是 0 到 `length-1`（即 0~2）。**举一反三**：String 的长度是 `str.length()`（方法），数组是 `.length`（属性），初学者常混淆。
> **5-B**：`int[] b = a;` 不是复制数组，而是复制**引用**——a 和 b 指向堆上同一个数组对象。修改 `b[0]` 等于修改 `a[0]`。**举一反三**：如果要复制数组内容，用 `Arrays.copyOf()` 或 `System.arraycopy()`。
> **6-B**：`for-each` 中的 `x` 是数组元素的**副本**，修改 `x` 不影响原数组。最终 `arr[0]` 仍为 1。**举一反三**：需要修改原数组元素，必须用传统 `for` + 索引：`for(int i=0; i<arr.length; i++) arr[i] *= 2;`。
> **7-B**：`arr.length` 为 3，`i <= arr.length` 会让 i 取到 3，访问 `arr[3]` 时越界抛异常。正确写法：`i < arr.length`。**举一反三**：所有"遍历所有元素"的场景都记住口诀——"从 0 到 length-1"。
> **8-B**：编译时 `-5` 是合法的 `int` 字面量，语法不报错。运行时 JVM 发现数组长度为负数，抛出 `NegativeArraySizeException`。**举一反三**：如果长度是变量，务必先验证 `size >= 0`。
> **9-C**：获取数组长度用 `arr.length`（属性），不是 `arr.size()`（那是集合的方法）。A 正确：数组长度固定。B 正确：下标从 0 开始。D 正确：可以创建长度为 0 的空数组，用于方法返回"空结果"。
> **10-B**：`a == b` 比较引用地址——两个不同的数组对象，地址不同，返回 `false`。`a.equals(b)` 数组的 `equals` 继承自 `Object`，默认也是比较引用，同样返回 `false`。**举一反三**：比较数组内容用 `Arrays.equals(a, b)`，这才是逐元素比较。

### 二、解答题（3 道）

1. [概念阐述] `int[] a = {1,2,3};` 和 `int[] a = new int[]{1,2,3};` 有什么区别？什么场景下只能用后者而前者不行？

2. [场景解释] 咖啡机系统用两个数组 `MENU[i]` 存名称、`PRICES[i]` 存价格，下标对齐维护对应关系。这种"下标暗合"的设计有什么风险？请提出至少一种改进思路。

3. [综合分析] Java 数组和 `ArrayList` 的根本区别是什么？在实际开发中，何时用数组、何时用 `ArrayList`？请从"是否可扩容""类型安全""性能""元素类型"四个维度进行对比分析。

> [!答案]
> **1**　两者创建的数组对象完全相同。区别在语法场景：`{1,2,3}` 是**数组初始化简写**，只能用在声明变量的同一条语句中；`new int[]{1,2,3}` 可以单独出现——作为方法返回值（`return new int[]{1,2,3};`）、作为方法实参（`method(new int[]{1,2,3})`）、或对已声明的变量重新赋值（`arr = new int[]{4,5,6}`）。**举一反三**：拆分声明和赋值的写法 `int[] a; a = {1,2,3};` 会编译报错，必须用 `a = new int[]{1,2,3};`。
> **2**　主要风险：①增删菜单项时容易漏改另一个数组，导致下标错位（拿铁显示成摩卡的价格）；②修改某道菜的价格时，需要在两个数组中定位同一索引，可维护性差；③无法表达"没有价格""暂时下架"等状态。改进思路：①用二维数组 `String[][] menu = {{"美式","15"},{"拿铁","18"}}` 但类型不安全；②用两个 ArrayList 配合；③最根本的——第二季引入 class Coffee 把名称和价格封装在一起，用对象数组或 List<Coffee>，从根本上消除"下标暗合"。**举一反三**：平行数组（parallel arrays）是重构信号——一旦发现多个数组通过下标关联，就应该考虑封装为对象或使用 Map。
> **3**　四维对比：①**扩容**：数组长度固定，不可改变；ArrayList 自动扩容（默认扩展 1.5 倍）。②**类型安全**：数组编译时检查元素类型，存入不匹配类型立即报错；ArrayList 通过泛型保证，离开泛型时代的旧代码有类型擦除风险。③**性能**：数组直接内存访问最快，无装箱开销；ArrayList 底层就是数组，但涉及自动装箱/拆箱和扩容拷贝。④**元素类型**：数组支持基本类型（`int[]`）；ArrayList 只存对象，基本类型需装箱为包装类。选择策略：元素数量确定 + 基本类型 → 用数组；元素数量不确定或需要增删 → 用 ArrayList。**举一反三**：现代 Java 中绝大部分场景推荐 List（ArrayList），除非你在写底层算法、IO 缓冲区等需要极致性能的代码。

### 三、代码题（2 道）

1. [基础实现] 有一个数组 `double[] prices = {15.0, 18.5, 22.0, 25.5, 30.0};` 存放 5 款咖啡的单价。请计算：①所有咖啡的总价；②平均价格；③最贵和最便宜的价格。用传统 for 和 for-each 各实现一次，对比索引的相关性。

2. [综合设计] 写一个"饮品销量统计器"：用一个 `int[]` 数组存储 7 种饮品的日销量（用随机数 0~20 初始化），输出：①销量柱状图（每个销量打印等量的 `▓` 符号）；②总销量和日均销量；③销量最高和最低的饮品编号（若并列则都列出）。要求全部用数组操作完成，不得借助 Arrays.sort。

> [!答案]
> **1 验收**：
> ```java
> double[] prices = {15.0, 18.5, 22.0, 25.5, 30.0};
>
> // 传统 for 版
> double total = 0, max = prices[0], min = prices[0];
> for (int i = 0; i < prices.length; i++) {
>     total += prices[i];
>     if (prices[i] > max) max = prices[i];
>     if (prices[i] < min) min = prices[i];
> }
> System.out.printf("总价:%.1f 均价:%.1f\n", total, total / prices.length);
> System.out.printf("最贵:%.1f 最便宜:%.1f\n", max, min);
>
> // for-each 版（不能同时获取索引，但遍历更简洁）
> double total2 = 0;
> for (double p : prices) total2 += p;
> System.out.println("均价(fe): " + (total2 / prices.length));
> // 注意：求最值用 for-each 同样可行，但无法知道最贵的是第几款
> ```
> 运行验证：总价 111.0, 均价 22.2, 最贵 30.0, 最便宜 15.0。**举一反三**：需要索引信息时用传统 for，只关心元素本身用 for-each。
>
> **2 验收**：
> ```java
> int[] sales = new int[7];
> java.util.Random rand = new java.util.Random();
> for (int i = 0; i < sales.length; i++) {
>     sales[i] = rand.nextInt(21); // 0~20
> }
>
> // ① 柱状图
> for (int i = 0; i < sales.length; i++) {
>     System.out.printf("饮品%d(%2d杯): ", i, sales[i]);
>     for (int j = 0; j < sales[i]; j++) {
>         System.out.print("▓");
>     }
>     System.out.println();
> }
>
> // ② 总销量和日均
> int totalSales = 0;
> for (int s : sales) totalSales += s;
> System.out.printf("总销量: %d, 日均: %.1f\n", totalSales, totalSales / 7.0);
>
> // ③ 最值（并列处理）
> int maxSale = sales[0], minSale = sales[0];
> for (int s : sales) {
>     if (s > maxSale) maxSale = s;
>     if (s < minSale) minSale = s;
> }
>
> System.out.print("最高销量(" + maxSale + "杯): 饮品");
> for (int i = 0; i < sales.length; i++) {
>     if (sales[i] == maxSale) System.out.print(" " + i);
> }
> System.out.println();
>
> System.out.print("最低销量(" + minSale + "杯): 饮品");
> for (int i = 0; i < sales.length; i++) {
>     if (sales[i] == minSale) System.out.print(" " + i);
> }
> System.out.println();
> /* 示例输出：
> 饮品0(12杯): ▓▓▓▓▓▓▓▓▓▓▓▓
> 饮品1( 5杯): ▓▓▓▓▓
> ...
> 最高销量(18杯): 饮品 3
> 最低销量( 1杯): 饮品 5
> */
> ```
> **举一反三**：找并列最值的套路——先遍历一次找到最大/最小值，再遍历一次列出所有等于该值的索引。这是 O(n) 的两次遍历，比排序 O(n log n) 更优。
