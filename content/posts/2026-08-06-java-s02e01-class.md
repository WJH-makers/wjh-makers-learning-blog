# 《从零开始学 Java》13 · Coffee 设计图:类与对象

> 第二季「对象大陆」第 1 话 · 基线 JDK 25 · 承接:第一季那台用平行数组拼出来的控制台咖啡机 v1。

## 一、需求:把「一杯咖啡」当成一个整体

第一季的菜单是三个平行数组:`MENU[]`、`PRICES[]`、还想再加一个 `STOCK[]`。它们靠**下标对齐**硬凑成一杯咖啡——`MENU[2]` 的价是 `PRICES[2]`、库存是 `STOCK[2]`。可只要有人排一次序、或往中间插一杯,三个数组各动各的,下标就错位:美式卖成了拿铁的价。

豆豆叼着豆子敲桌子:「一杯咖啡的名字、价格、库存,本来就该**长在一起**。你却把它拆成三根平行线,靠下标这根细绳绑着——绳一断就散架。今天把它们**打包成一个整体**,这个整体就叫**对象**。」

## 三、本话目标

- 用 `class` 定义一类事物的字段(属性)和方法(行为);
- 用 `new` 创建对象、用 `.` 访问成员;
- 分清「图纸(类)」与「实物(对象)」,并**亲手验证对象彼此独立**;
- 用构造器给对象一次性初始化;
- 搞懂「实例字段有默认值,局部变量却必须显式初始化」这条面试点。

---

## 四、原理图

```text
class Coffee {              图纸:定义有哪些字段、哪些方法
    String name;
    double price;
    int stock;
}
Coffee a = new Coffee(...);   new:按图纸在堆里造一个实物,a 是指向它的引用
Coffee b = new Coffee(...);   再 new 一次 = 另一块内存、另一份数据
a.stock = 99;                 . :访问 a 指向的那杯的成员;动 a 不碰 b
```

一张图纸 → 任意多个实物,每个实物**各存一份自己的字段**。这就是上面漫画里「改美式不影响拿铁」的底层真相。

## 五、代码:Coffee 类登场

```java
public class Coffee {
    String name;    // 字段:一杯咖啡有哪些数据
    double price;
    int stock;

    // 构造器:造对象时一次性初始化(方法名 = 类名,无返回类型)
    Coffee(String name, double price, int stock) {
        this.name = name;      // this.name 是本对象的字段,name 是参数
        this.price = price;
        this.stock = stock;
    }

    // 方法:一杯咖啡能做的事(行为)
    String describe() {
        return name + " ¥" + price + "(库存 " + stock + ")";
    }

    public static void main(String[] args) {
        Coffee americano = new Coffee("美式", 15.0, 20);
        Coffee latte = new Coffee("拿铁", 18.0, 10);

        americano.stock = 99;      // 只动美式这一杯
        System.out.println(americano.describe());
        System.out.println(latte.describe());   // 拿铁不受影响
    }
}
```

输出:

```text
美式 ¥15.0(库存 99)
拿铁 ¥18.0(库存 10)
```

改了 `americano.stock`,`latte.stock` 岿然不动——名字、价格、库存现在**天然绑在一起**,且每个对象各存一份,再也不会像平行数组那样错位。

## 六、故意制造一个 Bug

把构造器里的 `this.` 全去掉:

```java
Coffee(String name, double price, int stock) {
    name = name;      // ← 故意:参数赋给参数自己,字段没被碰
    price = price;
    stock = stock;
}
```

---

## 七、读懂现象(Logic Bug:不报错,却打印默认值)

编译**不报错**,但 `describe()` 打印出:

```text
null ¥0.0(库存 0)
```

`name = name` 是把**参数赋给参数自己**——在方法内部,`name` 优先指最近的那个局部变量(参数)。同名的**字段**从头到尾没被碰过,于是它保持**默认值**。为什么字段没赋值也有值?因为:

> **🎯 面试直击**:实例字段和局部变量的初始化有什么区别?
> **实例字段**(和数组元素)会被 JVM 自动赋**默认值**:引用类型 → `null`,数值 → `0`/`0.0`,`boolean` → `false`,`char` → `'\0'`。所以本例里 `name` 是 `null`、`price` 是 `0.0`。而**局部变量没有默认值**,用之前**必须显式初始化**,否则编译期直接报 `variable might not have been initialized`。追问点:两者差在哪?字段随对象分配在堆上、由 JVM 清零;局部变量在栈帧里、JVM 不替你兜底,逼你自己负责。

结论:必须用 `this.name = name` 把「本对象的字段」和「参数」区分开。

---

## 八、修复,并用测试证明

补回 `this.`。对象的方法照样能被单独测——顺手把「对象独立性」也钉死:

```java
@Test
void coffee_describes_itself() {
    Coffee c = new Coffee("美式", 15.0, 20);
    assertEquals("美式 ¥15.0(库存 20)", c.describe());
}

@Test
void objects_are_independent() {
    Coffee a = new Coffee("美式", 15.0, 20);
    Coffee b = new Coffee("拿铁", 18.0, 10);
    a.stock = 99;
    assertEquals(10, b.stock);     // 改 a 不影响 b
}
```

## 🎯 随堂练习

先自己做,再对答案。每道答案都带一句「举一反三」,帮你把这一个点连成一片。

### 选择题(10 道)

1. 类和对象的关系,最准确的说法是?
   - A) 类是实物,对象是图纸　B) 类是图纸(类型),对象是按图纸造出来的实物(实例)　C) 两者是同一个东西的不同叫法　D) 一个类只能造一个对象
2. `Coffee a = new Coffee(...); Coffee b = new Coffee(...); a.stock = 99;` 之后 `b.stock`?
   - A) 也变成 99　B) 不受影响,两个对象各占各的内存　C) 变成 0　D) 编译报错
3. 构造器里写成 `name = name;`(去掉 `this.`),结果是?
   - A) 编译报错　B) 编译通过,但把参数赋给了参数自己,字段保持默认值　C) 正常赋值　D) 抛 NPE
4. 上题中 `describe()` 会打印出什么?
   - A) `美式 ¥15.0(库存 20)`　B) `null ¥0.0(库存 0)`　C) 空字符串　D) 抛异常
5. 实例字段和局部变量在初始化上的区别是?
   - A) 都有默认值　B) 实例字段由 JVM 自动赋默认值,局部变量必须显式初始化　C) 都必须显式初始化　D) 局部变量有默认值,字段没有
6. 局部变量没初始化就使用,会?
   - A) 得到 0　B) 得到 null　C) 编译报错 `variable might not have been initialized`　D) 运行期抛异常
7. 构造器的两个语法特征是?
   - A) 方法名任意 + 返回 void　B) 方法名 = 类名 + **没有**返回类型　C) 必须是 static　D) 必须是 private
8. 引用类型字段的默认值是?
   - A) `""`　B) `0`　C) `null`　D) 未定义
9. 第一季用三个平行数组存菜单,最大的隐患是?
   - A) 占内存太多　B) 靠下标「暗中约定」对齐,一排序或插入就错位　C) 数组不能遍历　D) 无法打印
10. 为什么说 `this.name = name` 里的 `this` 不可省?
    - A) 语法强制要求　B) 因为方法内同名时,`name` 优先指最近的局部变量(参数),`this.name` 才是本对象的字段　C) 为了可读性　D) 为了性能

> [!答案]
> **1-B**　图纸只有一张,杯子可以有一百只。**举一反三**:「类是类型,对象是实例」这句话在泛型、反射、序列化里都会反复用到。
> **2-B**　两个对象各存一份自己的字段。**举一反三**:这正是把数据从平行数组里救出来的全部意义 —— 数据天然绑在一起,还互不干扰。
> **3-B**　自赋值不报错,字段从头到尾没被碰过。**举一反三**:现代 IDE 会对自赋值给黄色警告,别忽略警告 —— 它经常是真 Bug。
> **4-B**　字段保持 JVM 给的默认值。**举一反三**:看到「打印出一排 null / 0」,先怀疑构造器是不是没真正赋上值。
> **5-B**　字段在堆上由 JVM 清零,局部变量在栈帧里 JVM 不替你兜底。**举一反三**:所以「字段有默认值」不该被当成偷懒的理由 —— 显式初始化仍是好习惯。
> **6-C**　编译期直接拦下。**举一反三**:Java 用「明确赋值分析」逼你负责,这是它比 C 更安全的地方之一。
> **7-B**　方法名与类名同名,且不写返回类型(连 `void` 都不写)。**举一反三**:若手滑写了 `void`,它就退化成一个普通方法 —— 编译能过,但 `new` 时根本不会调用它,这是经典找茬题。
> **8-C**　引用类型默认 `null`,数值 `0`/`0.0`,`boolean` 是 `false`,`char` 是 `'\u0000'`。**举一反三**:这也解释了很多「莫名其妙的 NPE」—— 字段忘了初始化就直接用。
> **9-B**　下标是根细绳,绳一断就散架。**举一反三**:凡是「几个集合靠下标对齐」的设计,都该被一个对象取代。
> **10-B**　同名时局部变量优先,`this.` 才能指到字段。**举一反三**:这就是为什么很多团队要求字段用 `this.` 显式访问 —— 消除歧义比省几个字符值钱。
