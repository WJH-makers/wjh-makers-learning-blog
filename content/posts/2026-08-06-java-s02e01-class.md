# 《从零开始学 Java》13 · Coffee 设计图:类与对象

> 第二季「对象大陆」第 1 话 · 基线 JDK 25 · 承接:第一季那台用平行数组拼出来的控制台咖啡机 v1。

## 一、需求:把「一杯咖啡」当成一个整体

第一季的菜单是三个平行数组:`MENU[]`、`PRICES[]`、还想再加一个 `STOCK[]`。它们靠**下标对齐**硬凑成一杯咖啡——`MENU[2]` 的价是 `PRICES[2]`、库存是 `STOCK[2]`。可只要有人排一次序、或往中间插一杯,三个数组各动各的,下标就错位:美式卖成了拿铁的价。

豆豆叼着豆子敲桌子:「一杯咖啡的名字、价格、库存,本来就该**长在一起**。你却把它拆成三根平行线,靠下标这根细绳绑着——绳一断就散架。今天把它们**打包成一个整体**,这个整体就叫**对象**。」

## 三、本话目标

- 用 `class` 定义一类事物的字段(属性)和方法(行为);
- 用 `new` 创建对象、用 `.` 访问成员;
- 分清「图纸(类)」与「实物(对象)」,并**亲手验证对象彼此独立**;
- 用构造器给对象一次性初始化;
- 搞懂「实例字段有默认值,局部变量却必须显式初始化」这条面试点。

---

## 四、原理图

```text
class Coffee {              图纸:定义有哪些字段、哪些方法
    String name;
    double price;
    int stock;
}
Coffee a = new Coffee(...);   new:按图纸在堆里造一个实物,a 是指向它的引用
Coffee b = new Coffee(...);   再 new 一次 = 另一块内存、另一份数据
a.stock = 99;                 . :访问 a 指向的那杯的成员;动 a 不碰 b
```

一张图纸 → 任意多个实物,每个实物**各存一份自己的字段**。这就是上面漫画里「改美式不影响拿铁」的底层真相。

## 五、代码:Coffee 类登场

```java
public class Coffee {
    String name;    // 字段:一杯咖啡有哪些数据
    double price;
    int stock;

    // 构造器:造对象时一次性初始化(方法名 = 类名,无返回类型)
    Coffee(String name, double price, int stock) {
        this.name = name;      // this.name 是本对象的字段,name 是参数
        this.price = price;
        this.stock = stock;
    }

    // 方法:一杯咖啡能做的事(行为)
    String describe() {
        return name + " ¥" + price + "(库存 " + stock + ")";
    }

    public static void main(String[] args) {
        Coffee americano = new Coffee("美式", 15.0, 20);
        Coffee latte = new Coffee("拿铁", 18.0, 10);

        americano.stock = 99;      // 只动美式这一杯
        System.out.println(americano.describe());
        System.out.println(latte.describe());   // 拿铁不受影响
    }
}
```

输出:

```text
美式 ¥15.0(库存 99)
拿铁 ¥18.0(库存 10)
```

改了 `americano.stock`,`latte.stock` 岿然不动——名字、价格、库存现在**天然绑在一起**,且每个对象各存一份,再也不会像平行数组那样错位。

## 六、故意制造一个 Bug

把构造器里的 `this.` 全去掉:

```java
Coffee(String name, double price, int stock) {
    name = name;      // ← 故意:参数赋给参数自己,字段没被碰
    price = price;
    stock = stock;
}
```

---

## 七、读懂现象(Logic Bug:不报错,却打印默认值)

编译**不报错**,但 `describe()` 打印出:

```text
null ¥0.0(库存 0)
```

`name = name` 是把**参数赋给参数自己**——在方法内部,`name` 优先指最近的那个局部变量(参数)。同名的**字段**从头到尾没被碰过,于是它保持**默认值**。为什么字段没赋值也有值?因为:

> **🎯 面试直击**:实例字段和局部变量的初始化有什么区别?
> **实例字段**(和数组元素)会被 JVM 自动赋**默认值**:引用类型 → `null`,数值 → `0`/`0.0`,`boolean` → `false`,`char` → `'\0'`。所以本例里 `name` 是 `null`、`price` 是 `0.0`。而**局部变量没有默认值**,用之前**必须显式初始化**,否则编译期直接报 `variable might not have been initialized`。追问点:两者差在哪?字段随对象分配在堆上、由 JVM 清零;局部变量在栈帧里、JVM 不替你兜底,逼你自己负责。

结论:必须用 `this.name = name` 把「本对象的字段」和「参数」区分开。

---

## 八、修复,并用测试证明

补回 `this.`。对象的方法照样能被单独测——顺手把「对象独立性」也钉死:

```java
@Test
void coffee_describes_itself() {
    Coffee c = new Coffee("美式", 15.0, 20);
    assertEquals("美式 ¥15.0(库存 20)", c.describe());
}

@Test
void objects_are_independent() {
    Coffee a = new Coffee("美式", 15.0, 20);
    Coffee b = new Coffee("拿铁", 18.0, 10);
    a.stock = 99;
    assertEquals(10, b.stock);     // 改 a 不影响 b
}
```

### 一、选择题（10 道）

1. [基础] Java 中用哪个关键字定义类？- A) `struct`　B) `class`　C) `type`　D) `object`
2. [基础] 以下哪个是合法的字段声明？- A) `String name;`　B) `String name`　C) `name String;`　D) `field String name;`
3. [基础] 构造器的名称必须跟什么一致？- A) 文件名　B) 方法名　C) 类名　D) 包名
4. [基础] `new Coffee()` 底层做了什么事？- A) 只在栈上分配内存　B) 只在堆上分配内存　C) 堆分配 + 构造器初始化 + 返回引用　D) 只调用构造器
5. [进阶] 如果类中没有显式写构造器，编译器会？- A) 报错　B) 自动插入无参构造器　C) 插入带参构造器　D) 不做任何处理
6. [进阶] `this` 关键字的核心作用是？- A) 调用父类方法　B) 引用当前调用对象　C) 创建新对象　D) 回收对象
7. [进阶] 以下哪个是合法的对象引用声明？- A) `Coffee c = Coffee();`　B) `Coffee c = new Coffee();`　C) `Coffee c = new Coffee;`　D) `new c = Coffee();`
8. [进阶] 下面代码输出什么？```java class Test { int x; boolean flag; String s; public static void main(String[] a) { Test t = new Test(); System.out.println(t.x + "," + t.flag + "," + t.s); } }```- A) `0,false,""`　B) `0,false,null`　C) 编译错误　D) `null,null,null`
9. [综合] 局部变量与实例字段的区别，正确的是？- A) 两者都有默认值　B) 局部变量无默认值，必须显式初始化才能用　C) 字段无默认值　D) 局部变量在堆上
10. [综合] 一个 `.java` 源文件中关于顶层类的规则是？- A) 可以声明任意多个 `public` 类　B) 最多一个 `public` 类，且类名与文件名一致　C) 至少一个 `public` 类　D) 不能声明多个类

> [!答案] **1-B**　`class` 是 Java 定义类的唯一关键字。**2-A**　字段声明格式为 `类型 变量名;`。**3-C**　构造器名 = 类名，大小写也必须一致。**4-C**　`new` 三步走：堆上分配 → 构造器初始化 → 返回堆地址（引用）。**5-B**　编译器自动插入无参构造器，前提是你一个构造器都没写。**6-B**　`this` 指向调用该方法的当前对象实例。**7-B**　Java 创建对象必须 `new 类名()`，括号不可省略。**8-B**　字段默认值：`int`=0，`boolean`=false，引用类型=`null`。**9-B**　局部变量在栈上、无默认值、不初始化编译器就报错——这和字段完全不同。**10-B**　顶层类最多一个 `public`，内部类不受此限。
**举一反三**：第 4、8 题是面试高频组合——`new` 三部曲 + 字段默认值表，能说清这两道，类/对象的底层理解就过关了。

### 二、解答题（3 道）

1. [概念] 用生活类比解释"类"和"对象"的关系，并说明为什么同一个类能创建多个对象且互不影响。
2. [场景] 一个 `Coffee` 类有字段 `int stock`，张三写 `Coffee c = new Coffee(); c.stock = 10;` 李四写 `Coffee d = c; d.stock = 5;`。请问 `c.stock` 现在是多少？为什么？
3. [综合] 说明 `new` 关键字背后 JVM 做了哪三步工作；如果构造器执行时抛出异常，堆上分配的内存会怎样？

> [!答案] **1**　类是**模具/蓝图**，对象是**按模具造出来的实物**。同一个模具（类）可以压出无数独立的产品（对象），每个对象在堆上有自己的内存区，改 A 不影响 B——就像同一份图纸盖出的两栋房子，装修一栋不改变另一栋。**举一反三**：`static` 字段是反例——它属于类本身，所有对象共享一份，改一处全变。**2**　`c.stock` 是 5。因为 `Coffee d = c;` 并没有创建新对象，而是让 `d` 和 `c` 都指向堆上的**同一个对象**——改 `d.stock` 就是在改同一个对象的字段。这叫**引用赋值**，不是对象复制。**举一反三**：Java 方法参数传的是引用的副本，所以方法内修改对象字段会反映到外面，但修改引用本身（`obj = new ...`）不影响外面。**3**　三步：①在堆上分配对象内存并清零默认值；②调用构造器逐字段初始化；③将堆内存地址（引用）返回给变量。如果构造器异常，堆上分配的内存变成不可达对象，由 GC 自动回收。**举一反三**：这就是"对象一出生就守规矩"的根基——字段的默认值（0/null/false）在第①步完成，构造器在第②步覆盖。

### 三、代码题（2 道）

1. [基础] 定义 `Student` 类：字段 `String name` 和 `int score`，提供两个构造器——无参构造器（name 默认 "无名"，score 默认 0）和全参构造器。在 `main` 中分别用两种构造器创建对象并打印，验证默认值机制。
2. [综合] 设计 `BankAccount` 类：字段 `String owner`、`double balance`，方法 `deposit(double)` 和 `withdraw(double)`。规则：①初始余额必须 ≥ 0（否则构造器抛异常）；②取款时余额不足拒绝并打印 `"余额不足"`；③取款金额必须 > 0。写测试代码覆盖成功取款、余额不足和非法构造三种边界。

> [!答案] **1 验收**：
> ```java
> class Student {
>     String name;
>     int score;
>     Student() { name = "无名"; score = 0; }
>     Student(String name, int score) {
>         this.name = name;
>         this.score = score;
>     }
> }
> Student s1 = new Student();
> Student s2 = new Student("阿零", 88);
> System.out.println(s1.name + " " + s1.score); // 无名 0
> System.out.println(s2.name + " " + s2.score); // 阿零 88
> ```
> **举一反三**：无参构造器里显式赋默认值（`name = "无名"`）覆盖了 JVM 层面的 `null` 默认值——对于需要展示的字段很有用。**2 验收**：
> ```java
> class BankAccount {
>     String owner;
>     double balance;
>     BankAccount(String owner, double balance) {
>         if (balance < 0) throw new IllegalArgumentException("余额不能为负");
>         this.owner = owner;
>         this.balance = balance;
>     }
>     void deposit(double amount) { balance += amount; }
>     void withdraw(double amount) {
>         if (amount <= 0) { System.out.println("取款金额必须 > 0"); return; }
>         if (amount > balance) { System.out.println("余额不足"); return; }
>         balance -= amount;
>     }
> }
> // 边界测试:
> BankAccount a = new BankAccount("阿零", 100);
> a.withdraw(50);  // 成功 → balance = 50
> a.withdraw(200); // 余额不足 → 余额不变
> a.withdraw(-10); // 取款金额必须 > 0
> // new BankAccount("bad", -5); → 构造时抛异常
> ```
> **举一反三**：构造器里做校验（`balance < 0 → 抛异常`）是从源头堵住非法对象——这就是下两话"封装 + 不变量"的雏形。
