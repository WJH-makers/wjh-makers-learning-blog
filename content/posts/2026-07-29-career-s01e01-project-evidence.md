# 《从零开始当工程师》01 · 先让项目能被验证

> 这不是第二套课程。目标只有一个：让你已经做过的项目，能被陌生人运行、理解、追问和验证。

## 一、项目不是技术栈陈列柜

“Spring Boot、MySQL、Redis、Docker”不能证明你解决过问题。面试官真正能验证的是：你解决了什么、约束是什么、为什么这样做、如何确认它有效、失败时怎么办。

每一个准备投递的项目都要有同一份证据卡：

| 字段 | 必须回答的问题 | 可交付物 |
|---|---|---|
| 问题 | 谁遇到什么痛点？ | 一句话场景 |
| 主链路 | 请求怎样进入、处理、落库、返回？ | 一张图或一段时序 |
| 运行 | 新机器怎样启动？ | README 与命令 |
| 证据 | 成功或失败如何判定？ | 测试、日志、压测记录 |
| 取舍 | 为什么不用另一个方案？ | 一条明确边界 |
| 下一步 | 目前还不解决什么？ | 风险清单 |

不要把没有跑过的性能数字、没有审过的“高可用”、没有亲自实现的中间件写成成果。诚实的边界比漂亮但不可追问的名词更经得起面试。

## 二、最低验收：六项全过才进入简历

- [ ] 从干净环境按 README 在合理时间内启动。
- [ ] 演示一条核心业务链路，并说明每个状态如何变化。
- [ ] 有至少一个自动化测试或可重复的手工验收脚本。
- [ ] 能指出一个真实失败场景及定位方法。
- [ ] 能解释一个取舍：一致性、延迟、成本或复杂度中放弃了什么。
- [ ] 能在五分钟内讲完，再承受三轮随机追问。

前四项证明“做过”，后两项证明“理解过”。

## 三、五分钟项目陈述模板

按六句讲，不要从框架版本开始：

1. **问题**：我做的是……，核心用户/业务动作是……。
2. **约束**：最大的难点是……，因此不能只用……。
3. **方案**：主链路是……，关键数据由……保证。
4. **证据**：我用……验证；结果按……口径记录。
5. **取舍**：当前选择优先保证……，代价是……。
6. **下一步**：如果流量/数据量到……，我会先补……。

这六句要与代码、README、测试或演示记录能互相印证。讲不清的地方不是背稿不够，而是项目证据缺了一环。

## 四、两周内的正确顺序

| 顺序 | 任务 | 产出 |
|---|---|---|
| 1 | 选一个 Java 后端项目作主项目 | 一页项目证据卡 |
| 2 | 跑通核心链路并固定环境 | 可复制启动命令 |
| 3 | 加一条并发或异常验收 | 测试/脚本与结果 |
| 4 | 写 README、架构图、复盘 | 可公开链接或仓库文档 |
| 5 | 录一次五分钟讲解并自问三题 | 待补清单 |
| 6 | 再把 RSVQA 作为差异化项目 | 工程化证据，而非模型名词 |

Java 基础、MySQL、Redis 与面试题仍然是主干；项目证据包让这些知识在投递时有落点。站内的 [Java 面试与生产排障题库](/posts/2026-07-29-java-interview-production-playbook) 可作为随机追问清单，而不是新的背诵任务。

## 五、今天就做

创建一个 `PROJECT_EVIDENCE.md`，先只写六个标题：问题、主链路、运行、证据、取舍、下一步。空白比虚构好；每补齐一项，就用命令、截图、测试输出或代码链接作证。
