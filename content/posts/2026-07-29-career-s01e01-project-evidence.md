# 《从零开始当工程师》01 · 先让项目能被验证

> 连载特刊 · 第四部《从零开始当工程师》第一卷「把能力变成证据」第 1 话
> 长期项目：阿零从只会写代码，到带着咖啡站团队把事做成。

> 这不是第二套课程。目标只有一个：让你已经做过的项目，能被陌生人运行、理解、追问和验证。

## 一、简历发出去二十七份，回音一个没有

阿零把咖啡站的点单系统写完了。技术栈拉得挺齐：Spring Boot、MySQL、Redis、Docker 全用上了。他把这四个词端端正正写进简历，投了二十七家。

一个回音都没有。

> **〔1〕** 深夜的咖啡站。阿零把笔记本推开，屏幕上是第二十七封"感谢投递"。桌上摊着一摞打印的简历，最上面那份"技术栈"一栏写得密密麻麻。
> 阿零（脸埋在手臂里）：「……我明明真的做出来了啊。」
> 豆豆（在收银台上叉腰）：「做出来了。然后呢？」
> 阿零：「然后……我写在简历上了？」
> 豆豆：「你写了四个名词。招聘的人一天看两百份，四个名词他见过两百次。」

> **〔2〕** 屋檐上传来翅膀收拢的声音。一只沉稳的大雁落在窗台，翅膀上驮着一张纸，风一吹就自己翻页。
> 领姐：「你不是没做成事。你是做成了，但没人能验证。」
> 阿零（愣住）：「验证？我系统真的能跑！」
> 领姐：「你能跑。陌生人能跑吗？」

> **〔3〕** 阿零把项目丢进一台刚装好的干净虚拟机，想现场证明给她看。
> `mvn spring-boot:run` —— 报错：数据库连不上。
> 阿零：「哦，要先建库……建库脚本我放哪了？」翻了四分钟，在某个分支的一个叫 `临时.sql` 的文件里找到了。
> 改完再跑 —— 又报错：Redis 没起。
> 阿零（声音越来越小）：「……我本地一直开着，所以我从来没发现。」
> 豆豆：「所以你这系统，只在'你那台电脑，且你记得开三个服务'的时候能跑。这叫作品，还是叫习惯？」

> **〔4〕** 领姐翅膀上那张路线图翻到一页，上面只画了六个空格子。
> 领姐：「面试官不会问'你用了什么'。他会问：这解决了谁的什么问题？主链路怎么走？换台机器怎么起？你怎么知道它是对的？为什么不用另一个方案？现在还有什么没解决？」
> 阿零（数了数）：「六个……我一个都答不利索。」
> 领姐：「这六个格子填满，就是你的项目证据。**技术是船，方向是舵**——你造好了船，但没告诉任何人它能开去哪。」

## 二、本话目标

- 分清"技术栈清单"与"可验证的项目证据"。
- 建立一份六字段项目证据卡。
- 跑一遍干净环境启动，暴露隐藏依赖。
- 用六句话把项目讲给陌生人听。
- 定下"没验证过的数字不写进简历"这条红线。

## 三、项目不是技术栈陈列柜

“Spring Boot、MySQL、Redis、Docker”不能证明你解决过问题。面试官真正能验证的是：你解决了什么、约束是什么、为什么这样做、如何确认它有效、失败时怎么办。

每一个准备投递的项目都要有同一份证据卡：

| 字段 | 必须回答的问题 | 可交付物 |
|---|---|---|
| 问题 | 谁遇到什么痛点？ | 一句话场景 |
| 主链路 | 请求怎样进入、处理、落库、返回？ | 一张图或一段时序 |
| 运行 | 新机器怎样启动？ | README 与命令 |
| 证据 | 成功或失败如何判定？ | 测试、日志、压测记录 |
| 取舍 | 为什么不用另一个方案？ | 一条明确边界 |
| 下一步 | 目前还不解决什么？ | 风险清单 |

不要把没有跑过的性能数字、没有审过的“高可用”、没有亲自实现的中间件写成成果。诚实的边界比漂亮但不可追问的名词更经得起面试。

## 四、最低验收：六项全过才进入简历

- [ ] 从干净环境按 README 在合理时间内启动。
- [ ] 演示一条核心业务链路，并说明每个状态如何变化。
- [ ] 有至少一个自动化测试或可重复的手工验收脚本。
- [ ] 能指出一个真实失败场景及定位方法。
- [ ] 能解释一个取舍：一致性、延迟、成本或复杂度中放弃了什么。
- [ ] 能在五分钟内讲完，再承受三轮随机追问。

前四项证明“做过”，后两项证明“理解过”。

## 五、五分钟项目陈述模板

按六句讲，不要从框架版本开始：

1. **问题**：我做的是……，核心用户/业务动作是……。
2. **约束**：最大的难点是……，因此不能只用……。
3. **方案**：主链路是……，关键数据由……保证。
4. **证据**：我用……验证；结果按……口径记录。
5. **取舍**：当前选择优先保证……，代价是……。
6. **下一步**：如果流量/数据量到……，我会先补……。

这六句要与代码、README、测试或演示记录能互相印证。讲不清的地方不是背稿不够，而是项目证据缺了一环。

## 六、一次真实翻车：把"我以为"说成了"我做到"

阿零第一次真人模拟面试，对面是领姐找来的一位老板。

阿零讲得挺顺，讲到性能那段，他脱口而出：「秒杀这块能撑住三千 QPS。」

对面停了一下，问：「怎么测的？」

阿零：「……我用 JMeter 压过。」
「多少并发？数据库什么配置？连接池多大？测了多久？」
「……我记不太清了，反正当时看到过这个数。」
「那你现在能再跑一遍给我看吗？」
「……脚本我好像没存。」

场面安静了五秒。老板没为难他，只说了一句：「你前面讲得都挺好。就这一句，让我开始怀疑前面那些是不是也这样。」

> [!吐槽] 豆豆：「三千 QPS 你留不住，倒是把'不可信'三个字牢牢刻在人家心里了。这波性价比真高。」

## 七、复盘出根因

| 层次 | 内容 |
|---|---|
| 表象 | 一个数字答不上追问 |
| 直接原因 | 压测没有留脚本、参数和环境记录 |
| 根因 | 把"我曾经看到过"当成了"我能证明" |
| 本可以怎样 | 要么留下可重放的记录，要么老实说"这块我还没有测过口径" |

真正伤人的不是那个数字不对，而是**一处不可验证会污染全部叙述**。面试官没法逐条核你，他只能抽样；抽到一处编的，就默认其余也可能是编的。

反过来说：一句"这块我暂时没有可信数据，我只能给出我验证过的部分"，代价小得多。诚实的边界不减分，虚构的成果才减分。

> **💬 沟通拆解 · 项目里的数字怎么说才对**
>
> | 场景 | 常见说法（反面） | 问题出在哪 | 改写后 |
> |---|---|---|---|
> | 讲性能 | 「能撑三千 QPS。」 | 无口径、无法复现，一追就崩 | 「我在本机 8 核 / MySQL 8.0 / 连接池 20 的条件下压过 200 并发，成功率 100%，脚本在仓库 `bench/`。更高的量我没测过。」 |
> | 讲可用性 | 「做了高可用。」 | "高可用"是形容词不是事实 | 「单点仍然存在：数据库只有一个实例。我做的是接口幂等和失败重试，挂了不会脏数据，但会不可用。」 |
> | 讲不会的 | 「这个我了解一些。」 | 模糊，追问必翻车 | 「这块我只读过文档没落地过。我能讲清它解决什么问题，但没有实践证据。」 |
>
> 一句套路小结：**说数字必带口径，说能力必带边界，没做过的直接说没做过。**

## 八、两周内的正确顺序

| 顺序 | 任务 | 产出 |
|---|---|---|
| 1 | 选一个 Java 后端项目作主项目 | 一页项目证据卡 |
| 2 | 跑通核心链路并固定环境 | 可复制启动命令 |
| 3 | 加一条并发或异常验收 | 测试/脚本与结果 |
| 4 | 写 README、架构图、复盘 | 可公开链接或仓库文档 |
| 5 | 录一次五分钟讲解并自问三题 | 待补清单 |
| 6 | 再把 RSVQA 作为差异化项目 | 工程化证据，而非模型名词 |

Java 基础、MySQL、Redis 与面试题仍然是主干；项目证据包让这些知识在投递时有落点。站内的 [Java 面试与生产排障题库](/posts/2026-07-29-java-interview-production-playbook) 可作为随机追问清单，而不是新的背诵任务。

## 九、今天就做

创建一个 `PROJECT_EVIDENCE.md`，先只写六个标题：问题、主链路、运行、证据、取舍、下一步。空白比虚构好；每补齐一项，就用命令、截图、测试输出或代码链接作证。

> **🧭 路线台 · 这周你可以做的三件事**
>
> 1. 找一台干净环境（新虚拟机、同学的电脑、或 `docker run` 一个空容器），只照着自己的 README 走，不许凭记忆补任何一步。把每一次卡住都记下来——那就是 README 缺的行。
> 2. 挑简历上最硬的一个数字，现在重跑一遍。跑得出来就把脚本和环境写进仓库；跑不出来就今天从简历里删掉。
> 3. 下周自检一句：把项目讲给一个不懂技术的人听，五分钟内他能说出"这东西是给谁解决什么麻烦的"吗？说不出，是你的主链路还没想清，不是他笨。
>
> 领姐结语：技术是船，方向是舵——先校准方向，再谈速度。

## 十、项目检查点

咖啡站点单系统此刻的状态：

- **已具备**：一份六字段项目证据卡的骨架；一条能对外讲的主链路；一条"数字必带口径"的红线。
- **还没有**：干净环境的一键启动；自动化验收；三次可解释的亲手改动记录。

阿零的变化：他还是那个技术过关的人，但第一次意识到「做出来」和「能被验证」是两件事。

## 十一、对应招聘技能

项目表达、工程素养、README 与文档能力、工程诚信（不虚构成果）。

## 十二、下一话

证据卡的第一栏"问题"，阿零填的是"秒杀不能超卖"。领姐看了一眼，问他：「那你怎么证明它不超卖？」阿零说我测过啊。领姐说，测过不算——**得让"不超卖"变成一条会失败的测试**。
