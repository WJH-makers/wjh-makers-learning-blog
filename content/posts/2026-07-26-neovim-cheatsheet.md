# Neovim 速查 · 从打开到退出的全周期

> 基线：Neovim 0.11+（Lua 配置、内置 `vim.lsp.config` / `vim.lsp.enable`）。纯 Vim 8 与 0.10 及以下用户看到「0.11 起」标注处需自行降级替换。

## 快速导航

| 阶段 | 一句话 |
|------|--------|
| 一、打开与退出 | 先学会怎么出去，再学怎么进来 |
| 二、模式与移动 | 光标不是靠 `hjkl` 挪的，是靠语义跳的 |
| 三、编辑与文本对象 | 全部编辑 = 算子 × 范围，不是背快捷键 |
| 四、搜索与替换 | `/` 找、`:s` 换、`:g` 批量、quickfix 跨文件 |
| 五、多文件与缓冲区 | buffer / argslist / quickfix 三张列表的分工 |
| 六、窗口与分屏 | `<C-w>` 前缀一族 + tab 是「布局」不是「文件」 |
| 七、寄存器与宏 | 剪贴板只是寄存器的一种；宏是可回放的编辑 |
| 八、配置与插件管理 | init.lua、stdpath、runtimepath 与插件加载 |
| 九、LSP 与补全 | 0.11 新 API 与默认键位、内置补全 |
| 十、救命操作 | 撤销树、swap 恢复、最小化复现 |

## 一、打开与退出（先解决「怎么出去」）

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `nvim file` | 打开文件 | 文件不存在不会立刻创建，`:w` 时才真正落盘 |
| `nvim +42 file` / `nvim +/pat file` | 打开即跳到第 42 行 / 首个匹配 | 脚本、日志定位常用；`+` 后是 Ex 命令，可写 `+"set ft=json"` |
| `nvim -R file` | 只读打开 | 「只读」只是提示，仍可 `:w!` 强写；要真禁改用 `-M`（关掉 modifiable） |
| `:w` | 存盘，不退出 | 只写当前 buffer；`:w newname` 是另存但**当前 buffer 仍指向原文件** |
| `:q` | 关闭当前窗口 | 有未保存改动报 `E37`；分屏时只关一个窗口，不是退出程序 |
| ⚠ `:q!` | 丢弃改动强退 | 改动直接消失且不进撤销树，不可挽回。犹豫就先 `:w /tmp/backup` |
| `:wq` | 写盘 + 退出 | **无论是否修改都执行写入** → mtime 变化，会误触发 watch/热重载/`make` 重编译 |
| `:x` / `ZZ` | 有改动才写，然后退出 | 日常首选，比 `:wq` 干净。`ZZ` 是 Normal 模式两键版 |
| `ZQ` | 等价 `:q!` | 记忆法：`ZZ` 保存走人，`ZQ` 摔门就走 |
| `:qa` / `:qa!` | 关闭所有窗口退出 | 多分屏 / 多 tab 时 `:q` 关不干净，`:qa` 才是真退出 |
| `:wqa` / `:xa` | 全部写盘并退出 | `:xa` 同样是「改了才写」，优于 `:wqa` |
| `:e!` | 重读磁盘内容，丢弃所有改动 | 「不退出版的 `:q!`」；改砸了但不想退出时用它 |
| `Ctrl-z` | 挂起到 shell | **不是退出**，进程还在。`fg` 回来；直接 `kill` 会丢 swap 未落盘内容 |
| `:terminal` | 打开内置终端 | 终端模式下 `<Esc>` 会被透传给子进程，回 Normal 要按 `<C-\><C-n>` |
| ⚠ `:w !sudo tee % > /dev/null` | 无权限时提权写 | 这条在 Neovim 里**基本不可用**（无法交互式输密码）。正解：`:w /tmp/f` 再在 shell 里 `sudo mv` |

## 二、模式与移动

### 模式切换

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `i` / `a` / `I` / `A` | 进入插入：光标前 / 后 / 行首非空 / 行尾 | `A` 比 `$a` 少一次按键，写代码结尾分号必用 |
| `o` / `O` | 下方 / 上方开新行并插入 | 会带 autoindent；纯粹加空行不想动光标用 `:normal! o<Esc>` |
| `<Esc>` / `<C-[>` / `<C-c>` | 回 Normal | `<C-c>` 会中断 `InsertLeave` 相关自动命令与 abbrev，插件行为可能异常，优先 `<Esc>` |
| `v` / `V` / `<C-v>` | 字符 / 行 / **块**可视模式 | 块选是 Vim 独门武器，列编辑靠它。Windows 终端里 `<C-v>` 可能被粘贴占用 |
| `gv` | 重选上次可视区域 | 缩进反复调整（`>` 后选区丢失）时救命 |
| `R` | 替换模式 | 按退格是「还原原字符」而非删除，容易看懵 |
| `:` | 命令行模式 | 中文输入法下打出全角 `：` 无效，先切英文 |
| `q:` | 打开命令行历史窗口 | 可像普通 buffer 一样编辑再回车执行；误触很常见，`:q` 退出即可 |

### 移动

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `w` / `b` / `e` | 按单词前 / 后 / 词尾 | 小写以标点分词，大写 `W B E` 以空白分词，改路径、URL 用大写 |
| `0` / `^` / `$` / `g_` | 行首 / 首个非空 / 行尾 / 末个非空 | `$` 在有行尾空格时会停在空格上，`g_` 更适合接 `d` |
| `gg` / `G` / `42G` | 首行 / 末行 / 第 42 行 | `42gg` 等价；`:42` 也行但会进命令行 |
| `{` / `}` | 上/下一个空行（段落） | 代码里等价于「按空行分块跳」，比翻页精准 |
| `f{c}` / `t{c}` / `F` / `T` | 行内跳到 / 跳到前一位 字符 | `;` 重复、`,` 反向重复。`t` 配合 `d` 是 `dt,` 这类操作的基础 |
| `%` | 在配对括号间跳 | 光标不在括号上时会先向后找到本行第一个括号；能配对 `#if/#endif` 等 |
| `H` / `M` / `L` | 跳到屏幕顶 / 中 / 底 | 是「屏幕」不是「文件」，滚屏后含义就变了 |
| `<C-d>` / `<C-u>` / `<C-f>` / `<C-b>` | 半页下/上、整页下/上 | `<C-f>/<C-b>` 容易迷失上下文，日常优先半页 |
| `zz` / `zt` / `zb` | 当前行居中 / 置顶 / 置底 | 跳转后立刻 `zz` 是找回上下文的肌肉记忆 |
| `m{a-z}` / `` `{a-z} `` | 打标记 / 跳回标记 | 小写标记只在本 buffer 有效，大写 `mA` 跨文件全局有效 |
| `` `` `` / `''` | 跳回上次跳转位置（精确到列 / 行首） | 大跳后想回头，最快的一招 |
| `<C-o>` / `<C-i>` | 跳转列表后退 / 前进 | 像浏览器前进后退；`<C-i>` 与 `<Tab>` 是同一个键码，重映射 `<Tab>` 会连带失效 |
| `g;` / `g,` | 在**修改点**之间跳 | 与跳转列表不同，专门找「我刚才改哪了」 |

## 三、编辑与文本对象（核心心智模型）

**记住这一条公式，胜过背 50 个快捷键：**

```
{算子}{数量}{动作或文本对象}
   d      2        w        → 删两个词
   c      i        "        → 改引号内内容
   y      a        {        → 复制含花括号的整块
```

### 算子（作用于一段范围）

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `d` / `c` / `y` | 删除 / 改（删+进插入） / 复制 | 三者接受完全相同的范围语法，学会一个等于学会三个 |
| `d`/`c`/`y` 双写 | `dd` `cc` `yy` 作用于整行 | `cc` 保留缩进，`S` 是它的同义词 |
| `>` / `<` / `=` | 缩进 / 反缩进 / 自动对齐 | `=` 依赖 `indentexpr`，无 treesitter/插件时对某些语言效果一般 |
| `gu` / `gU` / `g~` | 转小写 / 大写 / 反转 | `guiw` 把当前词变小写 |
| `gq` / `gw` | 按 `textwidth` 重排段落 | `gw` 排完光标不动，写 Markdown 更顺手。注意 LSP 附着后 `gq` 会走 `formatexpr` 变成调用 LSP 格式化 |
| `gc`（0.10+ 内置） | 注释/取消注释 | `gcc` 整行、`gcap` 整段。0.10 以前需插件 |
| `!` | 把范围送给外部命令过滤 | `!ipsort<CR>` 排序一段；⚠ 命令出错会用错误输出**覆盖**原文，先 `u` 可救 |

### 文本对象（范围）

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `iw` / `aw` | 词内 / 词加相邻空白 | `daw` 删词后不留双空格，`diw` 会留 |
| `is` / `as` | 句内 / 句含尾随空白 | 句子边界靠 `.!?` + 空白判定，中文全角标点通常不生效 |
| `ip` / `ap` | 段内 / 段含空行 | 代码里就是「一个空行分隔的块」 |
| `i"` `i'` `` i` `` / `a"` … | 引号内 / 含引号 | 光标在引号**之前的同一行**也能生效，不必精准停在里面 |
| `i(` `i)` `ib` / `a(` … | 圆括号内 / 含括号 | `ci(` 换函数参数是最高频组合之一 |
| `i{` `i}` `iB` / `a{` … | 花括号块内 / 含大括号 | `ya{` 复制整个代码块，`di{` 清空函数体 |
| `i[` / `a[` | 方括号内 / 含括号 | 改数组下标、JSON 数组常用 |
| `i<` / `a<` | 尖括号内 / 含括号 | 改泛型 `List<String>` 的 `String`：`ci<` |
| `it` / `at` | XML/HTML 标签内 / 含标签 | 对 JSX、Vue 模板同样有效；标签不闭合时会往外找错层级 |

### 高频组合（背这些就够）

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `diw` / `ciw` | 删/改光标所在词 | 不用先移到词首，光标在词中任意位置都行 |
| `ci"` / `ci'` | 换掉引号里的字符串 | 改配置文件、改路径的默认动作 |
| `ci(` / `da(` | 改参数列表 / 连括号删掉调用 | `da(` 常用于删掉多余的一层包装调用 |
| `ya{` / `di{` | 整块复制 / 清空块体 | 配合 `%` 检查配对是否如预期 |
| `dt,` / `ct)` | 删到下一个逗号前 / 改到右括号前 | `t` 系列不吃掉目标字符，正是想要的边界 |
| `x` / `s` / `D` / `C` | 删字符 / 删字符并插入 / 删到行尾 / 改到行尾 | `D` = `d$`，`C` = `c$` |
| `J` / `gJ` | 合并下一行（补空格）/ 合并且不补 | `J` 会把缩进和多余空白压成一个空格，粘贴代码后修复很好用 |
| `<C-a>` / `<C-x>` | 数字加一 / 减一 | 可带数量：`10<C-a>`。注意 `007` 默认可能被当八进制，可 `set nrformats-=octal` |
| `.` | 重复上一次「改变文本」的操作 | 移动和 Ex 命令不算改变，`.` 不会重复它们。设计操作时尽量让它可被 `.` 复用 |
| `<C-v>` → `I`/`A` → `<Esc>` | 块选后批量在多行行首/行尾插入 | 必须按 `<Esc>` 才会同步到其余各行，按 `<C-c>` 有时不同步 |

## 四、搜索与替换

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `/pat` / `?pat` | 向下 / 向上搜索 | 回车后 `n` / `N` 继续；`N` 的方向随初始方向反转 |
| `*` / `#` | 搜索光标下的词（向下/向上） | 自动加词边界 `\<\>`，搜变量名比手打准 |
| `:noh` | 清掉高亮 | 高亮是「状态」不是「模式」，换个搜索不清也行 |
| `\v` | very magic，正则接近 PCRE | `/\v(foo\|bar)+` 省掉一堆反斜杠，强烈建议养成习惯 |
| `\c` / `\C` | 本次搜索强制忽略/区分大小写 | 写在模式任意位置都生效，比改 `ignorecase` 省事 |
| `:%s/old/new/g` | 全文替换 | 少了 `%` 就只替换当前行；少了 `g` 每行只替换第一个 |
| `:%s/old/new/gc` | 逐个确认替换 | `y` 换 / `n` 跳 / `a` 全部 / `q` 停 / `l` 换完就停 |
| `:%s//new/g` | 复用上一次搜索模式 | 先 `/pat` 看准命中，再空模式替换，比一次写对更稳 |
| `:'<,'>s/…` | 仅在可视选区替换 | 可视模式按 `:` 会自动补出 `'<,'>` |
| `:s/…/…/` + `&` | 在下一处重复上次替换 | `&` 不带 flag，需要 flag 用 `g&` |
| `inccommand` | 替换实时预览 | Neovim 默认已开（`nosplit`）。设 `:set inccommand=split` 可在分屏中预览全部命中 |
| ⚠ `:g/pat/d` | 删除所有匹配行 | 极易误伤：先 `:g/pat/p` 或 `:g/pat/#` 看清命中行再执行 |
| `:v/pat/d` | 删除所有**不**匹配的行 | `:v` = `:g!`，做日志抽取神器 |
| `:g/pat/normal @a` | 对每个匹配行回放宏 | 比录一个「大宏」稳得多 |
| `:vimgrep /pat/ **/*.java` | 全项目搜索进 quickfix | 纯 Vimscript 实现，大项目慢；有 rg 时优先下一条 |
| `:grep pat` | 走外部 grep 程序 | 先 `:set grepprg=rg\ --vimgrep\ --smart-case`，速度差一个数量级 |
| `:cdo s/a/b/g \| update` | 对 quickfix 中每一**行**执行替换并保存 | 跨文件重构主力；`:cfdo` 是按**文件**粒度 |

## 五、多文件与缓冲区

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `:e path` | 打开/切换到文件 | 相对当前工作目录，不是相对当前文件；`:e %:h/` 才是「当前文件同级」 |
| `:ls` / `:buffers` | 列出所有 buffer | `%` 当前、`#` 轮换、`+` 已修改、`h` 隐藏 |
| `:b N` / `:b name` | 按编号 / 名字片段切 buffer | 名字支持模糊片段，多个命中会报错，加 `:b#` 更快 |
| `<C-^>` / `<C-6>` | 在当前与上一个 buffer 间来回切 | 双文件对照编辑最快的一招 |
| `:bn` / `:bp` / `:bf` / `:bl` | 下/上/首/末一个 buffer | buffer 顺序是打开顺序，不是显示顺序，用多了容易乱 |
| `:bd` | 卸载 buffer | **不会关闭窗口**；有未保存改动会拒绝，`:bd!` 丢改动 |
| `:bufdo cmd` | 对每个 buffer 执行命令 | 需要 `set hidden`（Neovim 默认已开）；批量操作前先 `:bufdo` 加 `\| update` 落盘 |
| `:args *.java` / `:argdo cmd` | 设定参数列表并批处理 | argslist 是「本次任务清单」，比 buffer 列表更可控 |
| `:copen` / `:cclose` | 打开/关闭 quickfix | `:cnext` `:cprev` 逐条跳；`:cnewer` / `:colder` 在历史结果间切换 |
| `:lopen` / `:lnext` | location list（窗口局部） | LSP 诊断常写进 location list，别和 quickfix 搞混 |
| `:cd` / `:lcd` / `:tcd` | 改全局 / 窗口 / tab 的工作目录 | `:lcd` 只影响当前窗口，多项目并行时用它避免互相污染 |
| `gf` / `<C-w>f` | 打开光标下路径 / 在新窗口打开 | 依赖 `path` 与 `suffixesadd` 设置，Java 包名路径通常需要自行配 |
| `:earlier` 前先 `:w` | 切文件前存盘 | Neovim 允许带修改切走（hidden），退出时才提醒，容易堆一堆未保存 buffer |

## 六、窗口与分屏

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `:sp` / `<C-w>s` | 水平分屏（上下） | 分的是同一个 buffer 的两个视图，改一处两处同步 |
| `:vs` / `<C-w>v` | 垂直分屏（左右） | 记忆：`v` = vertical；`:vs file` 可直接在新窗口开文件 |
| `<C-w>h/j/k/l` | 按方向切换窗口 | 最值得映射成 `<C-h/j/k/l>` 的一组键 |
| `<C-w>w` / `<C-w>p` | 循环切换 / 回上一个窗口 | 窗口多时 `p` 比 `w` 好用 |
| `<C-w>c` / `<C-w>q` | 关闭窗口 / 退出窗口 | `q` 在最后一个窗口时会退出 Neovim，`c` 不会 |
| `<C-w>o` | 只保留当前窗口 | ⚠ 一次关掉其余全部窗口，布局无法撤销，慎用 |
| `<C-w>H/J/K/L` | 把当前窗口移到最左/下/上/右 | 大写=搬窗口，小写=挪光标，这是最常混的一对 |
| `<C-w>=` | 所有窗口等宽等高 | 调乱了先按它复位 |
| `<C-w>_` / `<C-w>\|` | 当前窗口高度/宽度最大化 | 配合 `<C-w>=` 做「临时聚焦」 |
| `10<C-w>+` / `10<C-w><` | 增高 10 行 / 减宽 10 列 | 也可 `:resize 30` / `:vertical resize 100` |
| `<C-w>T` | 把当前窗口拆成新 tab | tab 在 Vim 里是**布局容器**，不是「文件标签页」，别按 IDE 直觉用 |
| `:tabnew` / `gt` / `gT` / `2gt` | 新建 / 下一个 / 上一个 / 第 2 个 tab | 想要 IDE 式标签栏应该管理 buffer，而不是开一堆 tab |
| `:diffthis` / `:diffoff` | 把当前窗口加入/移出 diff | 两个窗口各 `:diffthis` 即可比对；`]c` `[c` 跳差异，`do` / `dp` 取入/推出 |
| `nvim -d a b` | 直接进 diff 模式 | 等价 `vimdiff`；可作为 git 的 difftool |

## 七、寄存器与宏

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `:reg` / `:reg a` | 查看全部 / 指定寄存器 | 排查「粘出来的怎么不是我复制的」第一步 |
| `"ayy` / `"ap` | 存入/取出具名寄存器 a | 大写 `"Ayy` 是**追加**到 a，收集多处片段很好用 |
| `""` | 无名寄存器 | 任何 `d` `c` `x` `y` 都会写它 —— 这就是「删一行后粘贴丢失」的原因 |
| `"0` | 最近一次 yank 专用寄存器 | 复制后又删过东西？用 `"0p` 找回原来复制的内容 |
| `"1` ~ `"9` | 删除历史（滚动） | `"1p` 后按 `.` 会依次粘 `"2` `"3`，翻删除历史的隐藏技巧 |
| `"+` / `"*` | 系统剪贴板 / 选择区 | 需要剪贴板提供者（`win32yank`、`wl-copy`、`pbcopy` 等），`:checkhealth provider` 自查 |
| ⚠ `"_d` | 黑洞寄存器删除 | 删除且**不污染**无名寄存器；`viw"_dP`（先删再粘）是「用剪贴板覆盖单词」的正确写法 |
| `"%` / `":` / `".` | 当前文件名 / 上条命令 / 上次插入文本 | `:put %` 快速把路径写进文件 |
| `<C-r>a`（插入模式） | 插入寄存器 a 内容 | 命令行模式同样可用：`:%s/<C-r>a//g` |
| `<C-r><C-w>`（命令行） | 把光标下的词塞进命令行 | 写替换命令时省掉手打变量名 |
| `q{a-z}` … `q` | 开始 / 结束录制宏 | 状态栏显示 `recording @a`；忘了在录制中会越录越乱，先 `q` 再 `:reg a` 确认 |
| `@a` / `@@` | 回放宏 / 重放上次宏 | `100@a` 批量回放，出错（如搜索不到）会自动中断，反而是安全阀 |
| `qA` | 追加录制到寄存器 a | 宏录漏一步时不必重录 |
| `:'<,'>normal @a` | 对选区每行回放宏 | 比 `100@a` 更可控，边界明确 |
| 宏编辑 | `"ap` 粘出宏 → 改文本 → `"ayy` 存回 | 宏就是一串按键文本，可以像编辑代码一样修它 |

## 八、配置与插件管理（Lua）

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `:echo stdpath('config')` | 配置目录 | Linux/macOS `~/.config/nvim`，Windows `~/AppData/Local/nvim`。改 `XDG_CONFIG_HOME` 会整体搬家 |
| `:echo stdpath('data')` / `('state')` | 插件数据 / 运行状态（swap、undo、shada） | 清插件缓存删 `data`，救数据去 `state`，别删错 |
| `init.lua` | 主配置入口 | 与 `init.vim` **只能存在一个**，两个都在会报错 |
| `vim.o.opt = val` | 设置选项 | `vim.o` 通用标量；列表型选项（`runtimepath`、`shortmess`）用 `vim.opt` 才有 `:append/:remove` |
| `vim.g.mapleader = ' '` | 设 leader 键 | **必须在任何映射定义之前**执行，否则先定义的映射记的是旧 leader |
| `vim.keymap.set('n','<leader>w','<cmd>w<CR>')` | 定义映射 | 默认 `remap=false`；`<cmd>` 优于 `:`，不会打断可视选区或触发模式切换 |
| `vim.api.nvim_create_autocmd` | 自动命令 | 一定配 `group = vim.api.nvim_create_augroup('x', { clear = true })`，否则 reload 配置会重复注册 |
| `require('mod')` | 加载 `lua/mod.lua` | 有缓存；改完文件同一会话内不会自动重载，需重启或 `package.loaded['mod'] = nil` |
| `:lua= vim.o.shiftwidth` | 求值并打印 | 0.9+ 的 `=` 简写，调试配置最快的手段 |
| `:source %` / `:luafile %` | 重载当前配置文件 | 只对幂等配置安全；带副作用的（autocmd、插件 setup）重载后行为可能叠加 |
| `:verbose set sw?` | 查这个选项**被谁**改的 | 排查「我明明设了却不生效」的唯一正解，`:verbose map <C-h>` 同理 |
| `~/.config/nvim/pack/x/start/` | 内置包机制，启动即加载 | 无需插件管理器；放 `opt/` 下则需 `:packadd name` 手动加载 |
| `:h packages` | 内置包文档 | 只用两三个插件时，内置包 + git submodule 比引入管理器更省心 |
| lazy.nvim | 社区主流插件管理器 | 生态最全；`:Lazy` 面板看加载耗时，懒加载配错会出现「命令找不到」 |
| `vim.pack.add{...}` | **内置**插件管理（0.12+ / nightly） | 0.11 稳定版**没有**这个 API，别照抄新文章的配置 |
| `:checkhealth` | 全面体检 | 装完插件、换完终端第一件事；`:checkhealth vim.lsp` 单查 LSP |

## 九、LSP 与补全

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `vim.lsp.config('name', {...})` | 定义某个 server 配置（0.11 起） | 取代旧的 `require('lspconfig').name.setup{}`；`vim.lsp.config('*', {...})` 设全局默认 |
| `vim.lsp.enable('name')` | 启用 server（0.11 起） | 必须调用，`config` 只是登记不启动 |
| `~/.config/nvim/lsp/name.lua` | 按文件放置 server 配置（0.11 起） | 返回一个 table 即可，会被 `vim.lsp.enable` 自动拾取，无需 `require` |
| `root_markers = {'pom.xml','.git'}` | 项目根识别 | 找不到根 → server 起不来或索引整个 home，卡死多半是这里 |
| `K` | 悬浮文档（0.11 默认已映射） | 无 LSP 时 `K` 是查 man page，行为不同别惊讶 |
| `grn` / `gra` / `grr` / `gri` | 重命名 / code action / 引用 / 实现（0.11 默认） | 是 `gr` 前缀不是 `<leader>`；旧配置里手动映射的 `gr` 会与之冲突 |
| `gO` | 文档符号大纲（0.11 默认） | 在 help 文件里 `gO` 是显示目录，同一个键两种用途 |
| `<C-s>`（插入模式） | 签名帮助（0.11 默认） | 部分终端把 `<C-s>` 当流控会假死，按 `<C-q>` 解开或在终端关掉 `ixon` |
| `<C-]>` / `<C-t>` | 跳定义 / 跳回 | LSP 附着后 `tagfunc` 自动接管，不需要额外映射就能跳定义 |
| `<C-x><C-o>` | omni 补全 | LSP 会自动设 `omnifunc`，这是**零插件补全**的入口 |
| `vim.lsp.completion.enable(true, client_id, bufnr, { autotrigger = true })` | 内置自动补全（0.11 起） | 写在 `LspAttach` 自动命令里；不加 `autotrigger` 就只能手动 `<C-x><C-o>` |
| `<C-n>` / `<C-p>` / `<C-x><C-f>` / `<C-x><C-l>` | 关键字 / 反向 / 路径 / 整行 补全 | 不依赖任何插件与 LSP，救急永远可用 |
| `vim.lsp.buf.format({ async = true })` | 格式化 | 保存时格式化务必用**同步**版本，`async` 会与写盘竞态导致格式化丢失 |
| `]d` / `[d` | 跳下/上一个诊断 | 0.11 起底层是 `vim.diagnostic.jump({count=1, float=true})`，`goto_next/goto_prev` 已废弃 |
| `vim.diagnostic.open_float()` | 显示当前行诊断详情 | 行尾虚拟文本被截断时用它看全文 |
| `vim.diagnostic.config({ virtual_lines = true })` | 诊断多行展示（0.11 起） | 长报错（泛型、TS 类型）可读性提升明显；占屏，可只在 `current_line` 开 |
| `vim.diagnostic.setqflist()` | 把诊断汇总进 quickfix | 配合 `:cdo` 可批量处理同类问题 |
| `vim.o.winborder = 'rounded'` | 全局浮窗边框（0.11 起） | 一行搞定 hover/签名框边框，不必再逐个插件配 |
| `:checkhealth vim.lsp` | 查 LSP 状态 | 看 client 是否 attach、root 在哪、cmd 是否找得到 |
| `:LspLog` / `vim.lsp.set_log_level('debug')` | 查 LSP 日志 | 日志在 `stdpath('state')/lsp.log`，调完记得关，debug 级别文件涨得飞快 |

## 十、救命操作（撤销树、崩溃恢复）

| 命令 | 作用 | 备注 / 坑 |
|------|------|-----------|
| `u` / `<C-r>` | 撤销 / 重做 | 一次插入过程算**一次**撤销单元，长时间不出 Normal 会一撤全没；打断点可在插入模式按 `<C-g>u` |
| `U` | 撤销对当前行的全部修改 | 是 Vim 独有的「行级撤销」，本身也可被 `u` 撤销 |
| `g-` / `g+` | 在撤销**树**上按时间前后移动 | `u` 撤销后又编辑会开新分支，旧分支只能靠 `g-` 找回，这是最常被丢掉的数据 |
| `:undolist` | 列出撤销树各分支 | 看 number / changes / time，再用 `:undo N` 精确跳到某个状态 |
| `:earlier 10m` / `:later 5m` | 回到 10 分钟前 / 前进 5 分钟 | 单位 `s/m/h/d`；`:earlier 3f` 是「回退 3 次文件写入」，最贴近「回到上次保存」 |
| `vim.o.undofile = true` | 持久化撤销历史 | 关闭文件重开仍能 `u`。历史存在 `stdpath('state')/undo`，含文件内容片段，**敏感项目慎开** |
| `:e!` | 丢弃改动重读磁盘 | 改砸了的最快复位；执行后本次改动仍在撤销树里，可 `u` 反悔 |
| `nvim -r file` | 从 swap 恢复崩溃前内容 | 恢复后另存为新文件对比，确认无误再覆盖，最后删掉 `.swp` |
| `:recover` | 已打开时从 swap 恢复 | 出现 `E325 ATTENTION` 说明有 swap：要么是崩溃残留，要么**另一个实例正开着同一文件** |
| `:sw` 目录定位 | swap 在 `stdpath('state')/swap` | 确认无用再删；`:set noswapfile` 只对当前 buffer 生效 |
| `:w %.bak` | 就地留一份备份 | 大改前一秒的保险，比事后追悔便宜 |
| `nvim --clean` | 不加载任何配置与插件启动 | 复现问题第一步：能复现 = Neovim/终端问题，不能复现 = 你的配置问题 |
| `nvim -u NONE -N` | 无配置 + 强制 nocompatible | 比 `--clean` 更干净，写最小复现给上游提 issue 用 |
| `:messages` | 回看被刷掉的报错 | 启动瞬间闪过的错误全在这；`:h news` 看当前版本的破坏性变更 |
| ⚠ `:qa!` | 强退所有窗口 | 所有未保存 buffer 一起丢；退出前先 `:ls` 看有没有带 `+` 的 |

## 常见错误速判

| 症状 | 多半是 | 先试这条 |
|------|--------|----------|
| 敲什么都变成插入字符 | 还在 Insert / Replace 模式 | `<Esc>`，看状态栏是否还有 `-- INSERT --` |
| `:q` 报 `E37` 退不出去 | 有未保存改动 | `:w` 后 `:q`，确定要丢改动才 `:q!` |
| 整个界面按键无响应，也没崩 | 误按 `<C-s>` 触发终端流控 | `<C-q>` 解锁；根治在终端关掉 `ixon` |
| 打开文件提示 `E325 ATTENTION` | 上次崩溃残留 swap，或另一实例正开着 | 先确认没有第二个 nvim 进程，再 `nvim -r file` |
| `y` 复制的内容在系统里粘不出来 | 没写进 `"+`，或缺剪贴板提供者 | `"+y`；`:checkhealth provider` 看是否缺 `win32yank`/`wl-clipboard` |
| 删一行后 `p` 粘出来的不是刚复制的 | `dd` 覆盖了无名寄存器 | 用 `"0p`；根治用 `"_dd` 删除 |
| `.` 重复不生效 | 上一步是移动或 Ex 命令 | `.` 只重复改变文本的操作；批量走宏或 `:g` |
| `gq` 变成了 LSP 格式化 | LSP 附着后接管了 `formatexpr` | `:setlocal formatexpr=` 恢复内置换行 |
| LSP 完全没反应 | server 没启动或项目根没识别 | `:checkhealth vim.lsp`，重点看 `root_markers` 与 `cmd` 路径 |
| 补全弹不出来 | 未启用内置补全，且没装补全插件 | 先试 `<C-x><C-o>`；能出说明只是没开 `vim.lsp.completion.enable` |
| 设置的选项莫名被改回去 | 插件或 ftplugin 覆盖了 | `:verbose set 选项?` 直接看是哪个文件第几行改的 |
| 撤销撤不回三分钟前的状态 | 撤销树分叉了 | `g-` 沿时间倒退，或 `:earlier 3m` |
| 中文/图标显示错位 | 终端字体缺字形或宽度判定不一致 | 换 Nerd Font 等宽字体，必要时 `:set ambiwidth=single` |
| 配置改完启动变慢好几秒 | 插件同步加载或 shada/undo 文件过大 | `nvim --startuptime /tmp/st.log` 看耗时排序 |

## 一页纸口诀

1. 先学会出去：`:x` 改了才写，`:wq` 一律都写（会触发 watcher），`:q!` 是把改动直接扔掉。
2. 一切编辑 = **算子 × 范围**：会了 `d/c/y` 配 `iw / i" / a{`，就不用再背快捷键表。
3. 光标靠语义移动：`w } f{c} % <C-o>`，`hjkl` 连按超过三下就说明选错了动作。
4. 能被 `.` 重复的操作优先，重复三次以上再考虑录宏，跨文件才动 quickfix + `:cdo`。
5. 感叹号 = 强制 = 有东西要丢：`q!` `e!` `bd!` `%s` 少了确认，按下前先问一句「丢的是什么」。
6. 剪贴板只是寄存器之一：`"+` 系统、`"0` 最近复制、`"_` 黑洞、`"1`~`"9` 删除历史。
7. 撤销是**树**不是栈：`u` 回不去的地方，交给 `g-` 和 `:earlier`；重要项目开 `undofile`。
8. 0.11 的 LSP 不再需要包装层：`vim.lsp.config` + `vim.lsp.enable`，键位默认给了 `grn/gra/grr/K`。
9. 出问题的顺序永远是：`:messages` → `:checkhealth` → `nvim --clean` 二分，别一上来就删配置。
