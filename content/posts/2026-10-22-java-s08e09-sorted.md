## 三、本话目标

- 分清 Comparable(自然序)与 Comparator(外部序),用 `comparing/thenComparing/reversed` 组装规则;
- 用 TreeSet/TreeMap 维护恒有序排行榜,吃透 O(log n) 代价与 **compare==0 即判重**;
- 用 LinkedHashMap 的 `accessOrder` + `removeEldestEntry` 三行写出 LRU 热点榜;
- 用 Sequenced Collections(JDK 21)统一取首尾与倒序。

## 四、原理图:两把尺子与一棵树

```text
把「怎么比」告诉容器,只有两条路:
  Comparable<T>  自然序 —— 类自己实现 compareTo,写死在类里,一个类只有一种
                 (String、Integer、LocalDate 自带,所以 TreeSet<String> 裸奔也行)
  Comparator<T>  外部序 —— 尺子在类外,想要几把造几把,流水线组装:
                 comparing(主键) → thenComparing(平局补维) → reversed(翻转)

TreeSet / TreeMap(同一棵红黑树;TreeSet 就是 TreeMap 的马甲:add = put(e, 占位符))
  · 增删查全是 O(log n) —— 「永远有序」的价签(HashMap O(1) 但无序)
  · 判重铁律:compare(a, b) == 0 ⇒ 视为同一个元素,与 equals 无关
  · TreeMap 键有序还能切片:headMap / tailMap / subMap(「30 杯以上的」一刀切出)

LinkedHashMap(哈希表 + 一条双向链表)
  · 默认记「插入序」;构造传 accessOrder=true 改记「访问序」——每 get 一次挪到队尾
  · 访问序 + removeEldestEntry ⇒ 三行手写 LRU 缓存
```

> **豆豆锐评**:选容器先问一句「要不要顺序、要哪种」:插入序 → LinkedHashMap,比较序 → TreeMap/TreeSet,不要序 → HashMap/HashSet。有序从来不免费,O(log n) 就是价签。

## 五、代码:排行榜与热点榜

叫号系统(上一话的 PriorityQueue)照常跑,本话在它旁边新立一个 `Leaderboard`。

**第一脚:没递尺子。**`record` 又没实现 Comparable,无参 TreeSet 默认赌你有自然序——第一杯进门就要 `compare(自己, 自己)` 验明正身,当场炸:

```java
record SalesEntry(String name, int cups) {}

var board = new TreeSet<SalesEntry>();   // 没递尺子
board.add(new SalesEntry("拿铁", 41));   // ← 第一杯就炸
```

```text
Exception in thread "main" java.lang.ClassCastException: class SalesEntry cannot be cast
to class java.lang.Comparable (SalesEntry is in unnamed module of loader 'app';
java.lang.Comparable is in module java.base of loader 'bootstrap')
        at java.base/java.util.TreeMap.compare(TreeMap.java:1569)
        at java.base/java.util.TreeMap.addEntryToEmptyMap(TreeMap.java:776)
        at java.base/java.util.TreeMap.put(TreeMap.java:785)
        at java.base/java.util.TreeMap.put(TreeMap.java:534)
        at java.base/java.util.TreeSet.add(TreeSet.java:255)
        at Leaderboard.main(Leaderboard.java:12)
```

**递上尺子(Comparator 外部序),排行榜上线:**

```java
import java.util.Comparator;
import java.util.TreeSet;

record SalesEntry(String name, int cups) {}

public class Leaderboard {
    // 尺子:按销量降序(暂时只有这一维——伏笔)
    static final Comparator<SalesEntry> BY_SALES =
            Comparator.comparingInt(SalesEntry::cups).reversed();

    public static void main(String[] args) {
        var board = new TreeSet<>(BY_SALES);
        board.add(new SalesEntry("拿铁", 41));
        board.add(new SalesEntry("美式", 27));
        board.add(new SalesEntry("燕麦拿铁", 33));

        System.out.println("销冠:" + board.getFirst().name());   // JDK 21 起,统一入口
        System.out.println("垫底:" + board.reversed().getFirst().name());  // 倒序视图,不复制
        for (var e : board) {                                     // 中序一走,就是榜单
            System.out.println(e.name() + " " + e.cups() + " 杯");
        }
    }
}
```

> **⏳ 版本时光机 · 「取首尾元素」怎么变的**

| JDK 版本 | 写法 | 关键变化 |
|---|---|---|
| Java 8 | 首:`set.iterator().next()` / `list.get(0)`;尾:`list.get(list.size() - 1)`,SortedSet 另有 `first()/last()`,Deque 又是 `peekFirst()` | 每种容器一套方言,取个尾巴要么绕要么先数长度 |
| Java 21 | `getFirst()` / `getLast()` / `reversed()`(JEP 431,Sequenced Collections) | List、Deque、LinkedHashSet、TreeSet 统一入口;`reversed()` 是视图,倒着看不复制 |

一句演进小结:从「每个容器背一套 API」到「有顺序的容器共用一套」。

**热点榜:三行 LRU。**老板还要「最近被点过的 3 款」。LinkedHashMap 构造第三参 `accessOrder=true` 开访问序,再覆写一个钩子:

```java
var hot = new LinkedHashMap<String, Integer>(16, 0.75f, true) {
    @Override protected boolean removeEldestEntry(Map.Entry<String, Integer> eldest) {
        return size() > 3;   // 第 4 款进门,最久没人点的出局
    }
};
hot.put("拿铁", 1); hot.put("美式", 1); hot.put("摩卡", 1);
hot.get("拿铁");                    // 拿铁被翻牌,挪到队尾最新位
hot.put("可可", 1);                 // 第 4 款 → 踢掉最久未访问的「美式」
System.out.println(hot.keySet());   // [摩卡, 拿铁, 可可]
```

## 六、故意制造一个 Bug:尺子只量销量

新品「摩卡」冲量,恰好也卖到 27 杯,和美式打平。上榜:

```java
board.add(new SalesEntry("摩卡", 27));   // 与美式同销量
System.out.println(board.size());        // 期望 4
```

## 七、观察现象:后来者凭空消失

```text
3
拿铁 41 杯
燕麦拿铁 33 杯
美式 27 杯
```

没有异常、没有日志,摩卡**无声蒸发**。真凶就是漫画〔4〕那个门卫:`BY_SALES` 只量销量,27 对 27 量出 **0**——TreeSet 判定「你就是美式」,保留旧的、丢掉新的,`add` 默默返回 `false`,而阿零根本没看返回值。**在排序容器里,相等由 compare 说了算,equals 说了不算**;比较维度不全 = 判重规则漏水。

> **🎯 面试直击**:Comparable 与 Comparator 什么区别?TreeSet 判重靠什么?
> Comparable 是自然序:类自己实现 `compareTo`,写死类里、一类一种;Comparator 是外部序:规则在类外,可造多把、可 `thenComparing` 组装。TreeSet 判重**只看 compare 是否为 0,与 equals/hashCode 无关**。追问点:同一批对象放 HashSet(看 hashCode+equals)和 TreeSet(看 compare),size 可能不同——不是 Bug,是两套判重规则。

## 八、修复,并用测试证明

给尺子补上第二维:平局再按名字比,谁也不吞谁。

```java
static final Comparator<SalesEntry> BY_SALES =
        Comparator.comparingInt(SalesEntry::cups).reversed()
                  .thenComparing(SalesEntry::name);   // 平局补维
```

> **豆豆旁白**:`thenComparing` 要接在 `reversed()` **之后**——主维降序、平局升序。写成 `comparing(...).thenComparing(...).reversed()` 是整串一起翻转,名字也跟着倒。另:String 自然序按字符码位,中文不是拼音序,「摩」码位就排在「美」前;真要拼音序得换 `Collator`,今天不展开。

JUnit 质检员:「证据呢?」

```java
import org.junit.jupiter.api.Test;
import java.util.TreeSet;
import static org.junit.jupiter.api.Assertions.assertEquals;

class LeaderboardTest {
    @Test
    void tied_sales_both_stay_on_board() {
        var board = new TreeSet<>(Leaderboard.BY_SALES);
        board.add(new SalesEntry("拿铁", 41));
        board.add(new SalesEntry("美式", 27));
        board.add(new SalesEntry("摩卡", 27));   // 同销量,一杯都不许吞

        assertEquals(3, board.size());
        assertEquals("拿铁", board.getFirst().name());
        assertEquals("美式", board.getLast().name());   // 同 27 杯按名字升序,「摩」在「美」前
    }
}
```

绿灯。排行榜四款齐全,黑板恢复诚实。

## 十、对应招聘技能

| 本话技能 | 在招聘里的样子 |
|---|---|
| Comparable/Comparator 与比较器组装 | 集合排序必考,手写比较器是笔试常客 |

## 🎯 随堂练习

先自己做,再对答案。每道答案都带一句「举一反三」,帮你把这一个点连成一片。

### 选择题(10 道)

1. Comparable 和 Comparator 的区别是?
   - A) 前者更快　B) **Comparable 是自然序(类自己实现 `compareTo`,一个类只有一种);Comparator 是外部序(尺子在类外,想造几把造几把)**　C) 前者已废弃　D) 两者可互换
2. `TreeSet` 判断「是不是重复元素」靠的是?
   - A) `equals` + `hashCode`　B) **`compare(a, b) == 0`**,与 equals 无关　C) `==`　D) `toString`
3. 给无参 `TreeSet` 添加一个没实现 Comparable 的 record,会?
   - A) 按插入顺序存　B) **第一次 `add` 就抛 `ClassCastException`**　C) 编译报错　D) 静默失败
4. 尺子只按销量比较,两款咖啡销量打平时会?
   - A) 都保留　B) **后来者被判定为「同一个」,`add` 返回 false 后无声丢弃**　C) 抛异常　D) 覆盖旧的
5. 主维降序、平局按名字升序,正确写法是?
   - A) `comparing(...).thenComparing(...).reversed()`　B) **`comparingInt(...).reversed().thenComparing(...)`**　C) 两者等价　D) 必须写两个 Comparator
6. `TreeSet` 和 `TreeMap` 的关系是?
   - A) 完全独立　B) **`TreeSet` 就是 `TreeMap` 的马甲**:`add(e)` = `put(e, 占位符)`　C) TreeMap 基于 TreeSet　D) 两者底层不同
7. 「永远有序」的代价是?
   - A) 内存翻倍　B) **增删查全是 O(log n)**(对比 HashMap 的 O(1))　C) 线程不安全　D) 不能存 null
8. 三行手写 LRU 用到的两样东西是?
   - A) `TreeMap` + Comparator　B) **`LinkedHashMap` 的 `accessOrder=true` + 覆写 `removeEldestEntry`**　C) `PriorityQueue` + 堆　D) `WeakHashMap` + GC
9. JDK 21 的 Sequenced Collections(JEP 431)带来了什么?
   - A) 新的排序算法　B) **`getFirst()` / `getLast()` / `reversed()` 统一入口**,`reversed()` 还是视图不复制　C) 并行遍历　D) 不可变集合
10. 同一批对象分别放进 `HashSet` 和 `TreeSet`,size 可能不同,原因是?
    - A) 有 bug　B) **两套判重规则**:HashSet 看 `hashCode`+`equals`,TreeSet 看 `compare`　C) TreeSet 会去重更彻底　D) HashSet 允许重复

> [!答案]
> **1-B**　一把写死在类里,一把可以随时换。**举一反三**:同一批数据要按不同维度排,就是 Comparator 存在的意义。
> **2-B**　排序容器里「相等」由 compare 说了算。**举一反三**:所以比较维度不全 = 判重规则漏水,数据会无声丢失。
> **3-B**　无参构造默认赌你有自然序。**举一反三**:异常发生在第一次 `add`(自己和自己比),而不是 new 的时候 —— 这个时机很容易误导排查。
> **4-B**　`add` 返回 false 而没人看返回值。**举一反三**:集合的返回值经常被忽略,`add`/`remove`/`put` 的返回值其实都在告诉你发生了什么。
> **5-B**　`reversed()` 只翻转它前面的部分。**举一反三**:写成 A 的形式会把整串一起翻转,名字也跟着倒 —— 顺序敏感。
> **6-B**　马甲关系。**举一反三**:`HashSet` 和 `HashMap` 也是同款关系 —— Java 集合里「Set 是 Map 的皮」是普遍设计。
> **7-B**　有序从不免费。**举一反三**:选容器先问「要不要顺序、要哪种」:插入序用 LinkedHashMap,比较序用 TreeMap,不要序用 HashMap。
> **8-B**　两个开关就够了。**举一反三**:这是大厂手撕 LRU 的最短答案,但面试常要求手写双向链表版 —— 两种都该会。
> **9-B**　统一入口 + 倒序视图。**举一反三**:视图意味着改视图会影响原集合,别当成副本用。
> **10-B**　不是 Bug,是两套规则。**举一反三**:这也是为什么「重写 equals 就要重写 hashCode」管不到 TreeSet —— 它压根不看这两个方法。
