## 四、炉内原理图:那张入场表是为谁填的

传统入口的每个修饰符都对应一件当年 JVM 必须知道的事:

| 样板 | 当年为什么必须 | Java 25 之后 |
|---|---|---|
| `public` | 启动器要从类外找到它 | 启动器改为容忍包级可见 |
| `static` | 还没有实例,谁来调用它? | 启动器先 `new` 一个实例再调 |
| `String[] args` | 命令行参数的唯一入口 | 不需要参数就可以不声明 |
| 显式类声明 | 类文件必须有类名 | 编译器替你合成一个 |

关键在最后一行:**样板没有被删除,是被搬到了编译器和启动器那一侧**。这正是本线要反复确认的事——上层一行糖,炉底几行霜。

> **⏳ 版本时光机 · 一句输出的入口怎么变的**
>
> | JDK | 写法 | 关键变化 |
> |---|---|---|
> | Java 8 | `public class X { public static void main(String[] a) { System.out.println(...) } }` | 五个概念一次性砸给新手 |
> | Java 21 起 | 同上,但单文件可直接 `java X.java` | 省掉编译一步,样板还在 |
> | Java 25 | `void main() { IO.println(...) }` | 类声明、修饰符、参数、`System.out` 四样一起退场 |
>
> 一句演进小结:入口的复杂度一直在往**工具链**那边挪,而不是消失。

## 五、把后厨第一段代码切到 Java 25

新建 `Menu.java`,全文就是下面这些——没有 `class`,没有 `static`:

```java
import module java.base;

void main() {
    List<String> menu = List.of("美式", "拿铁", "手冲");
    Map<String, Integer> price = Map.of("美式", 15);
    IO.println("菜单: " + menu + " 价目: " + price);
}
```

直接跑,不需要任何预览开关:

```bash
java Menu.java
```

真实输出:

```text
菜单: [美式, 拿铁, 手冲] 价目: {美式=15}
```

两个 Java 25 转正特性在这里同时生效:**紧凑源文件与实例 main(JEP 512)** 省掉了入口样板;**模块导入声明(JEP 511)** 让 `import module java.base;` 一句顶替了 `java.util.List`、`java.util.Map` 等一串逐类导入。

> [!重点]
> `IO.println` 不是"新的正确写法",`System.out.println` 也没有被废弃。`java.lang.IO` 是给**单文件、教学、脚本**场景准备的窄接口;进了正式工程,该走日志框架的地方仍然走日志框架。

## 六、故意翻一次车:整仓门一开,Date 是谁的 Date

阿零觉得一个模块不够爽,把 `java.sql` 也导了进来——毕竟以后要连库:

```java
import module java.base;
import module java.sql;

void main() {
    Date today = new Date();
    IO.println(today);
}
```

`import module` 展开的是模块**导出的全部包**。`java.base` 里有 `java.util.Date`,`java.sql` 里有 `java.sql.Date`——两个同名类同时在作用域里,编译器无从选择。

## 七、编译官罚单

> **📋 编译官罚单**

```text
Ambiguous.java:5: 错误: 对Date的引用不明确
    Date today = new Date();
    ^
  java.sql 中的类 java.sql.Date 和 java.util 中的类 java.util.Date 都匹配
2 个错误
```

注意它报了 **2 个错误**:声明处和 `new` 处各算一次。这条罚单是编译期开的,不会留到运行时——按 §四 的说法,这正是样板搬到编译器那侧之后,编译器替你守住的一条线。

## 八、修复并验证

规则很简单:**单类导入的优先级高于模块导入**。想要哪个 `Date`,就显式写哪个:

```java
import module java.base;
import module java.sql;
import java.util.Date;

void main() {
    Date today = new Date();
    IO.println("今日班次: " + today.getClass().getName());
}
```

再跑一次,用类的全名作为验证判据——不猜,直接让它自己报出身:

```text
今日班次: java.util.Date
```

> [!坑]
> 别用"把 `java.sql` 删掉"来绕过。真实项目里两个模块都需要时,这条歧义一定会回来。**收窄靠显式 import,不靠少导模块。**

> **🎯 面试直击**:`import module` 和 `import java.util.*` 有什么区别?
> 前者按**模块**展开其导出的全部包,后者只展开**一个包**;两者都属于按需导入,遇到同名类都要靠单类导入消歧。追问点通常是优先级——单类导入永远压过任何按需导入。

## 九、🔬 炉底显微镜 · 三行代码,编译器替你写了几行?

复现命令(照抄可跑,基线 JDK 25):

```bash
javac Furnace.java && javap -c -p Furnace
```

其中 `Furnace.java` 就是最小版本:

```java
void main() {
    IO.println("焰焰: 先热身,再起飞。");
}
```

关键输出(节选,真实实录):

```text
final class Furnace {
  Furnace();
    Code:
         0: aload_0
         1: invokespecial #1                  // Method java/lang/Object."<init>":()V
         4: return

  void main();
    Code:
         0: ldc           #7                  // String 焰焰: 先热身,再起飞。
         2: invokestatic  #9                  // Method java/lang/IO.println:(Ljava/lang/Object;)V
         5: return
}
```

逐行解读:

① 类名 `Furnace` 来自**文件名**,而且是 `final`——你没写的类声明,编译器写了,还顺手封了口;
② 那个 `Furnace();` 是编译器合成的无参构造器,启动器要先 `new` 出实例才能调实例 `main`,所以它必须存在;
③ `main` 的描述符是 `void main()`,没有 `String[]`——省掉参数是真的省了,不是语法糖包装;
④ `IO.println` 落到字节码是一次普通的 `invokestatic java/lang/IO.println`,签名收 `Object`,不是什么编译期魔法。

顺手确认这四行不是"一直都能这么写"——把源码等级压回 24:

```text
Furnace.java:1: 错误: -source 24 中不支持 隐式声明的类
void main() {
^
  (请使用 -source 25 或更高版本以启用 隐式声明的类)
```

> 焰焰结语:你少写的那几行,一行都没消失——只是搬进了炉底。

## 🎯 随堂练习

先自己做,再对答案。每道答案都带一句「举一反三」,帮你把这一个点连成一片。

### 选择题(10 道)

1. Java 25 的紧凑源文件里,`main` 方法可以不写哪些东西?
   - A) 只能省掉 `String[] args`　B) 可以省掉 `public`、`static`、`String[] args` 与整个类声明　C) 只能省掉 `public`　D) 什么都不能省,只是换了个语法
2. 紧凑源文件编译出来的类,类名从哪来?
   - A) 固定叫 `Main`　B) 来自源文件名　C) 随机生成　D) 必须用 `--class-name` 指定
3. `javap` 显示编译器合成了一个无参构造器 `Furnace();`,为什么它必须存在?
   - A) 所有类都必须有构造器,与本特性无关　B) 因为实例 `main` 需要先有实例,启动器要 `new` 一个对象才能调用它　C) 为了让类变成 `final`　D) 为了兼容 `String[] args`
4. `import module java.base;` 展开的是什么?
   - A) 只有 `java.lang` 一个包　B) 该模块导出的全部包　C) 整个 JDK 的所有类　D) 只有 `java.util`
5. 同时 `import module java.base` 和 `import module java.sql` 后直接写 `Date`,结果是?
   - A) 默认选 `java.util.Date`　B) 默认选 `java.sql.Date`　C) 编译报错「对 Date 的引用不明确」　D) 运行时才抛异常
6. 上题该怎么修?
   - A) 删掉 `java.sql` 模块导入　B) 加一行 `import java.util.Date;`,单类导入优先级高于模块导入　C) 用全限定名是唯一办法　D) 改用 `var` 就没事了
7. `java.lang.IO` 与 `System.out` 的关系,最准确的说法是?
   - A) `IO` 取代了 `System.out`,后者已废弃　B) `IO` 是面向单文件/教学/脚本场景的窄接口,`System.out` 与日志框架在工程里照旧　C) 两者完全等价,随便用　D) `IO` 只能在预览模式下用
8. 跑本话的紧凑源文件需要加 `--enable-preview` 吗?
   - A) 需要,它是预览特性　B) 不需要,JEP 512 与 JEP 511 在 JDK 25 已转正　C) 需要,但只在 Windows 上　D) 取决于是否用了 `IO.println`
9. 用 `javac --release 24` 编译紧凑源文件会发生什么?
   - A) 正常编译,向下兼容　B) 报错「-source 24 中不支持 隐式声明的类」,并提示改用 25 或更高　C) 编译通过但运行时报错　D) 自动降级成传统写法
10. 「入口样板变少了,说明 JVM 变简单了」这句话错在哪?
    - A) 没错,确实变简单了　B) 样板是被挪到编译器与启动器那一侧,JVM 该做的事一件没少　C) 错在 JVM 其实变复杂了一倍　D) 错在样板根本没变少

> [!答案]
> **1-B**　类声明、`public`、`static`、参数四样都可以不写。**举一反三**:凡是"忽然可以不写"的东西,先问一句"那谁在写"——答案通常是编译器或启动器。
> **2-B**　类名取自文件名,所以文件名仍然重要。**举一反三**:这也解释了为什么单文件启动器对文件名敏感,重命名文件等于重命名类。
> **3-B**　实例方法必须有实例,启动器先 `new` 再调,所以无参构造器必须能被合成出来。**举一反三**:反过来说,如果你自己写了一个只有带参构造器的类,实例 `main` 就没法被启动器调起。
> **4-B**　按模块展开其**导出**的全部包,没导出的包不在其中。**举一反三**:所以模块导入的作用域大小取决于目标模块的 `exports`,不是它有多少个包。
> **5-C**　两个同名类同时在作用域里,编译期直接判歧义。**举一反三**:注意报错数量可能大于 1——声明处和 `new` 处各算一次,别被"2 个错误"误导成有两处不同的问题。
> **6-B**　单类导入的优先级高于任何按需导入,这是消歧的正规手段。**举一反三**:`import java.util.*` 时代的同名冲突用的也是这一条规则,新特性没有发明新机制。
> **7-B**　`IO` 是窄接口,不是替代品。**举一反三**:凡是被介绍成"新的正确写法"的 API,先确认它的设计场景——用错场景比用旧 API 更糟。
> **8-B**　两者在 JDK 25 均已转正,直接 `java Menu.java` 即可。**举一反三**:判断"要不要 `--enable-preview`"不要靠记忆,`javac --release <n>` 试一次,报错信息会直接告诉你门槛。
> **9-B**　编译器明确拒绝,并给出所需的最低源码等级。**举一反三**:这条报错是确认"特性从哪个版本开始可用"的最快手段,比查文章可靠。
> **10-B**　复杂度转移,不是复杂度消失。**举一反三**:这是本线的总纲——每见到一个语法糖,就去炉底看一眼它换成了什么。
