# 《从零开始当工程师》03 · 苍穹外卖：用一条业务链证明基本功

> 课程项目的价值不在于“我看过视频”，而在于你能从 HTTP 请求讲到数据落库，再讲到失败如何处理。

## 一、先尊重项目的真实版本

若课程项目的基线是 JDK 17 与 Spring Boot 2.7，就用它完成构建、测试和演示。Java 25 是本站技术文章的审计参考，不是把旧项目强行升级到新框架的理由。

开始前记录：

```text
java --version
./mvnw -v 或 mvn -v
数据库版本与初始化步骤
前端运行命令（若项目含前端）
```

版本对不上时先解决兼容问题；不要为了“技术栈最新”把 `javax`/`jakarta`、依赖版本和课程代码混在一起，再无法解释故障来源。

## 二、只挑一条主链路讲透

建议先锁定这一条：

```text
登录 → 身份校验 → 浏览商品 → 加购物车 → 提交订单 → 扣减/状态落库 → 返回订单结果
```

对每一步都能回答：入口控制器是谁？参数在哪里校验？身份如何传递？事务边界在哪？涉及哪些表？异常返回什么？

把这些答案画成一页图，比堆十张页面截图更有价值。

## 三、三个必须亲手改过的点

不要从功能列表里挑；挑能产生解释的改动：

1. **参数校验与错误响应**：非法数量、缺字段、无权限时不能默默成功。
2. **订单事务**：任一步失败后，订单状态与相关数据不能留下半成品。
3. **查询与索引**：为一个真实列表或订单查询看 `EXPLAIN`，再说明索引为何这样建。

每项改动保留“原问题 → 修改 → 验证 → 边界”四行记录。不能复现的改动不写进简历。

## 四、随机追问演练

| 追问 | 你必须落到的证据 |
|---|---|
| `@Transactional` 为什么生效/失效？ | 调用路径、代理边界、回滚规则 |
| 重复提交订单怎么办？ | 幂等键、唯一约束或状态机 |
| 慢查询怎么处理？ | SQL、执行计划、索引取舍 |
| 接口被滥用怎么办？ | 鉴权、参数校验、限流边界 |
| 订单创建后通知失败怎么办？ | 当前保证什么、暂不保证什么 |

不确定时先说当前实现的边界，再说明下一步验证方案。不要把单体课程项目说成已经具备分布式一致性。

## 五、交付清单

- `README`：环境、初始化、启动、演示账号/测试数据的安全处理方式。
- `ARCHITECTURE.md`：一条主链路和表关系。
- `PROJECT_EVIDENCE.md`：三次亲手改动、验证和边界。
- 一段五分钟录屏或现场演示路径。
