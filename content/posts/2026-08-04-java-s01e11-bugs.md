## 五、代码:一段带三处伤的下单逻辑

```java
public class Cafe {
    static double priceOf(int choice) {
        return switch (choice) {
            case 1 -> 15.0;
            case 2 -> 18.0;
            default -> 20.0;
        };
    }

    public static void main(String[] args) {
        int qty = 3;
        double total = priceOf(1) * qty      // ① 语法:少了分号
        double paid = 40.0;

        if (paid > total) {                  // ② 逻辑:钱刚好等于时也该出杯,应为 >=
            System.out.println("出杯");
        }

        String note = null;
        System.out.println("备注长度:" + note.length());   // ③ Null:对 null 调 length()
    }
}
```

---

## 六、逐个揪出

**① 语法 Bug**（编译官先拦):

```text
Cafe.java:13: error: ';' expected
        double total = priceOf(1) * qty
                                      ^
```

`';' expected` —— 第 13 行末尾漏了分号。补上 `;`。

**② 逻辑 Bug**（编译过了,但行为不对):`paid > total` 在「刚好付够」时判 `false`,顾客付了整钱却不出杯。改成 `paid >= total`。这类不报错,得靠想清楚边界或写测试才能发现。

**③ Null 幽灵**（运行到第三步才崩):

```text
Exception in thread "main" java.lang.NullPointerException:
        Cannot invoke "String.length()" because "note" is null
        at Cafe.main(Cafe.java:20)
```

现代 JDK 的报错会**直接点名**:`because "note" is null`。`note` 是 `null`,对它调 `.length()` 必崩。改成有意义的默认值,或先判空:`String note = "";`。

---

## 七、修复后

```java
double total = priceOf(1) * qty;      // 补分号
if (paid >= total) { ... }            // 改 >=
String note = "";                     // 不再是 null
```

三处修好,程序正常出杯、打印「备注长度:0」。

---

## 八、用测试守住逻辑 Bug

语法和 Null 会「吵着」暴露,最阴险的是逻辑 Bug 的边界。给它钉个测试:

```java
static boolean shouldServe(double paid, double total) {
    return paid >= total;   // 关键边界:相等也要出杯
}

@Test
void serve_when_exactly_paid() {
    assertTrue(Cafe.shouldServe(45.0, 45.0));   // 若写成 >,这里会红
}
```
