## 三、本话目标

- 用 `for` 做固定次数的重复;
- 用 `while` / `do-while` 做「直到某条件」的重复;
- 理解 `break`(跳出)/ `continue`(跳过本轮);
- 踩一次「忘记更新条件」的死循环。

---

## 四、原理图

```text
for (int i = 0; i < n; i++) { ... }   次数已知:起点 i=0、条件 i<n、每轮 i++
while (条件) { ... }                   次数未知,先判断再执行(可能一次都不执行)
do { ... } while (条件);               至少执行一次,再判断
```

死循环根因:**循环体里没有任何一句让「条件」逐步趋向 `false`**。`for` 把「起点/条件/步进」三样并排写在括号里,最不容易漏;`while` 的步进散落在循环体内,最容易忘 —— 阿零翻的正是这个车。

## 五、代码:做 5 杯 + 卖到库存为止

```java
public class Cafe {
    public static void main(String[] args) {
        // for:固定做 5 杯
        for (int i = 1; i <= 5; i++) {
            System.out.println("第 " + i + " 杯美式 ☕");
        }

        // while:一直卖,直到库存为 0
        int stock = 3;
        while (stock > 0) {
            System.out.println("售出一杯,剩余 " + (stock - 1));
            stock--;                 // ← 关键:让条件趋向结束
        }
    }
}
```

> **豆豆旁白**:其实还有第四种循环 —— `for-each`(`for (T x : 一排东西)`),专门「逐个取出、不管下标」。但它得**先有一排东西**可遍历,下一话数组登场后你会天天用它。先记住一句:for-each 底层是把活儿交给一个叫**迭代器(Iterator)**的角色,一个一个递给你 —— 第二季讲集合时,会有个叫 **CME** 的幽灵,专挑你「一边 for-each 一边改集合」的时候现身。这句先埋着,到时你会想起来。

`break` 和 `continue` 是循环里的两个开关:`break` 是「够了,整个循环立刻退出」,`continue` 是「这一杯跳过,直接做下一杯」。

```java
for (int i = 1; i <= 10; i++) {
    if (i == 4) continue;      // 第 4 位顾客临时走了 —— 跳过这一轮,不出杯
    if (i == 8) break;         // 豆子用完了 —— 整条传送带立即停机
    System.out.println("第 " + i + " 杯出杯 ☕");
}
```

上面这段会做 1、2、3、5、6、7 杯:`continue` 只跳过第 4 轮、循环照转;`break` 到第 8 轮直接掀桌走人,后面的 9、10 根本不做。

## 六、故意制造一个 Bug

把 `stock--` 删掉:

```java
while (stock > 0) {
    System.out.println("售出一杯,剩余 " + stock);
    // stock--;   ← 故意删掉
}
```

## 七、读懂现象(死循环)

终端疯狂刷屏「售出一杯,剩余 3」永不停止,得手动 `Ctrl+C` 才能停。`stock` 永远是 3,`stock > 0` 永远为 `true` —— 这就是**死循环**:忘了让条件靠近终点。它不报错、不崩溃,只会把一个 CPU 核**吃满到 100%**,在真实服务器上就是一次线上事故。

---

## 八、修复,并用测试证明

补回 `stock--`。把「按库存能卖多少杯」抽成方法:

```java
static int cupsSold(int stock) {
    int sold = 0;
    while (stock > 0) { sold++; stock--; }
    return sold;
}
```

```java
@Test
void sells_exactly_stock() {
    assertEquals(3, Cafe.cupsSold(3));
    assertEquals(0, Cafe.cupsSold(0));   // 库存 0:while 一次都不进,直接返回 0
}
```

> **🎯 面试直击**:线上某台机器 CPU 突然飙到 100%,怎么定位?
> 经典四步:① `top` 找到吃满 CPU 的 Java 进程 PID;② `top -Hp <pid>` 找到最忙的**线程** ID;③ 把线程 ID 转成十六进制,在 `jstack <pid>` 输出里搜它的栈;④ 栈顶往往就卡在某个**死循环 / 空转**的方法上。追问防身:死循环、正则回溯、频繁 Full GC 都能打满 CPU —— 本话的空转 `while` 就是最朴素的一种。(`jstack` 到第五季会带你亲手用。)

## 🎯 随堂练习

先自己做,再对答案。每道答案都带一句「举一反三」,帮你把这一个点连成一片。

### 选择题(10 道)

1. 死循环的根本原因是?
   - A) 循环次数写得太大　B) 循环体里没有任何一句让条件趋向 `false`　C) 忘了写 `break`　D) CPU 性能不够
2. `for (int i = 0; i < n; i++)` 括号里的三样零件依次是?
   - A) 条件、起点、步进　B) 起点、条件、每轮往终点挪一步　C) 起点、步进、条件　D) 次数、条件、结果
3. `while` 和 `do-while` 最关键的区别是?
   - A) `do-while` 更快　B) `while` 可能一次都不执行,`do-while` 至少执行一次　C) `do-while` 不能用 `break`　D) `while` 只能判断数字
4. 本话那段 `for (i=1; i<=10; i++)`(`i==4` 时 `continue`、`i==8` 时 `break`)会出几杯?
   - A) 1、2、3、5、6、7 共 6 杯　B) 1~10 共 10 杯　C) 1、2、3、5、6、7、9、10 共 8 杯　D) 1~7 共 7 杯
5. `cupsSold(0)` 的返回值是?
   - A) 抛异常　B) `1`　C) `0`,因为 `while` 先判断,一次都没进　D) `-1`
6. 死循环在真实服务器上的典型表现是?
   - A) 立刻抛异常并退出　B) 编译不过　C) 不报错不崩溃,但把一个 CPU 核吃满到 100%　D) 内存泄漏导致 OOM
7. 线上 CPU 飙到 100%,经典定位四步的正确顺序是?
   - A) `jstack` → `top` → 转十六进制 → 找线程　B) `top` 找进程 → `top -Hp` 找线程 → 线程 ID 转十六进制 → `jstack` 里搜栈　C) 重启 → 看日志 → 加机器 → 观察　D) 直接看代码找死循环
8. `for-each` 底层把活儿交给了谁?
   - A) 编译器展开成普通 for　B) 迭代器(Iterator)　C) JVM 的特殊指令　D) 数组下标
9. 为什么 `while` 比 `for` 更容易写出死循环?
   - A) `while` 语法更复杂　B) `for` 把起点/条件/步进并排写在括号里,`while` 的步进散落在循环体内,容易忘　C) `while` 不支持 `break`　D) `while` 的条件判断更慢
10. 「次数未知、卖到库存为 0 为止」这种场景最适合?
    - A) `for` 固定次数循环　B) `while` 按条件循环　C) `switch`　D) 递归

> [!答案]
> **1-B**　条件永远为真,循环就永远不停。**举一反三**:写循环前先问自己一句「它凭什么会停」,答不上来就别按回车。
> **2-B**　起点、条件、步进,缺一个就出事。**举一反三**:三样并排写在括号里是 `for` 的最大优点 —— 想漏都难。
> **3-B**　`while` 先判断再执行,`do-while` 先执行再判断。**举一反三**:所以「至少要跑一次」的场景(菜单交互、重试一次)天生适合 `do-while`。
> **4-A**　第 4 轮被 `continue` 跳过,第 8 轮 `break` 掀桌,9、10 根本不做。**举一反三**:`continue` 只跳过本轮、循环照转;`break` 是整个循环立刻退出。
> **5-C**　库存 0 时条件 `0 > 0` 为假,直接返回 `sold = 0`。**举一反三**:这就是为什么测试要专门写「零 / 空 / 边界」用例 —— 正常路径谁都会走,边界才见真章。
> **6-C**　它不报错、不崩溃,只把 CPU 吃满,在线上就是一次事故。**举一反三**:「不崩的故障」比「崩掉的故障」更难查,因为没有异常栈给你看。
> **7-B**　进程 → 线程 → 十六进制 → 栈,四步定位到那行空转代码。**举一反三**:死循环、正则回溯、频繁 Full GC 都能打满 CPU,第五季会带你亲手用 `jstack`。
> **8-B**　`for-each` 底层是迭代器一个一个递给你。**举一反三**:所以「一边 for-each 一边改集合」会撞上 `ConcurrentModificationException`,第二季那个幽灵就是从这来的。
> **9-B**　步进散落在循环体里,最容易忘 —— 阿零翻的正是这个车。**举一反三**:能用 `for` 表达的固定次数循环就别用 `while`,把「凭什么会停」写在最显眼的地方。
> **10-B**　次数未知、靠条件收敛,正是 `while` 的主场。**举一反三**:反过来「做 5 杯」这种次数已知的用 `for`,选对循环本身就能减少 Bug。
