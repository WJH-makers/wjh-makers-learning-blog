# 《从零开始学 Java》36 · JDBC / MyBatis 连 MySQL

> 连载特刊 · 第四季「咖啡帝国」第 4 话 · 基线 Java 25 · Spring Boot 4.x
> 承接:上一话三层分明了,但 `MenuRepository` 还是个内存 `Map`,一重启就复位。

## 一、需求:给咖啡站一份"跨重启的记忆"

内存里的菜单和库存,服务一重启全没;将来多台服务器分担流量,更是各存各的、数据对不上。豆豆:「要让数据活过重启、还能被多台机器共享,得把它放进**数据库**。今天连 MySQL,并且——**当心 SQL 注入这个经典大坑。**」

---

## 二、漫画 · 数据库大陆

> **〔1〕** 一片叫 MySQL 的大陆,一排排货架就是**表**,每层格子是**行**。
> 豆豆:「`coffee` 表存所有咖啡:名字、价格、库存。数据存这儿,谁重启都还在。」

> **〔2〕** 程序和数据库之间架着一队"连接"当桥,门口挂牌 `连接池`。
> 豆豆:「每次开新连接很贵。**连接池**(Spring Boot 默认 HikariCP)预备一批复用,用完还回去。」

> **〔3〕** MyBatis 快递员拿着**取货单**(SQL)去货架取货,`#{name}` 是留给参数的**空格子**。
> 豆豆:「注意这个空格子——SQL 和数据**分开传**,数据库才不会把顾客输入当成命令执行。」

> **〔4〕** 阿零图省事,把顾客输入直接**拼**进 SQL(`${name}`)。一个坏顾客输入 `' OR '1'='1`,货架被一锅端。
> 豆豆(叼豆子,脸沉):「这就是 **SQL 注入**。你把数据拼成了命令,等于把仓库钥匙递给了顾客。记死:**永远用 `#{}` 参数化,永远别用 `${}` 拼用户输入。**」

## 三、本话目标

- 配置数据源连接 MySQL,理解连接池;
- 用 **MyBatis** 的 `@Mapper` + SQL 注解做增删改查;
- 让 `MenuRepository` 从内存切换到数据库;
- 踩一次 **SQL 注入**,并用 `#{}` 参数化根治;
- 用测试验证查询正确。

## 四、原理图:从代码到数据库

```text
CoffeeService
     │ 调
CoffeeMapper(@Mapper 接口,写 SQL)
     │ MyBatis 执行、连接池借连接
     ▼
MySQL:  coffee 表
        ┌────────┬────────┬───────┐
        │ name   │ price  │ stock │
        ├────────┼────────┼───────┤
        │ 美式   │ 15.00  │  3    │
        │ 拿铁   │ 18.00  │  5    │
        └────────┴────────┴───────┘

#{name}  = 参数化占位(SQL 与数据分开传,防注入)  ✅
${name}  = 字符串直接拼进 SQL(注入门户)          ❌
```

## 五、配置与代码

建表 SQL:

```sql
CREATE TABLE coffee (
    name  VARCHAR(50)    PRIMARY KEY,
    price DECIMAL(10, 2) NOT NULL,
    stock INT            NOT NULL
);
INSERT INTO coffee VALUES ('美式', 15.00, 3), ('拿铁', 18.00, 5);
```

`pom.xml` 加依赖:

```xml
<dependency>
    <groupId>org.mybatis.spring.boot</groupId>
    <artifactId>mybatis-spring-boot-starter</artifactId>
    <version>3.0.3</version>
</dependency>
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>
```

`application.yml` 配数据源:

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/cafe?useUnicode=true&characterEncoding=utf8
    username: root
    password: your_password
    # 驱动与连接池(HikariCP)Spring Boot 自动配好,无需手写
```

`CoffeeMapper` 接口——SQL 就写在注解里:

```java
import org.apache.ibatis.annotations.*;
import java.util.List;

@Mapper
public interface CoffeeMapper {
    @Select("SELECT name, price, stock FROM coffee")
    List<Coffee> findAll();

    @Select("SELECT name, price, stock FROM coffee WHERE name = #{name}")   // ✅ 参数化
    Coffee findByName(String name);

    @Update("UPDATE coffee SET stock = #{stock} WHERE name = #{name}")
    int updateStock(@Param("name") String name, @Param("stock") int stock);
}
```

`MenuRepository` 从内存切到数据库(上层 Service 一行都不用改——这正是三层的好处):

```java
@Repository
public class MenuRepository {
    private final CoffeeMapper mapper;
    public MenuRepository(CoffeeMapper mapper) { this.mapper = mapper; }

    public List<Coffee> findAll() { return mapper.findAll(); }
    public Optional<Coffee> findByName(String name) {
        return Optional.ofNullable(mapper.findByName(name));
    }
    public void updateStock(String name, int stock) { mapper.updateStock(name, stock); }
}
```

## 七、读懂现象:SQL 注入

顾客查询名传入 `美式' OR '1'='1`,拼出来的 SQL 变成:

```sql
SELECT * FROM coffee WHERE name = '美式' OR '1'='1'
```

`'1'='1'` 恒真,**整张表被查了出来**——如果这是登录查询,攻击者就能绕过密码。更狠的输入还能删表。根因:`${}` 把**用户数据当成了 SQL 代码**拼进去。改回 `#{}`:

```java
@Select("SELECT * FROM coffee WHERE name = #{name}")   // 参数化:数据和 SQL 分开传
```

`#{}` 底层用 JDBC 的 `PreparedStatement`,把 `name` 作为**参数**单独发给数据库,数据库绝不会把它当命令解析。注入,根治。

> **⏳ 版本时光机 · 持久层的演进**

| 时期 | 方案 | 特点 |
|---|---|---|
| 最底层 | 原生 **JDBC** | 手写 `Connection`/`PreparedStatement`/`ResultSet`/`close`,啰嗦但你能看清一切 |
| 半自动 | Spring `JdbcTemplate` / **MyBatis** | 你写 SQL,框架管连接、映射;MyBatis 的 SQL 可控性强,国内主流 |
| 全自动 | **Spring Data JPA** | 连 SQL 都少写,方法名即查询,适合简单 CRUD |

> **🎯 面试直击**:MyBatis 的 `#{}` 和 `${}` 有什么区别?
> `#{}` 是**参数占位**,编译成 `PreparedStatement` 的 `?`,值单独传,**天然防 SQL 注入**——绝大多数情况用它。`${}` 是**字符串直接替换**,拼进 SQL 原文,**有注入风险**,仅在"动态表名/列名/排序字段"这类无法参数化的场景谨慎使用,且必须自己做白名单校验。追问:连接池为什么重要?建立 TCP + 认证的新连接很贵,HikariCP 预建一批复用,是高并发下的性能关键。

## 八、用测试证明:查得对、扣得动

用嵌入式数据库(如 H2)或测试库跑 Mapper:

```java
import org.mybatis.spring.boot.test.autoconfigure.MybatisTest;
import org.springframework.beans.factory.annotation.Autowired;
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

@MybatisTest   // 只装 MyBatis 相关组件,轻量
class CoffeeMapperTest {
    @Autowired CoffeeMapper mapper;

    @Test
    void find_by_name_is_parameterized() {
        Coffee c = mapper.findByName("美式");   // 恶意串不会被当 SQL,查不到就是 null
        assertEquals("美式", c.name());
    }
}
```
