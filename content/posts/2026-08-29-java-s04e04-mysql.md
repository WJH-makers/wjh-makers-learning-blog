## 一、需求:给咖啡站一份"跨重启的记忆"

内存里的菜单和库存,服务一重启全没;将来多台服务器分担流量,更是各存各的、数据对不上。豆豆:「要让数据活过重启、还能被多台机器共享,得把它放进**数据库**。今天连 MySQL,并且——**当心 SQL 注入这个经典大坑。**」

## 二、漫画 · 数据库大陆

> **〔1〕** 一片叫 MySQL 的大陆,一排排货架就是**表**,每层格子是**行**。
> 豆豆:「`coffee` 表存所有咖啡:名字、价格、库存。数据存这儿,谁重启都还在。」

> **〔2〕** 程序和数据库之间架着一队"连接"当桥,门口挂牌 `连接池`。
> 豆豆:「每次开新连接很贵。**连接池**(Spring Boot 默认 HikariCP)预备一批复用,用完还回去。」

> **〔3〕** MyBatis 快递员拿着**取货单**(SQL)去货架取货,`#{name}` 是留给参数的**空格子**。
> 豆豆:「注意这个空格子——SQL 和数据**分开传**,数据库才不会把顾客输入当成命令执行。」

> **〔4〕** 阿零图省事,把顾客输入直接**拼**进 SQL(`${name}`)。一个坏顾客输入 `' OR '1'='1`,货架被一锅端。
> 豆豆(叼豆子,脸沉):「这就是 **SQL 注入**。你把数据拼成了命令,等于把仓库钥匙递给了顾客。记死:**永远用 `#{}` 参数化,永远别用 `${}` 拼用户输入。**」


## 五、配置与代码

建表 SQL:

```sql
CREATE TABLE coffee (
    name  VARCHAR(50)    PRIMARY KEY,
    price DECIMAL(10, 2) NOT NULL,
    stock INT            NOT NULL
);
INSERT INTO coffee VALUES ('美式', 15.00, 3), ('拿铁', 18.00, 5);
```

`pom.xml` 加依赖:

```xml
<dependency>
    <groupId>org.mybatis.spring.boot</groupId>
    <artifactId>mybatis-spring-boot-starter</artifactId>
    <version>3.0.3</version>
</dependency>
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>
```

`application.yml` 配数据源:

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/cafe?useUnicode=true&characterEncoding=utf8
    username: root
    password: your_password
    # 驱动与连接池(HikariCP)Spring Boot 自动配好,无需手写
```

`CoffeeMapper` 接口——SQL 就写在注解里:

```java
import org.apache.ibatis.annotations.*;
import java.util.List;

@Mapper
public interface CoffeeMapper {
    @Select("SELECT name, price, stock FROM coffee")
    List<Coffee> findAll();

    @Select("SELECT name, price, stock FROM coffee WHERE name = #{name}")   // ✅ 参数化
    Coffee findByName(String name);

    @Update("UPDATE coffee SET stock = #{stock} WHERE name = #{name}")
    int updateStock(@Param("name") String name, @Param("stock") int stock);
}
```

`MenuRepository` 从内存切到数据库(上层 Service 一行都不用改——这正是三层的好处):

```java
@Repository
public class MenuRepository {
    private final CoffeeMapper mapper;
    public MenuRepository(CoffeeMapper mapper) { this.mapper = mapper; }

    public List<Coffee> findAll() { return mapper.findAll(); }
    public Optional<Coffee> findByName(String name) {
        return Optional.ofNullable(mapper.findByName(name));
    }
    public void updateStock(String name, int stock) { mapper.updateStock(name, stock); }
}
```

## 七、读懂现象:SQL 注入

顾客查询名传入 `美式' OR '1'='1`,拼出来的 SQL 变成:

```sql
SELECT * FROM coffee WHERE name = '美式' OR '1'='1'
```

`'1'='1'` 恒真,**整张表被查了出来**——如果这是登录查询,攻击者就能绕过密码。更狠的输入还能删表。根因:`${}` 把**用户数据当成了 SQL 代码**拼进去。改回 `#{}`:

```java
@Select("SELECT * FROM coffee WHERE name = #{name}")   // 参数化:数据和 SQL 分开传
```

`#{}` 底层用 JDBC 的 `PreparedStatement`,把 `name` 作为**参数**单独发给数据库,数据库绝不会把它当命令解析。注入,根治。

> **⏳ 版本时光机 · 持久层的演进**

| 时期 | 方案 | 特点 |
|---|---|---|
| 最底层 | 原生 **JDBC** | 手写 `Connection`/`PreparedStatement`/`ResultSet`/`close`,啰嗦但你能看清一切 |
| 半自动 | Spring `JdbcTemplate` / **MyBatis** | 你写 SQL,框架管连接、映射;MyBatis 的 SQL 可控性强,国内主流 |
| 全自动 | **Spring Data JPA** | 连 SQL 都少写,方法名即查询,适合简单 CRUD |

> **🎯 面试直击**:MyBatis 的 `#{}` 和 `${}` 有什么区别?
> `#{}` 是**参数占位**,编译成 `PreparedStatement` 的 `?`,值单独传,**天然防 SQL 注入**——绝大多数情况用它。`${}` 是**字符串直接替换**,拼进 SQL 原文,**有注入风险**,仅在"动态表名/列名/排序字段"这类无法参数化的场景谨慎使用,且必须自己做白名单校验。追问:连接池为什么重要?建立 TCP + 认证的新连接很贵,HikariCP 预建一批复用,是高并发下的性能关键。

### 一、选择题(10 道)
1. [基础]MyBatis 中,`@Mapper` 注解的作用是什么?
- A) 自动生成数据库表　B) 将该接口标记为 MyBatis 的映射器,MyBatis 自动为其生成实现类并注册为 Bean　C) 开启事务管理　D) 加密 SQL 语句
> [!答案] **1-B**　`@Mapper` 告诉 MyBatis"这个接口是一个映射器",框架通过动态代理生成实现类,把接口方法和 SQL 注解绑定。**举一反三**:也可以在启动类上使用 `@MapperScan("com.coffee.mapper")` 批量扫描,省去每个接口都写 `@Mapper`。

2. [进阶]MyBatis 中 `#{name}` 和 `${name}` 的核心区别是什么?
- A) 两者完全相同　B) `#{name}` 是参数化占位符,底层走 `PreparedStatement` 的 `?`,天然防 SQL 注入;`${name}` 是直接字符串替换,有注入风险　C) `#{name}` 更快　D) `#{name}` 只用于 SELECT,`${name}` 只用于 UPDATE
> [!答案] **2-B**　`#{}` 将参数作为值发送,SQL 与数据分开传;`${}` 把参数拼进 SQL 原文。**举一反三**:`${}` 仅在"动态表名/列名/ORDER BY 字段"等无法参数化的场景谨慎使用,且必须做白名单校验。

3. [深入]以下哪个用户输入能在使用 `${name}` 的查询中触发 SQL 注入?
- A) `美式`　B) `美式' OR '1'='1`　C) `null`　D) `12345`
> [!答案] **3-B**　输入 `美式' OR '1'='1` 拼进 SQL 后变成 `WHERE name = '美式' OR '1'='1'`,OR 后的恒真条件让整张表被查出。**举一反三**:更危险的注入如 `'; DROP TABLE coffee; --`,直接删表——这就是为什么用户输入绝对不能用 `${}` 拼接。

4. [基础]JDBC 中,防止 SQL 注入的正确做法是?
- A) 用 `Statement` 拼接 SQL　B) 用 `PreparedStatement`,以 `?` 占位,参数单独传入　C) 在前端正则过滤　D) 给数据库加防火墙
> [!答案] **4-B**　`PreparedStatement` 将 SQL 骨架和参数分开发送——骨架先编译,参数作为值传入,数据库不会把参数当命令解析。**举一反三**:MyBatis 的 `#{}` 底层就是 `PreparedStatement` 的 `?`——框架帮你做了正确的事。

5. [进阶]Spring Boot 中,数据库连接池的默认实现是?
- A) DBCP　B) C3P0　C) HikariCP　D) 无连接池
> [!答案] **5-C**　Spring Boot 2.x+ 默认使用 HikariCP——以高性能和低开销著称,启动时自动根据 `spring.datasource` 配置创建连接池。**举一反三**:连接池预先创建一批数据库连接并复用,避免每次请求都"TCP 握手+MySQL 认证"的昂贵开销——是高并发下的性能关键。

6. [深入]`application.yml` 中配置 `spring.datasource.url`,连接 MySQL 时需要携带哪些关键参数?
- A) 只要 host 和端口　B) 库名 + 字符编码(`useUnicode=true&characterEncoding=utf8`) + 时区(可选)　C) 只要用户名密码　D) 必须配 SSL
> [!答案] **6-B**　典型 URL:`jdbc:mysql://localhost:3306/cafe?useUnicode=true&characterEncoding=utf8`。**举一反三**:生产环境还需关注 `serverTimezone=Asia/Shanghai`、连接超时参数 `connectTimeout` 和 `socketTimeout`。

7. [基础]MyBatis 中,`@Select` 注解写在什么位置?
- A) 类上　B) Mapper 接口的方法上,如 `@Select("SELECT name, price FROM coffee") List<Coffee> findAll();`　C) Service 类上　D) Controller 方法上
> [!答案] **7-B**　MyBatis 的 SQL 注解(`@Select`/`@Insert`/`@Update`/`@Delete`)标注在 Mapper 接口的方法上,定义该方法执行的 SQL。**举一反三**:SQL 也可写在 XML 映射文件中——注解适合简单 SQL,XML 适合复杂 SQL(动态条件、多表关联)。

8. [进阶]当 `MenuRepository` 从内存 `Map` 切换到 MyBatis 连接 MySQL 时,上层 `CoffeeService` 需要改动吗?
- A) 需要全部重写　B) 一行都不需要改——因为三层架构中 Service 依赖的是 Repository 的接口,底层实现切换对上层透明　C) 需要改 Controller　D) 需要改 pom.xml 即可
> [!答案] **8-B**　这正是三层架构的价值:Repository 封装了数据存取细节,Service 只调用 `findAll()`/`findByName()`,不管底层是内存还是 MySQL。**举一反三**:同理,哪天从 MyBatis 换成 JPA,Service 依然不改——**依赖倒置原则**让每一层可独立替换。

9. [深入]MyBatis 的 `@Param` 注解什么情况下必须使用?
- A) 所有方法都要用　B) 当 Mapper 方法有多个参数时,需用 `@Param("name")` 为每个参数命名,以便 SQL 中 `#{name}` 引用　C) 只在 INSERT 时用　D) 不需要,自动识别
> [!答案] **9-B**　MyBatis 在多参数时无法自动推断参数名(Java 默认不保留参数名),必须用 `@Param` 显式命名。例如 `int updateStock(@Param("name") String name, @Param("stock") int stock);`。**举一反三**:Java 8+ 编译时加 `-parameters` 参数可保留参数名,但仍建议显式写 `@Param`——不依赖编译配置,更可靠。

10. [综合]持久层方案从原生 JDBC 到 MyBatis 再到 Spring Data JPA,控制力和开发效率的变化趋势是?
- A) 控制力递增,效率递减　B) 控制力递减(JDBC 最强→JPA 最弱),开发效率递增(JDBC 最低→JPA 最高)　C) 三者完全相同　D) MyBatis 控制力和效率都最优
> [!答案] **10-B**　JDBC:手写一切,控制力最强但样板代码巨多;MyBatis:手写 SQL 但自动映射,取平衡点;JPA:绝大部分 SQL 自动生成,效率最高但复杂查询需 JPQL。**举一反三**:三者可在一个项目中混用——JPA 做标准 CRUD,MyBatis 做复杂报表,JDBC 做批量导入——根据场景选工具,不是非此即彼。

### 二、解答题(3 道)
1. [概念]用自己的话解释 SQL 注入的攻击原理,并用"顾客查菜单"的场景说明 `${}` 和 `#{}` 的区别。
> [!答案] **1**　SQL 注入:攻击者将恶意的 SQL 片段混入用户输入,程序把它拼进查询后改变了原 SQL 的语义。咖啡站场景——查询 `SELECT * FROM coffee WHERE name = '${name}'`,顾客输入 `美式' OR '1'='1`,拼接后变成 `WHERE name = '美式' OR '1'='1'`,OR 后的恒真条件使整张表被查出。`#{}` 的版本:`SELECT * FROM coffee WHERE name = #{name}`,你输入同样的恶意串,数据库会把它当作"name 字段的值",在数据里搜一个名字叫"美式' OR '1'='1"的咖啡,当然搜不到——SQL 骨架没被篡改。**举一反三**:不仅是查询——注入同样可以劫持 UPDATE/DELETE,甚至用 `UNION SELECT` 拖走其他表的数据。防线只有一条:**永远用 `#{}`,永远别把用户输入拼进 SQL**。

2. [场景]咖啡站需要新增"按价格区间查咖啡"的功能。请写出 Mapper 接口方法签名、SQL、以及 Service 层的调用代码。要求:SQL 必须使用 `#{}` 参数化,且方法需要对两个价格参数做非 null 和合理性的基本判断。
> [!答案] **2**　Mapper:`@Select("SELECT name, price, stock FROM coffee WHERE price BETWEEN #{min} AND #{max}") List<Coffee> findByPriceRange(@Param("min") double min, @Param("max") double max);`。Service:`public List<Coffee> search(double min, double max) { if (min < 0 || max < 0 || min > max) throw new IllegalArgumentException("价格区间不合法"); return mapper.findByPriceRange(min, max); }`。**举一反三**:参数校验放在 Service 层——Controller 做格式校验(`@Positive`),Service 做业务校验(`min > max` 不合理),校验分层,职责清晰。

3. [综合]从"连接管理、SQL 编写、结果映射、防注入"四个维度,分析原生 JDBC 和 MyBatis 的差异,并说明为什么现代项目几乎不再手写原生 JDBC。
> [!答案] **3**　①连接管理:JDBC 需手动 `Connection.open()`/`close()`,代码冗长;MyBatis 复用 Spring 管理的连接池(HikariCP),自动归还。②SQL 编写:JDBC 需手写完整 SQL + `PreparedStatement.setXxx()` 逐个设参;MyBatis 注解/XMl 写 SQL + `#{}` 自动绑定。③结果映射:JDBC 需手动遍历 `ResultSet`、逐字段 `getString()`/`getInt()` 映射到对象;MyBatis 自动将结果集列名与对象字段对应映射。④防注入:两者底层都用 `PreparedStatement` 参数化,但 JDBC 可能被开发者误用 `Statement` 拼接;MyBatis 的 `#{}` 默认安全,只有 `${}` 危险——规范更清晰。**举一反三**:原生 JDBC 仍有学习价值——它让你看到框架底下发生了什么;`@MybatisTest` 测 Mapper 时用的就是内嵌数据库 + MyBatis 自动配置,继承自 JDBC 的根基。

### 三、代码题(2 道)
1. [基础]定义 `Coffee` record(name, price, stock),写一个 `CoffeeMapper` 接口,包含:①查询全部咖啡(`@Select`);②按名称精确查询(`@Select` + `#{name}`,返回 Optional);③更新库存(`@Update` + `#{stock}` + `#{name}`)。所有方法使用 `@Param` 显式命名参数。
> [!答案] **1 验收**:
> ```java
> record Coffee(String name, double price, int stock) {}
> 
> @Mapper
> interface CoffeeMapper {
>     @Select("SELECT name, price, stock FROM coffee")
>     List<Coffee> findAll();
> 
>     @Select("SELECT name, price, stock FROM coffee WHERE name = #{name}")
>     Coffee findByName(@Param("name") String name);
> 
>     @Update("UPDATE coffee SET stock = #{stock} WHERE name = #{name}")
>     int updateStock(@Param("name") String name, @Param("stock") int stock);
> }
> ```
> **举一反三**:`@Insert` 和 `@Delete` 同理;`@Update` 返回 `int`(受影响行数),可用于判断是否真正更新了数据(返回 0 说明 name 不存在)。

2. [综合]写一个 `@MybatisTest` 测试 `CoffeeMapper`,验证:①查询全部咖啡返回预插的 3 条记录;②对不存在的咖啡名 `findByName` 返回 `null`;③用注入字符串 `"' OR '1'='1"` 调 `findByName`,返回 `null`——证明 `#{}` 天然防注入。用 `@Sql` 注解在测试前执行建表+插数据脚本。
> [!答案] **2 验收**:
> ```java
> @MybatisTest
> @Sql(scripts = "/init-coffee.sql")  // CREATE TABLE coffee + INSERT 3 条
> class CoffeeMapperTest {
>     @Autowired CoffeeMapper mapper;
> 
>     @Test
>     void findAll_returns_all() {
>         assertEquals(3, mapper.findAll().size());
>     }
> 
>     @Test
>     void findByName_notExist_returnsNull() {
>         assertNull(mapper.findByName("独角兽拿铁"));
>     }
> 
>     @Test
>     void findByName_injectionString_returnsNull_notHacked() {
>         assertNull(mapper.findByName("美式' OR '1'='1"),
>                 "#{} 会把注入字符串当名字搜,搜不到,不会被当 SQL 执行");
>     }
> }
> ```
> **举一反三**:`@MybatisTest` 只加载 MyBatis 相关组件,默认使用内嵌 H2 数据库,比 `@SpringBootTest` 快得多;第三个测试是**安全性断言**——证明注入攻击在你的代码里天然无效。
