## 五、代码:用 HttpClient 发一次请求

Java 11 起内置了现代化的 `HttpClient`(在 `java.net.http`),不用再依赖第三方库:

```java
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;

public class HttpDemo {
    public static void main(String[] args) throws Exception {
        HttpClient client = HttpClient.newHttpClient();

        HttpRequest request = HttpRequest.newBuilder()
            .uri(URI.create("https://httpbin.org/get"))   // 一个回显请求的测试站
            .GET()                                          // 方法:取
            .build();

        HttpResponse<String> resp =
            client.send(request, HttpResponse.BodyHandlers.ofString());

        System.out.println("状态码:" + resp.statusCode());   // 200
        System.out.println("响应体:" + resp.body());
    }
}
```

`newBuilder()` 一步步拼出请求(URL、方法、头、体),`send` 发出去、拿回 `HttpResponse`,`statusCode()` 就是那张回执章。

## 六、故意制造一个 Bug:方法用错

`httpbin.org/post` 这个地址**只收 POST**,却用 GET 去调:

```java
HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://httpbin.org/post"))   // 只接受 POST 的地址
    .GET()                                           // ← 故意用错方法
    .build();
```

## 七、读懂现象:405 Method Not Allowed

```text
状态码:405
```

`405` 的意思是:**地址找到了,但你用的方法它不支持**。这和 `404`(地址根本不存在)是两码事——`404` 是"查无此人",`405` 是"人在、但你敲错了门"。改用 POST 并带上请求体即可:

```java
.uri(URI.create("https://httpbin.org/post"))
.POST(HttpRequest.BodyPublishers.ofString("{\"item\":\"美式\"}"))
.header("Content-Type", "application/json")
```

> **豆豆锐评 · 状态码是排障的第一现场**
> 看到报错先看状态码分类:**4xx 是你(请求方)的锅**——参数错、方法错、没权限、地址错;**5xx 是服务器的锅**——它自己炸了。分清这一点,能省掉一半"到底该改客户端还是改服务端"的扯皮。常背:200 成功、201 已创建、400 参数错、401 未认证、403 无权限、404 找不到、405 方法错、500 服务器内部错误。

> **⏳ 版本时光机 · Java 发 HTTP 请求的写法**

| JDK 版本 | 写法 | 问题 |
|---|---|---|
| Java 8 及以前 | `HttpURLConnection` | 冗长、要手动拼流、难用 |
| 老项目常见 | 第三方 Apache HttpClient / OkHttp | 得额外加依赖 |
| Java 11+ | **内置 `java.net.http.HttpClient`** | 官方、支持 HTTP/2、异步、无需第三方 |

> **🎯 面试直击**:GET 和 POST 有什么区别?
> 语义上:GET 用于**获取**资源、**幂等**(调多次结果一样)、参数在 URL、可被缓存;POST 用于**提交/创建**、**非幂等**(调两次可能下两单)、数据在请求体、不被缓存。追问点:① 幂等性是设计约定不是强制,别把有副作用的操作塞进 GET;② URL 长度有限,大量数据/敏感数据用 POST;③ 真正的安全靠 HTTPS,不是靠"POST 看不见"。

## 八、用测试证明:能拿到预期状态码

把"发请求"抽成方法,就能测它:

```java
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.Tag;
import static org.junit.jupiter.api.Assertions.*;

class HttpDemoTest {
    @Test
    @Tag("integration")   // 依赖外网,标记为集成测试,可单独跑
    void get_returns_200() throws Exception {
        var client = java.net.http.HttpClient.newHttpClient();
        var req = java.net.http.HttpRequest.newBuilder()
            .uri(java.net.URI.create("https://httpbin.org/get")).GET().build();
        var resp = client.send(req, java.net.http.HttpResponse.BodyHandlers.ofString());
        assertEquals(200, resp.statusCode());
    }
}
```

> **豆豆旁白**:碰网络、数据库的测试叫**集成测试**,慢且依赖环境,用 `@Tag` 标出来单独跑;纯逻辑的**单元测试**(第三季那种)要快、要能天天跑。两者分开,是成熟工程的习惯。

### 一、选择题(10 道)
1. [基础]以下哪个 HTTP 方法用于**获取**资源,且天然具备**幂等性**?
   - A) POST　B) GET　C) PATCH　D) CONNECT
> [!答案] **1-B**　GET/PUT/DELETE 都幂等;POST 每次新建资源,不幂等。**举一反三**:幂等性是语义约定而非强制,别把有副作用的操作塞进 GET。

2. [进阶]HTTP 状态码 `405 Method Not Allowed` 表示什么?
   - A) 请求的资源不存在　B) 服务器内部错误　C) 地址存在但方法不被支持　D) 请求参数格式不对
> [!答案] **2-C**　405 和 404 是不同的:404 是地址不存在,405 是地址在但方法用错。**举一反三**:遇到 405 先检查 URL,再确认 `@GetMapping`/`@PostMapping` 是否匹配。

3. [深入]以下哪个 HTTP 方法**不是幂等**的?
   - A) PUT　B) DELETE　C) POST　D) GET
> [!答案] **3-C**　POST 每次调用都创建新资源、产生副作用;其余三者多次调用结果不变。**举一反三**:PATCH 是否幂等取决于实现——部分更新可能累积,一般视为非幂等。

4. [基础]HTTP 请求-响应模型中,**请求行**必须包含哪三个要素?
   - A) 方法、URL、HTTP 版本　B) Host、Content-Type、Body　C) Accept、Cookie、User-Agent　D) GET、POST、PUT
> [!答案] **4-A**　请求行格式:`GET /api/menu HTTP/1.1`。**举一反三**:响应行格式是 `HTTP/1.1 200 OK`,状态码是排障的第一入口。

5. [进阶]Java 11+ 内置 `HttpClient` 相比旧版 `HttpURLConnection` 的优势不包括?
   - A) 支持 HTTP/2　B) 支持异步请求　C) API 更简洁　D) 不需要导入任何类
> [!答案] **5-D**　仍需 `import java.net.http.*`。**举一反三**:优势包括支持 HTTP/2、异步请求、链式 Builder 模式,不需要第三方依赖。

6. [深入]状态码 `201 Created` 通常在哪个 HTTP 方法成功后返回?
   - A) GET　B) PUT　C) POST　D) DELETE
> [!答案] **6-C**　POST 创建新资源成功返回 201;GET 返回 200;PUT 更新返回 200;DELETE 返回 204。**举一反三**:201 响应通常带 `Location` 头指向新创建资源的 URL。

7. [基础]`Content-Type: application/json` 这个 HTTP 头的作用是?
   - A) 告诉服务器"我发的是 JSON"　B) 告诉浏览器"用 JSON 方式显示"　C) 加密传输内容　D) 压缩响应体
> [!答案] **7-A**　Content-Type 声明**请求体或响应体**的媒体类型;服务端据此选择正确的 `HttpMessageConverter` 解析。**举一反三**:`Accept` 头是客户端告诉服务器"我能接收什么格式",两者配合协商内容格式。

8. [进阶]关于 RESTful 风格 API,以下描述正确的是?
   - A) URL 中应包含动词如 `/getOrders`　B) 同一 URL 配合不同方法实现不同操作　C) 只使用 GET 和 POST 就够了　D) 必须返回 JSON 格式
> [!答案] **8-B**　RESTful 的核心:URL 代表资源,GERT/POST/PUT/DELETE 代表操作——`GET /orders` 查订单,`POST /orders` 创建。**举一反三**:URL 用名词复数(`/orders` 不写 `/getOrders`),层级表示关系(`/orders/{id}/items`)。

9. [深入]HTTP 请求的 `Host` 头是什么作用?
   - A) 指定客户端的 IP 地址　B) 指定要访问的域名,支持一台服务器托管多个站点　C) 加速 DNS 解析　D) 加密身份信息
> [!答案] **9-B**　一台服务器可能运行多个网站,Host 头告诉服务器"我要访问哪个域名"。**举一反三**:HTTP/1.1 要求必须带 Host 头;Nginx 反向代理也依赖它做虚拟主机路由。

10. [综合]用 HttpClient 发送 POST 请求时,以下哪个步骤**不是必须**的?
   - A) 设置 `.POST(BodyPublisher)`　B) 设置 `.header("Content-Type","application/json")`　C) 设置 `.uri(URI.create(...))`　D) 调用 `client.send(request, BodyHandler)`
> [!答案] **10-B**　Content-Type 非 HTTP 协议强制要求,但发 JSON 时必须设置,否则服务端可能无法正确解析。**举一反三**:项目规范应要求所有 POST/PUT 请求**必须**带 Content-Type。

### 二、解答题(3 道)
1. [概念]用自己的话解释"HTTP 是无状态协议",并举出两种让 HTTP "记住用户"的技术方案及各自原理。
> [!答案] **1**　无状态 = 每次请求独立,服务器不自动保留上次交互的任何上下文(协议层没有"会话"概念)。绕过方案:①Cookie——客户端存 session-id,每次请求自动带上,服务端查 Session;②JWT——服务端签发带用户信息的签名令牌,客户端存 token 每次请求带上,服务端验签即可识别。**举一反三**:无状态设计天然适合横向扩展——任何服务器都能处理请求,无需"粘性会话"。

2. [场景]咖啡站需要一套 RESTful API 管理菜单。请设计增删改查四个接口的 URL、HTTP 方法和响应状态码。
> [!答案] **2**　①查全部菜单:`GET /api/menu` → 200;②查单品:`GET /api/menu/{id}` → 200/404;③新增咖啡:`POST /api/menu` → 201;④更新:`PUT /api/menu/{id}` → 200;⑤删除:`DELETE /api/menu/{id}` → 204。**举一反三**:PUT 要求传入完整对象(幂等替换),PATCH 用于部分字段更新——根据业务选择。

3. [综合]从连接复用、请求并发、头部压缩三个维度,对比 HTTP/1.1 和 HTTP/2 的核心差异。
> [!答案] **3**　①连接复用:HTTP/1.1 支持 Keep-Alive(同一连接串行多发),但仍有队头阻塞;HTTP/2 多路复用,同一连接可**同时**传输多个请求/响应。②请求并发:HTTP/1.1 通过开 6~8 个并行连接增加并发;HTTP/2 单连接多 Stream,天然高并发。③头部压缩:HTTP/1.1 每次请求带完整 Header;HTTP/2 用 HPACK 压缩,且重复 Header 不重复传。**举一反三**:HTTP/3 基于 QUIC(UDP),连 TCP 队头阻塞也消除了。

### 三、代码题(2 道)
1. [基础]用 Java 11+ HttpClient 向 `https://httpbin.org/get` 发 GET 请求,打印状态码和响应体前 150 个字符,捕获网络异常并给出友好提示。
> [!答案] **1 验收**:
> ```java
> HttpClient client = HttpClient.newHttpClient();
> HttpRequest request = HttpRequest.newBuilder()
>         .uri(URI.create("https://httpbin.org/get"))
>         .GET().build();
> try {
>     HttpResponse<String> resp = client.send(request,
>             HttpResponse.BodyHandlers.ofString());
>     System.out.println("状态码:" + resp.statusCode());
>     String body = resp.body();
>     System.out.println(body.substring(0, Math.min(150, body.length())));
> } catch (IOException e) {
>     System.err.println("网络异常:" + e.getMessage());
> } catch (InterruptedException e) {
>     Thread.currentThread().interrupt();
> }
> ```
> **举一反三**:用 `HttpClient.newBuilder().connectTimeout(Duration.ofSeconds(5)).build()` 可加连接超时;不设超时的 HttpClient 可能永久阻塞。

2. [综合]用 HttpClient 发一个带 JSON 请求体的 POST 请求到 `https://httpbin.org/post`,发一条下单数据 `{"name":"拿铁","qty":2}`,并验证响应状态码为 200 且响应体包含你发的数据。将验证逻辑写成 JUnit 测试。
> [!答案] **2 验收**:
> ```java
> @Test
> void post_order_echoes_back_data() throws Exception {
>     var client = HttpClient.newHttpClient();
>     String json = "{\"name\":\"拿铁\",\"qty\":2}";
>     var request = HttpRequest.newBuilder()
>             .uri(URI.create("https://httpbin.org/post"))
>             .header("Content-Type", "application/json")
>             .POST(HttpRequest.BodyPublishers.ofString(json))
>             .build();
>     var resp = client.send(request,
>             HttpResponse.BodyHandlers.ofString());
>     assertEquals(200, resp.statusCode());
>     assertTrue(resp.body().contains("拿铁"));
>     assertTrue(resp.body().contains("\"qty\": 2"));
> }
> ```
> **举一反三**:真实项目中不要每次请求都 `newHttpClient()`——应复用为静态单例;`httpbin.org` 适合练习但不适合集成测试(依赖外网),用 WireMock 或 MockServer 才能稳定。
