## 一、需求:一个能自动伸缩的订单容器

早高峰订单雪片一样来,晚上又冷清。阿零想用数组存订单,却卡在第一步:数组长度**一次定死**——开 `new String[10]` 高峰装不下,开 `new String[1000]` 平时全是空位白占内存。

豆豆:「你要的不是数组,是一个**能随订单增减自动伸缩**的容器——`List`。它底层还是数组,但满了会自己搬家换个更大的,你不用操心长度。」

## 二、漫画 · 会翻脸的传送带

> **〔1〕** 一条能自己接长的传送带,侧面刻着 `ArrayList`。订单一多,它「咔」地自动延长一截。
> 豆豆:「`ArrayList` 底层是数组,装满了就新建一个**更大的数组**、把旧元素搬过去——默认扩成原来的 **1.5 倍**。」

> **〔2〕** 旁边另一条链子串成的带子标着 `LinkedList`,两头加卸货飞快,可阿零想拿「第 500 个」时,得从头一节一节数过去,累到冒汗。
> 豆豆:「`LinkedList` 两端增删快,但**随机访问是 O(n)**——按下标取值它得从头走,别拿它当数组使。」

> **〔3〕** 阿零嫌麻烦,一边用 for-each 遍历订单、一边顺手把「美式」的杯子往外扔。
> 阿零:「反正边看边删,一趟搞定!」

> **〔4〕** 传送带突然「哐当」卡死、红灯狂闪,吐出一张报警条 `ConcurrentModificationException`。
> 豆豆:「一边遍历一边改结构,集合**当场翻脸**。它记着自己被改了几次,发现你绕过它偷偷动手,立刻掀桌。」

> **〔5〕** 阿零缩手:「那我少删一个、留倒数第二个不删呢?刚才那次它咋没报?」
> 豆豆(叼着豆子叉腰):「问到点子上了——这异常是**尽力而为**,不是每次都抛。别把『它没报』当成『我写对了』,那是运气,不是本事。」

## 三、本话目标

- 用 `List<T>` / `ArrayList` 做增删改查与遍历;
- 说清 `ArrayList`(数组,默认扩容 1.5 倍)与 `LinkedList`(链表,随机访问 O(n))的取舍;
- 踩一次遍历中删除触发的 `ConcurrentModificationException`;
- 想通它是 **fail-fast 尽力而为、不保证一定抛**,并学会用 `removeIf` / 迭代器安全删除。

## 四、原理图:List 的两种底盘

```text
List<String> orders = new ArrayList<>();
orders.add("美式");  orders.get(0);  orders.size();  orders.remove("美式");

ArrayList   底层=可扩容数组   随机访问 O(1)  中间增删要挪后面所有元素
            装满时:新建 1.5 倍大的数组,旧元素整体拷过去(所以别频繁扩)
LinkedList  底层=双向链表     随机访问 O(n)  两端增删 O(1)

遍历中改结构  → 迭代器发现 modCount 变了 → ConcurrentModificationException
安全删除     → removeIf(条件)  或  迭代器 it.remove()
```

## 五、代码:订单队列

```java
import java.util.ArrayList;
import java.util.List;

public class Orders {
    public static void main(String[] args) {
        List<String> orders = new ArrayList<>();
        orders.add("美式");
        orders.add("拿铁");
        orders.add("美式");

        System.out.println("共 " + orders.size() + " 单");
        for (String o : orders) System.out.println("制作 " + o);
    }
}
```

> **豆豆旁白**:`ArrayList` 默认初始容量为空,第一次 `add` 才分配。如果你已经知道大概要装多少,直接 `new ArrayList<>(1000)` 一次给够,能省掉中途一次次「搬家扩容」的开销——这在批量导入时是实打实的提速。

## 六、故意制造一个 Bug:遍历中删除

想在遍历时把所有「美式」取消掉:

```java
for (String o : orders) {
    if (o.equals("美式")) orders.remove(o);   // ← 故意:for-each 中直接改结构
}
```

## 七、读懂真实报错

```text
Exception in thread "main" java.util.ConcurrentModificationException
        at java.base/java.util.ArrayList$Itr.checkForComodification(ArrayList.java:1095)
        at java.base/java.util.ArrayList$Itr.next(ArrayList.java:1049)
        at Orders.main(Orders.java:12)
```

`ConcurrentModificationException`(并发修改异常,但**单线程也会抛**)。for-each 底层其实是个**迭代器**,它出生时记下集合的「修改次数」`modCount`;你绕过迭代器直接 `orders.remove(o)`,`modCount` 变了,迭代器下次 `next()` 一对账发现数字对不上,立刻抛异常——**防止你在一个不一致的状态上继续瞎跑**。

> **豆豆锐评**:注意它叫 **fail-fast(快速失败)**,不叫 **fail-safe**。它是**尽力而为**地帮你早发现,**不保证每次都抛**。经典反例:你删的是**倒数第二个**元素——删完后集合 `size` 少 1,迭代器的游标刚好等于新 `size`,`hasNext()` 直接返回 false、循环正常结束,`next()` 压根没再被调,那次对账就没发生,**异常也就没抛**。所以「这回没报」绝不等于「这么写是对的」。**永远别依赖它,该用安全删除就用安全删除。**

> **🔀 豆豆的多解台 · 遍历中删除元素,怎么删才安全?**

| 解法 | 代码要点 | 适合什么时候 | 坑 |
|---|---|---|---|
| 迭代器 `it.remove()` | `var it = list.iterator(); while(it.hasNext()){ if(...) it.remove(); }` | 删除逻辑复杂、需要在循环里干别的事 | 只能删「刚 `next()` 出来的那个」,别调错对象 |
| `Collection.removeIf` | `list.removeIf(o -> o.equals("美式"))` | **纯按条件批量删**(最常见) | 条件里别有副作用;一行搞定,首选 |
| 倒序索引 for | `for(int i=list.size()-1;i>=0;i--) if(...) list.remove(i);` | 需要按下标操作、或删除时还要看位置 | 必须**倒着删**,正序删会漏元素(删一个后面全前移) |

豆豆锐评:**默认用 `removeIf`**——它专为「按条件删」设计,内部走安全路径,一行、可读、不会踩 CME。只有当删除逻辑复杂到 `removeIf` 的一个 lambda 表达不清时,才退回迭代器。

## 八、修复,并用测试证明

用 `removeIf`,一行安全删除:

```java
static int cancelAll(List<String> orders, String name) {
    int before = orders.size();
    orders.removeIf(o -> o.equals(name));   // 内部走安全路径,不触发 CME
    return before - orders.size();          // 返回取消了几单
}
```

```java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.assertEquals;

class OrdersTest {
    @Test
    void cancel_all_americano() {
        var orders = new ArrayList<>(List.of("美式", "拿铁", "美式"));
        assertEquals(2, Orders.cancelAll(orders, "美式"));  // 取消 2 单
        assertEquals(1, orders.size());                     // 只剩拿铁
    }
}
```

### 一、选择题（10 道）

1. [基础] `ArrayList` 的底层数据结构是什么？- A) 双向链表　B) 动态数组　C) 哈希表　D) 红黑树
2. [基础] `LinkedList` 的底层数据结构是什么？- A) 动态数组　B) 双向链表　C) 哈希表　D) 队列
3. [基础] 以下哪种遍历方式最简洁（Java 8+）？- A) `for (int i = 0; i < list.size(); i++)`　B) `for (String s : list)`　C) `list.forEach(s -> System.out.println(s))`　D) `Iterator`
4. [进阶] `ArrayList` 按索引随机访问的时间复杂度是？- A) O(1)　B) O(n)　C) O(log n)　D) O(n²)
5. [进阶] `ArrayList` 默认扩容时增长多少倍？- A) 1.5 倍　B) 2 倍　C) 1 倍（翻倍不是 1 倍）　D) 不变
6. [进阶] 对于频繁在头部插入/删除的场景，应该用哪个？- A) `ArrayList`　B) `LinkedList`　C) `HashSet`　D) `HashMap`
7. [进阶] `for-each` 遍历 List 时调用 `list.remove(...)` 会发生什么？- A) 正常运行　B) 抛 `ConcurrentModificationException`　C) 编译错误　D) 元素跳过不报错
8. [综合] 如何安全地在遍历中删除元素？- A) `list.removeIf(condition)`　B) `for-each` 中 `list.remove(o)`　C) 普通 for 中 `list.remove(i)` 然后 `i++`　D) 无法安全删除
9. [综合] 下面代码输出什么？```java List<String> list = new ArrayList<>(List.of("A","B","C")); for (int i = 0; i < list.size(); i++) { if (list.get(i).equals("B")) list.remove(i); } System.out.println(list);```- A) `[A, B, C]`　B) `[A, C]`　C) `ConcurrentModificationException`　D) `[A, B]`
10. [综合] `ArrayList` vs `LinkedList` 日常开发怎么选？- A) 优先 `LinkedList`　B) 优先 `ArrayList`（缓存友好，遍历快，绝大多数场景性能更好）　C) 随机选　D) 只用 `LinkedList`

> [!答案] **1-B**　`ArrayList` = 动态数组（`Object[]`），自动扩容。**2-B**　`LinkedList` = 双向链表，每个节点有 prev/next 指针。**3-C**　`list.forEach(s -> ...)` 最简洁，但注意内部不能 `break`/`continue`。**4-A**　数组天然支持 O(1) 随机访问——按索引直接定位。**5-A**　`ArrayList` 扩容为 `oldCapacity + oldCapacity >> 1 = 1.5 倍`。**6-B**　`LinkedList` 头尾增删 O(1)，而 `ArrayList` 头插需要挪动所有元素（O(n)）。**7-B**　`for-each` 底层是 Iterator，并发修改检测（`modCount` 不一致）抛 `ConcurrentModificationException`。**8-A**　`removeIf` 是 Java 8+ 最优雅安全的方案，内部用 `Iterator.remove()`。**9-B**　普通 for 循环不抛 CME，但索引管理有坑——删除后 `i` 没递减，C 被跳过。结果 `[A, C]`（B 被删，但 C 被跳过）。**10-B**　日常 90%+ 场景用 `ArrayList`——CPU 缓存行的空间局部性让数组遍历非常快，`LinkedList` 的节点散布在内存各处。
**举一反三**：第 9 题展示了一个更隐蔽的 bug——普通 for 虽不抛 CME，但删除后索引不调会导致漏删。用 `removeIf`（第 8 题）是唯一既安全又不易写错的方案。

### 二、解答题（3 道）

1. [概念] `ArrayList` 的扩容机制是什么？为什么默认是 1.5 倍而不是 2 倍或每次只加 1？
2. [场景] 订单系统需要维护一个"最近的 5 单"列表——每次新下单，如果超过 5 单就删最早的。用 `ArrayList` 实现，写出伪代码并分析"删头"的复杂度。
3. [综合] `ConcurrentModificationException` 是怎么产生的（从 `modCount` 角度解释）？为什么文档说它是"尽力而为"的检测（best-effort）？什么情况下修改了 List 却**不抛** CME？

> [!答案] **1**　`ArrayList` 内部维护一个 `Object[]`，当 `add` 发现数组满了：①创建新数组，长度 = `oldCapacity + oldCapacity/2`（即 1.5 倍，通过 `>> 1` 计算）；②用 `Arrays.copyOf` 把老数据复制过去；③老数组变成垃圾被 GC。选 1.5 倍是平衡——2 倍会造成大量内存浪费（比如容量 9→18 实际只用 10，浪费近一半），+1 会导致扩容太频繁（每次满了都要复制数组，O(n) 操作变成常客）。**举一反三**：如果你知道数据量大，`new ArrayList<>(1000)` 预分配容量能避免多次扩容——这是常见优化手段。**2**　
> ```java
> List<String> recent = new ArrayList<>();
> void addOrder(String order) {
>     recent.add(order);
>     if (recent.size() > 5) {
>         recent.remove(0);  // 删头
>     }
> }
> ```
> `remove(0)` 在 `ArrayList` 中需要把后续所有元素往前挪一位——O(n)。如果订单量巨大、头删频繁，应该改用 `LinkedList`（`removeFirst()` O(1)）或 `ArrayDeque`（环形数组，比 `LinkedList` 缓存更友好）。**举一反三**：`ArrayDeque` 是大多数"队列/栈"场景的首选——比 `LinkedList` 更省内存、遍历更快。**3**　`ArrayList` 内部有 `modCount` 字段，每次结构性修改（add/remove）自增。创建 `Iterator` 时记录当前的 `modCount` 为 `expectedModCount`。每次 `next()`/`remove()` 时比较两者——不一致就抛 CME。它是 best-effort 因为文档明确说"不做硬性保证"——例如在单线程中，也不是所有修改都能被检测到。一种不抛的情形：普通 for 循环 + `remove(i)`（不走 Iterator，绕过了检测），如选择题 9。还有 `CopyOnWriteArrayList`——每次修改创建新数组快照，遍历时不受影响。**举一反三**：多线程环境下，`Vector` 的 `Iterator` 会抛 CME 但 `Vector` 自身的方法是 `synchronized` 的——这经常被搞混。

### 三、代码题（2 道）

1. [基础] 创建 `List<String> orders` 存入 "美式"、"拿铁"、"摩卡"。用三种方式遍历（普通 for、for-each、forEach Lambda）打印所有元素。验证三种方式输出一致。
2. [综合] 实现 `cancelAll(List<String> orders, String target)`：删除所有包含 `target` 的订单，返回被删除的数量。要求：①用 `removeIf`（一行代码）；②不能抛 `ConcurrentModificationException`；③写边界测试——删除不存在的品项（应返回 0）、所有元素都匹配（返回 size）、空列表、包含 null 元素的列表。

> [!答案] **1 验收**：
> ```java
> List<String> orders = new ArrayList<>();
> orders.add("美式"); orders.add("拿铁"); orders.add("摩卡");
> // 方式1: 普通 for
> for (int i = 0; i < orders.size(); i++) { System.out.println(orders.get(i)); }
> // 方式2: for-each
> for (String o : orders) { System.out.println(o); }
> // 方式3: forEach Lambda
> orders.forEach(o -> System.out.println(o));
> // 方式4（补充）: 方法引用
> orders.forEach(System.out::println);
> // 均输出: 美式 / 拿铁 / 摩卡
> ```
> **举一反三**：`forEach` Lambda 不能 `break`/`continue`；需要提前退出时用传统 `for-each`。**2 验收**：
> ```java
> static int cancelAll(List<String> orders, String target) {
>     int before = orders.size();
>     orders.removeIf(o -> target.equals(o));  // null-safe 需要 Objects.equals
>     return before - orders.size();
> }
> // 更健壮的版本（处理 null）:
> static int cancelAllSafe(List<String> orders, String target) {
>     int before = orders.size();
>     orders.removeIf(o -> Objects.equals(o, target));  // Objects.equals 天然 null-safe
>     return before - orders.size();
> }
> // 边界测试:
> // cancelAll(new ArrayList<>(List.of("A","B")), "C") → 0（不存在）
> // cancelAll(new ArrayList<>(List.of("A","A")), "A") → 2（全匹配）
> // cancelAll(new ArrayList<>(), "A") → 0（空列表）
> // cancelAll(new ArrayList<>(Arrays.asList("A", null)), "A") → Objects.equals 版本安全处理 null
> ```
> **举一反三**：`Objects.equals(o, target)` 比 `target.equals(o)` 更安全——当 `o` 是 `null` 时前者返回 `false`（不影响），后者抛 NPE。边界测试中的 null 元素就靠它兜底。
