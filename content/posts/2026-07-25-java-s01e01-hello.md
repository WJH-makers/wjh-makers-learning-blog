## 四、原理图:Java 不直接运行源码

很多人第一天都误会:以为写完代码就能跑。**Java 不直接运行你写的源码**,中间隔着一道翻译和一座虚拟机。

```text
  HelloCoffee.java        你写的源码(给人看的)
        │  javac  ← 编译官:查语法、类型、类名 = 文件名,翻译成字节码
        ▼
  HelloCoffee.class       字节码(给 JVM 看的,和操作系统无关)
        │  java   ← JVM 城主:类加载 → 校验 → 执行引擎(解释 + JIT 即时编译)
        ▼
   机器执行 → 终端打印
```

三个必须记住的点:

- **`javac` 负责翻译,`java` 负责运行。** 两步分开,是你以后判断"报错发生在哪一步""改了代码为什么要重新编译"的地基。
- 中间产物 `.class` 是**字节码**,它不认操作系统。同一份 `.class`,Windows / macOS / Linux 上的 JVM 都能跑——这就是那句面试常问的 **Write Once, Run Anywhere**。
- 所以别再纠结"Java 是编译型还是解释型":它是**先编译成字节码,再由 JVM 解释执行、热点代码 JIT 再编译成机器码**的混合模式。这一句能答明白,面试第一关就稳了。

## 五、代码:咖啡站的第一句话

规矩:文件名必须和 `public` 类名**一字不差**——类叫 `HelloCoffee`,文件就得叫 `HelloCoffee.java`。这条是编译官铁律,记错第一话就报错。

```java
public class HelloCoffee {
    // 招呼语单独抽成一个方法 —— 第八节要给它写测试
    static String greeting() {
        return "豆豆咖啡站 · 营业中 ☕";
    }

    public static void main(String[] args) {
        System.out.println(greeting());
    }
}
```

对这个 `HelloCoffee` 程序而言，`main` 是**启动入口**——JVM 城主进门就从它开始执行。Java 25 还支持其他可启动的 `main` 形态；先把这套最常见的 `public static void main(String[] args)` 读熟。跑起来分两步，正好对应上面的原理图:

```bash
javac HelloCoffee.java   # 编译官:生成 HelloCoffee.class
java HelloCoffee         # JVM 城主:执行(注意:没有 .class 后缀)
```

输出:

```text
豆豆咖啡站 · 营业中 ☕
```

> **豆豆旁白**:现代 JDK 还允许 `java HelloCoffee.java` 一步直接跑单文件,省掉手动编译。但你**先把两步走通**,再用捷径——否则出了错,你连它卡在编译还是运行都分不清。

**Java 25 给零基础铺的坡道(JEP 512 正式转正)**:其实你可以省掉 `public class` 和 `String[] args` 那一堆仪式,写成这样——

```java
void main() {
    IO.println("豆豆咖啡站 · 营业中 ☕");
}
```

存成 `HelloCoffee.java`,直接 `java HelloCoffee.java` 就能跑。`IO.println` 来自 Java 25 转正的 `java.lang.IO`——它和 `String` 一样在 `java.lang` 包里,**开箱即用、不用 `import`**,所以你不用再从背 `System.out.println` 这串"咒语"开始。这是官方特意为初学者削平的门槛。**但本连载仍会先带你把完整的 `class` + `main` 形态吃透**——因为你进任何一个真实项目,满屏都是它,躲不掉。

> **⏳ 版本时光机 · 一个 Hello 程序,三代 JDK 怎么写**

| JDK 版本 | 入门程序的写法 | 关键变化 |
|---|---|---|
| Java 8 ~ 20 | `public class HelloCoffee { public static void main(String[] args) { System.out.println("…"); } }` | 经典全套:`public class` + `static main` + `String[] args`,一个都不能少 |
| Java 21 | `void main() { System.out.println("…"); }`(预览,需 `--enable-preview`) | JEP 445 首次试水「隐式类 + 实例 `main`」,砍掉仪式 |
| Java 25 | `void main() { IO.println("…"); }`(正式) | JEP 512 转正为「紧凑源文件」,连 `System.out` 都省了 |

同一句「营业中」,十年间从三行仪式瘦成一行。本连载让你**两头都懂**:老项目里满屏的全套形态,和新语法的极简坡道——面试被问到「Java 25 的隐式类是什么」,你能说清它的来龙去脉。

## 六、故意制造一个 Bug

豆豆按住阿零想合电脑的手:「别急着高兴。**主动把它弄坏一次**,你才知道报错长什么样——将来它自己坏的时候,你才不慌。」

把 `println` 手滑写成 `printline`:

```java
System.out.printline(greeting());   // ← 故意写错,少见但致命
```

重新 `javac HelloCoffee.java`。

## 七、读懂真实报错(本话最值钱的技能)

编译官当场拦下,甩出一张罚单:

```text
HelloCoffee.java:9: error: cannot find symbol
        System.out.printline(greeting());
                  ^
  symbol:   method printline(String)
  location: variable out of type PrintStream
1 error
```

别怕这堆英文,它其实很啰嗦地告诉了你一切。三步读法:

- `HelloCoffee.java:9` —— **第 9 行**。先跳过去,别在别处瞎找;
- `cannot find symbol` / `method printline(String)` —— 它找不到叫 `printline` 的方法;
- `location: ... PrintStream` —— 在 `System.out`(类型是 `PrintStream`)身上找。

结论:`PrintStream` 根本没有 `printline`,正牌是 `println`(print **line**,打印一行)。这类"拼错名字"属于 **Syntax / 符号 Bug**,编译官在编译期就当场拦下,**根本到不了 JVM**。

> **豆豆锐评**:编译期就报错,是好事。你最怕的不是它报错,是它**不报错、跑起来却悄悄给你算错账**——那种 Bug 在第十一话才登场,现在先睡一觉。

## 八、修复,并用测试证明它对

改回 `println`,重新 `javac` + `java`,输出恢复正常。

但"看起来对"在工程里不算数。JUnit 质检员两手一摊:「**证据呢?**」下面先看一眼以后要写的测试长什么样：**当前这一话只有一个 `javac` 运行的单文件，尚未配置 JUnit，因此不要把这段代码直接和 `HelloCoffee.java` 一起编译。** 第 29 话会用 Maven 把依赖、目录和 `mvn test` 一次配好；到那时把测试放进 `src/test/java/HelloCoffeeTest.java` 即可运行。

```java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.assertEquals;

class HelloCoffeeTest {
    @Test
    void greeting_should_announce_open() {
        assertEquals("豆豆咖啡站 · 营业中 ☕", HelloCoffee.greeting());
    }
}
```

等第 29 话把它跑通后，你就有了两份保险：程序能跑，而且行为被测试**钉死**——以后任何人（包括三个月后的你自己）改坏了招呼语，测试立刻拉响警报。这就是为什么第一话就抽出 `greeting()` 方法：**能被单独测试的代码，才是能被信任的代码。**
