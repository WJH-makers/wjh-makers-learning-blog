# 《从零开始学 Java》01 · 第一次让程序开口

> 连载特刊 · 第一季「点火篇」第 1 话 · 主线基线 Java 25(最新 LTS)
> 长期项目:**豆豆咖啡站**。本话结束时,它还只是一个能开口的空终端。

## 一、需求:让计算机说出一句话

阿零盯着空白终端发愁:「Java 这么大,我从哪里开始?」

咖啡站要开业,总得先能对顾客说一句「营业中」。这就是第 0 版。

## 三、本话目标

- 写出并读懂第一个 Java 类;
- 分清 `javac`(编译)和 `java`(运行)各做了什么;
- 让程序打印出咖啡站的招呼;
- 亲手制造一个报错,再读懂它、修好它;
- 用一个测试证明「招呼语」真的对。

---

## 四、原理图:源码不是直接运行的

很多新人第一天不知道:**Java 不直接运行源码**,中间隔着编译和虚拟机。

```text
  HelloCoffee.java        你写的源码(人看的)
        │  javac  ← 编译官:查语法、类型、类名
        ▼
  HelloCoffee.class       字节码(JVM 看的)
        │  java   ← JVM 城主:类加载 → 执行引擎
        ▼
   机器执行 → 终端打印
```

一句话:**`javac` 负责翻译,`java` 负责运行。** 两步分开,是理解后面一切(报错在哪一步发生、为什么改了源码要重新编译)的地基。

---

## 五、代码:咖啡站的第一句话

文件名必须和 `public` 类名一致 —— `HelloCoffee.java`。

```java
public class HelloCoffee {
    // 招呼语单独抽成一个方法,方便第八节写测试
    static String greeting() {
        return "豆豆咖啡站 · 营业中 ☕";
    }

    public static void main(String[] args) {
        System.out.println(greeting());
    }
}
```

运行(命令行两步走,对应上面的原理图):

```bash
javac HelloCoffee.java   # 编译官:生成 HelloCoffee.class
java HelloCoffee         # JVM 城主:执行(注意没有 .class 后缀)
```

输出:

```text
豆豆咖啡站 · 营业中 ☕
```

> Java 现代版本还可以 `java HelloCoffee.java` 一步直接跑单文件源码。但先理解「编译 + 运行」两步,再用捷径。

> **最新 JDK 的极简入口(Java 25,JEP 512)**:初学者其实可以省掉 `public class` 和 `String[] args` 的仪式,写成——
>
> ```java
> void main() {
>     IO.println("豆豆咖啡站 · 营业中 ☕");
> }
> ```
>
> 保存为 `HelloCoffee.java`,直接 `java HelloCoffee.java` 就能跑。`IO.println` 来自新的 `java.lang.IO`。这是官方为「从零开始」铺的坡道。本连载仍会先带你把完整的 `class` + `main` 形态理解透 —— 因为真实项目里满眼都是它。

## 六、故意制造一个 Bug

豆豆:「别急着高兴。**主动把它弄坏一次**,你才知道报错长什么样。」

把 `println` 手滑写成 `printline`:

```java
System.out.printline(greeting());   // ← 故意写错
```

重新编译 `javac HelloCoffee.java`。

---

## 七、读懂真实报错

编译官当场拦下,报错大致是:

```text
HelloCoffee.java:9: error: cannot find symbol
        System.out.printline(greeting());
                  ^
  symbol:   method printline(String)
  location: variable out of type PrintStream
1 error
```

怎么读这条报错(这是本话最值钱的技能):

- `HelloCoffee.java:9` —— **文件第 9 行**,先跳到那里;
- `cannot find symbol` / `method printline(String)` —— 它找不到名为 `printline` 的方法;
- `location: ... PrintStream` —— 在 `System.out`(类型是 `PrintStream`)上找。

结论:`PrintStream` 没有 `printline`,正确的是 `println`(print line)。这类「拼错方法名」属于 **Syntax / 符号 Bug**,由编译官在编译期就挡下,根本到不了 JVM。

---

## 八、修复,并用测试证明它对

改回 `println`,重新 `javac` + `java`,输出恢复正常。

但「看起来对」不算数 —— JUnit 质检员会问:「**证据呢?**」给招呼语补一个测试:

```java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.assertEquals;

class HelloCoffeeTest {
    @Test
    void greeting_should_announce_open() {
        assertEquals("豆豆咖啡站 · 营业中 ☕", HelloCoffee.greeting());
    }
}
```

跑通后,你有了两份保障:程序能运行,而且行为被测试钉死 —— 以后谁改坏了招呼语,测试立刻报警。
