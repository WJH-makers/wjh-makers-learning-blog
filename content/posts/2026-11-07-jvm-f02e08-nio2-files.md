## 一、事故：老文件柜只会摇头不会说话

上一话把小票日志的读写编码修好了，阿零趁热打铁写历史归档汇总脚本。他拉出来的代码是：

```java
File dir = new File("logs/2026");
if (!dir.mkdir()) {
    // 为什么失败？磁盘满？没权限？父目录不存在？
    // 我们永远不知道。
    System.out.println("创建失败");
}
String[] files = dir.list();  // 返回 null 还是空数组？两种失败都有
```

焰焰看了一眼：「`File` 的问题有三个。失败只返回 `false`，不抛异常，不告诉你原因；路径拼接靠字符串，跨平台是噩梦（Windows 用 `\`，Unix 用 `/`）；没有原子移动、没有符号链接支持、没有文件属性访问。2011 年，JDK 7，NIO.2 来了——`Path + Files` 是新文件柜，会说话，失败时告诉你为什么。」

## 四、炉内原理图：Path + Files vs 老 File 类

| 维度 | 老 `java.io.File` | 新 `java.nio.file.Path + Files` |
|---|---|---|
| 失败反馈 | 返回 `false`，无原因 | 抛具体 `IOException`（如 `NoSuchFileException`、`AccessDeniedException`） |
| 路径拼接 | 字符串拼接，跨平台坑多 | `Path.of("a", "b", "c.txt")` 自动用平台分隔符 |
| 原子移动 | 不支持 | `Files.move(src, dst, ATOMIC_MOVE)` |
| 符号链接 | 不支持 | `Files.createSymbolicLink`、`Files.readSymbolicLink` |
| 递归遍历 | `listFiles()` + 手写递归 | `Files.walk(dir)` 返回惰性 `Stream` |
| 文本一行读写 | 无 | `Files.readString / writeString`（JDK 11） |
| 引入版本 | JDK 1.0 | **JDK 7（NIO.2，JSR 203）** |

这一话接上一话：上一话建立了「字节→字符需要显式指定编码」的意识，这一话建立「文件操作需要能说清失败原因」的意识——两者合起来，才是一套完整的 IO 观。`Files.readString` 内部已经帮你做好了 `BufferedReader + InputStreamReader(UTF-8)`，不需要再套娃。

## 五、从上一话继续改代码：日志读写全面升级 NIO.2

```java
// javac -encoding UTF-8 --release 25 NioDemo.java
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.*;

class NioDemo {

    public static void main(String[] args) throws IOException {
        Path tmpDir = Path.of(System.getProperty("java.io.tmpdir"), "cafe-logs");
        Files.createDirectories(tmpDir);

        // ── 1. 写文件（覆盖）────────────────────────────────
        Path report = tmpDir.resolve("today.txt");
        Files.writeString(report,
            "咖啡×5 ￥140\nCOUPON:BREW20\n合计 ￥140\n",
            StandardCharsets.UTF_8,
            StandardOpenOption.CREATE, StandardOpenOption.TRUNCATE_EXISTING);
        System.out.println("写入: " + report);

        // ── 2. 读全文 ────────────────────────────────────────
        String content = Files.readString(report, StandardCharsets.UTF_8);
        System.out.println("--- 读取 ---");
        content.lines().forEach(l -> System.out.println("  " + l));

        // ── 3. 追加写入 ──────────────────────────────────────
        Files.writeString(report, "# 追加行\n",
            StandardCharsets.UTF_8, StandardOpenOption.APPEND);

        // ── 4. 目录遍历（Files.walk）────────────────────────
        // 先创建一些测试文件
        for (int i = 1; i <= 3; i++) {
            Files.writeString(tmpDir.resolve("receipt-" + i + ".txt"), "order" + i);
        }
        System.out.println("--- 遍历目录 ---");
        try (var stream = Files.walk(tmpDir)) {
            stream.filter(Files::isRegularFile)
                  .forEach(p -> System.out.println("  " + p.getFileName()));
        }

        // ── 5. 原子移动（覆盖目标）──────────────────────────
        Path archived = tmpDir.resolve("archive").resolve("today-bak.txt");
        Files.createDirectories(archived.getParent());
        Files.move(report, archived,
            StandardCopyOption.ATOMIC_MOVE, StandardCopyOption.REPLACE_EXISTING);
        System.out.println("原子移动至: " + archived.getFileName());

        // ── 6. 路径拼接与信息 ────────────────────────────────
        Path base = Path.of("/logs/2026");
        Path sub  = base.resolve("receipts.txt");
        System.out.println("拼接: " + sub);
        System.out.println("父级: " + sub.getParent().getFileName());
        System.out.println("文件名: " + sub.getFileName());
    }
}
```

**实测输出**（GraalVM 25.0.4）：

```
写入: C:\Users\...\Temp\cafe-logs\today.txt
--- 读取 ---
  咖啡×5 ￥140
  COUPON:BREW20
  合计 ￥140
--- 遍历目录 ---
  receipt-1.txt
  receipt-2.txt
  receipt-3.txt
  today.txt
原子移动至: today-bak.txt
拼接: /logs/2026/receipts.txt
父级: 2026
文件名: receipts.txt
```

关键验证：`writeString/readString` 正确读写 UTF-8；`Files.walk` 遍历出正则文件；`ATOMIC_MOVE` 不抛异常；路径拼接跨平台正确。

## 六、故意翻一次车：Files.walk 不关闭

阿零故意试一次：直接用 `Files.walk` 而不放进 `try-with-resources`：

```java
// 阿零故意试一次：不关闭 Files.walk 返回的 Stream
Files.walk(tmpDir).filter(Files::isRegularFile)
                  .forEach(p -> System.out.println(p.getFileName()));
// Stream 没关闭，底层目录句柄泄漏
```

这段代码在小目录下能跑，但 `Files.walk` 内部打开了操作系统的目录流（文件描述符）。如果 `Stream` 不关闭，文件描述符会泄漏，大量目录遍历后耗尽系统 fd 上限，出现 `Too many open files` 异常——在生产环境里，这种泄漏往往在压力测试时才会暴露。

---

## 七、编译官罚单

> **📋 编译官罚单 · 这次编译官没吭声**
>
> `Files.walk(dir).forEach(...)` 不关闭 Stream——这不是编译错误。编译器无法静态分析「你忘了关闭返回的 Stream」。
>
> 资源泄漏是运行时问题，只在负载足够大、文件描述符被耗尽时才会爆发。编译器管不到这类错误，所以更危险——在低负载测试环境里完全正常，上了生产承压后才崩。`try-with-resources` 是唯一可靠的防线。

---

## 八、修复并验证

修复是把 `Files.walk` 和 `Files.lines` 都放进 `try-with-resources`。

验证判据：

1. **遍历正确**：`Files.walk(tmpDir)` 过滤 `isRegularFile` 后，输出文件名与实际文件一一对应。
2. **原子移动**：`Files.move(..., ATOMIC_MOVE)` 完成后，源路径不存在，目标路径存在且内容完整。
3. **`Files.readAllLines` 行数**：写入3行后 `readAllLines(p).size()` 应为3。

正常路径实测输出（GraalVM 25.0.4，同上文代码块）：

```
原子移动至: today-bak.txt
```

源文件消失，目标文件完整，中间没有「文件只写了一半」的状态可被读到。

## 九、🔬 炉底显微镜 · Files.lines 惰性读取 vs readAllLines

> 焰焰演示 `Files.lines` 的惰性读取与 `readAllLines` 的差别：

```bash
# 查看 Files 类方法签名
javap -p java.nio.file.Files | grep -E "read|write|walk|lines" | head -15

java -ea --source 25 - <<'EOF'
import java.nio.file.*;
import java.nio.charset.*;
import java.io.IOException;
void main() throws IOException {
    Path p = Files.createTempFile("jvm-test", ".txt");
    Files.writeString(p, "line1\nline2\nline3\n");

    // readAllLines：一次全部读入内存
    var all = Files.readAllLines(p, StandardCharsets.UTF_8);
    System.out.println("readAllLines 行数: " + all.size()); // 3

    // Files.lines：Stream，惰性读，适合大文件
    try (var stream = Files.lines(p, StandardCharsets.UTF_8)) {
        long count = stream.filter(l -> l.startsWith("line")).count();
        System.out.println("lines() 过滤计数: " + count); // 3
    }
    Files.deleteIfExists(p);
}
EOF
```

**实测输出**：

```
readAllLines 行数: 3
lines() 过滤计数: 3
```

关键观测点：
- `Files.readAllLines()` 把全部内容读入 `List<String>`，适合小文件；大文件会 OOM
- `Files.lines()` 返回惰性 `Stream<String>`，按需读取，必须 `try-with-resources` 关闭
- `Files.walk()` 底层打开目录流，同样必须关闭；深层目录遍历需注意 `maxDepth` 参数
- `StandardOpenOption.ATOMIC_MOVE` 在同一文件系统内是真正原子操作；跨文件系统会降级为普通复制+删除

**Q1.** `new File("a/b/c.txt")` 和 `Path.of("a", "b", "c.txt")` 的主要区别？

**Q2.** `Files.readString(path)` 和 `Files.readAllLines(path)` 的区别？

**Q3.** `Files.walk()` 返回的 `Stream` 为什么必须关闭？

**Q4.** 如何原子地把临时文件替换正式文件（避免读取到半写状态）？

**Q5.** `Files.delete()` 和 `Files.deleteIfExists()` 有什么区别？

**Q6.** `Path.resolve("../logs")` 会怎么处理 `..`？

**Q7.** `Files.createDirectories(path)` 和 `Files.createDirectory(path)` 的区别？

**Q8.** 如何用 `Files.lines()` 只读取大文件的前10行，同时保证资源释放？

**Q9.** `Files.copy(src, dst)` 默认行为是什么？如果目标已存在会怎样？

**Q10.** `Path.toFile()` 和 `File.toPath()` 的用途是什么？

---

> [!答案]
>
> **Q1. `Path` 是值对象，操作失败抛具体 `IOException`（如 `NoSuchFileException`、`AccessDeniedException`），`File` 操作失败只返回 `false`，无法知道原因。**另外 `Path.of("a","b","c.txt")` 自动用平台正确分隔符拼接，`new File("a/b/c.txt")` 在 Windows 上也能工作（Java 会自动处理），但多参数构造器更可读。
>
> **Q2. `Files.readString(path)` 返回 `String`（整个文件内容）；`Files.readAllLines(path)` 返回 `List<String>`（按行分割）。**两者都把全部内容读入内存，适合中小文件。`readString` 保留换行符，`readAllLines` 剔除行末换行符。
>
> **Q3. `Files.walk()` 内部打开了目录流（`DirectoryStream`）**，这是操作系统资源（文件描述符）。如果 `Stream` 不关闭，文件描述符会泄漏，在遍历大量目录时可能耗尽系统限制。始终用 `try-with-resources`。
>
> **Q4. 写到临时文件，再用 `Files.move(tmp, target, ATOMIC_MOVE, REPLACE_EXISTING)` 原子替换。**在同一文件系统内，`ATOMIC_MOVE` 保证读取方要么看到旧版本要么看到新版本，不会看到半写状态。
>
> **Q5. `Files.delete(path)` 在文件不存在时抛 `NoSuchFileException`；`Files.deleteIfExists(path)` 在文件不存在时返回 `false`，不抛异常。**清理操作用 `deleteIfExists`，明确期望文件存在时用 `delete`。
>
> **Q6. `Path.resolve()` 不自动规范化 `..`。**例如 `Path.of("a/b").resolve("../logs")` 得到 `a/b/../logs`。需要调用 `.normalize()` 才能得到 `a/logs`。
>
> **Q7. `Files.createDirectories(path)` 递归创建所有不存在的父目录**（相当于 `mkdir -p`），如果路径已存在则静默成功。`Files.createDirectory(path)` 只创建最后一级目录，父目录必须已存在，否则抛 `NoSuchFileException`。
>
> **Q8.**
> ```java
> try (var lines = Files.lines(path)) {
>     lines.limit(10).forEach(System.out::println);
> }
> ```
> `limit(10)` 是惰性操作，只读取前10行；`try-with-resources` 保证流关闭。
>
> **Q9. 默认不覆盖目标文件**——如果目标已存在抛 `FileAlreadyExistsException`。要覆盖需传 `StandardCopyOption.REPLACE_EXISTING`。
>
> **Q10. 用于新旧 API 之间的互操作。**`path.toFile()` 把 `Path` 转回 `File`（用于需要 `File` 参数的旧 API）；`file.toPath()` 把旧 `File` 转为 `Path`（用于迁移旧代码）。推荐新代码全程使用 `Path`，只在对接旧 API 时才做转换。
