## 建站目的

我希望这个博客不是“展示用的空壳”，而是每天都能使用的学习系统。

每篇文章尽量回答四个问题：

- 今天解决了什么问题？
- 我用了哪些命令、工具或资料？
- 中间踩了哪些坑？
- 下次遇到类似问题如何更快解决？

## 内容方向

- Java 全栈：Java、Spring、Maven、Gradle、MySQL。
- 工程工具：Git、GitHub、Vercel、Neovim、终端配置。
- AI 与系统：PyTorch、遥感 VQA、操作系统、编译原理。
- 个人成长：学习计划、复盘、项目总结。

## 写作格式

```text
目标 -> 过程 -> 命令 -> 结果 -> 复盘
```

先追求稳定记录，再追求表达质量。

### 具体执行方法

**每日流程（30-45 min）**
1. 打开 VS Code → 新建 `YYYY-MM-DD-<topic>.md`
2. 写 3 段：今天做了什么 → 哪个命令最有用 → 明天继续什么
3. 如果写了命令，**附上实际运行的输出片段**（不贴超长 log）
4. 推送前 `git diff` 检查敏感信息

**写什么有价值？**
- ✅ 踩坑 + 解决方案（最有价值）
- ✅ 一条命令解决了一个实际问题
- ✅ 对比两种方案的优劣
- ❌ 复制粘贴教程全文
- ❌ 超长日志/堆栈（截图即可）
- ❌ 只有标题没有内容的草稿

**如何持续？**
> "与其追求完美文章，不如追求每晚 10 分钟的记录习惯。"
> 写 50 篇 100 分的文章 = 做不到。
> 写 200 篇 60 分的笔记 = 可以做到，而且 Google 更喜欢高频更新。
