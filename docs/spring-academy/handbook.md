## 0. 一句话定位

Java 线把咖啡站送上了 Spring Boot,读者**会用**了;这一部负责把"框架魔法"**全部祛魅到第一性原理**——每一处"它自己就好了",都要落到**具体的类与方法**,并能用 ≤50 行手写复现。

面向的不再是零基础读者,而是**已经能写出 CRUD 接口、却说不出 `@Autowired` 背后发生了什么**的进阶者。因此本线的差异化立场是:**可控性优先于便利性**。判定一话是否合格的唯一标准:读完后,读者能对本话涉及的每个"魔法"回答三问——**谁创建了它?它从哪来?出事去哪查?**

## 1. 衔接与世界观

- 时间线:Java 线咖啡站进入 Spring Boot 时代之后。一次线上事故里,阿零发现自己**改不动也查不动**——加了 `@Transactional` 却不回滚、删掉一行依赖整个服务点不亮。豆豆把他赶到后院:"你不是在写代码,你在许愿。"
- 舞台:豆豆咖啡站**后院 · 依赖藤架**。一株会自己长枝的藤蔓,每长一节结出一颗 Bean,枝条走向就是依赖图;藤根扎在 Java 线的后厨,藤梢一路爬到卷六的云端。藤架角落堆着 `javax.*` 时代的旧木牌与 XML 配置的化石(彩蛋,只展览不教)。
- 六卷主线:卷一 容器的本质(01-06)→ 卷二 切面与事务(07-12)→ 卷三 自动装配的秘密(13-18)→ 卷四 Web 层内幕(19-24)→ 卷五 持久化(25-30)→ 卷六 安全与云(31-36)。
- 基线:**Spring Boot 4.x / Spring Framework 7 / jakarta 命名空间 / Java 25**。`javax.*` 只作为历史残留出现,一律不教。

## 2. 角色表(硬约束,防人设漂移)

### 跃跃(Yue)—— 本线导师,依赖藤上的树蛙

- **外形**:住在依赖藤上的小树蛙。**弹跳一次,就能把一个对象送到它该在的位置**(依赖注入的具象化);**背上的吸盘能贴住任何接口**(代理与切面的具象化,贴上去之后原对象的每次调用都要先从它背上过一遍);藤蔓每长一节自动结一颗 Bean,枝条断了就是循环依赖打了死结。
- **性格**:轻快、爱拆东西,见不得任何人用"它自己就会好"解释问题;不嘲讽读者,只嘲讽**说不清楚的说法**。
- **口头禅**:"**容器里,万物皆 Bean。**"(讲装配 / 讲边界 / 讲"这东西归谁管"三关一语)
- **副口头禅**:"你以为的魔法,都是别人写好的 if。"(引导读者点开源码,对标特米的"man 一下"、焰焰的"这事,JEP 里都写着呢")
- **能力边界(铁律)**:
  1. 只讲机制与**定位方法**,不替阿零做业务设计;给类名、给断点位置,让阿零自己跟一遍调用栈。
  2. **绝不用"框架帮你做了"收尾**——凡说"自动",必须紧跟一句"由 `X` 类的 `y()` 完成"。
  3. 不吹任何"最佳实践"却说不出代价的方案;每个便利特性都要点名它换走了什么(可控性 / 可测性 / 启动耗时 / 排障难度)。
  4. 沿用豆豆的五步排障法(观察 → 收集 → 假设 → 改一个变量 → 重跑验证),跃跃版第一步永远是"**先看它是不是代理**"。

### 阿零 —— 本线成长弧:从"会用"进化到"敢改"

延续前作人设:能交付接口,但对容器内部一无所知。**每卷一次可见的能力上涨**:

| 卷 | 卷终时阿零能做到 |
|---|---|
| 卷一 | 画得出咖啡站的依赖图,并对每个对象说出"谁造的、什么时候造的" |
| 卷二 | 看一眼 `getClass()` 就知道拿到的是不是代理;能独立判定一次事务为何没回滚 |
| 卷三 | 亲手写出并发布一个 starter——第一次从"魔法的受害者"变成"魔法的作者" |
| 卷四 | 能画出请求全链路时序图,并指出一个请求死在了哪一层 |
| 卷五 | 能从日志反推 SQL 由哪行代码生出,独立定位并修掉一次 N+1 |
| 卷六 | 独立收敛安全与依赖边界;结局从跃跃手里接过藤——**遇到新框架也能自己拆开** |

- **豆豆**:需求发起人 + **毒舌验收员**——每卷终出面,只问一句"你说得清吗",说不清就打回;不当导师(本线导师是跃跃)。

## 4. 本线专属深度栏目

### 4.1 🔍 源码放大镜(每话必有,恰好 1 个)

- **定位**:对标 Java 线的 🔀 多解台、JVM 线的 🔬 炉底显微镜;差异化 = **把"自动"钉死成坐标**。口号:"你以为的魔法,都是别人写好的 if。"
- **规则**:
  1. 必须给出**类名 + 方法名 + 一句职责**,精确到方法;不确定就去点开,别写"大概在某个 Processor 里"。
  2. **只给骨架不贴长源码**:节选 ≤15 行,或用三到五行伪代码概括;禁止整段拷贝源码充篇幅。
  3. 必须附**一个可自己验证的动作**:打断点的位置、打印什么、看哪段启动日志、开哪个 debug 开关——读者要能自己复现这次"照见"。
  4. 版本敏感:类名与方法名随大版本变动,凡引用一律标注"基线 Spring Framework 7 / Spring Boot 4.x",并按 §8 复核。
- **格式模板**:

  ```text
  > **🔍 源码放大镜 · 这行注解到底谁在读?**
  >
  > 落点:`类名#方法名` —— 一句话职责。
  > 调用链(节选):入口 → 中间环节 → 落点 → 产出。
  > 自己验证:在 `类名#方法名` 打个断点 / 打印 `xxx.getClass()`,重启看第一屏日志。
  > 跃跃结语:所谓自动,就是这三行 if 替你做了判断——判断依据你自己也能改。
  ```

### 4.2 🪄 祛魅实验(每卷 ≥1 次,卷一/卷二/卷三各有专话)

- **定位**:用 **≤50 行**手写复现该特性,跑通即祛魅。它是本线的杀手锏——**读者亲手写过一遍,魔法就永远回不去了**。
- **规则**:
  1. 代码 ≤50 行且**可整段照抄跑通**,依赖只允许 JDK 标准库(反射、动态代理);不引第三方。
  2. 结尾必须有一段"**它与真货差在哪**":列 3–5 条真实框架多做的事(线程安全、循环依赖、生命周期、扩展点、性能),防止读者误以为自己写了个 Spring。
  3. 只在机制**可被压缩**时开栏(容器、代理、切面、starter);像事务传播、安全过滤器链这类靠约定而非小机制的,一律不硬凑。
- 专话落点:第 02 话(迷你容器)、第 09 话(迷你 AOP)、第 17 话(自研 starter);其余卷以栏目形态穿插。

## 8. 写作红线

### 8.1 版本敏感事实:发布前必须联网复核

- **铁律**:凡涉及"哪个版本引入 / 改名 / 移除 / 默认开关",以及**具体类名与方法名**,发布前逐条用 opencode+DeepSeek 或 context7 联网复核,**不凭记忆、不信旧博客**。核实优先于假设。
- 每话触及即必查的高危清单:自动配置的导入清单文件路径与格式(与旧版 `spring.factories` 已不同,严禁混写);`javax.*` → `jakarta.*` 的包名;Spring Security 配置写法(已由适配器基类改为组件式配置,严禁教旧写法);HTTP 客户端选型(`RestTemplate` 为维护态,新写法优先);任何"某注解已废弃"的断言。
- **不确定的版本号一律写通用表述**("自 Spring Boot 3 起""较新版本已改为"),宁可模糊,不可编造。
- 旧写法只能以**历史残留**身份出现(XML 配置、`javax.*`、适配器基类),用于讲清演进,**不得作为可抄的示例**。

### 8.2 术语一致性表(全线统一,首现标注英文)

| 统一用词 | 禁用 / 别名 |
|---|---|
| 容器(IoC container) | 不写"框架帮你管" |
| Bean 定义(BeanDefinition) | 不与"Bean 实例"混用 |
| 依赖注入(DI) | 不写"自动装配"指代 DI(自动装配专指 auto-configuration) |
| 自动配置(auto-configuration) | 与"条件装配"分开用 |
| 代理对象(proxy) | 首现必标英文;不写"增强对象" |
| 织入(weaving) / 切点(pointcut) / 通知(advice) | 术语首现成组给出 |
| 持久化上下文(persistence context) | 不写"一级缓存"当唯一说法,首现并列标注 |

### 8.3 其他红线
