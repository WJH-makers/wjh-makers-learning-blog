## 0. 一句话定位

技术线教你"怎么把代码写对";这一部教你**纯技术之外真正拉开差距的部分**——沟通、协作、影响力、成长与选择。

面向的是**已能独立交付、却在"代码没错、事却没做成"上栽过跟头的工程师**。本线的差异化立场是一条铁律:**每一话都必须给出可执行的成长动作,绝不写空洞鸡汤**。凡是"要多沟通""要有格局"这类正确的废话,一律替换成"下周一你具体做哪三件事"。

## 1. 衔接与世界观

- 时间线:阿零已走过 Java 线、CLI 线、JVM 线,技术上能独立交付系统。一次项目"代码全对、上线却搞砸"的复盘,让他第一次意识到瓶颈不在技术。
- 舞台:豆豆咖啡站从"一个人的后厨"扩张成"要带团队的门店",阿零第一次要和产品、同事、新人、老板打交道。
- 新导师登场:天上飞来一支雁阵,领头的大雁**领姐(Ling)**落在咖啡站屋檐上——她替全队破风,也懂得何时退到队尾。
- 四卷主线:卷一 写给别人看的工程(01-07)→ 卷二 协作与沟通(08-14)→ 卷三 成长与影响力(15-21)→ 卷四 选择与长期主义(22-28)。

## 2. 角色表(硬约束,防人设漂移)

### 领姐(Ling)—— 本线导师,雁阵领飞者

- **外形**:一只沉稳的大雁,飞在雁阵最前面替全队破风;累了会主动换到队尾跟飞——**懂得什么时候领飞、什么时候跟随**。翅膀上驮着一张会不断更新的《成长路线图》,风一吹就翻页(长期主义与方向感的具象化)。
- **能力隐喻**:破风=承担压力与开路;换到队尾=学会退位与授权;路线图=方向优先于速度。
- **性格**:温和、有耐心、擅长把混乱的处境拆成可执行的下一步;不灌鸡汤,只给动作。
- **口头禅**:"**技术是船,方向是舵。**"(点破:油门再猛,方向错了也白搭)
- **副口头禅**:"一个人飞得快,一群人飞得远。"(点破:协作的复利)
- **能力边界(铁律)**:
  1. 只讲职业方法与软技能,**不替阿零做技术判断**——涉及具体技术一律链回对应技术线。
  2. 不给"正确的废话";每次开口必须落到一个阿零下周能做的具体动作(见 §4 🧭 路线台)。
  3. 不贩卖焦虑、不做成功学;倦怠、跳槽等话题按"复盘 + 选项"处理,不下"必须怎样"的断言。
  4. 领飞与退位交替:前三卷多领飞(给方向),卷四逐步退到队尾(把决定权交还阿零)。

### 阿零 —— 本线成长弧:从"只会写代码"到"能带团队把事做成"

延续前作人设:技术已过关,但一到"和人打交道 / 做选择"就翻车。**每卷一次可见的能力上涨**:

| 卷 | 卷终时阿零能做到 |
|---|---|
| 卷一 | 交付出"别人愿意读、乐意合"的产出:命名、注释、提交、文档、表达、评审都过关 |
| 卷二 | 独立把一件事说清楚:澄清需求、给带区间的估时、向上向下同步、吵架不伤人 |
| 卷三 | 从"完成分配的任务"变成"对一件事的结果负责":能读系统、做设计、做分享、带新人 |
| 卷四 | 会为长期做选择:取舍技术、判断造与用、双向看面试、算清跳槽账、识别倦怠——想清自己要成为哪种工程师 |

### 客串规则(豆豆 / 焰焰 / 特米)

- **豆豆**:阿零的第一位"团队成员"与毒舌镜子——在协作/带人话里出现,负责把阿零的沟通毛病当场怼回来,但**不当导师**(本线导师是领姐)。
- **焰焰**(JVM 线):象征"把技术钻到底";与领姐互为**船与舵**——涉及"要不要深挖某项技术"时一句话联动,深挖本身链回 /jvm。
- **特米**(CLI 线):客串"异步沟通反面教材"(只发'在吗'就消失),用于第 12 话(异步礼仪);台词一句,不抢戏。
- 领姐不去别线当导师;跨线联动只走 §8 钩子表。

## 3. 每话固定骨架(在 Java 线 11 步上特化为软技能版)

差异点:本线没有"编译报错",把"故意造 Bug → 真实报错 → 修复"三步替换为"**一次真实的职场翻车 → 复盘出根因 → 给出可复用套路**";**🧭 路线台升格为固定步**(每话必给可执行动作)。

| 步 | 段落 | 职责 | 字数量级 |
|---|---|---|---|
| 1 | 职场事故/协作疑云 | 真实痛点开场;首句**承上**(接上一话埋的坑) | ~150 |
| 2 | 4–8 格漫画 | `> **〔n〕**` 分格;必含"阿零因软技能翻车 + 领姐点破 + ≥1 个客串角色或场景" | 600–900 |
| 3 | 本话目标 | ≤5 条,动词开头 | ~100 |
| 4 | 心智模型图 | 把软技能讲成可操作的框架(表格/流程/对照),讲"为什么这样有效" | 400–700 |
| 5 | 从上一话继续推进项目 | 明确"在上一话基础上,团队/协作往前挪了哪一步" | 500–800 |
| 6 | 一次真实翻车 | 本话最典型的坑:说不清、估错、吵翻、跟风、倦怠等,情境具体到能对号入座 | 300–500 |
| 7 | 复盘出根因 | 把翻车拆开:表象 → 根因 → 本可以怎样;不甩锅、不喊口号 | 200–400 |
| 8 | 💬 沟通拆解 | 本线固定栏目之一,见 §4;把一次沟通拆成可复用套路 | 300–500 |
| 9 | 🧭 路线台 | 本线固定栏目之二,见 §4;给出下周可执行的具体动作 | 300–500 |
| 10 | 项目检查点 | 团队/阿零长成什么样(已具备 / 还没有),对齐 `projectStage` | ~150 |
| 11 | 对应招聘技能 | 不能空(软技能同样是招聘项) | ~50 |
| 12 | 下一话悬念 | 一句**启下**;相邻话的启下/承上必须咬合 | 50–100 |

- 篇幅硬约束:普通话 **4.0k–5.6k 字符**;卷终话 5.2k–6.2k;加深度靠密度不靠长度。
- 小节用中文数字 `## 一、…`,顺序对齐上表;H1 唯一,标题格式 `《从零开始当工程师》NN · 本话名`;首行元信息引用块固定两行(卷/话定位 + 项目提示);结尾署名行:`*本话属于连载《从零开始当工程师》。世界观与卷次地图见 /career。*`(**公开内容禁止出现 handbook.md 等内部路径**,由 `tests/content-audit.test.ts` 守卫)

## 4. 本线专属深度栏目(两个,每话都上)

本线区别于技术线的核心资产:一个负责"想清楚",一个负责"做出来"。两者每话必有,是身份不是点缀。

### 🧭 路线台(每话必有,恰好 1 个)

- **定位**:每话末尾给出**可执行的成长动作**,而不是鸡汤。口号:"技术是船,方向是舵——这是你下周要划的三桨。"
- **规则**:动作必须**具体、可验证、一周内能做**;禁止"要多沟通""提升格局"这类无法执行的正确废话。
- **格式模板**:

  ```text
  > **🧭 路线台 · 这周你可以做的三件事**
  >
  > 1. <一个具体动作,含"对谁、做什么、产出是什么">
  > 2. <一个可当场验证的小练习>
  > 3. <一个下周复盘的自检问题>
  >
  > 领姐结语:技术是船,方向是舵——先校准方向,再谈速度。
  ```

### 💬 沟通拆解(每话必有,恰好 1 个)

- **定位**:把一次真实的技术沟通(评审留言、需求澄清、向上汇报、争论收场……)**拆成可复用的套路**,读者能照着套。
- **规则**:必须给出"反面台词 → 问题 → 改写后台词"的三段对照,让读者看见差别而非听道理。
- **格式模板**:

  ```text
  > **💬 沟通拆解 · <这次沟通>怎么说才对**
  >
  > | 场景 | 常见说法(反面) | 问题出在哪 | 改写后 |
  > |---|---|---|---|
  > | … | "…" | … | "…" |
  >
  > 一句套路小结:<把它压缩成一句能随手复用的公式>。
  ```

- 兼容规则:Java 线的 🎯 面试直击可按需借用(卷四面试/跳槽话天然适配),一话最多 2 个深度栏目——🧭 与 💬 是骨架固定步,**不计入**此限;额外栏目才计。

## 5. 检查点版本链与项目主线推进规则(对齐 `series-career.ts` 的 `projectStage`)

- 版本链(卷终话为里程碑):
  `career-v1 让人愿意合并的 PR(07)→ career-v2 没有火药味的方案评审(14)→ career-v3 第一次主导项目(21)→ career-v4 职业大成·想清楚要成为哪种工程师(28)`
- 每话 `projectStage` 一句话 = **这话之后"阿零 + 团队"多了什么能力**(如"团队评审有了基本礼仪""会算跳槽账"),第 10 步"项目检查点"必须与之对得上。
- 主线载体是**咖啡站从一个人到一支团队**的过程,不是代码仓库;能力从上一话产物继续长,绝不推倒重来。
- 卷终话 `chapterType: "project"`,是本卷软技能的综合实战(一次真实的 PR / 评审 / 项目 / 抉择),而非知识罗列。
- 发布节奏沿用前作:蓝图全量 planned;每周翻 1 话——写完当话 md、slug 对齐、当话 status 翻 published,**三件事同一 commit**。

## 6. 依赖铁律(本线知识 + 跨线定位)

- **软技能也有前置**:本话只用"本话或更早话"建立的方法与词汇;卷一先立"可读性/评审"的共识,卷二才谈"协作/沟通",卷三才谈"影响力/设计",卷四才谈"选择/长期"。严禁倒挂(如卷一就大谈"技术判断力")。
- **不与技术线抢知识点**:凡涉及具体语法、框架、性能、部署,一律一句话带过 + 链回对应技术线(Java / CLI / JVM),本线只谈"围绕它的人与选择"。
- 卷内依赖速查:
  - 卷一(松顺序,建议顺读):01 可读性心法 → 02 命名注释 → 03 提交/PR → 04 文档 → 05 表达 → 06 评审 → 07 综合 PR。
  - 卷二:08 需求会变 → 09 问真需求 → 10 估时 → 11 向上向下同步 → 12 异步礼仪 → 13 冲突 → 14 综合评审(用到 08–13)。
  - 卷三:15 T 型能力 → 16 读系统 → 17 设计跳跃 → 18 分享写作 → 19 带新人 → 20 判断力 → 21 主导项目(综合)。
  - 卷四:22 技术该不该学 → 23 造/用轮子 → 24 面试双向 → 25 跳槽账 → 26 倦怠 → 27 十年视角 → 28 终章(综合并回扣全线)。

## 7. 写作红线

- **铁律:绝不写空洞鸡汤**。每话结束前自检——🧭 路线台里的动作,读者今天能不能照着做?不能就重写。
- **不贩卖焦虑、不做成功学**:跳槽、倦怠、十年规划等话题只给"复盘框架 + 选项 + 权衡",不下"必须离职/必须坚持"的绝对断言。
- **场景要真实到能对号入座**:翻车桥段用具体台词和具体处境,不用"沟通不畅""协作困难"这类抽象概括。
- **技术名词保留原文**,但深度不越界:本线不解释技术本身,只解释"围绕它的判断与沟通"。
- 便利贴语法沿用全站规范(`lib/markdown.ts` STICKY_CLASS):`> [!吐槽]`、`> [!彩蛋]`、`> [!警告]` / `> [!坑]`、`> [!强调]` / `> [!重点]`、`> [!答案]`(折叠)、`> [!文字版]`;漫画分格 `> **〔n〕**` 格间空行;固定栏目前缀 `> **🧭 路线台 · …**`、`> **💬 沟通拆解 · …**`,便于一眼识别。
- 继承 Java 线 §10 全部"必须坚持 / 绝不做";本线追加两条不做:**不把软技能写成道理堆砌**(必须落到动作)、**不越界替读者做技术决定**(只给方法,决定权归读者)。

## 9. 复核红线(发布前逐项自检)

1. **话数**:全线精确 28 话(4 卷 × 7),与 `series-career.ts` 完全一致,不多不少。
2. **鸡汤检测**:每话 🧭 路线台的动作可执行、可验证、一周内能做?否则重写。
3. **承上启下**:相邻话的启下/承上咬合成一条河;卷终 `projectStage` 落在版本链上。
4. **不越界**:没有替读者做技术决定,具体技术都链回了技术线。
5. **人设不漂移**:领姐只给动作不灌鸡汤、领飞与退位随卷推进;阿零技术不弱、只在"和人/选择"上翻车。
