## 一、需求:抓住半路丢包的门卫

上一话结尾,外网访问从 refused 变成了 timed out——包到了机器门口,被人无声没收。特米只回了一个词:「`ufw`。」

```bash
$ sudo ufw status verbose
Status: active
Default: deny (incoming), allow (outgoing), disabled (routed)

To                         Action      From
--                         ------      ----
OpenSSH                    ALLOW IN    Anywhere
OpenSSH (v6)               ALLOW IN    Anywhere (v6)
```

真相大白:这台机器初始化时的加固脚本开了 **ufw 防火墙**,默认**拒绝一切入站**,名单上只有 OpenSSH——不然阿零连 ssh 都进不来。8080 的包,全被静默丢弃(DROP),所以是超时而不是拒绝。

但特米拦住了想直接 `ufw allow 8080` 的阿零:「裸的应用端口不见客。**雇个前台。**」

---

## 二、漫画 · 门卫与前台

> **〔1〕** 服务器门口,门卫 ufw 抱臂而立,手里名单只有一行「OpenSSH」。写着 8080 的包裹被他随手扔进虚空,连个回执都没有。
> 阿零:「你倒是说一声啊!」门卫:「DROP,不解释。」

> **〔2〕** 特米:「门卫没错,错的是你想让顾客**直接冲进后厨**。80 端口才是店面,雇个前台——nginx。」
> 一位穿绿制服的前台登场,胸牌:**反向代理**。

> **〔3〕** 前台的工作台一目了然:顾客只看见 80 号门;前台接单,**转身递给后厨 127.0.0.1:8080**,端回来时顾客全程不知道后厨在哪。
> 特米:「顾客的代理叫正向,**服务器这边的代理叫反向**。」

> **〔4〕** 阿零写好配置、`nginx -t` 亮绿灯,得意刷新——页面却是 nginx 的 404。
> 阿零:「测试都通过了啊?!」特米:「`-t` 只检查**纸上的字**,没让干活的人**换脑子**。」

> **〔5〕** 特米在墙上钉了块铁牌:「改配置保命三连:**`nginx -t` → `reload` → 看日志**。少一步,都算没改。」
> 豆豆(探头):「建议加粗。某人的博客上个月就栽在第三步没看。」

## 三、本话目标

- 看懂 `ufw` 的默认拒绝策略,给 80 端口递名单;
- 装 nginx,写第一份**反向代理**配置:80 对外,转发 `127.0.0.1:8080`;
- 刻进肌肉:配置生效三连 **`nginx -t` → `systemctl reload nginx` → 看日志**;
- 踩一次「`-t` 通过了却忘 `reload`」的坑,再听一个 proxy_cache 真实事故。

## 四、原理图:门卫、前台与后厨

```text
顾客(公网)
   │ http://203.0.113.10/
   ▼
[ufw 门卫]  名单:22 ✓  80 ✓(本话新增)  8080 ✗(永不对外)
   ▼
[nginx 前台 :80]  ← /etc/nginx/sites-enabled/coffee(真正生效的是这里的软链接)
   │ proxy_pass
   ▼
[后厨 coffee-api 127.0.0.1:8080]  只听本机 —— 上一话的 Bug,今天成了设计

上一话你恨透的 server.address=127.0.0.1,现在请改回去:
后厨只信前台,外人一个都不见 —— 同一行配置,语境不同,好坏互换。
```

## 五、上手:递名单、雇前台

```bash
$ sudo ufw allow 80/tcp          # ① 门卫名单加一行
Rule added
Rule added (v6)

$ sudo apt install nginx         # ② 雇前台(Ubuntu 24.04 装的是 1.24.0)
$ curl -I http://203.0.113.10/   # 外网立刻能摸到默认欢迎页了
HTTP/1.1 200 OK
Server: nginx/1.24.0 (Ubuntu)
```

写站点配置 `/etc/nginx/sites-available/coffee`:

```nginx
server {
    listen 80;
    server_name _;                          # 域名下一话才有,先接住一切

    location / {
        proxy_pass http://127.0.0.1:8080;   # 转身递给后厨
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

挂到 `sites-enabled` 并停用默认站:

```bash
$ sudo ln -s /etc/nginx/sites-available/coffee /etc/nginx/sites-enabled/coffee
$ sudo rm /etc/nginx/sites-enabled/default
$ sudo nginx -t
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful
```

> **特米旁白**:nginx 只读 `sites-enabled/` 里的**软链接**;`sites-available/` 只是仓库。改了仓库里的文件却没链接过去 = 白改——排障时先确认「生效的到底是哪份文件」。

## 七、读懂真实报错

```html
<html>
<head><title>404 Not Found</title></head>
<body>
<center><h1>404 Not Found</h1></center>
<hr><center>nginx/1.24.0 (Ubuntu)</center>
</body>
</html>
```

404 的落款是 **nginx 自己**——说明请求根本没被转发,应答的还是**内存里的旧配置**。`nginx -t` 只做静态检查:语法对不对、文件在不在;**它不会让正在运行的 worker 进程重读配置**。缺的是第二连:

```bash
$ sudo systemctl reload nginx      # 平滑换脑子:老 worker 处理完手头请求才退休
$ sudo tail -n 1 /var/log/nginx/access.log   # 第三连:亲眼看到请求被转发
203.0.113.99 - - [11/Oct/2026:03:12:45 +0000] "GET /api/menu HTTP/1.1" 200 512 "-" "curl/8.5.0"
```

> **特米锐评 · proxy_cache 会让「改了没生效」再上一个境界**:某人的博客(不点名)给页面开了 `proxy_cache`,把**登录后的鉴权页也缓存了**——所有访客共享同一个人的页面,reload 多少遍都没用,因为供货的是缓存不是后厨。三条铁律:**动态接口别缓存;要缓存就想清楚 key 里有没有 Cookie;排障时加 `add_header X-Cache-Status $upstream_cache_status` 看一眼是不是 HIT 在坑你**。

> **🪟 双系统对照 · 防火墙这道门,两边怎么开**

| 干什么 | Ubuntu (ufw) | Windows (PowerShell 7 管理员) |
|---|---|---|
| 看状态 | `sudo ufw status verbose` | `Get-NetFirewallProfile` |
| 放行 80 | `sudo ufw allow 80/tcp` | `New-NetFirewallRule -DisplayName "HTTP" -Direction Inbound -Protocol TCP -LocalPort 80 -Action Allow` |
| 查某条规则 | `sudo ufw status numbered` | `Get-NetFirewallRule -DisplayName "HTTP"` |
| 图形界面 | 无(这就是本连载存在的意义) | `wf.msc` |

两边之上还有一层**云厂商安全组**——ufw 全放行了外网还是不通时,去控制台看那道更外面的门。

> **🎯 面试直击**:正向代理和反向代理的区别?
> 看代理**替谁说话**:正向代理站在**客户端**一侧,替客户端出门(服务器不知道真实用户);反向代理站在**服务端**一侧,替后端接客(用户不知道真实后端)。追问:反向代理还顺手承包 TLS 终止、静态文件、限流、多实例负载均衡——所以生产上应用几乎从不裸奔对外。

## 八、用命令验证:三连走完才算数

```bash
$ sudo nginx -t                                  # 一连:纸面正确
nginx: configuration file /etc/nginx/nginx.conf test is successful
$ sudo systemctl reload nginx && echo $?         # 二连:换脑子成功
0
$ curl -I http://203.0.113.10/api/menu           # 三连的另一半:外网亲测

Server: nginx/1.24.0 (Ubuntu)
Content-Type: application/json
```
