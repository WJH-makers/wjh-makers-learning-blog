## 0. 一句话定位

跟着阿零和一只退役载波信鸽,从三次握手一路飞到 QUIC 与 ECH——**每一话都在博主自己的真实链路(浏览器 → Cloudflare → nginx → txcloud)上抓包验证,拒绝纸上谈兵**。

叙事外壳:豆豆咖啡站要上线"线上点单"小程序,第一天就遭遇三连击——"外卖员找不到店"(DNS 炸了)、"订单重复下了三杯"(重传 + 非幂等)、"隔壁桌能看到你点了啥"(明文 HTTP)。阿零意识到:不懂网络,咖啡站永远走不出这条街。

全线 **6 卷 32 话**(话号连续 01–32):卷一 快递之城(网络地基,01–05)→ 卷二 握手协议(TCP 深水区,06–11)→ 卷三 寻址之翼(DNS,12–15)→ 卷四 协议进化史(HTTP,16–22)→ 卷五 加密航线(TLS,23–27)→ 卷六 边缘之城(CDN/实战/前沿,28–32)。章节表全量定稿在 `lib/series-net.ts`。

## 1. 角色表(硬约束,防人设漂移)

### 帕特(Pat)—— 本线导师,退役 RFC 1149 载波信鸽

真实存在的 RFC 1149("IP over Avian Carriers",把 IP 包绑在鸽子腿上)之梗。自称"活体数据报",年轻时替 ARPANET 送过包。

- **外形**:灰蓝色信鸽机器人;腿环上刻着序列号(SEQ 编号梗);翅膀下夹一台微型 Wireshark。**每根羽毛是一层报文头**——最外层羽毛是以太网帧,往里依次 IP、TCP、TLS、HTTP;**讲到哪层就竖起哪根羽毛**(固定视觉记号,每话漫画至少一次羽毛特写)。
- **性格**:丢过包、绕过路、被防火墙拒过,对每个协议的设计动机都有**切肤之痛**——讲协议先讲"当年疼在哪"。职业病:说话必须收到对方"ACK"(点头)才继续下一句,**超时就一字不差原话重传**(固定笑点,阿零走神时触发)。
- **口头禅**:主——**"先抓包,再开口。"**(排障纪律);副——"丢包不丢鸽,重传就是了。"
- **能力边界(铁律)**:
  1. 只管"包从 A 到 B"——各层协议与链路是本行;**应用业务代码(Java/Spring)不写**,推给豆豆;**服务器系统操作(systemd/权限/装软件)不代劳**,一句"这个去问特米,man 一下"带过。
  2. **只示范抓包与解读,不替阿零下结论**——结论必须由证据(抓包 / 命令输出)推出,对应豆豆的五步排障法在本线的变体:抓包 → 定层 → 假设 → 改一个变量 → 再抓包比对。
  3. **不预言未核实的版本事实**:拿不准就说"回巢查 RFC",绝不现场编(这条同样约束作者,见 §7)。

### 阿零 —— 读者代理,本线成长弧

承接 Java 线大结局与 CLI 线毕业:**他已经会写代码、会用服务器,唯独把网络当黑盒**("能 curl 通就行")。本线核心冲突 = "会部署 ≠ 懂网络"。**不许为剧情装傻退回 Java S1 的小白人设**;每卷至少一次可见的能力上涨:

| 卷 | 卷末能力检查点 |
|---|---|
| N1 | 遇到故障能先说出"挂在第几层",工具箱(ping/dig/curl/ss)上手 |
| N2 | 能看着 `ss` 输出解释一次重传 / 一屋子 TIME_WAIT |
| N3 | 能独立排一次"DNS 改了为什么不生效" |
| N4 | 能为一个功能选对协议(轮询/SSE/WS、H1.1/H2/H3)并说清权衡 |
| N5 | 能独立给一个新域名配好全套 TLS(证书/自动续期/ECH) |
| N6 | 能画出并排查整条边缘链路;大结局从帕特手里**接过 Wireshark**(导师退场 = 出师) |

## 2. 每话固定骨架(11 步,继承 Java v2 并做网络特化)

网络线的"产物"不是一坨越长越大的代码,而是**一条越修越通的链路**(配置 + 抓包记录 + 少量最小代码)。骨架仍是 11 步,三处特化:第 5 步"改代码"→"真机推进";第 8 步沿用 CLI 线放宽("用命令验证");第 9 步固定为本线专属栏目 📡 真链路实验室。

| # | 段落 | 职责 | 字数量级 |
|---|---|---|---|
| 1 | 事故或需求(承上) | 点单小程序遇到的真实网络故障;开头一句接上一话埋的坑 | 150–250 |
| 2 | 4–8 格漫画 | 必含:阿零翻车 + 帕特"先抓包"点破 + **竖起本话对应羽毛**;比喻剧场按 series 章节表的桥段创意展开 | 600–900 |
| 3 | 本话目标 | ≤5 条,动词开头 | ≤100 |

## 3. 本线专属深度栏目:📡 真链路实验室

**作用**:每话第 9 步,帕特带阿零在博主真实站点 `wwjjhh.online` 的链路(浏览器 → Cloudflare → nginx → txcloud)上复现本话知识点。卖点 = **每个知识点都有一份可复制的真机实验命令**。对标 Java 线 🎯 面试直击、CLI 线 🪟 双系统对照。

### 格式模板

```text
> **📡 真链路实验室 · <本话知识点>上真机**
>
> 环境:<本机 PowerShell 7 / txcloud Ubuntu / 浏览器 DevTools,三选一并标明>。目标:一句话。
>
> ```bash
> <可直接复制的命令,1–3 条>
> ```
>
> ```text
> <真实输出节选,≤15 行,长的用 … 截断,全文折叠进 [!答案]>
> ```
>
> 三行解读:① 看到了什么;② 为什么会这样;③ 对上本话原理的哪一条。
> 帕特提醒:<环境差异 / 复现注意事项,可省>
```

### 示例(话 13「迟到的新地址」用)

```text
> **📡 真链路实验室 · 亲眼看 TTL 倒数**
>
> 环境:本机 PowerShell 7。目标:看同一条 A 记录的剩余 TTL 随缓存倒数。
>
> ```bash
> dig wwjjhh.online A +noall +answer
> # 隔 30 秒再跑一次,对比第二列
> ```
>
> ```text
> wwjjhh.online.  300  IN  A  104.21.x.x
> wwjjhh.online.  270  IN  A  104.21.x.x   ← 30 秒后:TTL 在倒数
> ```
>
> 三行解读:① 第二列就是剩余 TTL(秒);② 在倒数说明命中的是递归解析器缓存,不是权威;
> ③ 归零后才会重新去问权威——这就是"改解析不立即生效"的全部真相。
```

(上例为**格式示意**;正文发布时必须替换为当日真实输出,含真实 TTL 数值。)

### 实验室硬规则

1. 命令必须在真实环境跑过(基线:本机 Windows 11 / PowerShell 7;服务器 txcloud Ubuntu,以实机为准),**严禁编造输出**。
2. 一话恰好一个实验,不贪多;输出节选 ≤15 行。
3. **脱敏红线**:不出现 token、证书私钥、内网拓扑细节;IP 与域名以已公开信息为限。
4. 三行解读是固定格式,第 ③ 条必须回指本话原理图,形成"漫画 → 原理 → 真机"闭环。

### 沿用栏目及本线触发清单

- **🔀 多解台**(选型题富矿):实时推送(轮询/SSE/WebSocket)、内部通信(REST/gRPC)、证书方案(Let's Encrypt/付费/CF 托管)、内网暴露(端口映射/frp/CF Tunnel)、拥塞算法(CUBIC/BBR)。格式与"必给默认推荐"约束同 Java 手册 §5。
- **⏳ 版本时光机 → 本线多为"协议时光机"**:HTTP/0.9→1.1→2→3、TLS 1.2→1.3、SNI 明文→ECH、netstat→ss / ifconfig→ip(后者顺手回指 CLI 线)。
- **🎯 面试直击**:网络是八股第一重灾区,只放真高频——为什么三次握手不是两次、TIME_WAIT 为何 2MSL、HTTPS 完整过程、"输入 URL 后发生了什么"(话 32 可做集大成收束)。

### 本线依赖速查(防倒挂,写前对照)

- **N1**:分层 → IP/CIDR → NAT → UDP → 工具箱
- **N2**:三次握手 → 四次挥手/TIME_WAIT → 序号/重传/滑动窗口 → 流控 vs 拥塞 + 四阶段 → CUBIC/BBR → 端口耗尽事故整合
- **N3**:解析流程/记录类型 → TTL 与缓存 → DoH/EDNS/GeoDNS → Anycast/BGP
- **N4**:HTTP/1.1 → keep-alive/队头阻塞 → 强缓存/协商缓存 → H2 分帧/HPACK → H3/QUIC → QUIC 流控/QPACK/0-RTT → 双栈现状
- **N5**:加密原语/前向保密 → TLS 1.3 握手 → 证书链/CA/ACME → SNI/ECH → mTLS/零信任/后量子
- **N6**:WS vs SSE → 反向代理/nginx 陷阱 → CDN/回源/缓存键 → Tunnel/容器网络 → eBPF/前沿/告别

典型校验例:话 20 讲 QUIC 之前,"队头阻塞"必须已在话 17 立住;话 26 的 ECH 依赖话 25 先讲清 SNI;话 21 的 0-RTT 重放依赖话 06 的握手与话 08 的重传心智。

## 7. 写作红线

### 7.1 版本敏感事实:发布前必须联网复核清单

知识底稿(knowledge-network.md)的核实基准日为 **2026-07-26**(opencode + DeepSeek 联网检索)。以下条目**底稿中即标 ⚠ 未核实,原样列出——涉及话数发布前必须先联网复核,复核不过就降级为"趋势提法"或删除**:

1. **#38 后量子 TLS**(话 27):"X25519+ML-KEM 混合密钥交换已在 Chrome/Cloudflare 大规模部署;⚠ 具体默认组合名未核实。"
2. **#40 MASQUE 与 WebTransport**(话 32):"⚠ 浏览器支持面未核实。"
3. **#41 BBRv3 与 L4S**(话 10 彩蛋、话 32):"⚠ 部署进度未核实。"
4. **#43 QUIC 在 Java 生态**(话 32):"⚠ 最新孵化状态未核实。"

已核实(✅)但**有时效**的数字与事实,发布当话时若距核实日超 90 天,同样必须复核后再引用:H3 Top-1M 站点约 34% 支持、裸源站仅约 2.3%、nginx 1.25.3 起 H3 production-ready、Server Push 自 Chrome M107 移除、ECH = RFC 9849(2026-03 发布)。**覆盖率类百分比时效最短,发布前一律重查。**

复核方式:委托 opencode + DeepSeek 联网检索并对结果复验(全局约定);RFC 编号类可直接查 rfc-editor。**绝不凭记忆写版本号 / RFC 号 / 百分比**——帕特的"回巢查 RFC"约束的首先是作者。

- 悬疑、死亡、致郁展开一概不碰(那是 cafe 线都不做的事);本线基调 = 硬核 + 冷幽默。

## 8. 篇幅与发布节奏(继承防臃肿硬约束)

- 普通话 **3.8k–5.5k 字符**;卷终整合话可到 **5.5k–6.5k**;深度靠密度(表格化)不靠长度。
- 漫画 4–8 格;一话除 📡 实验室外最多 2 个深度栏目。
- 蓝图全量挂 `lib/series-net.ts`(planned),**周更一话** published:写完当话 md、slug 对齐、当话 status 翻转,三件事同 commit(对齐 CLI 线状态流)。
