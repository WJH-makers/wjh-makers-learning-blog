## 0. 一句话定位

《从零开始拆微服务》教你**怎么拆干净**,这一部教你**该不该拆**。

两条线互为镜像:奥朵拿手术刀,筑叔按住手术刀。本线不追新技术、不比谁的框架版本高,只训练一种能力——**在信息不全、资源有限、人还会吵架的现实里,做出一个能被追问、能被推翻、能被归档的决策**。

面向读者:已经能交付系统、开始被问"这个方案为什么这么设计"的工程师。因此本线的差异化立场是:**任何结论都必须写清放弃了什么**——只谈收益不谈代价的方案,在这条线上一律不成立。

## 1. 衔接与世界观

- 时间线:《拆微服务》连锁化之后。咖啡站开到第五家,一次"为拆而拆"把订单域切成两半,跨服务对账天天差、赔进去整整一个月的账。豆豆合上账本,把阿零赶到上游河湾——"先去学学什么时候**不该**动手。"
- 舞台:河湾上游的**咖啡站规划院**(一座半截坝体改的工作室)。墙上是层层叠叠的图纸;坝体里嵌着一排刻字石板,每块是一份归档的架构决策记录;院子正中挂着那架取舍天平。
- 五卷主线:卷一 从需求到模型(01–07)→ 卷二 接口的契约(08–13)→ 卷三 该不该拆(14–20)→ 卷四 数据的架构(21–26)→ 卷五 决策与落地(27–32)。

## 2. 角色表(硬约束,防人设漂移)

### 筑叔(Zhu)—— 本线导师,规划院的海狸

- **外形**:嘴里永远叼着一根刻度已被磨平的标尺(量了太多年);建坝前必先画**三张图**——约束图、边界图、取舍图——三张不齐,一根树枝都不动。
- **随身道具**:
  - **取舍天平**:左盘放收益、右盘放代价,称不平就不许开工。天平是本线的仪式感来源,每话至少上秤一次。
  - **石板凿子**:每做一个决定就凿一块石板压进坝体(ADR),十年后还能被翻出来问"当年为什么"。
- **性格**:慢、稳、爱追问;对"业界都这么干"零容忍,对"先做了再说"零容忍,但对**有依据的激进方案**非常宽容。
- **口头禅**:"**先问:拆了,谁受益?**"(受益人说不出名字的拆分,一律不批)
- **副口头禅**:"架构不是画出来的,是被约束逼出来的。"
- **能力边界(铁律)**:
  1. 只给**判据和提问**,不给标准答案;方案永远由阿零提,筑叔负责称重和追问。
  2. 不下没有量化依据的架构断言——他自己也守 §7 红线。
  3. 不承诺"这样设计就不会出事";只承诺"这样设计,出事时你知道该退回哪一步"。
  4. 遇到"两个方案都行"的场面,必须公开说出来,并给出**默认推荐 + 复审触发条件**,不装作只有一条路。

### 阿零 —— 本线成长弧:从"能实现"进化到"能拍板"

延续前作人设:此时已能独立交付服务,但一被追问"为什么这么设计"就只会答"业界都这么做"。**每卷一次可见的能力上涨**:

| 卷 | 卷终时阿零能做到 |
|---|---|
| 卷一 | 能把一句模糊需求翻译成约束 + 质量属性 + 一张领域模型图 |
| 卷二 | 能设计一套三年不破的对外契约,并说清版本策略的代价 |
| 卷三 | 第一次说出"这个不拆",并拿得出量化依据 |
| 卷四 | 能给每条数据定一致性等级,并设计出可补偿、可回退的事务链 |
| 卷五 | 独立主持一次架构评审、独立产出 ADR;结局从筑叔手里接过标尺 |

### 客串规则(奥朵 / 豆豆 / 特米)

- **奥朵**(微服务线章鱼架构师):卷三固定对手戏,人设是"急着开刀的外科医生"——她主张拆、筑叔主张先量;**两人不分胜负**,最后由数据裁决。奥朵不在本线降智,她的每条主张都必须站得住。
- **豆豆**:升格为**甲方**——出需求、拿账本、算钱;毒舌照旧("你这张图很好看,能省钱吗?"),但**不当导师**(本线导师是筑叔)。
- **特米**:卷五架构守护一话从流水线探头递一句命令(只递 CLI 线教过的),台词量级一句;固定梗:"man 一下?你们这边好像是'先上天平'。"
- 筑叔不去别线当导师;跨线联动只走 §8 钩子表。

## 4. 本线专属深度栏目(两个,每话各恰好 1 个)

### 4.1 ⚖️ 取舍天平

- **定位**:对标 Java 线 🔀 多解台、JVM 线 🔬 炉底显微镜。差异化 = **强制写"放弃了什么"**。口号:"称不平,就不开工。"
- **规则**:
  1. 左盘"收益"、右盘"代价"必须**都非空**;代价一栏写"基本没有"的,直接判本话不合格。
  2. 至少列 2 个备选方案(含"什么都不做"这个永远合法的选项)。
  3. 必须给**默认推荐 + 一句理由**,不许罗列完让读者自己晕。
  4. 尽量给可量化项:多几跳调用、多几张表、多几人日、多几个失败模式。
- **格式模板**:

  ```text
  > **⚖️ 取舍天平 · <这个决策>值不值?**
  >
  > | 方案 | 收益(左盘) | 代价(右盘) | 什么时候选它 |
  > |---|---|---|---|
  > | 什么都不做 | … | … | … |
  > | 方案 A | … | … | … |
  > | 方案 B | … | … | … |
  >
  > 默认推荐:<方案> —— <一句理由>。
  > 放弃了什么:<明确写出这次牺牲掉的质量属性/能力>。
  ```

### 4.2 📐 ADR 存档

- **定位**:每话产出一份可归档的架构决策记录(Architecture Decision Record),全线累计 32 块石板,卷五结集成索引。
- **规则**:
  1. 五段齐全:**背景 / 备选 / 决定 / 后果 / 复审触发条件**,一段都不许省。
  2. "后果"必须写**正负两面**;"复审触发条件"必须可观测(如"日订单破 X 万"、"团队超过 Y 人"、"该接口调用方多于 Z 个")。
  3. 编号连续:`ADR-001` … `ADR-032`,与全局话号一一对应;被后面推翻的 ADR **不删除**,改状态为"已被 ADR-0XX 取代"——推翻记录本身就是教学内容。
  4. 用词克制:决定一段只写"我们决定 X",不写"我们认为 X 最好"。
- **格式模板**:

  ```text
  > **📐 ADR-0NN · <决策标题>**
  >
  > - **背景**:<触发这个决策的约束与现状,2–3 句>
  > - **备选**:<A / B / 什么都不做,各一句>
  > - **决定**:我们决定 <X>。
  > - **后果**:正面 <…>;负面 <…>。
  > - **复审触发**:<可观测的条件,达到即重开这块石板>
  ```

## 7. 写作红线

### 7.1 决策类内容的证据纪律

- **铁律**:任何"应该这样设计"的断言,必须落到**约束**上——延迟预算、团队规模、变更频率、数据量级、故障预算。说不出约束的建议一律删掉。
- **禁止绝对化**:不写"微服务比单体好""DDD 是最佳实践";一切写成"在 <约束> 下,<方案> 优于 <备选>,代价是 <X>"。
- **不给银弹**:每个模式(Saga / CQRS / 事件溯源 / 绞杀者)出场都必须同时给出**不适用场景**,否则本话不合格。
- **量化优先**:能写数字就别写形容词——"慢"改成"多两跳跨服务调用","复杂"改成"多维护三张对账表"。数字是设定的量级(咖啡站虚构场景),写清"这是本例设定",不冒充行业统计数据。

### 7.2 技术事实纪律

- 基线:**Java 25 LTS / Spring Boot 4.x / jakarta 命名空间**。涉及"哪个版本引入/变更"时,写前联网复核(opencode+DeepSeek 或 context7),不凭记忆编版本号;**没把握的次版本号一律不写,改用通用表述**(如"Spring Boot 4.x""当前 LTS")。
- 本线大量概念(限界上下文、聚合、Saga、CQRS、事件溯源、绞杀者、康威定律)属于**方法论而非版本特性**,不要给它们编造版本归属或"官方推荐"。
- 工具类(契约测试框架、架构测试框架)只写能力与用法形态,**不写具体版本号**;命令与配置片段照抄可跑,跑不通就换例子。

### 7.3 术语一致性表(全线统一,首现标注英文)

| 统一用词 | 禁用/别名 |
|---|---|
| 限界上下文(Bounded Context) | 不写"业务域""模块域" |
| 聚合根(Aggregate Root) | 不写"主实体" |
| 统一语言(Ubiquitous Language) | 不写"通用语言" |
| 模块化单体(modular monolith) | 不写"大单体""巨石"(贬义词禁用) |
| 绞杀者模式(Strangler Fig) | 不写"替换法" |
| 最终一致性 / 因果一致性 / 强一致性 | 三者不混用,首现标英文 |
| 架构决策记录(ADR) | 首现全称,后文 ADR |
| 取舍(trade-off) | 不写"平衡"敷衍过去 |

### 7.4 其他红线

- 便利贴语法沿用全站规范(`lib/markdown.ts` STICKY_CLASS):`> [!吐槽]`、`> [!彩蛋]`、`> [!警告]` / `> [!坑]`、`> [!强调]` / `> [!重点]`、`> [!答案]`(折叠 details,放选读硬核推导)、`> [!文字版]`;漫画分格 `> **〔n〕**` 格间空行;固定栏目前缀 `> **⚖️ 取舍天平 · …**`、`> **📐 ADR-0NN · …**`,便于一眼识别。
- 继承 Java 线 §10 全部"必须坚持 / 绝不做";本线追加三条不做:
  1. **不画只有方框没有箭头的图**——每张图必须标出依赖方向与数据流向。
  2. **不把架构讲成道德**(拆是先进、单体是落后);咖啡站的每一次不拆,都得和拆一样理直气壮。
  3. **不用真实公司名背书**("某大厂就是这么干的");要引证据就引可验证的公开模式,并说明它的适用约束。
