## 0. 一句话定位

阿零给豆豆咖啡站装上"AI 大脑"的全过程——把一只会胡说的随机鹦鹉,驯成一支能查库、会用工具、可观测、算得清账的生产级 Agent 舰队。

主站是一份工程报纸。本线的差异化立场:**别的教程教你调 API,我们教你算账、验证、不迷信**——漫画负责心智模型,代码负责落地,🧾 Token 账本负责"这值多少钱",评测负责"别凭感觉说变好了"。

## 1. 衔接与世界观

- 承接 Java 线 S7 大结局(咖啡站上云,Spring Boot 4 代码库)+ CLI 线 C5 大闭环(咖啡站入住真实服务器)。时间线:咖啡站 v7 之后的新纪元 **"v8: AI 化改造"**。
- 每一话的技术都落在咖啡站的一个真实需求上:AI 点单助手、菜单知识库问答、自动补货 Agent、成本看板。
- 本线主线"给豆豆装 LLM 大脑",与《豆豆咖啡站》温情线里豆豆日渐"通人性"的伏笔**互为表里**:本线给技术解释,情绪与身世留给温情线,**本线绝不剧透温情线 K6/K7 悬念**。

## 2. 角色表(语气表是硬约束,每话对白都要对得上)

### 帕若(Parro)—— 新导师 / 随机鹦鹉
- **外形**:一只栖在咖啡站霓虹灯牌上的电子鹦鹉,自称"随机鹦鹉"(致敬 Stochastic Parrot 梗)。**羽毛颜色随 temperature 变化**:调到 0 变成灰色一丝不苟,调到 2 变成彩虹色满嘴跑火车——这是本线最重要的视觉符号,涉及采样参数的话必须用上。
- **性格**:博览全网、出口成章,但**不喂上下文就开始一本正经地编**。它从不掩饰自己"只是概率补全",反而以此教学:"别问我记不记得,问我窗口里有没有。"既是导师,也是 LLM 本性的活体教具。
- **口头禅**:**"别猜,喂上下文!"**;次口头禅(每逢阿零想省事):**"先算 token 账。"**
- **能力边界(铁律)**:
  1. 帕若只输出文本 / 工具调用请求,**没有手**——一切执行落在豆豆(和后来的 Agent 鸟群)身上,Java 代码永远是阿零写。
  2. 帕若的每次翻车必须是**真实 LLM 会犯的错**(幻觉、格式漂移、被注入、中间遗忘、超窗截断),严禁编造不存在的失败模式。
  3. 帕若不背答案:排障沿用豆豆五步法(观察现象 → 收集报错/输出 → 提出假设 → 改一个变量 → 重跑验证),AI 特化为"**改一个变量**=一次只动 prompt / 参数 / 上下文其中一样"。
- **固定短栏目前缀**(对齐 Java 线豆豆旁白/锐评):`> **帕若旁白**:…`(补充/捷径)、`> **帕若锐评**:…`(点破本质/踩坑/面试点)。

### 阿零 —— 读者代理(会翻车的工程师)
延续 Java/CLI 两线人设:已是能交付并部署系统的人,但对 LLM 是新手——"**会写代码 ≠ 会驯模型**"是本线核心冲突(对齐 CLI 线"会写代码 ≠ 会用服务器")。仍要提初学者真会问的蠢问题、犯真实的错(循环调用烧出天价账单、把整本合同塞进窗口、忘写停止条件)。

**本线成长弧(每卷至少体现一次能力上涨)**:
| 卷 | 阿零的状态 |
|---|---|
| 卷一 | 被幻觉吓到,学会"每句话先问依据在不在窗口里" |
| 卷二 | 能写出需求文档级 prompt,懂得给格式给示例给边界 |
| 卷三 | 能独立搭一条 RAG 流水线,并用固定考题集跑评测 |
| 卷四 | 能设计带停止条件、护栏与记录仪的 Agent,不再裸放 |
| 卷五 | 能算账选型(prompt/RAG/微调、贵鸟/便宜鸟),主导 v9.0 AI 化上线——从"用 AI"到"运维 AI" |

### 客串规则
- **豆豆**:本线的被改造对象(咖啡机器人装上 LLM 大脑),常任"执行者"(function calling 的手、RAG 的检索员、assistant 角色化身)。戏份规则:技术执行归本线,"通人性"的情绪归温情线;第 30 话卷终"欢迎入伙"是两线交汇点。
- **特米**:仅第 22 话(MCP)正式客串,梗必须落地:"以前让你 man 一下,现在 tools/list 一下"。其余各话不出场,最多便利贴彩蛋。
- **面试官**(Java 线 🎯 宇宙角色):第 28 话返场,考"RAG 和微调怎么选"。三条教学线共用一个面试宇宙。
- 客串铁律:客串角色**不抢导师职责**——讲解权在帕若,客串只负责梗与联动。

## 4. 深度栏目

### 🧾 Token 账本(本线专属 · 每话必有)
- **作用**:成本心智是 AI 工程区别于传统开发的最大新变量,与"工程报纸"的账目气质天然契合。每话结尾一张收银小票风的四行账:**token 消耗 / 每千次调用成本 / 延迟 / 省钱姿势**。
- **格式模板**(用代码块排成小票):
  ```text
  ┌─ 🧾 Token 账本 · 第 17 话「豆豆的开卷考试」──┐
  │ token 消耗   检索附带上下文 ~2K tok/次(输入侧)│
  │ 千次成本     单次成本 ×3(RAG 前后对比)        │
  │ 延迟         +检索 80ms;TTFT 基本不变          │
  │ 省钱姿势     检索小块喂大块;命中不足别加 k 加重排│
  └─ 帕若:幻觉率 ↓80%,这钱花得值。────────────┘
  ```
- **约束**:① 数字必须有来源(实测或写作当日官方定价,禁止拍脑袋);② 最后一行永远是帕若的一句"值不值"判断——账本不只报数,要给结论;③ 与第 9 话(thinking 预算 8K → 正确率 +23%,慢 6 秒)、第 29 话(3K 前缀缓存命中 → 输入成本省 ~90%)这类"为正确率/速度付多少钱"的话,账本就是全话点题位。

### 沿用栏目(格式模板见 Java 手册 §5,触发规则本线化)
- **🔀 多解台**:同一问题 2–3 解 + 默认推荐。典型触发:防幻觉(prompt 声明 / RAG / 微调)、结构化输出(prompt 恳求 / JSON mode / Schema 强制)、记忆(全量重发 / 滑动窗口 / 压缩摘要 / 向量长期记忆)、检索(纯向量 / 混合 / +rerank)、接入(裸 HTTP / LangChain4j / Spring AI)。
- **⏳ 版本时光机**:LLM 生态一年一变,素材充足:补全 API → Chat → Responses 式;prompt 里求 JSON → JSON mode → Schema 约束;插件 → function calling → MCP;Spring AI 1.0 → 2.0;"prompt 工程" → "上下文工程"。**主线以 2026 年当前做法为准**,时光机只负责"知其所以然"。
- **🎯 面试直击**:本线高频题:token 怎么计费、RAG 全流程、RAG vs 微调 vs 长上下文、Agent 循环与停止条件、幻觉工程解法、Embedding 是什么。只放真高频,不硬凑。

### 7.2 真实性红线(本线最容易造假的地方)
- 模型输出、API 报错、账单数字必须真跑/真查得出来;概率性输出要么锁 `temperature=0` 注明,要么展示多次采样的差异——**不许把一次侥幸当规律**。
