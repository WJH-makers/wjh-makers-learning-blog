## 0. 一句话定位

**这一部不教你把覆盖率刷上去,教你敢改代码。**

测试的产出不是绿灯,是**修改代码的胆量**——一个团队敢不敢重构、敢不敢周五发版,取决于失败会不会被自动抓住。因此本线每一话都必须能回答同一个问题:**这条测试买回了什么自由,又值不值这份维护成本?**

面向的是**已经能交付功能的进阶者**(读完 Java 线 + 至少一条工程线)。差异化立场有两条:
1. **一切缺陷都要剖到根因层**,不停在「改好了」;
2. **一切测试都要标出边界**,明确写出「这一层我不测,交给谁测」——反对全量测试式的自我感动。

## 1. 衔接与世界观

- 时间线:Java 线 v7 上云、CLI 线部署大闭环、build 线流水线成型**之后**。咖啡站生意做大,代码却进入「谁也不敢动」的僵局:一个定价规则要改,先手工回归两小时,还是漏。
- 触发事件:一次上线把会员折扣算反,顾客白喝三天。复盘会上没人说得清「哪段代码验证过、哪段没有」——质量第一次从口号变成账本。
- 舞台:豆豆咖啡站**二楼·质检室**。墙上一整面是「虫标本墙」(逃逸缺陷陈列),旁边挂着一块红绿灯板(流水线状态);窗台那棵老木头上,常年有敲击声。
- 四卷主线:卷一 测试基本功(01–08)→ 卷二 隔离的艺术(09–15)→ 卷三 流水线上的质量(16–23)→ 卷四 更高阶的把握(24–30)。

## 2. 角色表(硬约束,防人设漂移)

### 叩叩(Kou)—— 本线导师,啄木鸟

- **外形**:栖在质检室窗外老木上的啄木鸟。**喙尖敲三下就能听出木头里空心的位置**(缺陷探测的具象化,空心 = 未被验证的代码路径);爪子上挂一串**虫标本**,每一只都是曾经真上过线的 bug,按品种钉牌分类(空指针、边界、时序、并发、编码、契约漂移)。
- **习惯**:写任何一段代码之前,他先写一句「**这段会怎么坏**」——本线所有测试都从这句话长出来,而不是从「这段代码有哪些分支」长出来。
- **口头禅**:「**敲一敲,虫自现。**」(先验证,再相信)
- **副口头禅**:「没被测过的代码,只是恰好还没坏。」(对标特米的「man 一下」、焰焰的「JEP 里都写着呢」)
- **能力边界(铁律)**:
  1. 只给**验证方法与判据**,不替阿零写业务实现;测试用例可以给,业务代码让阿零自己写。
  2. 不下没有失败样本的质量断言——他说一个地方空心,必须当场敲出一个**真的红灯**。
  3. **绝不推荐「全都测一遍」**;每次给方案,必须同时给出「这次不测什么、为什么可以不测」。
  4. 拿出虫标本时只讲根因与预防,不讲「谁写的」——本线**没有追责剧情**,只有系统性防线。

### 阿零 —— 本线成长弧:从「写完就算完」到「为失败设计」

| 卷 | 卷终时阿零能做到 |
|---|---|
| 卷一 | 给核心域写出读得懂、跑得快、命名即报告的单元测试,并说得出为什么这段代码原来没法测 |
| 卷二 | 自主判断什么该用替身、什么必须用真依赖;把时间/随机/网络全部握在手里 |
| 卷三 | 把测试搬上流水线并对耗时负责;治得住 flaky,看得穿覆盖率,立得起门禁 |
| 卷四 | 主动逼问系统:TDD 驱动设计、变异测试审判测试、混沌演习验证韧性,并用度量说话 |

### 客串规则(豆豆 / 特米 / 焰焰 / 格叔)

- **豆豆**:**混乱制造机**——专造脏数据、重复下单、半夜跨月的边界订单;毒舌照旧,但**不当导师**(本线导师是叩叩),它只负责把系统弄坏并吐槽一句。
- **特米**(CLI 线企鹅):从流水线日志里 `grep` 出 flaky 用例、用管道统计失败频次;台词量级一句,固定梗:「man 一下?你们这儿是敲一下。」
- **焰焰**(JVM 线火蜥蜴):只在「性能进 CI」一话出场,递 JFR / 压测观测口径,与叩叩互相拆台(「先热身,再起飞」vs「先敲一敲」)。
- **格叔**(build 线大象工头):卷三门禁话出场,负责把质量卡点焊进流水线;涉及构建细节一律引 build 线,本线不重讲。
- 叩叩不去别线当导师;跨线联动只走 §7 钩子表。

## 4. 本线专属深度栏目(两个)

### 4.1 🐛 缺陷解剖台(按触发,一话至多 1 个)

- **定位**:对标 Java 线 🔀 多解台、JVM 线 🔬 炉底显微镜。差异化 = **把一个真实缺陷剖到根因层**,并从根因反推「哪一层测试本该抓住它」。
- **触发**:本话对应叩叩虫标本墙上的某只虫时;incident 话必有,其余话按需。
- **四层解剖法(缺一不可)**:
  1. **表象**:用户看到什么(白喝三天 / 订单重复 / 半夜 500);
  2. **触发条件**:什么输入或时序才会发作(边界值、并发、时区、重试);
  3. **根因**:代码/设计层面到底哪里错了(不是「忘了判空」,而是「这个字段的可空性从未被表达」);
  4. **本该被谁抓住**:指名到测试层级(单元 / 集成 / 契约 / E2E),并说明当时为什么没抓住。
- **格式模板**:

  ```text
  > **🐛 缺陷解剖台 · <虫的名字>**
  >
  > | 层 | 内容 |
  > |---|---|
  > | 表象 | 会员折扣算反,顾客白喝三天 |
  > | 触发条件 | 折扣率恰好为 0 且叠加满减 |
  > | 根因 | 折扣模型允许 0 与「无折扣」两种含义并存,语义从未被表达 |
  > | 本该被谁抓住 | 单元测试(边界值),参数化用例里缺 0 这一行 |
  >
  > 叩叩结语:<一句预防措施,必须可执行>。
  ```

- **约束**:根因一栏**禁止写成「粗心」「漏了」**;必须落到类型、契约、状态机或时序上。预防措施必须是一条可执行的工程动作(补一行参数化、改一个类型、加一条架构规则)。

### 4.2 🎯 测什么不测什么(每话必有,恰好 1 个)

- **定位**:本线的价值主张栏目。每话结束前,明确画出**这一话教的手段的投入产出边界**。
- **格式模板**:

  ```text
  > **🎯 测什么不测什么 · <本话手段>**
  >
  > | 测 | 不测 | 理由 |
  > |---|---|---|
  > | 定价规则的边界与叠加 | getter/setter、record 的访问器 | 编译器已保证,测了只增维护成本 |
  > | 折扣叠加的顺序 | 框架自身的行为 | 框架有自己的测试,重测等于替别人打工 |
  >
  > 一句成本账:<这些用例每月大约花多少维护时间,换回什么自由>。
  ```

- **约束**:
  1. 「不测」栏**至少两条**,且必须给理由——只写「测什么」等于没画边界;
  2. 禁止出现「都要测」「尽量都覆盖」这类话术;
  3. 成本账用**相对量级**(如「一次接口改名要同步改 3 处」),不编造精确数字。

## 8. 复核红线

### 8.1 工具与版本敏感事实:发布前必须联网复核

- **铁律**:凡涉及测试框架/工具的 API 形态、注解名、默认行为、是否已废弃,发布前逐条用 opencode+DeepSeek 或 context7 联网复核,**不凭记忆、不信旧博客**。核实优先于假设。
- 基线:**Java 25 LTS / Spring Boot 4.x / jakarta 命名空间 / JUnit 5(Jupiter)**。不确定的小版本号一律写通用表述(如「Spring Boot 4.x」「JUnit 5」),**绝不编造精确版本号与发布时间**。
- 每话触及即必查的高危清单:Spring 测试替身注解的现行名称(旧写法已被取代,勿沿用过时注解名);JUnit 5 扩展模型与并行执行配置项;Testcontainers 的模块坐标与生命周期注解;覆盖率/变异测试/契约测试工具与 Java 25 的兼容性;任何「默认开启/关闭」断言。
- 引用外部工具时,**只讲思想 + 给官方文档方向**,不复述可能已过期的配置片段(尤其契约测试:讲 Pact 思想,不逐行抄 DSL)。

### 8.2 内容红线

- **红灯必须真跑得出来**:断言失败输出、堆栈、流水线报告一律真实实录,不许编造;编不出来就换一个真跑得出的例子。
- **反向验证**:每次修复后必须确认「把修复撤掉,红灯会重新亮」——只会变绿的测试不算证据。
- **禁止覆盖率崇拜**:全线不得出现「覆盖率越高越好」的表述;18 话正面拆穿它,其余话遇到覆盖率一律只作体检项。
- **禁止全量测试话术**:任何方案必须配 §4.2 的边界表;写不出「不测什么」说明这一话没想清楚。
- **不追责**:虫标本只讲根因与预防,不出现「谁写的」剧情。
- 便利贴语法沿用全站规范(`lib/markdown.ts` STICKY_CLASS):`> [!吐槽]`、`> [!彩蛋]`、`> [!警告]` / `> [!坑]`、`> [!强调]` / `> [!重点]`、`> [!答案]`(折叠 details,放选读的硬核推导)、`> [!文字版]`;漫画分格 `> **〔n〕**` 格间空行;固定栏目前缀 `> **🐛 缺陷解剖台 · …**`、`> **🎯 测什么不测什么 · …**`、`> **🚨 红灯实录**`,便于一眼识别。
- 继承 Java 线 §10 全部「必须坚持 / 绝不做」;本线追加一条不做:**不把测试写成教条**——每条实践出场都必须绑一次成本账(它挡住了什么、它每月要花多少维护)。
