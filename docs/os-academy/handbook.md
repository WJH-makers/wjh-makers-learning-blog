## 0. 一句话定位

把操作系统拆成咖啡站的**水电煤地下管网**——你看得见的每一杯咖啡(每一次请求),背后都有一整层看不见的地下工程。跟着阿零和摩尔下地下室,亲手摸管道。**Java 线教"怎么写",CLI 线教"怎么敲",OS 线教"怎么看穿"。**

## 1. 衔接与世界观

- 承接 Java 线 S7 大结局 + CLI 线 C5 部署闭环:点单系统 v7 用户暴涨,阿零把服务迁进自建机房 + 云主机,第一次发现代码之下还有一整个地下世界。
- 空间隐喻(全线通用,不许换):**一楼 = 用户态**(特米的地盘,shell 是通往地下的对讲机);**地下室 = 内核态**;**syscall = 隔在两层之间的地板与门铃**。每次"陷入内核"都画成"按门铃/下楼梯"。

## 2. 角色表

### 摩尔(Mole)—— 本线导师,地下管理员

| 维度 | 设定(硬约束,每话对白对照) |
|---|---|
| 外形 | 戴矿工头灯的老鼹鼠,住咖啡站地下锅炉房;腰间一圈钥匙,**每把钥匙 = 一个系统调用**;头灯光束照到哪里,哪里的"真相"就现形(头灯 = 观测工具的具象) |
| 性格 | 低调、极度务实、看不惯"用户态的想当然";嘴上嫌弃阿零"地面上的少爷",手把手教得比谁都细 |
| 口头禅 | **"别猜——strace 一下!"**;副口头禅:"地面上的每一杯咖啡,地下都有一根管子在响。" |
| 教学铁律 | 一切结论必须有**观测证据**,禁止"我觉得/大概是";先让阿零猜,再用一条命令把猜想当场证实或证伪 |
| 能力边界 | 只管**本机内核以下**的事:不懂业务代码(Java 的事让阿零"上楼问豆豆"),不管 shell 用法与网络之外的地面工具(甩给特米"man 一下");**从不上地面**——只在地下室、对讲机、或头灯光束里出现 |
| 与特米关系 | 老相识;特米管地面窗口(shell),摩尔管地下管道(kernel),隔着 syscall 地板斗嘴多年("man 一下!"/"strace 一下!"是固定对台词) |

固定短栏目前缀(对齐豆豆旁白/锐评的双栏目制):

- `> **摩尔头灯**:…` —— 补充/捷径/一条顺手的观测命令(对标"豆豆旁白")
- `> **摩尔冷笑**:…` —— 点破本质/用户态想当然的打脸/踩坑(对标"豆豆锐评")

### 阿零 —— 读者代理(本线成长弧)

延续 Java + CLI 线人设:已是能写代码、能用终端交付系统的人,**但对"命令和代码底下发生了什么"一无所知**——"会用 ≠ 看得穿"是本线核心冲突。职责不变:提初学者真会问的蠢问题、犯真实的错、先给"想当然"的错误解释。

成长弧(每卷至少体现一次能力上涨,不能永远靠摩尔开灯):

| 阶段 | 阿零的样子 |
|---|---|
| 卷一 | 连"卡住"和"忙碌"都分不清,事事等摩尔开头灯 |
| 卷二 | 会自己看 `/proc/<pid>/`,能独立解释一次 VIRT vs RSS |
| 卷三–四 | 能自己 strace 出 fd 泄漏;能讲清 epoll 为什么快 |
| 卷五 | 独立把点单系统写成带资源限制的 systemd service |
| 卷六 | **反客为主**:自己用 perf + 火焰图定位一次线上热点,摩尔只在旁边点头 |
| 卷七 | 大结局能给豆豆和特米讲"虚拟线程底下发生了什么"——从"被开灯的人"变成"举灯的人" |

## 3. 每话固定骨架(11 步,继承 Java v2 并按"观测优先"特化)

Java 线的循环是"写码→造 Bug→修";OS 线的循环是**"地面出事→下地取证→读懂口供→修复并复测"**。每话严格走这 11 步,小节仍用中文数字 `## 一、…` 顺序对齐:

| # | 段落 | 职责 | 字数量级 |
|---|---|---|---|
| 1 | 地面事故 | 咖啡站真实线上现象(卡死/变慢/消失/写丢),开头一句**承上** | 150–250 |
| 2 | 4–8 格漫画 | 心智模型 + 冲突 + 情绪;必含"阿零想当然 + 摩尔头灯照出真相 + ≥1 个技术角色";格式 `> **〔n〕**`,格间空行 | 800–1200 |
| 3 | 本话目标 | ≤5 条,动词开头 | ≤120 |
| 4 | 地下剖面图 | 内核机制原理图(地下管网/楼层剖面/流程图),精确版心智模型 | 400–700 |
| 5 | 下地取证 | **在上一话的环境与服务基础上**复现现象:命令 + 真实输出(必须真跑得出来) | 500–900 |
| 6 | 亲手翻车一次 | 故意触发本话最典型的事故(fork 炸弹限流版 / 僵尸堆积 / 拔电丢数据 / kill -9 惯犯…),对标 Java 线"故意造 Bug" | 300–500 |
| 7 | 读懂内核的口供 | 逐字段解读真实输出(dmesg / strace / /proc / 报错),摩尔金句:"程序不会撒谎,系统调用就是它的口供" | 400–700 |
| 8 | 修复并用观测复测 | 修复 + **用命令验证**(继承 CLI 线放宽:观测命令替代 JUnit;`echo $?`、复跑对比数字) | 300–600 |
| 9 | 🩺 内核听诊器 | 本线专属栏目,**每话必有**,格式见 §4 | 300–500 |
| 10 | 项目检查点 + 招聘技能 | 基础设施 vN 长到什么程度(已具备/还没有)+ 对应招聘技能节点(不能空) | 100–200 |
| 11 | 下一话悬念 | 一句**启下**,与下一话第 1 步能对上 | ≤80 |

- 沿用深度栏目:🔀 多解台 / 🎯 面试直击 / ⏳ 版本时光机(select→poll→epoll→io_uring、cgroup v1→v2、CFS→EEVDF、netstat→ss 都是好素材),**每话至多 1 个**(听诊器不计入),插在第 4 或第 8 步之后。
- 篇幅:普通话 **3.8k–5.5k 字符**;卷终话 5.5k–6.5k;加深靠密度不靠长度,深度内容一律表格化。
- 标题:`《从零开始拆内核》第 XX 话 · 章题`,H1 唯一;首行元信息引用块两行(卷/话定位 + 基础设施版本提示);结尾署名行:`*本话属于连载《从零开始拆内核》。世界观见 handbook.md;卷次地图见 /os。*`
- 复现基线:**Ubuntu 24.04 LTS**(容器/云主机同基线);凡依赖新内核的特性必须标注最低版本(如"需内核 ≥7.0"),不许让读者在 6.x 上跑不出来还不知道为什么。

## 4. 本线专属深度栏目:🩺 内核听诊器(每话必有)

**作用**:每话结尾给**一条读者可当场复现的观测命令**,把本话讲的抽象概念**当场抓现行**——这是 OS 线"教你看穿"的落点,也是与所有 OS 教材的差异点。

**格式模板**:

```text
> **🩺 内核听诊器 · 把〔本话概念〕抓现行**
>
> ```bash
> <一条(至多三条)可直接复制的命令,Ubuntu 24.04 可复现>
> ```
>
> **你会看到**:<贴 3~8 行真实输出(可截断)>
>
> | 字段 | 它说明什么 |
> |---|---|
> | <字段1> | <一句话> |
> | <字段2> | <一句话> |
>
> 摩尔冷笑:<一句点破——这个数字和本话地面事故的因果关系>。
```

**约束**:

1. 命令必须真跑过,输出必须真实可复现(允许注明"数字因机器而异,关注量级/趋势");
2. 无 root 也能跑的优先;必须 root/特权的注明并给退路;
3. 字段表只解释**本话讲过的字段**,没讲的写"下 X 话见",严禁顺手剧透;
4. 一话一个听诊器,不许堆命令清单——一条命令看穿一个概念。

**示例(第 10 话 · 写时复制)**:

```text
> **🩺 内核听诊器 · 把 COW 抓现行**
>
> ```bash
> strace -e trace=clone -f redis-server --daemonize no &
> grep -E 'Rss|Shared' /proc/$(pgrep -f redis-server | head -1)/smaps_rollup
> ```
>
> **你会看到**:bgsave 触发的 clone 瞬间返回(fork 几乎不花时间);
> 随着写流量进来,smaps_rollup 里 Shared 逐渐变小、Rss 逐渐上涨——共享页在一页页"分家"。
>
> | 字段 | 它说明什么 |
> |---|---|
> | Shared_* | 还和子进程共用的页——没人动过的家当 |
> | Rss | 真正落在物理内存里的部分——分了家就各算各的 |
>
> 摩尔冷笑:快照"秒级完成"的账,是之后每一次写操作在慢慢还的。
```

## 5. 项目主线与检查点版本链(对应 series 文件 projectStage)

本线长期项目 = **咖啡站基础设施**(不再长业务代码,长的是"这台机器被驯服的程度")。每话 `projectStage` 写"能力口径"(如"能验尸 OOM""服务崩了自动扶起"),每卷卷终话固定给一次**版本检查点**:

| 检查点 | 卷终话 | 基础设施长成什么样 |
|---|---|---|
| v0 | E01(起点) | 裸机 + 一个会莫名卡死的点单进程,阿零只会重启 |
| v1 | E06(卷一) | 进程/线程数受控,能解释每一次卡顿是谁在换班 |
| v2 | E13(卷二) | 内存账目清晰:VIRT/RSS 分得清,OOM 有验尸流程,fork/COW 心里有数 |
| v3 | E19(卷三) | 数据可靠落盘:fsync 策略明确,fd 有预算,磁盘队列看得懂 |
| v4 | E25(卷四) | 单机扛万连接:epoll/Reactor 上线,静态资源走零拷贝 |
| v5 | E30(卷五) | 交给 1 号老爷爷:systemd 托管 + 优雅停机 + 资源上限 + timer |
| v6 | E35(卷六) | 全站可观测:仪表盘 + strace/perf/eBPF 三级听诊,外加看穿容器 |
| v7 | E37(大结局) | 现代咖啡站:可观测 + 容器化 + 虚拟线程,与 Java 线 v7 点单系统合龙 |

规则(继承"绝不推倒重来"):

1. 每话的取证/翻车/修复都发生在**同一套环境**上,明确写"接着上一话的 vN 环境";
2. 卷终话第 10 步用"已具备 / 还没有"两列盘点,"还没有"就是下一卷的钩子;
3. `projectStage` 是能力口径不是知识名词——写"能验尸 OOM",不写"学了 OOM Killer"。

## 6. 依赖铁律(本线 + 跨线)

**本线铁律**(继承 Java §7 原文):本话只能使用"本话或更早话"讲过的概念;不得不提前用,只有两个合法选择——挪后,或补"最小够用"解释并标注"细节见第 X 话"。**严禁先用后讲。** 相邻两话"启下/承上"必须能对上。

本线依赖速查(写新话前对照,防倒挂):

- 卷一:syscall→fork/exec→进程状态→线程→调度→切换与 IPC
- 卷二:地址空间→页表/TLB→缺页→COW→mmap→swap/OOM→分配器/NUMA/大页
- 卷三:fd→inode/链接→VFS/挂载→page cache/fsync→journal/CoW→IO 栈
- 卷四:阻塞模型→select/poll→epoll→Reactor→零拷贝→io_uring
- 卷五:信号→JVM 与信号→权限/capabilities→systemd→timer/socket activation
- 卷六:仪表盘→strace→perf/火焰图→eBPF→容器(namespace+cgroup+overlayfs)
- 卷七:futex/内存屏障/伪共享→虚拟线程与未来
- 典型倒挂陷阱:E01 就想秀 epoll(在卷四)、卷二讲 mmap 时展开 page cache(在 E17)、卷五讲信号提 safepoint 细节(E27 才讲)。

**跨线依赖(默认读者已读,正文可直接用、不再解释)**:

| 前置 | 范围 | 本线怎么用 |
|---|---|---|
| Java 线 S1–S2 | 语法、OOP、集合 | 示例里出现 Java 代码不解释语法 |
| Java 线 S5(JVM/并发) | 线程、GC、JVM 内存 | E04/27/35/37"JVM 断面"话直接互文,明写"与《从零开始学 Java》第 X 卷互文" |
| CLI 线 C1–C2 | shell 走动、管道/重定向 | 每话观测命令直接敲,不教 shell;E14 讲 fd 时把 C2 的 `2>&1` 讲穿 |
| CLI 线 C4 | ps/top/kill、chmod/sudo、systemctl 会用 | 本线卷五/卷六是 C4 的"地下深挖版":C4 教会敲,本线讲为什么 |

超出以上范围的(如 Java 虚拟线程语法),按"最小够用 + 指路互文"处理。

## 7. 写作红线

### 7.1 版本敏感事实,发布前必须联网复核(opencode 检索,禁凭记忆)

凡正文出现**内核版本号、systemd 版本、特性引入版本、默认启用状态、发行版行为**,发布前当话逐条复核。知识底稿(2026-07-26)已核实基线:内核 7.1.5 / LTS 6.18·6.12·6.6·6.1 / systemd v261 / io_uring 容器默认禁用与 7.0 `IORING_REGISTER_BPF_FILTER` / PostgreSQL 18 等生产采用——**写到对应话时仍要复核是否过时**。

以下条目底稿明确标注 ⚠ 未核实,**原样列入,写到相关话(E34/E37/E25/E13)前必须先核实,核实不了就删改为定性表述**:

- ⚠ sched_ext 生态成熟度细节
- ⚠ Rust for Linux 2026 年内合并进展
- ⚠ MGLRU/DAMON 最新默认启用范围
- ⚠ CXL 商用落地进度
- ⚠ "Google kCTF 60% 漏洞来自 io_uring"数字为单来源转述(引用时必须注明来源或改为"绝大部分")

### 7.2 术语一致性(全线统一,首次出现给中英对照,此后只用左列)

系统调用(syscall)、用户态/内核态、上下文切换、写时复制(COW)、缺页中断、页表、文件描述符(fd)、僵尸进程、孤儿进程、就绪/睡眠/不可中断睡眠(R/S/D)、页缓存(page cache)、内存映射(mmap)、多路复用、边缘/水平触发(ET/LT)、零拷贝、命名空间(namespace)、控制组(cgroup)。禁止同义词漂移(如一会儿"页缓存"一会儿"页高速缓存");命令与内核对象名一律代码字体。

### 7.3 输出真实性

所有命令输出、dmesg、strace 结果必须真实可复现(Ubuntu 24.04 基线),不能编;数字因机器而异时注明"关注量级"。

### 7.4 便利贴语法(沿用主站渲染,`lib/markdown.ts` 已支持)

- `> [!吐槽]` / `> [!诉苦]` —— 阿零受害者发言、导师毒舌
- `> [!强调]` / `> [!重点]` —— 本话必须带走的一句
- `> [!警告]` / `> [!坑]` —— 危险操作(本线高频:fork 炸弹、`kill -9`、`echo 1 > /proc/...` 类调参)
- `> [!打趣]` / `> [!彩蛋]` —— 跨线彩蛋、导师斗嘴
- 兼容英文 NOTE/TIP/IMPORTANT/WARNING,新正文一律用中文类型。

### 7.5 继承的"绝不做"

一次写完 37 话不迭代;每个名词造角色;把观测命令堆成 cheatsheet(那是 /posts 速查表的事);给还在卷一的读者塞 eBPF;注水拉长;先用后讲。
