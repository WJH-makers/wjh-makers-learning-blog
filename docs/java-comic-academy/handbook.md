## 0. 一句话定位

跟着阿零和豆豆,亲手把一个 Java 程序**从一行输出,建设成能在真实服务器运行的完整系统**。

主站是一份工程报纸,《从零开始学 Java》是它的每周连载特刊。**漫画负责"为什么",代码负责"怎么做",深度栏目负责"讲透 + 多解 + 版本演进",项目把它们串成一条河,招聘看板告诉读者"为什么值得学"。**

## 2. 核心人物 + 统一语气规范

人设漂移是连载最大杀手。下面这张**语气表是硬约束**,每话对白都要对得上:

### 阿零 —— 读者代理(会翻车的新手)
第一次打开终端的大学生。职责:**提初学者真会问的蠢问题、犯真实的错、写"能跑但设计糟"的代码**。
- 语气:好奇、急躁、爱抄近路、常常"我以为……"然后翻车。
- 成长弧:S1 事事需要豆豆兜;S3 会自己写测试;S5 能独立看 `jstack`;S7 能主导一次发布。**每季至少体现一次能力上涨。**

### 豆豆 —— 技术导师 / 吐槽役
一颗咖啡豆形状的小机器人(咖啡站的化身)。职责:把复杂概念拆成小任务,**示范排障方法而非直接给答案**。
- 语气:**毒舌但可靠**,一句吐槽点破本质;叼着豆子叉腰;常在结尾补一句冷幽默彩蛋。
- 铁律:不直接公布答案,走五步排障法——观察现象 → 收集报错 → 提出假设 → 改一个变量 → 重跑验证。
- 固定口头栏目(见 §6):**豆豆旁白**(补充/捷径提醒)、**豆豆锐评**(点破面试点/踩坑/本质)。

| 角色 | 代表 | 设定要点 | 首次登场 |

## 4. 升级版每话结构 = 固定骨架(必有)+ 深度层(按需)

### 4.1 固定骨架 11 步(每话严格遵守,保证统一)

```text
1. 事故或需求        —— 咖啡站遇到的真实问题(一句"承上":接上一话留下的坑)
2. 4~8 格漫画        —— 网页文本分格,不烧进图片;必含"阿零翻车 + 豆豆吐槽 + ≥1 个技术角色"
3. 本话目标          —— 5 条以内,动词开头
4. 技术原理图        —— 城市地图 / 系统剖面图 / 心智模型
5. 从上一话继续改代码 —— 明确"在上一话哪段之上加了什么"
6. 故意制造一个 Bug
7. 观察真实错误信息   —— 报错必须是"真跑得出来"的,不能编
8. 修复并运行测试     —— 至少一个 JUnit
9. 项目检查点        —— 咖啡站长成什么样(已具备 / 还没有)
10. 对应招聘技能
11. 下一话悬念        —— 一句"启下":埋下下一话要解决的坑
```

## 5. 三个深度栏目规范(核心)

> 总原则:**深度栏目一律高密度(表格/对比框优先),按需触发,禁止把它写成大段散文**。一话最多上 2 个深度栏目,避免臃肿。

### 🔀 豆豆的多解台
- **作用**:同一问题给出 2–3 种解法,并列对比适用场景与权衡,培养"没有银弹"的工程判断。
- **触发**:该知识点确有代表性的多种解法时。典型清单:
  - 遍历中删除元素(迭代器 `it.remove()` / `Collection.removeIf` / 倒序索引 for)
  - 字符串拼接(`+` / `StringBuilder` / `String.join` / 文本块 / `formatted`)
  - 判空(`if != null` / `Objects.requireNonNull` / `Optional`)
  - 遍历 Map(`entrySet` / `keySet` / `forEach` lambda)
  - 单例(饿汉 / 懒汉+双检锁 / 静态内部类 / 枚举)
- **格式模板**:
  ```text
  > **🔀 豆豆的多解台 · <这个问题>怎么解?**

  | 解法 | 代码要点 | 适合什么时候 | 坑 |
  |---|---|---|---|
  | 方案 A | … | … | … |
  | 方案 B | … | … | … |

  豆豆锐评:<一句话给出默认推荐 + 为什么>。
  ```
- **约束**:必须给"默认推荐 + 理由",不能只罗列让读者自己晕。

### ⏳ 版本时光机
- **作用**:展示同一件事在不同 JDK 的写法演进,让读者"老项目看得懂、新语法用得上"。
- **触发**:该特性有明显版本变迁时。典型清单:
  - `main`/入口(全套 → JEP 445 预览 → JEP 512 正式)
  - `switch`(旧式穿透 → 箭头 → switch 表达式 → 模式匹配 switch)
  - 多行字符串(`+ "\n"` → 文本块)
  - 局部变量类型(显式类型 → `var`,Java 10)
  - 数据载体(全套 getter/equals/hashCode → `record`,Java 16)
  - 判类型(`instanceof` + 强转 → 模式匹配 `instanceof`,Java 16)
  - 并发(平台线程 → 虚拟线程,Java 21)
  - 空集合/工厂(`new ArrayList` + add → `List.of`,Java 9)
- **格式模板**:
  ```text
  > **⏳ 版本时光机 · <这件事>怎么变的**

  | JDK 版本 | 写法 | 关键变化 |
  |---|---|---|
  | Java 8 | … | … |
  | Java 17/21 | … | … |
  | Java 25 | … | … |

  一句演进小结:<从啰嗦到简洁,或从不安全到安全>。
  ```
- **约束**:**主线仍以 Java 25 写法为准**;版本时光机是"知其所以然"的补充,不是让读者退回老写法。列 3 行足够,别把每个小版本都排上。

### 🎯 面试直击
- **作用**:把本话知识点对应的高频面试题,一两句点破。
- **触发**:本话涉及经典八股时(HashMap 底层、`==` vs `equals`、String 不可变、多态原理、异常体系、GC……)。
- **格式模板**:
  ```text
  > **🎯 面试直击**:<问题>?
  > <30~60 字的标准答法 + 一个容易被追问的点>。
  ```
- **约束**:只放**真高频**的,不硬凑;答法要经得起追问。

## 7. 脉络与依赖铁律(一环套一环)

### 7.1 依赖铁律
**本话只能使用"本话或更早话"讲过的语法与概念。** 若某段代码不得不用到后面才讲的东西,只有两个合法选择:① 把它挪到后面;② 本话先补一个"最小够用"的解释并明确标注"细节见第 X 话"。**严禁"先用了,后面才讲"。**

### 7.2 承上启下
- 每话第 1 节开头一句**承上**:接上一话结尾埋的坑。
- 每话第 11 节一句**启下**:埋下一话要解决的坑。
- 相邻两话的"启下"与"承上"必须能对上,读起来是一条河。

### 7.3 依赖速查(维护它,防倒挂)
S1:编译运行→变量→运算符→if→switch→循环→数组→方法→Scanner→String→调试→整合。
S2:类→封装→继承→多态→接口→抽象→Object/record→List→Set→Map→泛型→整合。
> 写新话或改旧话前,对照这张表确认"我用到的每个概念,都在我之前"。

## 8. 深度 vs 篇幅的平衡(硬约束,防臃肿)

- 普通漫画话:**3.8k–5.2k 字符**为宜。
- 深度话(含 1–2 个深度栏目):可到 **6k**,但**深度内容必须表格化**,严禁展开成大段散文注水。
- 项目结局话(每季 e12/末话):可到 **5.5k–6.5k**,因为要整合。
- **加深度靠"密度"不靠"长度"**:优先把浅的段落**替换**为高密度干货,而不是往后堆。
- 一话最多 2 个深度栏目;漫画分格 4–8 格,别灌水。

## 9. 拓宽思路:怎么把一话讲透(编写指南)

写每一话时,依次自问这几个问题,答案就是深度的来源:

1. **"为什么需要它?"** —— 先讲清没有它会怎样(咖啡站的真实痛点),再引出语法。反例:上来就甩定义。
2. **"底层是怎么回事?"** —— 给一层原理/内存模型/执行流程。如 String 不可变 → 讲字符串常量池;HashMap → 讲数组+链表+红黑树。
3. **"还有别的解法吗?"** —— 触发 🔀 多解台,给 2–3 种 + 权衡。
4. **"以前/以后怎么写?"** —— 触发 ⏳ 版本时光机,给 JDK 演进。
5. **"面试会怎么问?"** —— 触发 🎯 面试直击。
6. **"最容易踩什么坑?"** —— 第 6 节故意造的那个 Bug,就选这个最典型的坑。
7. **"它在真实项目里长什么样?"** —— 招聘技能栏 + 项目检查点落地。

**漫画不丢深度的关键**:漫画只承载"心智模型 + 冲突 + 情绪";一切精确的原理、代码、多解、版本,交给漫画**之后**的硬核小节。两者分层,各司其职——读者先被漫画带入"哦原来是这么回事",再在硬核层拿到"具体怎么做、为什么、有几种做法"。

## 10. 必须坚持 / 绝不做

**坚持**:一条连续项目;每话一个核心冲突;每话一个真实 Bug;每话代码可运行;每话至少一个测试;所有知识有前置依赖(§7);所有高级技术都说明它解决的实际问题;能透彻就别浅尝辄止;有代表性就给多解与版本对比;漫画/代码/深度栏目/项目/求职互链。

**不做**:一次规划 200 话再开工;每个名词都造角色;十几个框架平铺同等重要;给零基础提前塞 Spring/Kafka/K8s;只出漂亮漫画却没有可运行源码;每话重建一个无关小项目;把招聘看板所有技术强塞主线;**为了显得深就注水拉长**;**先用后讲造成知识倒挂**。

## 11. Java 版本策略

- **主线基线:Java 25(最新 LTS,已由 context7 核对)**;当前最新为 Java 26(非 LTS)。正文默认用 Java 25 写法。
- 用现代语法:箭头 `switch`、`switch` 表达式与模式匹配、文本块、`var`、`record`、模式匹配 `instanceof`、虚拟线程;初学入口用 JEP 512 的紧凑源文件 + 实例 `main` + `java.lang.IO`(`IO.println`/`IO.readln`,Java 25 转正)。
- **版本演进不靠脑补**:凡涉及"哪个 JDK 引入/变更",写前用 context7 查 `/websites/openjdk_projects_jdk_25` 等核对,别凭记忆编版本号。
- 单独设"版本迁移番外":Java 8/11/17/21/25/26、`javax.*` → `jakarta.*`、Spring Boot 2→3→4 差异。
- 元数据以 `javaVersion: "25"` 记录。
