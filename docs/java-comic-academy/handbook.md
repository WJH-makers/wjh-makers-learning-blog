## 一句话定位

跟着阿零和豆豆,亲手把一个 Java 程序**从一行输出,建设成能在真实服务器运行的完整系统**。

主站是一份工程报纸,《从零开始学 Java》是它的每周连载特刊。漫画负责"为什么",代码负责"怎么做",速查负责"以后怎么查",项目把它们连起来,招聘看板告诉读者"为什么要学"。

## 长期项目:豆豆咖啡站

整个系列只围绕一个项目成长,每个知识点都在解决咖啡站真正遇到的问题,而不是孤立例子。

```text
控制台咖啡机 → 面向对象咖啡站 → 可维护订单系统
→ Spring Boot 咖啡店 API → 上线并可排障的服务 → 分布式咖啡平台
```

阶段与季次的对应关系见 `lib/series.ts` 的 `PROJECT_STAGES`。

## 核心人物

### 阿零 —— 读者代理
第一次打开终端的大学生。负责:提初学者真会问的问题、犯真实错误、写"能跑但设计不好"的代码。
**成长弧**:第一季事事需要豆豆提醒;到第五季能自己定位简单线上故障。阿零不能永远很笨。

### 豆豆 —— 技术导师 / 系统助手
一颗能把复杂概念拆成小任务的咖啡豆机器人(正好是咖啡站的化身)。
**关键约束**:豆豆**不直接公布答案**,而是示范工程排障方法:
1. 观察现象 → 2. 收集报错 → 3. 提出假设 → 4. 改一个变量 → 5. 重跑验证。

## 技术角色(各自代表一种心智模型)

| 角色 | 代表 | 设定要点 |
|---|---|---|
| 编译官 Javac | 编译期检查 | 严格但可靠的检察官,**不是反派**;查语法、类型、类名文件名、泛型 |
| JVM 城主 | 运行时 | 内部分:类加载站 / 堆内存城区 / 线程调度中心 / JIT 加速工厂 / GC 清洁队 / JFR 黑匣子 |
| Bug 怪(家族) | 各类缺陷 | Syntax Bug、Logic Bug、Null 幽灵、Race 双胞胎、Memory Leak 藤蔓、Timeout 迷雾 |
| Maven 仓库管理员 | 依赖与构建 | 物资与装备管理员:依赖、生命周期、打包、测试 |
| JUnit 质检员 | 自动化验证 | 口头禅「证据呢?」;从早期就长期存在,不是只出现一话 |
| Spring 管家 | IoC 容器 | 负责创建/连接对象;**禁止讲成魔法**,每次自动配置都要补"地下机械图" |

> Spring 铁律:凡出现自动配置,必须解释——谁创建了对象、Bean 从哪来、配置从哪读、请求如何到 Controller、Repository 如何连库。

## 固定每话模板(11 步)

每一话严格按此结构,漫画只承载心智模型与冲突,细节交给代码与手册:

```text
1. 事故或需求        —— 咖啡站遇到的真实问题
2. 4~8 格漫画(网页文本分格,不烧进图片)
3. 本话目标
4. 技术原理图        —— 城市地图 / 系统剖面图
5. 从上一话继续修改代码
6. 故意制造一个 Bug
7. 观察真实错误信息
8. 修复并运行测试
9. 项目检查点        —— 咖啡站长成什么样
10. 对应招聘技能      —— 与求职瞭望台联动
11. 下一话悬念
```

完成一话的闭环条件:看懂漫画 → 运行代码 → 主动触发一次错误 → 按报错修复 → 通过 JUnit → 完成小挑战 → 解锁项目新功能 → 进入下一话。

## Java 版本策略

- **主线基线:Java 25(最新 LTS)**;当前最新发布为 Java 26(非 LTS)。按最新 JDK 语法讲解。
- 用现代语法:箭头 `switch`、文本块、`var`、record、模式匹配、虚拟线程;初学入口可用 JEP 512 的隐式类 + 实例 `main` + `java.lang.IO`(`IO.println` / `IO.readln`,Java 25 转正)。
- 单独设"版本迁移番外":Java 8/11/17/21/25/26、`javax.*` → `jakarta.*`、Spring Boot 2→3→4 差异。
- 元数据里以 `javaVersion: "25"` 记录。

## 必须坚持 / 绝不做

**坚持**:一条连续项目;每话一个核心冲突;每话一个真实 Bug;每话代码可运行;每话至少一个测试;所有知识有前置依赖;所有高级技术说明它解决的实际问题;漫画/代码/手册/项目/求职互链。

**不做**:一次规划 200 话再开始;每个名词都造角色;十几个框架平铺同等重要;给零基础提前塞 Spring/Kafka/K8s;只出漂亮漫画却没有可运行源码;每话重建一个无关小项目;把招聘看板所有技术强塞主线。
