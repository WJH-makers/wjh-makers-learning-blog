## 0. 一句话定位

Java 线教你把咖啡站建成系统、JVM 线带你钻进炉底,这一部**让阿零学会「一群人一起算」**——把批处理与流处理的本质讲清,不堆术语。

面向的不是零基础读者,而是**读完 Java / JVM 线、想转数据方向的工程师**。本线差异化立场:**每个大数据概念都先还原成「一群人怎么分工」,每一次数据搬运都要能算清代价**——术语只是蚁群协作的名字。

## 1. 衔接与世界观

- 时间线:Java 线 S7(咖啡站上云)、JVM 线 F5(炉心大成)**之后**。咖啡站开了十年,订单数据堆到单机再也 load 不动,阿零决定把「一个人算」升级成「一群人搬」。
- 舞台:豆豆咖啡站**新建的数据机房**。第一次进机房,阿零在地砖缝里遇到本线导师——蚂蚁「群姐」。
- 五卷主线:卷一 数据变大之后(1-7)→ 卷二 批处理 MapReduce 到 Spark(8-14)→ 卷三 数仓与建模(15-21)→ 卷四 实时流处理(22-28)→ 卷五 湖仓与治理(29-34)。

## 2. 角色表(硬约束,防人设漂移)

### 群姐(Qun)—— 本线导师,蚁群指挥官

- **外形**:一只个头小得毫不起眼的蚂蚁,背上永远驮着一小块发亮的**数据分片**,走到哪把哪块地图补全。看着不起眼,一声令下却能召来千万只工蚁,协同搬运比自己重千倍的东西。
- **能力隐喻**:她本人就是"分而治之 + 移动计算"的具象化——从不亲自扛,只负责**把大问题拆成可并行的小问题、把计算调度到数据所在处**。
- **性格**:沉稳、务实、不吹术语;讨厌"没算过代价就上架构"的行为,凡事先掏出📦数据搬运账。
- **口头禅**:"**一个人搬不动,就让一万个人一起搬。**"(分而治之 / 水平扩展 / 并行度三关一语)
- **副口头禅**:"数据太大,就把计算搬到数据那儿去。"(移动计算而非移动数据;讲存算、shuffle、本地性时的一手原则)
- **能力边界(铁律)**:
  1. 只讲数据系统的事实与**代价账**,不替阿零写业务逻辑;给拆分思路、给搬运账,让阿零自己跑。
  2. 不下没有搬运账支撑的性能断言——她自己也遵守 §7 红线。
  3. 不吹"银弹引擎/架构";一切选型都摆权衡表,一句"看你要搬什么"。
  4. 排障沿用豆豆五步法,但群姐版第一步永远是"**先算这笔搬了多少**"。

### 阿零 —— 本线成长弧:从"一个人算"到"指挥一群人算"

延续前作人设:已能交付系统与调优 JVM,但面对"数据大到单机装不下"依旧本能地想 `load` 进内存。**每卷一次可见的能力上涨**:

| 卷 | 卷终时阿零能做到 |
|---|---|
| 卷一 | 想清楚"数据大了难在哪",把十年订单分区列存搬进数据湖 |
| 卷二 | 独立用 Spark 跑通离线报表,能读执行计划、能治倾斜 |
| 卷三 | 独立做维度建模、搭 ODS/DWD/DWS 分层、给出统一口径 |
| 卷四 | 独立写一个有状态、Exactly-Once 的 Flink 实时任务并接大屏 |
| 卷五 | 独立做一次湖仓/引擎选型并给出成本与治理方案——**能自己扛起大数据** |

### 客串规则(豆豆 / 特米 / 焰焰)

- **豆豆**:压测 / 造数发生器——**只在需要真实数据量的话出现**(把午高峰十年订单一次性砸下来当试炼),保持毒舌但**不当导师**(本线导师是群姐,豆豆只制造麻烦 + 吐槽一句)。
- **特米**(CLI 线):从机房通风管**递一句命令**(只递 CLI 线已教过的:`hdfs dfs`、`kafka-console-consumer`、管道、`ss` 等),台词一句,不抢戏。
- **焰焰**(JVM 线):在 shuffle / GC 卡顿话探头一句"先热身,再起飞",把 JVM 侧观测钩回 JVM 线;不在本线当导师。
- 群姐不去别线当导师;跨线联动只走 §8 钩子表。

## 4. 本线专属深度栏目(每话至少上其一)

### 🐜 分而治之台(把术语翻译成蚁群协作)

- **定位**:对标 JVM 线的 🔬 炉底显微镜;差异化 = **每个大数据概念,先还原成"一群人/一群蚂蚁怎么分工",再对回技术名词**。口号:"想不清一群人怎么搬,就别急着背术语。"
- **规则**:先画一句话的蚁群场景(谁扛哪段、在哪汇合、谁是瓶颈),再用一张表把"蚁群角色 ↔ 技术组件"对齐;严禁只堆概念不给分工画面。
- **格式模板**(以 MapReduce 为例):

  ```text
  > **🐜 分而治之台 · MapReduce 是一群蚂蚁怎么分工?**
  >
  > 场景:一万只蚂蚁,每只领一段小票各自数(局部),再按品类归到同一堆合计(汇总)。
  >
  > | 蚁群动作 | 技术名词 | 关键点 |
  > |---|---|---|
  > | 每只各扫一段 | map | 只碰本地数据,天然并行 |
  > | 按品类归堆 | shuffle | 跨蚂蚁搬运,最贵一步 |
  > | 同堆合计 | reduce | 每类一个结果 |
  >
  > 群姐结语:先想清一群人怎么分工,map/reduce 就不用背了。
  ```

### 📦 数据搬运账(算清一次搬运到底搬了多少)

- **定位**:本线的"证据栏"。凡涉及 shuffle / join / 全量扫描 / 网络传输,**必须把量算出来**——多少行、多少字节、跨多少机器、走多少网络,别只说"很慢/很贵"。
- **规则**:给出估算口径(行数 × 单行字节 × 副本/分区数),数量级正确即可,标注是估算还是实测;能给真实作业指标(Spark UI shuffle read/write、Flink 反压)则优先贴实测。
- **格式模板**:

  ```text
  > **📦 数据搬运账 · 这次 shuffle 搬了多少?**
  >
  > | 项 | 估算 |
  > |---|---|
  > | 参与行数 | 10 年 × 每天 5k 单 ≈ 1800 万行 |
  > | 单行字节 | ~200 B |
  > | shuffle 数据量 | ≈ 3.4 GB 跨网络重排 |
  >
  > 群姐锐评:能不 shuffle 就不 shuffle;真要搬,先把这笔账算给自己看。
  ```

## 7. 写作红线

### 7.1 版本敏感事实:发布前必须联网复核

- **铁律**:凡涉及"哪个引擎哪个版本引入/默认/移除某能力"(Spark/Flink/Iceberg/Hudi 的特性与 API、Exactly-Once 的实现细节、CDC 连接器),发布前逐条用 opencode+DeepSeek 或 context7 联网复核,**不凭记忆、不信旧博客**。核实优先于假设。
- 基线:Java 25 LTS;Spark 与 Flink 取撰写时稳定版,**具体小版本行为写前必查**,不确定的版本号写通用表述("现代 Spark/Flink 已支持…")。
- 每话触及即必查的高危清单:各引擎版本相关的 API 形态与默认值;Exactly-Once / 两阶段提交的前置条件;Iceberg/Hudi 表能力差异;OLAP 引擎选型事实(别把某家吹成银弹)。

### 7.2 术语一致性表(全线统一,首现标注英文)

| 统一用词 | 禁用/别名 |
|---|---|
| 数据倾斜(data skew) | 不写"数据偏斜/热点"混用,统一"数据倾斜" |
| shuffle(重排) | 首现标英文,后文 shuffle |
| 存算分离(storage-compute separation) | 不写"存储计算解耦"混用 |
| 数据湖 / 数仓 / 湖仓一体 | 三者严格区分,见卷五 29 话 |
| 事件时间(event time)/ 水位线(watermark) | 不写"处理时间"顶替事件时间 |
| Exactly-Once(精确一次) | 与 at-least-once/at-most-once 并列时保留英文 |
| 移动计算而非移动数据 | 副口头禅原句,不改写 |

### 7.3 其他红线

- **性能/成本断言必附📦数据搬运账**(估算口径或作业实测);没证据的性能话一律让群姐说"先把这笔账算给自己看"。
- 报错、作业输出、UI 指标一律真实实录,不许编造;编不出来就换一个真跑得出的例子。
- 便利贴语法沿用全站规范:`> [!吐槽]`、`> [!彩蛋]`、`> [!警告]` / `> [!坑]`、`> [!强调]` / `> [!重点]`、`> [!答案]`、`> [!文字版]`;漫画分格 `> **〔n〕**` 格间空行;固定栏目前缀 `> **🐜 分而治之台 · …**`、`> **📦 数据搬运账 · …**`、`> **📋 作业罚单**`。
- 继承 Java 线 §10 全部"必须坚持 / 绝不做";本线追加一条不做:**不堆术语当深度**——每个术语出场都必须先在🐜台还原成"一群人怎么分工"。
