## 0. 一句话定位

豆豆咖啡站要开连锁了——从一台咖啡机到一支舰队。跟着阿零和库舵,把"单机部署的手艺"炼成"声明式运维的道法",**每一话都能在博主自己那台 txcloud 服务器上真机复现**。

故事引擎一个隐喻贯穿到底:**咖啡站连锁化 = 应用云原生化**。开分店=多实例;任何一家断电顾客无感=自愈与弹性;新品配方全城同步上架=CI/CD;知道哪家店排队最长=可观测。

- 全 **5 卷 32 话** + 卷终附「前沿瞭望塔」番外页(不占话数)。
- 技术基线:Java 25 LTS / Spring Boot 4 / Ubuntu 24.04 / Docker Engine 29 / K8s v1.36.x(版本敏感,见 §10 红线)。

## 1. 角色表

### 库舵(Kubo)—— 本线导师,领航鲸

- **外形**:一头戴船长帽的领航鲸,曾是集装箱远洋货轮的传奇引航员("Kubernetes"本意即希腊语"舵手")。背上驮着一座微型集装箱码头,货柜可以随时吊装成任何设施。生气时喷水柱(OOMKill 的具象化)。
- **性格**:与特米的极客毒舌相反——**极度沉稳**,信奉"不描述过程,只宣告终态"。不催、不吼,只把海图摊开。
- **口头禅**:「**对不齐?Reconcile 一下。**」(对标特米的"man 一下")——任何现实与期望不符的场景,都用这句把阿零从"手动抢救"拉回"声明式收敛"。
  副口头禅:「Pending 不是病,是调度器在替你想。」
- **能力边界(硬约束)**:
  - 只管**编排与终态**,不写业务代码——Java 代码是阿零(和豆豆)的事;
  - 不替阿零敲命令:只报对象名和该看的字段("describe 一下那个 Pod,看 Events"),让阿零自己查——继承豆豆五步排障法与特米"授人以渔"的家风;
  - **反过度工程**是他的原则性台词:对"单机够用"的场景会主动劝退 K8s("不是所有店都要开连锁,单店本身就是一种正确架构")。

### 阿零 —— 读者代理,本线成长弧

延续 Java 线、CLI 线人设与已获能力:**会写能交付的 Spring Boot 4 系统(Java S1–S7),会驯服一台真实服务器(CLI C1–C5)**。本线核心冲突:"会部署一台机器 ≠ 会运维一支舰队"。每卷能力必须**可见地上涨**:

| 卷 | 阿零的状态 | 卷末拿到的能力 |
|---|---|---|
| 卷一 | docker 命令侠,靠手敲 run/exec 抢救 | 会把整店写成一页 compose,理解镜像与容器的本质 |
| 卷二 | 会写 YAML,但一出事仍想 `kubectl exec` 进去手改 | 被"Reconcile"驯化:改期望不改现实,读得懂对象模型 |
| 卷三 | 遇 Pending/OOM 只会喊库舵 | 能独立从 Events + describe 定位调度与资源问题 |
| 卷四 | 发版仍靠 ssh 上服务器拉代码 | 亲手搭起流水线,**戒掉 ssh 改线上**;懂"Git 没改就等于没改" |
| 卷五 | 出事后靠猜和重启 | 能用三支柱从告警走到根因,主动给库舵提 SLO 方案 |

### 豆豆 —— 被编排的对象(常驻客串)

咖啡站化身,本线身份是**工作负载视角**:库舵是编排者,豆豆是被编排者。两者"管理者 vs 被管理者"的对话是常驻笑点(被罩进 namespace 隔间、被 OOM 水柱冲走、日记被要求改成 JSON)。规则:**每卷至少客串 1 次,不喧宾夺主**;卷一、卷二戏份最多。

### 特米 —— 卷四常驻客串

CLI 线导师。**卷四(22–27 话)以"流水线脚本顾问"常驻**:Actions 的 `run:` 步骤全是 CLI 线学过的命令,由特米点评。与库舵固定互怼:「man 一下就懂」vs「Reconcile 一下就好」。其余卷不出现,或最多一格彩蛋。

### 技术角色(每个 = 一种稳定心智模型;禁止每个名词都造角色)

| 角色 | 代表 | 设定要点 | 首次登场 |
|---|---|---|---|
| 海图 | etcd / 期望状态 | 库舵随身摊开的航海图,画上去的就是"该有的世界" | E08 |
| 总机小姐 | Service 与集群 DNS | 手持实时花名册(Endpoints),顾客只拨名字不拨工位号 | E11 |
| 事故怪家族 | 云上典型故障 | Pending 迷雾、CrashLoop 旋涡、ImagePull 幽灵、OOM 水柱、latest 漂移怪 | 逐卷登场 |
| 巡查鸟 Argo | GitOps 控制器 | 盯着圣旨仓库,谁私改集群就当场改回(漂移纠正) | E27 |
| 抄表员普罗米 | Prometheus pull 模型 | 定时巡店抄数,只信仪表不信"感觉" | E29 |

## 2. 每话固定骨架(11 步,继承 Java 线,本线特化)

每话严格遵守;第 9 步为本线专属固定段(见 §3)。字数量级为**字符数**,合计对齐 §4 篇幅约束。

```text
1. 事故或需求(~150)     —— 连锁化路上的真实问题;一句"承上"接上一话的坑
2. 4~8 格漫画(800–1200) —— 网页文本分格;必含"阿零翻车 + 库舵点拨 + ≥1 个技术角色或豆豆"
3. 本话目标(~100)       —— 5 条以内,动词开头
4. 技术原理图(400–600)  —— 海图 / 码头剖面 / 对象关系图;先给心智模型再给 YAML
5. 从上一话继续改清单(600–900)—— Dockerfile/compose/YAML/workflow 从上一话的产物继续长,
                              明确"在上一话哪段之上加了什么";绝不推倒重来
6. 故意制造一个事故(200–300)—— 优先真实云原生翻车,见下方事故清单
7. 观察真实输出(300–400) —— kubectl describe/events、docker logs、Actions 日志,
                              必须"真跑得出来",不能编
8. 修复并验证收敛(300–500)—— 声明式验证:改期望→看收敛(rollout status / get -w /
                              curl 探活 / echo $?);继承 CLI 线"用命令验证"的放宽
9. ⚓ 真机靠港(400–600)  —— 本线专属固定段,格式见 §3;每话必有
10. 项目检查点 + 对应招聘技能(~200)—— 连锁版本链走到哪(见 §5);招聘技能不能空
11. 下一话悬念(~50)      —— 一句"启下",与下一话"承上"必须能对上
```

**事故清单(第 6 步优先从这里选)**:ImagePullBackOff、CrashLoopBackOff、OOMKilled、Pending、`latest` 漂移导致两店风味不同、层缓存顺序写反、容器重启数据清零、Secret 被当成加密、liveness 把慢启动的 JVM 杀成死循环、CI 凭证明文进 YAML、crontab→CronJob 时区错位。

**深度层**:🔀 多解台 / 🎯 面试直击 沿用 Java 线格式;⏳ 版本时光机按需(典型:Ingress→Gateway API、docker-compose v1→compose v2、长期 AK/SK→OIDC、厂商 SDK→OTel、Terraform→OpenTofu)。一话最多 2 个深度栏目;**⚓真机靠港是固定段,不占深度栏目额度**。

## 3. 本线专属深度栏目:⚓ 真机靠港(每话必有,固定在第 9 步)

**作用**:把当话概念"靠港"到博主真实部署链路——GitHub Actions 构建 → 镜像 → txcloud 服务器 docker compose → nginx → Cloudflare Tunnel → wwjjhh.online。左栏教科书姿势,右栏 2C 小水管的务实姿势,**明说取舍**。这与 CLI 线的 🪟双系统对照呼应:那边对照两种 shell,这边对照"理想集群 vs 真实小服务器"。

**格式模板**:

```text
> **⚓ 真机靠港 · <本话概念>落在 wwjjhh.online**

| | 教科书姿势(K8s / 云上) | 我这台 2C 小水管(compose / 单机) |
|---|---|---|
| 做法 | … | … |
| 为什么 | … | … |
| 取舍 | … | … |

库舵结语:<一句话点破取舍——单店(单机 compose)本身就是一种正确架构>。
```

**示例(E06 断电惊魂 · Volume 持久化)**:

> **⚓ 真机靠港 · 数据持久化落在 wwjjhh.online**
>
> | | 教科书姿势(K8s / 云上) | 我这台 2C 小水管(compose / 单机) |
> |---|---|---|
> | 做法 | PVC + StorageClass 动态供给,Pod 漂到哪卷跟到哪 | compose 具名卷 `mongo-data`,落在宿主 `/var/lib/docker/volumes` |
> | 为什么 | 集群里 Pod 会被重新调度,存储必须与节点解耦 | 单机不漂移,本地卷 + 每晚 cron 备份足够 |
> | 取舍 | 多一层抽象,换来可调度性 | 少一层抽象,换来可理解;**备份纪律替代存储冗余** |
>
> 库舵结语:账本放保险柜是原则,保险柜租在银行还是砌在自家墙里,看你有几家店。

**约束**:必须表格化;右栏必须是博主真实配置的事实(compose 文件、deploy-final 脚本、nginx、CF Tunnel),不许虚构"假装我有集群";涉及线上真实路径/密钥一律脱敏。

## 7. 统一视觉与命名符号

- 标题:`《从零开始上云原生》0x · 本话名`,H1 唯一;小节 `## 一、…` 对齐 §2 骨架。
- 首行元信息引用块两行:卷/话定位 + 连锁版本提示。
- 漫画分格 `> **〔n〕**` + 对白,格间空行;引用内可嵌代码围栏(渲染引擎已支持)。
- 固定短栏目前缀:
  - `> **库舵航志**:…`(旁白/补充/捷径,对标豆豆旁白)
  - `> **库舵锐评**:…`(点破本质/踩坑,对标豆豆锐评)
  - `> **📋 事件簿**` + 真实 `kubectl describe`/Events/日志代码块(对标编译官罚单)
  - `> **⚓ 真机靠港 · …**` / `> **🔀 多解台 · …**` / `> **⏳ 版本时光机 · …**` / `> **🎯 面试直击**`
- **便利贴语法沿用**(`lib/markdown.ts` 已支持):`> [!吐槽]`(豆豆/阿零吐槽)、`> [!强调]`/`> [!重点]`、`> [!警告]`/`> [!坑]`、`> [!打趣]`/`> [!彩蛋]`;`> [!答案]` 渲染为折叠块(放选做的进阶推导)。
- 结尾署名行:`*本话属于连载《从零开始上云原生》。世界观见 handbook.md;卷次地图见 /cloud。*`

### 术语一致性(硬约束)

- 隐喻词典全线唯一,不得中途换喻:吧台=Pod、店员=容器、开店令=compose 文件、海图=etcd/期望状态、总机=Service、菜单上墙/秘方锁抽屉=ConfigMap/Secret、饭量申报=requests/limits、圣旨仓库=Git、批次号=digest。
- 术语首次出现给"中文 + 英文原词",此后全线统一同一译名;`kubectl`/Actions 输出保持英文原样不翻译。
- 主线写法基线:Compose 规范(`docker compose` 子命令,不写 `docker-compose`)、Gateway API(Ingress 只出现在"退役"叙事里)、GHCR、OpenTofu 与 Terraform 并提。
