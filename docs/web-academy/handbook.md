## 一、一句话定位与衔接

从一个 `<div>` 到豆豆咖啡站官网上线——用 Java 工程师的第一性原理,把 TS / React 19 / Next 16 的"魔法"逐层拆成看得见的机器。

- 承接:Java 线 S7 咖啡站后端上云、CLI 线 C5 服务器安家之后,**顾客抱怨"没有官网、点单靠喊"**。阿零决定给豆豆咖啡站做官网 + 在线点单站。
- 本线核心冲突:**会写后端 ≠ 会写界面**。阿零满脑子 Controller/DTO/名义类型,前端世界处处反直觉——这既是他的翻车来源,也是本线区别于所有前端教程的差异点(每个概念都给 Java 对照)。

## 二、角色表

### 薇塔(Vita)—— 本线导师

- **外形**:一只蜂鸟,名字取自 Web **Vita**ls。每秒振翅恰好 60 次("掉到 59 我就浑身难受")。常驻咖啡站窗台的喂食器;羽毛颜色随页面主题色实时变化(体内流着 CSS 变量);脖子上挂一块**毫秒怀表**,任何页面看一眼就报出 LCP/INP/CLS 三个数。
- **性格**:优雅、毒舌、拒绝一切"我感觉挺快的"。看到卡顿会炸毛:"掉帧了!掉帧了!"
- **口头禅**:「**别猜,量一下。**」
- **能力边界(硬约束)**:
  - 只管**浏览器半径**:类型、渲染、样式、组件、性能。**不写后端**(API 归豆豆 / Java 线),**不碰服务器运维**(归特米)。
  - 不替阿零写代码:她只**报数字、给方向、拆心智模型**,动手永远是阿零(对应特米的"只报命令名不代敲")。
  - 排障沿用豆豆五步法:观察现象 → 收集报错/读表 → 提出假设 → 改一个变量 → 重跑验证。
- **固定短栏目**(对应 Java 线"豆豆旁白/豆豆锐评"):
  - `> **薇塔读表**:LCP …s / INP …ms / CLS …`(用真实可测的数字开场或验收)
  - `> **薇塔锐评**:…`(一句点破本质/踩坑)
  - `> **📋 tsc 罚单**` + 真实 TS 报错代码块(编译官罚单的本线版)

## 四、本线专属深度栏目:🧭 渲染罗盘(每话必有)

把本话代码钉在一张四象限小地图上——**构建期 / 服务器 / 边缘 / 浏览器**,标出"这段代码到底在哪跑、什么时候跑、跑几次",并固定补一句 Spring Boot 对照。38 话连起来 = 一张完整的现代 Web 渲染位置总图。

格式模板:

```text
> **🧭 渲染罗盘 · 本话代码钉在哪**
>
> | 本话代码 | 位置 | 时机 | 跑几次 |
> |---|---|---|---|
> | <文件/函数> | 构建期/服务器/边缘/浏览器 | 构建时/请求时/水合后/交互时 | 一次/每次请求/每次交互 |
>
> ☕ 如果是 Spring Boot:<一句对照,如"相当于 Controller + 模板引擎在服务器渲染,只是这里连'接口层'都省了">。
```

示例(话 29"在后厨直接拿数据"):

> **🧭 渲染罗盘 · 本话代码钉在哪**
>
> | 本话代码 | 位置 | 时机 | 跑几次 |
> |---|---|---|---|
> | `app/menu/page.tsx`(async 组件) | 服务器 | 请求时 | 每次请求(同请求内 fetch 记忆化只跑一次) |
> | `AddToCartButton.tsx`('use client') | 浏览器 | 水合后 | 每次交互 |
>
> ☕ 如果是 Spring Boot:相当于 `@Controller` 查库后塞给模板——但这里组件自己就是"查库的地方",没有中间商。

约束:每话罗盘只钉**本话新增代码**(2–4 行表格),不重复钉旧代码;"Spring 对照"只许一句,展开欲望留给 🎯 面试直击。
其余栏目沿用 Java 线:**🔀 多解台**(典型触发:状态放哪/样式方案/数据获取方式/表单三写法)、**🎯 面试直击**(事件循环、key、水合、缓存四层是本线高频区)、**⏳ 版本时光机**(class 组件→Hooks→Compiler、float→flex→grid、CJS→ESM、手写 memo→自动记忆化;主线仍以 2026 现行写法为准)。

## 七、写作红线

### 7.1 版本敏感事实:发布前必须联网复核

前端版本迭代远快于 Java——**凡出现在正文的版本号/稳定状态/浏览器支持度,发布当话前用 opencode+deepseek 或 context7 复核一次**,以复核日期为准,不吃底稿老本。基线(2026-07-26 已核实 ✅):TS 7.0(tsgo,Go 重写)已稳定;Next.js 最新 16.x、无 17,`use cache`/Cache Components 已稳定(需 `cacheComponents: true`);React 最新 19.2.x、无 20;React Compiler 1.0 于 2025-10 稳定;INP 已取代 FID。

**底稿遗留 ⚠ 未核实条目(写到对应话前必须先核实,原样照录):**

- 「52. CSS Anchor Positioning 与 Popover API — 弹层/浮层不再依赖 JS 定位库;⚠ 各浏览器 Baseline 覆盖进度未核实。」(涉及话 38 彩蛋/番外)
- 「53. Baseline 与 Interop — 以 "Baseline 2026" 判断 CSS/JS 特性可用性,替代逐浏览器查表;⚠ Interop 2026 重点项未核实。」(涉及话 38)

复现基线:Node 22+ / Next 16 / React 19.2 / TS 7 / Chrome 最新稳定版;所有报错与怀表读数必须在此基线下真实跑出。

### 7.2 术语一致性(全线统一,首次出现括注英文)

水合(Hydration,禁"注水");重排(Layout,禁与"回流"混用);服务端组件/客户端组件(禁"服务器组件"混写);判别联合(Discriminated Union);受控/非受控;依赖数组;协调(Reconciliation)。RSC/SSR/SSG/ISR/PPR/CWV 等缩写首次出现必须展开一次。

### 7.3 便利贴与折叠语法(沿用既有渲染引擎)

- `> [!文字版]`:漫画分格的文字版容器(同 Java 线)。
- `> [!吐槽]`:薇塔/豆豆吐槽便利贴。
- `> [!答案]`:折叠块(渲染为 details),放练习答案或可跳过的延伸原理。
- `> [!彩蛋]`:结尾冷幽默/跨线彩蛋。
- 引用块内可嵌代码围栏(`lib/posts.ts` 已支持),漫画分格里可直接放小段 tsx。

### 7.4 其余继承 Java v2 的硬约束

每话一个核心冲突、一个真实 Bug、代码可运行且延续;加深度靠密度不靠长度;不做:一次写完 38 话、给每个 API 造角色、把框架平铺同权重、只出漫画没有可跑代码、先用后讲。
