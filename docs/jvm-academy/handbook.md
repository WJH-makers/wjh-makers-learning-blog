## 0. 一句话定位

Java 线教你"会写",这一部带阿零钻进烘豆炉——**看懂 JDK 21→25 每一次进化在 JVM 里到底烧了什么**,顺手补齐附录 D 欠下的类库债(时间/正则/队列/IO/反射/枚举)。

面向的不再是零基础读者,而是**读完 Java 线的进阶者**。因此本线的差异化立场是:**一切结论都要能在自己机器上观测复现**——"上层一行糖,炉底几行霜"。

## 1. 衔接与世界观

- 时间线:Java 线 S7 大结局(咖啡站 v7 上云)与 CLI 线 C5(部署大闭环)**之后**。订单暴涨引发性能危机,阿零决定把整个后厨系统升级到 Java 25,却发现地下一层"烘焙工坊"的 HotSpot 烘豆炉里住着一位老住户。

## 2. 角色表(硬约束,防人设漂移)

### 焰焰(Yan-Yan)—— 本线导师,HotSpot 火蜥蜴

- **外形**:栖息在烘豆炉里的火蜥蜴。**尾巴温度随代码"热度"变红**(热点探测的具象化);蜕下的旧皮自己分拣进"新皮区/老皮区"(分代 GC 的日常)。随身一本会自动续页的《JEP 编年史》,能召唤历代 JDK 的**版本残影**重演当年的设计争论(每话至多召唤一次,防滥用)。
- **性格**:慢热毒舌,嫌弃一切"没预热就下结论"的行为;对"网上抄来的旧攻略"零容忍。

  4. 沿用豆豆的五步排障法(观察 → 收集 → 假设 → 改一个变量 → 重跑验证),但焰焰版第一步永远是"**先复现,再谈论**"。

## 4. 本线专属深度栏目:🔬 炉底显微镜(每话必有,恰好 1 个)

- **定位**:对标 Java 线的 🔀 多解台、CLI 线的 🪟 双系统对照;差异化 = **永远给出"可自己复现的观测命令"+ 真实输出实录**。口号:"上层一行糖,炉底几行霜。"
- **规则**:
  1. 命令照抄可跑,基线 JDK 25;Windows(PowerShell 7)与 Linux(deployment-server Ubuntu)写法有差异时一句注明。
  2. 输出必须真实跑出来再节选,**≤15 行**,不许手编;逐行解读 2–4 条,每条一句话。
  3. 按卷推荐工具箱:卷一 `javap -c/-p`;卷二 `java` 单文件直跑 + JShell;卷三 `javap` + 反射耗时对比;卷四 `jcmd <pid> Thread.dump_to_file`、JFR 虚拟线程事件;卷五 `-Xlog:gc*`、`-XX:+PrintCompilation`、`jfr print`。
- **格式模板与示例**(以第 02 话 record 为例):

  ```text
  > **🔬 炉底显微镜 · 一行 record,编译器替你写了几行?**
  >
  > 复现命令(照抄可跑):
  > ```bash
  > javac OrderCard.java && javap -p OrderCard
  > ```
  > 关键输出(节选,真实实录):
  > ```text
  > final class OrderCard extends java.lang.Record {
  >   private final java.lang.String item;
  >   private final int price;
  >   public final boolean equals(java.lang.Object);
  >   public final int hashCode();
  >   public final java.lang.String toString();
  >   public java.lang.String item();
  >   public int price();
  > }
  > ```
  > 逐行解读:① 隐式继承 Record 且 final,没人能 extends 你的订单;② 字段全 final——不可变从字节码层面兑现;③ equals/hashCode/toString 是编译器盖的章,不是运行时魔法。
  > 焰焰结语:你少写的 40 行,一行都没消失——只是搬进了炉底。
  ```

## 7. 写作红线

### 7.1 版本敏感事实:发布前必须联网复核

- **铁律**:凡涉及"哪个 JDK 引入/转正/预览/默认开或关/被移除",发布前逐条用 opencode+DeepSeek 或 context7(`/websites/openjdk_projects_jdk_25` 等)联网复核,**不凭记忆、不信旧攻略**。核实优先于假设。
- 本线知识底稿(`knowledge-java-lang.md`)中标 **⚠未核实 的条目:零条**(通篇无 ⚠ 标记;底稿全部版本敏感事实已于 2026-07-26 核实)。底稿头部四项核实锚点原样转录如下——注意"已核实"有效期截至 2026-07-26,**发布日仍须复查**:
  1. Scoped Values(JEP 506)在 JDK 25 **已转正**;
  2. Structured Concurrency 在 25 **仍为预览**(第五预览,26 为第六预览);
  3. Compact Object Headers(JEP 519)在 25 **转正为产品特性但默认关闭**(需 `-XX:+UseCompactObjectHeaders`);
  4. 截至 2026-07 最新版为 **JDK 26**(2026-03-17 GA,含 HTTP/3 JEP 517、结构化并发六预 JEP 525 等)。
- 每话触及即必查的高危清单:所有 JEP 编号与其在目标 JDK 的状态;一切"默认开启/关闭"断言(ZGC 分代默认、UTF-8 默认 charset、紧凑对象头);预览特性的启用 flag 写法;JDK 26+ 的任何内容;结构化并发的 API 形态(预览期易变)。
- **String Templates 已于 JDK 23 撤回——严禁再教**;它只能以"纪念碑彩蛋"身份出现。
