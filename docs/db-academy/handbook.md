## 0. 一句话定位

豆豆咖啡站的订单越来越多,一张 Excel 撑不住了——阿零跟着万象图书馆的海豚馆长琪拉,从建库建表一路修到向量检索,把"数据存在哪、怎么找得快、坏了怎么办"讲成一部图书馆经营记。

**世界观映射(全线统一,不许一话一变)**:数据库 = 万象图书馆;表 = 书架;行 = 图书;索引 = 目录卡片柜;事务 = 借阅登记流程;缓存 = 前台速取架;备份 = 地下典藏库。咖啡站每次搞活动(秒杀、会员日),图书馆就迎来一次大考。

**本线灵魂句(对标 Java 线"漫画负责为什么"):证据,不是感觉。** 一切优化与断言都要先看执行痕迹,再下结论。

## 1. 角色表

### 1.1 导师:海豚馆长"琪拉"(Sakila)

| 维度 | 设定 |
|---|---|
| 外形 | 蓝色海豚,细框眼镜,鳍上永远夹着一叠目录卡片(致敬 MySQL 吉祥物 Sakila) |
| 性格 | 处女座式严谨;痛恨"凭感觉优化";任何断言必须先看证据;严厉但从不羞辱人 |
| 口头禅 | **"先 EXPLAIN 一下!"**(与特米"man 一下"隔线呼应);阿零说"我觉得……"时用鳍拍桌:"觉得?图书馆不收'觉得'。" |
| 教法 | 不替阿零写 SQL;先让他跑出证据(EXPLAIN / STATUS / slow log),再带他逐列读;修复后必须"前后证据对比"收尾 |
| 能力边界 | 只精通关系库(MySQL 域);速取架的事尊重红枣、自由书舍的事尊重阿檬,**不越界代答**;不懂咖啡站业务,业务侧永远问豆豆/阿零 |

## 3. 本线专属深度栏目:🔬 显微镜下

**作用**:每话一格,把当话的一条真实 SQL / 命令放到"显微镜"下,展示内部执行痕迹——这是本线区别于所有数据库教程的差异点(对标 Java 线 🔀/⏳/🎯、CLI 线 🪟)。口号:**"证据,不是感觉。"**

**素材来源(按话选一)**:EXPLAIN 输出逐列解读、`SHOW ENGINE INNODB STATUS` 片段、`SHOW PROFILE`/performance_schema、Redis `OBJECT ENCODING` / `MEMORY USAGE` / `DEBUG`、Mongo `explain("executionStats")`。

**格式模板**:

```text
> **🔬 显微镜下 · <本话标本名>**
>
> ```sql
> EXPLAIN SELECT ...;
> ```
>
> | 列 | 值 | 琪拉的解读 |
> |---|---|---|
> | type | range | 用上了索引范围扫,不是全表 |
> | key | idx_xxx | 优化器选中的目录柜 |
> | rows | 42 | 预计翻 42 张卡片(优化前是 20 万) |
> | Extra | Using index | 覆盖索引,免回表 |
>
> 琪拉结论:<一句证据驱动的判断,禁止"感觉快多了">。
```

**约束**:输出必须来自基线环境真跑(§8);逐列解读只讲本话已授概念,超纲列写"下回分解(第 X 话)";每话一格,不重复堆多份证据。

**其余栏目沿用 Java 线规范**:🔀 多解台(如:分页三解法、判重三解法、缓存一致性方案对比)、🎯 面试直击(本线弹药极充足:回表、MVCC、两阶段提交、缓存三连……)、⏳ 版本时光机按需(如 5.7→8.0→8.4/9.7、ziplist→listpack、语句复制→行复制)。**🔬 为固定段不占配额;此外一话最多再上 2 个深度栏目**,全部表格化,防臃肿。

## 6. 写作红线

### 6.1 版本敏感事实:发布前必须联网复核清单

知识底稿(`knowledge-database.md`)的版本事实于 **2026-07 用 opencode+DeepSeek 核实(标 ✅)**;底稿当前**没有 ⚠未核实 条目**——若日后底稿新增 ⚠ 条目,必须**原样搬进本清单**,未核实前该话禁止发布。✅ 条目**发布距核实超过 30 天的,发布前重核一次**(用 `search` 技能委托 opencode,绝不凭记忆):

1. ✅ MySQL 版本现状 — 8.0 已于 2026-04(8.0.46)EOL;8.4 LTS 维护至约 2032;最新 LTS 为 9.7(2026-04 GA),Innovation 线 9.6.x。选版本认准 LTS。(用于第 34 话版本年鉴、⏳ 栏目)
2. ✅ Redis 8 与许可证回归 — Redis 8.0(2025-05 GA)起采用 AGPLv3/RSALv2/SSPLv1 三许可,重新算开源;此前分叉出的 Valkey(Linux 基金会、BSD、最新 9.x)已被 AWS/GCP 默认支持——选型要认清"Redis 系"已是两家。(用于卷五、第 34 话)
3. ✅ MongoDB 现状 — 最新大版本 8.0(2024-10 GA,EOL 2029),Rapid Release 已到 8.3.x,9.0 已出 alpha;SSPL 许可未变。(用于卷六)

以及散落在正文里的版本敏感断言,凡出现必复核:listpack 取代 ziplist 的版本、hash join(8.0.18+)、ICP(5.6+)、Online DDL instant 支持范围、MySQL 9 原生 VECTOR 类型、HikariCP 在 Spring Boot 当前大版本中的默认参数、Valkey/Milvus/Qdrant/pgvector 最新版本号。

### 6.2 环境基线(输出可复现的前提)

- MySQL:**8.4 LTS** 为主线基线(部署面最广);9.7 LTS 新特性只进 ⏳ 版本时光机或卷六前沿,必须标注版本。
- Redis 8.x / MongoDB 8.0 / Ubuntu 24.04(继承 CLI 线服务器设定);Java 侧沿用 Java 线基线(Java 25 + Spring Boot 4)。
- **所有 SQL/命令输出必须在基线环境真跑得出**;造数规模要写明(如"orders 100 万行"),否则 EXPLAIN 的 rows 无法复现。

### 6.3 术语一致性

- 比喻词只出现在漫画格与剖面图;硬核段(5–9 步)一律用标准术语,首次出现给英文:回表(back to index / 二级索引回聚簇)、覆盖索引(covering index)、临键锁(Next-Key Lock)、缓冲池(Buffer Pool)、两阶段提交(2PC)、读视图(ReadView)。
- 固定映射不许漂移:目录卡片柜=索引、主目录柜=聚簇索引、卡片柜=二级索引、"再跑一趟"=回表、速记板=redo log、《馆务日报》=binlog、时间眼镜=ReadView、速取架=缓存、典藏库=备份。新比喻先加进本表再用。
- "琪拉"行文一律用中文名;括注 Sakila 只在首话出现一次。
